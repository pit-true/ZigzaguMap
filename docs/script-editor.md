# スクリプト編集と再生

イベントのスクリプトを、ラベルの名前で `.s`（`assembly/overworld_scripts`）と結び付け、内蔵のスクリプトエディタで書けるようにしました。CFRU-JP のフォルダ（プロジェクトフォルダ）を開いているときに使えます。素の ROM だけのときは、ROM のスクリプトを読み取り専用で見られます。

ふだんの流れ:

1. イベントタブでイベントを置く（イベントマネージャーで数を増やす）と、ラベル（例 `Moegi_Npc3`）が付き、ひな形がすぐマップの `.s` と `.string` に書かれます（「[ラベルの自動命名とひな形](#ラベルの自動命名とひな形)」）。マップの `.s` が決まっていなければ、ファイル名を聞いて作ります。
2. イベントをダブルクリック（か「スクリプトを開く」）すると、スクリプトエディタの別ウィンドウでそのラベルの行が開きます。補完・ホバー・色付け・定義へ移動・波線を使って本文を書き、文字列はホバーの「本文を編集」でその場で直します（入力中は字数の幅検査。Chronos は保存時に `check_text_width.py` も動く）。Ctrl+S で保存します。
3. ラベル名を変えたいときは、エディタで F2 を押します。`.s` の定義と参照と、そのラベルを使っているイベントのラベルが一緒に変わります。
4. メインで出力（Ctrl+S）すると、`eventscripts` の行と `maps\BB\scripts_MM.json` を書きます。
5. エディタの下のビルドの欄（Ctrl+B。メインはツール > ビルド、F7）でビルドし、エラーの行を押すとその行を開きます。

ラベルの付いていない（ROM のスクリプトを指す）イベントは、ROM のスクリプトを `xse_commands.s` の書き方で読み取り専用のタブに出し、「.s に取り込む」でラベルを付けて `.s` と `.string` に書き足せます。マップスクリプトは、場所の設定タブの「かんたん（CFRU）」表示の専用のパネルで、種類ごとの行き先と条件表を編集します。

### 書き出すファイル

| ファイル | 中身 | 書くとき |
|---|---|---|
| `eventscripts` | 1 行 1 件の `種別 バンク マップ [番号] シンボル`（CFRU の `scripts/insert.py` が読む）。ZigzaguMap が変えるのは `#ifdef` の外の、ラベルを変えたマップの行だけ | 出力（Ctrl+S） |
| `maps\scripts.json` | バンク・マップと `.s`・`.string` の対応表（「[eventscripts と maps\scripts.json](#eventscripts-と-mapsscriptsjson)」） | 出力（表を変えたときだけ） |
| `maps\BB\scripts_MM.json` | マップごとのイベントのラベルと照合用の座標、マップスクリプトの表（「[ラベルの持ち方](#ラベルの持ち方mapsbbscripts_mmjson)」） | 出力 |
| `assembly\overworld_scripts\*.s`、`strings\*.string` | ひな形・取り込み・マップスクリプトの表。新しい `.s` は決まった先頭で作る | ひな形と取り込みはすぐ（エディタで開いていればエディタの本文へ）、表と新しいファイルは出力 |

### ND と Chronos の違い

方言は `xse_commands.s` の `loadpointer` の引数の数で決めます（「[スクリプトの設定](#スクリプトの設定zigzagumapjson)」）。

| 項目 | ND（NeoDark-CFRU） | Chronos |
|---|---|---|
| 0F（`loadpointer`） | 2 ポインタ（ひらがなと漢字、10 バイト） | 1 ポインタ（6 バイト） |
| `msgbox` の文字列の引数 | 2 つ（`msgbox gText_X MSG_FACE gText_X_k`） | 1 つ |
| ひな形と取り込みの文字列 | ひらがなと漢字の 2 つ（同じ本文の `_k` も作る） | 1 つ |
| `.global` | 付けない | 付ける |
| `.string` の名前 | `overworld_strings_<.s の名前>.string` | 機能ごとの名前が多い（対応表で指定する） |
| ビルド | CFRU の `python scripts/make.py` → `test.gba` を DPE の `BPRJ0.gba` へ写す → DPE の `python scripts/make.py` | 1 つ上の `Chronos` で `python build.py` |
| できる ROM | `../NeoDark-DPE-main/test.gba` | `../build/Chronos.gba` |
| 保存時の幅検査 | 無し | `python tools/check_text_width.py --source`（新しい `#org` は `strings/text_width_registry.json` に登録する） |

### 写しのテスト（ND と Chronos）

ユーザーの実フォルダには書かず、写しで確かめます（ローカルだけ。設定は「[開発](development.md#開発)」の `tests/realcopy/local.config.json`）。

```sh
python tests/realcopy/run.py --smoke --reuse            # 開いて何もせずに出力し、写しでビルドする
python tests/realcopy/run.py --link --reuse             # Phase2 の通し（下の流れ）
python tests/realcopy/run.py --delete --reuse          # イベントの削除と複数行の文字列（下の流れ）
python tests/realcopy/run.py --connection --reuse --only nd  # 接続の編集（Phase3。角のつまみ・新しいマップ）を出力してビルドし、ROM の接続を確かめる
python tests/realcopy/run.py --template --reuse        # 使われている番号の索引とイベントのひな形（下の流れ）
python tests/realcopy/run.py --all --reuse --only nd    # 全部。--only で ND か Chronos だけ
python tests/automation/rom_only_script_check.py --rom <素の BPRJ>   # 素の ROM だけのときの表示
```

`--link` は、写しで次を順に行います: 新しい `.s` の行を対応表に足す → マップ 3.0 に人・看板・スクリプトタイルを置く（ラベルとひな形）→ 元に戻す・やり直す → エディタで人のスクリプトを開いて 1 行足し、文字列をその場編集する（幅検査の波線が出て、直すと消える。Chronos は `check_text_width.py` が動く）→ F2 でラベル名を変え、イベントのラベルが変わる → 素の ROM のスクリプトを取り込む → マップスクリプトの表を作り、行き先を取り込む → 出力 → ビルドの欄でビルド → できた ROM を開き、イベントのスクリプトの番地が `offsets.ini` のラベルの位置と同じこと、足した行がスクリプトに入ったことを確かめる。写しのテキストファイルは最後に元へ戻し、実フォルダの更新日時が変わっていないことも確かめます。

`--template` は、写しで次を順に行います（#227・#243〜#245。trainers のパッチを当てた写しで動かす）: 索引を作り終え、未使用の最小のフラグ・変数・隠しアイテムの番号・トレーナーの番号が索引のどこにも無く、`.s` と C にも（数でも名前でも）出てこないことを確かめる → マップ 3.0 にひな形を 1 つずつ置く（人・看板・スクリプトタイル・落とし物の看板とボール・アイテムをくれる人・ショップ・既存のトレーナー・自動生成した新しいトレーナー）→ 最後のものを元に戻す・やり直す → 「未使用」ボタンで人のフラグとスクリプトタイルの変数を入れる → 右クリックの「ここにひな形を置く」の窓を出す → 出力して `maps\trainers.json` を確かめる → ビルドする（ND は CFRU と DPE）→ できた ROM で、置いたイベントのスクリプトの番地が `offsets.ini` のラベルの位置と同じこと、アイテムをくれる人の `checkflag`・ショップの品物・`trainerbattle` の番号・隠しアイテムの看板の中身・トレーナーの表の新しい行（ほかの行は元の ROM と同じ）を確かめる。

`--delete` は、写しのビルド側を新しい版にしてから（ND は build-support のパッチを当て、Chronos は実フォルダの string.py・map_project.py・check_text_width.py を写す）、次を順に行います: マップ 3.0 に人を置き、「本文を編集」で文字列を制御記号のあとで改行した複数行にして保存する（Chronos は幅検査が通る）→ 素の ROM のスクリプトの人を探して確認のダイアログから消す（`maps\rom_erase.json` に範囲が記録され、元に戻す・やり直すも）→ 出力してビルドし、記録した範囲がすべて 0xFF で、複数行の文字列のバイト列が 1 行で書いたときと同じことを確かめる → 置いた人を右クリックの「イベントを削除」で消し、`.s` と `.string`（ND は `_k` も、Chronos は幅検査の登録も）から消え、元に戻すと戻ることを確かめる。

画面の部品からの確認は `tests/automation/` の `script_editor_check.py`（エディタの土台）、`script_editor_features_check.py`（補完・ホバー・定義へ移動・検索など）、`script_width_check.py`（幅検査）、`script_link_check.py`（イベントタブの欄・取り込み・F2・ビルドの欄）、`scripts_table_check.py`（対応表の画面）にあります。自動操作の命令は [docs/automation.md](automation.md) の「スクリプト連携」と「別ウィンドウ（スクリプトエディタ）」の表にあります。

### スクリプトの設定（zigzagumap.json）

- 設定はプロジェクトフォルダ（ZigzaguMap で開く CFRU-JP のフォルダ）の `zigzagumap.json` の `"script"` の節に書きます。ファイルや節が無いとき、項目を省いたときは、方言ごとの既定値を使います。読み書きは core の `ScriptConfigJson`（`packages/core/src/script/config/`）だけで行い、知らない項目はファイルの最上位と節の中のどちらも、書き戻しても残します。
- パスはプロジェクトフォルダからの相対パスで、区切りは `/` です。`..` で上のフォルダも指せます。`\` で書いてあっても、読むときに `/` にそろえます。
- 項目は次のとおりです。

| 項目 | 内容 | ND の既定値 | Chronos の既定値 |
|---|---|---|---|
| `dialect` | 方言。`nd`・`chronos`・`auto` | `auto` | `auto` |
| `build` | ビルドの手順の列。1 つの手順は `{ "command", "args", "cwd" }`。上から順に動かす。`command` が `copy` なら、`args` の 1 つ目のファイルを 2 つ目へ写す | CFRU の `python scripts/make.py`（`cwd` は `.`）→ `copy test.gba ../NeoDark-DPE-main/BPRJ0.gba` → DPE の `python scripts/make.py`（`cwd` は `../NeoDark-DPE-main`） | `python build.py`（`cwd` は `..`） |
| `outputRom` | ビルドで出来る ROM | `../NeoDark-DPE-main/test.gba` | `../build/Chronos.gba` |
| `widthCheck` | `.string` の幅検査のコマンド（形は `build` の 1 手順と同じ）。`null` なら無し | `null` | `python tools/check_text_width.py --source`（`cwd` は `..`） |
| `labelTemplate` | ラベルの規則。`{map}`（`.s` の名前から作った名前）・`{kind}`（`Npc` / `Sign` / `Tile`）・`{index}`（番号）を置き換える | `{map}_{kind}{index}` | 同じ |
| `useGlobal` | 新しいラベルに `.global` を付けるか | `false` | `true` |
| `lineMaxChars` / `linesPerPage` | 簡易の幅検査の、1 行の字数と 1 ページの行数 | 18 / 2 | 18 / 2 |
| `commandsCsv` | 命令の説明を足す commands.csv。`null` なら使わない | `null` | `null` |
| `widthRegistry` | 幅検査の追加の登録ファイル（`path`・`.string` のパスの頭 `prefix`・足すときの窓 `window`）。`null` なら書き足さない | `null` | `{ "path": "strings/text_width_registry.json", "prefix": "cfru/", "window": "field" }` |

- `auto` のときは、プロジェクトフォルダの `xse_commands.s` の `loadpointer` マクロを見ます。引数が 3 つ（`destination, value, value_kanji`）なら ND、2 つなら Chronos です。`xse_commands.s` が無いときや `loadpointer` が見つからないときは、Chronos（素の CFRU と同じ 1 ポインタ）として扱います。
- ND の既定のビルドは、CFRU のビルド → DPE へのコピー → DPE のビルドまでを 1 回で行います（#198 で決めた）。エミュレータの起動は作りません（#199 は閉じた）。前の版にあった `emulator` の項目は読まず、書いてあれば知らない項目として残します。

### 命令表（xse_commands.s と commands.csv）

- 命令表は、開いたプロジェクトの `xse_commands.s` のマクロから毎回作ります。ND と Chronos では 0F（`loadpointer`）などの長さが違うため（ND は 2 ポインタで 10 バイト、Chronos は 1 ポインタで 6 バイト）、決まった表は持ちません。
- マクロの名前、引数（`:req` は必須、`=値` は既定値、無印は省略可）、直前のコメント行（説明）を読みます。本文の `.byte`・`.hword`・`.2byte`・`.4byte`・`.word` と、ほかのマクロの呼び出しを中まで展開し、命令のバイトの並びを作ります。先頭の 1 バイトが決まった値なら、それを命令番号とします。
- `.ifb` / `.ifnb` の分岐は、「どの引数を省いたか」ごとの並びに分けて持ちます（例: ND の `applymovement` は、マップを省くと 0x4F の 7 バイト、書くと 0x50 の 9 バイト）。`.equ` の定数は `xse_commands.s`・`xse_defines.s`・`asm_defines.s` から求めます。`/* */` の中は読みません。
- 読めないマクロ（呼び先のマクロが無い、自分を呼ぶ、対応していない書き方）は、理由を付けて一覧に出します。ほかのマクロは続けて読みます。
- `commands.csv`（列は name, detail, hover, opcode, args。BOM 付き UTF-8、`#` で始まる行と空行は飛ばす）があれば、同じ名前の命令に説明（detail と hover）を付けます。同じ名前の行が複数あれば、命令番号の合う行を使います。CSV にだけある名前（`#Org` など）も命令として引けます。
- 引数の種類は、文字列・ラベル・移動・変数・フラグ・定数に分けます。Gen3 Script Assistant 改造版の規則（命令ごとの上書きと、引数の名前の規則）を使い、文字列は本文で 4 バイトのまま書く引数から求めます。このため `msgbox` の文字列の引数は ND で 2 つ、Chronos で 1 つ、`customchoice` は ND で 4 つ、Chronos で 2 つになります。

### .s の解析とラベルの索引

- `.s` の 1 行を、ラベル定義・命令（マクロ）かディレクティブ・引数・コメントに分け、それぞれの桁の範囲を返します。エディタの色付けと索引は、同じ解析を使います。
- ラベルは、行頭（空白の後）の `名前:` です。同じ行に `.byte` などを続けて書けます（`m_Walk: .byte walk_up, end_m`）。
- 引数は空白とカンマで区切ります。`"..."` と括弧の中では区切りません。`VAR + 1` のように演算子をはさんだ並びは 1 つの式として扱います。`.equ` は、名前とその後ろ全部（値）の 2 つに分けます。
- コメントは `@`（行の途中からも）、行頭の `#`、`/* */` です。`/* */` は複数の行にまたがってよく、中にあるラベルのような行は拾いません。`"..."` の中の `@` はコメントにしません。
- 索引に入れるのは、`assembly/` の下のすべての `.s` と、プロジェクトフォルダ直下の `xse_commands.s`・`xse_defines.s`・`asm_defines.s` です。
- ラベルごとに、ファイル・行・桁・`.global` の有無と、続く最大 4 行（1 行 80 字まで。コメントは除く）を持ちます。`.equ` は値と、同じ行の `@` コメント（説明）を持ちます。移動の名前は、`xse_defines.s` の `look_down` から `end_m` までの `.equ` です。
- 名前は大文字と小文字を区別します。同じ名前が複数あれば、すべてを持ちます。
- 索引はファイルごとに持ちます。1 ファイルを読み直すと、そのファイルの分だけが入れ替わります。
- ファイルごとに改行（LF / CRLF）を覚え、書き戻すときは同じ改行にそろえます。
- ND の全ファイルの索引は、JSON にして 1MB 未満（約 840KB）です。

### .string と簡易の幅検査

`strings\*.string` の読み方は、CFRU の `scripts/string.py` に合わせています。

- `#org @ラベル` の次の行が本文です。本文の 1 行が 1 つの文字列になります。
- 本文の行の末尾がちょうど `\n`・`\p`・`\l`・`\m`（改行と改ページの制御記号）で終わり、次の行も本文なら、次の行は同じ文字列の続きです（#221。build-support のパッチを当てた string.py と同じ規則）。つなぐときは何も足さず、何も削りません。長い文を、制御記号のあとで改行して書けます。

  ```
  #org @gText_Moegi_Npc3
  こんにちは！\n
  きょうは いいてんきだね\p
  またね
  ```

  は 1 行の `こんにちは！\nきょうは いいてんきだね\pまたね` と同じバイト列になります。制御記号のあとに空白があるとき、`\n` のように打ち消されているとき、次の行が空行・コメント・`#org`・指定のときはつながりません。それ以外で続く行は、今までどおりラベルの無い別の文字列として直後に置かれます（エディタは「続きになりません」の警告を出し、制御記号のあとの空白が原因なら、その空白に警告を出します）。既存の ND と Chronos の `.string` には、制御記号で終わって次に本文が続く行が無いことを調べてあり、どのファイルも意味は変わりません。
- `#org` が続いて本文の無いラベルは、次のラベルと同じ文字列を指します。
- 空白だけの行（全角の空白だけの行も）は空行、行頭が `//` の行はコメントです。
- `#include "…"`、`#ifdef` / `#ifndef` / `#else` / `#endif` の行は指定として読みます。`#ifdef` の中のラベルも読み、どの条件の中にあるかを覚えます（条件が成り立つかは判断しません）。
- 最初の `#org` より前の `MAX_LENGTH=` と `FILL_FF=` は設定として読みます。
- 改行の形（LF・CRLF・CR、最後の改行の有無）と BOM は行ごとに残します。読んで書き戻すと 1 バイトも変わりません。

書き戻し:

- 本文の差し替えでは、そのラベルの文字列の行（1 行か、続きの行を含む複数の行）だけを書き換えます。`\n` `\p` `\l` は文字のまま書きます。本文の中の改行の文字は、制御記号のすぐ後ろにだけ書け、そこで行を分けて書きます。空の本文、`//` や `#org` で始まる本文、続きの行が空白だけ・`//` か `#` で始まる・`MAX_LENGTH` か `FILL_FF` を含む（Chronos の幅検査が指定や設定として読む）ものは書けません（エラーにします）。
- ひな形と、ROM のスクリプトの取り込みで書く文は、制御記号のあとで改行した形で書きます（分けた後ろが続きの行にできないところでは分けない）。
- イベントの削除では、`#org` の行と本文の行（続きの行と、ラベルの付かない 2 つ目からの文字列も）と後ろの空行を除きます。次の `#org` の前のコメントと指定の行は残し、取り込みの印のコメントは一緒に除きます。
- 本文の無いラベルを差し替えると、`#org` の直後に本文の行を 1 行足します。次のラベルとの共有はなくなります。
- 新しいラベルはファイルの最後に足します。前に空行を 1 つはさみ、改行はファイルでいちばん多い形にそろえます。

本文の見せ方: `\p` で次のページ、`\n` `\l` `\m` で次の行にします。`[PLAYER]`、`{Lv}`、`<FF 09>`、`[FD]` などは書かれたまま見せます。

簡易の幅検査は、ピクセルではなく字数で数えます。続きの行はつないで 1 つの文字列として数え、上限を超えたところはその字のある行に印を付けます。

| 字 | 字数 |
|---|---|
| 全角の字 | 1 |
| 半角の英数字・記号、半角カナ | 0.5（設定で変えられる） |
| 空白（半角も全角も） | 1（ゲームでは半角の空白も全角と同じ幅） |
| `[PLAYER]` `[RIVAL]` | 5 |
| `[BUFFER1]` などの `[BUFFER…]` | 8（道具・技の名前の長さ） |
| `[ATTACKER]` `[TARGET]` など戦闘のポケモン | 11（「あいての 」と名前） |
| 矢印・ボタンの絵、`{Lv}` などの `{…}`、`\$` | 1 |
| 色・待ちなどの制御（`[RED]` など）、`[XX]`、`<XX YY>` | 0 |

1 行の字数の上限は 18、1 ページの行数の上限は 2 です（Chronos の窓の幅 208px に全角 10px の字が 18 字入る）。`\l` も 1 行と数えます。上限、半角の重み、プレースホルダの字数は検査を呼ぶ側から変えられます。上限を超えた行は、ページと行の番号、ファイルの中の位置（行の始まり・終わりと、超え始めた字の位置）を返します。ピクセルの検査（Chronos の `tools/check_text_width.py`）とは結果が違うことがあります。全角の `！`（5px）や小さい字（9px）も 1 字と数えるので、そこは厳しめに出ます。半角の数字（8px）は 0.5 字と数えるので、そこは甘めに出ます。

### eventscripts と maps\scripts.json

読み書きは core の `script/project/` にあります。scripts.json の画面は「[scripts.json の編集画面](#scriptsjson-の編集画面)」です。

- eventscripts は 1 行 1 件で `種別 バンク マップ [番号] シンボル` と書きます。種別は `map` / `npc` / `trainer` / `item` / `tile` / `sign` で、大文字小文字は区別しません。行の見分け方は CFRU の `scripts/insert.py` に合わせています。トークンの数が違う行や、`npc` などで番号が無い行は「読めない行」として残します（insert.py も使いません）。
- コメント（`#` で始まる行）、空行、`#include` / `#define` / `#ifdef` / `#ifndef` / `#else` / `#endif` の行、読めない行は、どれも元の位置にそのまま残します。改行（LF / CRLF / CR）も行ごとに覚えるので、読んで書き戻すと 1 バイトも変わりません。編集で変わるのは、足す・変える・消す行だけです。
- `#ifdef` の中の行は、どの条件の下にあるかを覚えます。insert.py は eventscripts の中の `#define` を読まず、`#include` 先の `#define` だけを使います。
- `trainer` はシンボルの頭に `EventScript_`、`item` は `ItemFindScript_` を付けた名前がラベル名です（insert.py と同じ）。ラベル名からシンボルに戻すときは、この頭の文字列を外します。
- 番号はイベントの並びの中の位置（0 から）です。人（`npc` / `trainer` / `item` は同じ番号を使う）、看板（`sign`）、スクリプトタイル（`tile`）でそれぞれ数えます。`map` は番号を使いません。
- イベントを消すと、そのイベントの行を消し、同じマップの同じ並びで後ろにある番号を 1 つずつ減らします。入れ替えと移動でも、同じ並びの番号を付け直します。`#ifdef` の中の行も同じように付け直します（どの条件でビルドしても、番号は同じ並びを指すためです）。番号を `05` のように 0 で桁をそろえて書いた行は、同じ桁数で書き直します。
- 行を足すときは、同じバンク・マップの項目のうち `#ifdef` の外にある最後の項目の次に入れます。無ければファイルの末尾に足します。区切りは空白 1 つで、改行はファイルで最初に出てくる改行に合わせます。
- `maps\scripts.json` は `{ "Format": 1, "Entries": [{ "Bank", "Map", "Name", "Script", "Strings" }] }` です。`Map` を省くとバンク全体の項目になり、マップを指定した項目のほうが優先されます。`Strings` を省くと `strings/overworld_strings_<.s の名前（拡張子なし）>.string` を使います（ND の名前の付け方）。
- `scripts.json` は Bochi の maps\ の JSON と同じ整形（2 空白の字下げ、CRLF、ASCII 以外の文字は `\uXXXX`）で書きます。知らない項目は消さずに書き戻します（決まった項目の後ろに、読んだときの順で並べます）。

### ROM のスクリプトの逆アセンブル

ROM のスクリプトのバイト列を、`xse_commands.s` の書き方の文に戻します。処理は core の `script/disasm/` にあります。画面は「[素の ROM のスクリプトの表示と取り込み](#素の-rom-のスクリプトの表示と取り込み)」です。

命令表:

- プロジェクトを開いているときは、そのプロジェクトの `xse_commands.s` から作った命令表を使います。ND のベース ROM は 0F が 2 ポインタ（10 バイト）なので、素の FR の長さで読むと壊れます。
- プロジェクトの無い素の ROM では、同梱の表を使います。同梱の表は Chronos の cfru の `xse_commands.s` と `xse_defines.s`（0F が 1 ポインタ）から、命令番号・名前・バイトの並び・引数の名前と種類と、移動の名前だけを抜き出したものです。0x2C・0x2D・0x74 は Chronos と ND が自分で変えた命令なので入れていません。作り直すときは `packages/core/scripts/gen-disasm-commands.ts` に、`xse_commands.s` のあるフォルダを渡します。
- 使うのは、`.byte` などだけで書いたマクロです。別名のマクロと、`msgbox` のように複数の命令をまとめたマクロは使いません（`msgbox` は `loadpointer` と `callstd` の 2 行に戻ります）。
- 同じ命令番号のマクロがいくつかあるときは、決まった値（trainerbattle の種類など）の多いもの、ファイルで先に書いたもの、省ける引数を書いた型、の順に試します。ND の 0F は、2 つのポインタが同じなら漢字を省いた形（`loadpointer 0x0 X`）、違えば `loadpointer 0x0 X X_kanji` にします。

読み方:

- 入口から順に読み、`end`・`return`・`goto`・`gotostd`・`jumpram`・`killscript`・0x5D・0x5E・`virtualgoto` で止めます。
- たどる分岐先は、0x04〜0x07（`call`・`goto`・`goto_if`・`ifcall`）の行き先と、trainerbattle の続きのスクリプト（種類 1・2 は 3 つ目、6・8 は 4 つ目のポインタ）です。trainerbattle のほかのポインタは文字列として読みます。
- 引数の種類が文字列の 4 バイトは文字列、移動の引数は移動データ（`end_m` の 0xFE まで）、`mart`・`mart2`・`mart3` の引数はショップの一覧（2 バイトずつ、0 まで）として読みます。`callasm` などのほかのポインタはたどらず、数のまま書きます。
- たどった先、文字列、移動データ、ショップの一覧には `ROM_08XXXXXX`（ポインタの値、大文字の 16 進 8 桁）のラベルを付けます。入口には呼ぶ側で名前を付けられます。
- どの型にも合わない命令は `.byte 0xXX` を 1 つ書いて、その道は止めます。命令の途中を指す分岐や ROM の外を指す分岐は、数のまま書いて問題の一覧に出します。読んだ行に戻る分岐（輪）は、2 回目からは読みません。
- 上限は、命令が全体で 20000 個、文字列が 1024 バイト、移動データとショップの一覧が 256 個です。超えたら止めて問題の一覧に出します。

書き方:

- `.s` は、ラベルの行の後に命令をタブで字下げして書き、まとまりの間に空行を入れます。引数は空白で区切り、数は `0x` の 16 進です。
- 省いた引数（`.ifb` で空の側の引数、本文で使わない既定値の引数）は書きません。途中の引数を省くときだけ、カンマで区切って空のまま書きます。本文で使わない必須の引数（`trainerbattle1` の `type` など）には、命令番号の次の決まった値を書きます。
- 移動データは `.byte walk_up, exclaim, end_m`、ショップの一覧は `.align 1` の後に `.hword 0xD, 0x0` と書きます。名前の無い移動の値は 16 進で書きます。
- 文字列は `.string` の形（`#org @ラベル` と 1 行の本文）で別に書きます。
- 結果は、まとまり・行・引数・文字列・移動データ・ショップの一覧・問題を構造のまま返し、文字にした行にはそれぞれ ROM の位置を付けます。

文字列の戻し方は、CFRU の `scripts/string.py` の読み方に合わせています。

- string.py は charmap.tbl の右辺を書いたまま使い、同じ字が何度も出るときは最後の定義を使います。そのため、string.py で同じバイトに戻る定義だけを使います。たとえば ND の charmap では `?` が AC と EF の 2 つにあり、string.py は `?` を EF にするので、AC は全角の `？` で書きます。
- FD 01・02・03・04・06 は `[PLAYER]`・`[BUFFER1]`・`[BUFFER2]`・`[BUFFER3]`・`[RIVAL]` にします。表に無い 1 バイトは `[F7]`、表に無い FC xx yy は `<FC 88 9F>` にします。
- 書いた本文を string.py の読み方で戻して元のバイト列にならないときは、本文をすべて `[XX]` で書きます。
- 文字コード表は、プロジェクトの charmap.tbl を渡せます。渡さなければ同梱のもの（ND の charmap.tbl）を使います。

確かめたこと:

- 素の BPRJ のマサラタウン（バンク 3・マップ 0）の人と看板の入口 7 つから、14 のまとまりと移動データ 5 つ、文字列 13 個に戻りました。これを `arm-none-eabi-as` でアセンブルし直すと、どのまとまりも元のバイト列と一致しました（まとまりごとに元の位置へ `.org` で置き、文字列のラベルは元の位置の `.equ` にして比べました）。
- 素の BPRJ の全マップの人・看板・スクリプトタイルを読むと、知らない命令は 1 か所（0xD1）だけでした。そこで拾った 3453 個の文字列は、ND の string.py で書き戻すとすべて元のバイト列になりました。
- ND のベース ROM のいあいぎり・なみのりのスクリプトは、0F を 2 ポインタで読み、ひらがなと漢字の文字列を戻せました。アセンブルし直しても一致しました。

### スクリプトエディタ（別ウィンドウ）

スクリプトの `.s` と `.string` を編集する別ウィンドウです（CodeMirror 6）。色付け・補完・検索などの機能は「[スクリプトエディタの機能](#スクリプトエディタの機能)」に書きます。

開き方:

- イベントタブでイベント（人・看板・スクリプト）をダブルクリックすると、そのイベントのスクリプトを開きます。プロジェクトフォルダを開いていないとき（素の ROM だけ）は、ROM のスクリプトを読み取り専用のタブで出します（「素の ROM のスクリプトの表示と取り込み」）。
- 開く場所の求め方: eventscripts からそのイベント（バンク・マップ・種別・番号。スクリプトはスクリプトタイルの `tile`）の行を探し、ラベル名にしてから、ラベルの索引（「.s の解析とラベルの索引」）で `.s` と行を引きます。`#ifdef` で同じイベントの行がいくつもあるときは、`#include` 先の `#define` で条件が成り立つ行を使います（無ければ最初の行）。
- ラベルが見つからないとき（eventscripts に行が無い、ラベルが assembly に無い、開けないフォルダにある）は、maps\scripts.json のそのマップの `.s` を 1 行目から開きます。それも無ければ、ステータスバーに「このイベントのスクリプトが見つかりません」と出して開きません。
- ラベルの索引はメインウィンドウが持ちます（名前・ファイル・行だけ）。初めてスクリプトを開くときに作り、エディタで保存したファイルの分だけ読み直します。メインウィンドウが前面に戻ったとき（外のエディタで書き換えたかもしれないので）は捨てて、次に開くときに作り直します。

開けるファイル:

- プロジェクトフォルダの `assembly/overworld_scripts/` と `strings/` の中のファイルだけです（大文字小文字は区別しません）。ほかのパスはエディタではエラーのダイアログ、メインからはステータスバーで断ります。
- 読み書きは、メインがプロジェクトフォルダを開いたときに決めたフォルダからの相対パスで行います（Rust 側の許可はウィンドウどうしで共通）。別のプロジェクトフォルダを開くと、エディタは閉じます（同じフォルダで ROM を開き直したときは残します）。

画面と操作:

- 上にタブの帯、真ん中に本文、下にカーソルの位置（行・桁）・改行の形・BOM の有無と、保存などのお知らせを出します。タブはファイルごとに 1 つで、同じファイルを開き直すとそのタブへ切り替えます。未保存のタブには ● を付け、ウィンドウの題名の前にも ● を付けます。
- キー: Ctrl+S で表示中のファイルを保存（メインの「出力」は動きません）、Ctrl+W で表示中のタブを閉じる、Ctrl+Tab / Ctrl+Shift+Tab でタブの切り替え、Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z）で元に戻す・やり直す（履歴はファイルごと）、Tab で字下げ（タブ文字）。タブの × かホイールのクリックでもタブを閉じます。
- 未保存のタブを閉じるとき、未保存のままウィンドウを閉じるときは「保存しますか？」と聞きます（はい = 保存して閉じる、いいえ = 保存せずに閉じる、キャンセル = 閉じない）。メインウィンドウを閉じるとき、別のプロジェクトフォルダを開くときも、エディタに未保存のファイルがあればメインで同じように聞きます。ダイアログはどれも画面内のもので、Windows の標準のダイアログは使いません。
- ウィンドウは大きさを変えられ、最大化もできます（最小 420×260）。位置と大きさは個人設定の `toolWindows` に覚え、次に開くときに同じ場所に出します（自動操作で起動したときは覚えず、画面外に出します）。

保存と外部の変更:

- 保存は、読んだときの改行の形（LF / CRLF / CR）と BOM の有無を保ちます。改行が混ざっているファイルは、いちばん多い形にそろえて保存します。書き込みは一時ファイルに書いてから置き換えます。
- 開いているファイルの更新日時と大きさを 1 秒ごとと、ウィンドウが前面に戻ったときに調べます。外で変わっていて、未保存の変更が無ければ黙って読み直します（変わった範囲だけを置き換えるので、カーソルと選択はそのまま残ります）。未保存の変更があれば「読み直しますか？」と聞きます（いいえなら編集中の内容を残し、同じ変更では二度聞きません）。読み直しも元に戻す履歴に入ります。ファイルが消えたときはタブの名前に取り消し線を引き、保存すると作り直します。

マップの編集との違い: マップとイベントの編集は CommandBus で実行し、メインの履歴に入ります。テキストファイル（`.s`・`.string`）の正本はディスクと、エディタが開いている間の編集中のバッファです。エディタの編集は CommandBus を通さず、元に戻す履歴もエディタのファイルごとに持ちます（Ctrl+Z はメインの履歴を戻しません）。

読み込みとメモリ: CodeMirror とエディタのコードは、エディタのウィンドウ（`tool.html`）を開いたときに初めて読み込みます。メインの `index.html` の束には入れません（`apps/desktop/test/bundle.test.ts` が `vite build` の出力を調べて確かめます）。メイン側の窓口 `ui/script/ScriptHost.ts` も、初めてスクリプトを開くときに読み込みます。

作りの決まり（後の issue で機能を足すとき）:

- エディタの機能は `apps/desktop/src/windows/script-editor/extensions/` に 1 機能 1 ファイルで書き、`extensions/index.ts` の一覧に 1 行足します。拡張はファイル（タブ）ごとに作るので、`.s` と `.string` で違うものを返せます（`EditorFileContext` の `path`・`kind`、保存 `save()`、別のファイルを開く `openFile()` を受け取る）。
- メインとのやり取りは `windows/script-editor/protocol.ts` にまとめています。エディタ → メインは `script-editor:request`（返事は `script-editor:reply`）で、種類ごとの中身と返事の型を表 `ScriptEditorRequestMap` に持ちます（`hello`・`saved`・`mainDirty`・`exportMain`・`importRom`・`labelRenamed`・`labelUses`・`setting`）。メイン → エディタの問い合わせは `script-editor:query`（答えは `script-editor:answer`）で、表は `ScriptEditorQueryMap`（`dirty`・`saveAll`・`bufferText`・`setBufferText`）、返事の要らない知らせ（`open`・`build`・`openRom`）は `ScriptEditorNoticeMap` です。種類を足すときは、表に 1 項目と、受け手の処理の表（メインは `ScriptHost` の `requestHandlers`、エディタは窓の `queryHandlers`）に 1 つ足します（処理を書き忘れると型の誤りになります）。
- エディタの自動操作の命令は `windows/script-editor/automation/` に機能ごとのファイルで書き、メインと同じ `CommandRegistry` に登録します（同じ名前を 2 か所で登録すると起動時に誤りになる）。命令を足すときは、その機能のファイルの表に 1 行足します。
- エディタ → メインの `setting` は、エディタの個人設定（今はテーマ `scriptEditorTheme`）を変えたときに送ります。settings.json はメインが書くので、エディタは読むだけです。

### スクリプトエディタの機能

Gen3 Script Assistant 改造版（VS Code の拡張）の色付け・ホバー・補完を再現し、拡張に無い定義へ移動・波線・文字列の編集・テーマなどを足しています。命令表・ラベルと `.equ` の索引・文字列のラベルの索引は、エディタのウィンドウを開いたときに裏で読みます（ND で 1 秒前後。メインのウィンドウのメモリは使いません）。索引は、開いているタブの編集中の本文で置き換えるので、保存前に足したラベルも補完や定義へ移動に出ます（保存せずにタブを閉じるとディスクの内容に戻ります）。ウィンドウが前面に戻ったときに、外で書き換えたファイルを読み直します。処理は core の `script/assist/`（DOM なし）と、エディタの `windows/script-editor/extensions/` の 1 機能 1 ファイルにあります。

- 読み込みとメモリ: CodeMirror と補助の機能はエディタの束（`ScriptEditorWindow-*.js`）だけに入り、メインの束は変わりません（エディタの束は 296KB から 465KB、gzip で 152KB）。ND の写しで、エディタを開いている間のエディタのウィンドウ（レンダラー）の専用ワーキングセットは約 38MB です（中身の無いプロジェクトで開いたときは約 23MB。命令表・索引などの知識は Node で測って約 12MB）。読み込みが済んだら、手の空いたときに V8 の GC を「空いた領域も OS へ返す」形（`util/idleGc.ts` の `scheduleIdleGc(true)`）で 1 回走らせます。これをしないと、読み込みの一時的なもの（ファイルの本文・行の解析・IPC の受け取り）を集めたあとの空き領域を V8 が 30 秒ほど持ったままにし、その間は約 80MB に見えていました。閉じるとメインだけの値に戻ります。メインのウィンドウの値は、機能を足す前と同じです。

色付けとテーマ（#191）:

- `.s` は、コメント（`@`、行頭の `#`、`/* */`）・ラベル定義・ディレクティブ・数・文字列・マクロの引数参照（`\引数`）を字句で色分けします。命令名と引数の種類は命令表と索引で決め、見えている行にだけ色を付けます（拡張の semantic token と同じ役目）。種類は、命令（xse_commands.s のマクロと、同じファイルの `.macro`）、ARM / Thumb の命令（`callasm` で呼ぶ関数の行）、文字列の参照（`.string` のラベル。斜体）、ラベルの参照、変数、定数です。知らない命令は色を付けません。
- `.string` は、`#org @ラベル`、`//` のコメント、`#include` などの指定、本文の制御（`\n` `\p` `\l`、`[PLAYER]`、`{...}`、`<FF 09>` と `[XX]`）を色分けします。
- テーマは Dark+ 風・Light+ 風（既定）・Monokai 風・Solarized Dark 風の 4 つで、下の帯の右端で選びます。選んだテーマは個人設定（settings.json の `scriptEditorTheme`）に残します。テーマのパッケージは使わず、色の表は `extensions/palettes.ts` に書いています（CodeMirror への当て方は `extensions/themes.ts`）。
- テーマは本文だけでなく、エディタのウィンドウ全体に当てます（#218）。タブの帯、下の帯、ROM のタブの帯、検索と置換の欄、補完とホバーの枠、文字列の入力欄、波線の一覧、ビルドの欄（ログと誤りの一覧）、画面内のダイアログ（保存の確認・ラベル名の変更・取り込みの一覧など）、ボタン・入力欄・選択欄、スクロールバー、題名の帯（暗いテーマのとき）です。テーマごとに部品の色（`ui`: 帯・一覧・文字・控えめな文字・枠・選んだ行・表示中のタブ・下の帯・ボタン・入力欄・誤り・知らせ・リンク・スクロールバー）を持ち、CSS 変数にしてエディタのウィンドウの `<html>` に付けます（共通の部品が使う `--face` などを上書きする）。メインのウィンドウのテーマ（設定 > テーマ の明るい標準色とダーク）とは別で、互いに影響しません。
- 部品の色は、文字と地のコントラストを単体テスト（`apps/desktop/test/editorPalettes.test.ts`。文字は 4.5 以上、控えめな文字・誤り・リンクは 3 以上）で、実際に描かれた色を自動操作のテスト（`tests/automation/script_theme_check.py`。暗いテーマで明るいまま残る部品が無いこと）で確かめています。
- 4,584 行の `.s` で 1 字打ってから画面が描き直されるまで、平均 16.5 ms（次のフレームを待つ時間を含む）でした。

全ファイル検索（#520）:

- Ctrl+Shift+F で、下の欄に全ファイル検索を出します。ビルドの欄と同じ場所で、上のタブ（「ビルド」「全ファイル検索」）で切り替えます。選んでいる文字があれば、最初から入れます。欄は初めて開いたときに読み込みます。
- 範囲は、エディタで開ける `assembly` の `.s` と `strings` の `.string` の全部です。欄で「.s だけ」「.string だけ」に絞れます。探すたびにディスクから読み、開いているタブは未保存の本文で探します。
- 大文字と小文字の区別・正規表現・単語単位を選べます（単語単位は、前後が英数字と `_` でない所）。正しくない正規表現は結果なしにして、欄を赤くします。
- 結果はファイルごとにまとめ、行番号と行の文を出し、一致した所に色を付けます。押すとそのファイルをタブで開き、その行の一致した所を選びます。上限は 500 行で、超えたら「500 件で止めました」と出します。置換はしません（ファイルをまたぐ置換は、間違えたときに戻しにくいため）。
- 1 回の検索の時間（3 回の値。ファイルを 1 つ読むごとに画面へ返すので、探している間も画面は止まりません）: ND の写し（30 ファイル）で 50〜230 ms、Chronos の写し（61 ファイル）で 96〜432 ms。
- 計算は core の `script/search/ProjectSearch.ts`、欄はエディタの `windows/script-editor/ProjectSearch.ts` です。

ホバーと補完（#192）:

- ホバーは拡張と同じ順で決めます。命令は commands.csv の hover（無ければマクロの引数の並びと直前のコメント）と、マクロの場所。文字列の参照は `.string` の本文（`\p` は空行、`\n` `\l` は改行にして見せ、700 字で切る）。ND の `msgbox` と `loadpointer` は、ひらがなと漢字の両方を出します（漢字を省いた行は「省略。ひらがなと同じ文字列」）。Chronos は 1 つです。そのほかの引数は、役割（`代入先イベント変数` など）、必須か省略時の値、`.equ` の値と説明、10 進と 16 進、変数の説明（0x800D は LASTRESULT など）、数と同じ値の名前（最大 8）、ラベルの定義の先頭の行（最大 3 か所）です。拡張では英語だった見出し（Signature・Source・Decimal・Hex・Known names）は日本語にしました。
- 補完は Ctrl+Space か、名前を打ったとき、引数の区切りの空白を打ったときに出ます。命令名の位置では命令とディレクティブ、引数の位置では引数の種類に合わせて、文字列のラベル・ラベル・移動の名前（`.byte` の行も）・変数・フラグ・定数を出します。`msgbox` の種類の引数は拡張と同じ `MSG_*` の 8 つです（値は xse_defines.s の `.equ` があればそちら）。ラベル・フラグ・変数の補完は拡張に無かったものです。
- commands.csv の hover の Markdown は、ヘルプの `markdown.ts` の行の中の変換（太字・コード）を使い、段落と改行はホバー用に自前で扱います（ヘルプの変換は段落の中の改行を空白にするため）。

定義へ移動（#193）:

- F12 か Ctrl+クリックで、カーソルの名前の定義へ移ります。引く順は、ラベル（assembly の `.s`）、文字列のラベル（`.string` の `#org` の行）、`.equ` です。同じファイルの定義が先に選ばれます。別のファイルならタブを開きます。Alt+←（マウスの「戻る」ボタンでも）で、移る前の位置へ戻ります。
- 見つからないときと、エディタで開けないファイル（xse_commands.s など）にある定義は、下の帯に場所を出します。
- Ctrl+クリックは、定義のある名前の上では定義へ移動、それ以外ではカーソルを足します（#194 の複数カーソルと同じキーのため、こう分けました）。

編集の操作（#194）:

- 検索と置換（Ctrl+F、Ctrl+H）。正規表現・大文字小文字の区別・単語単位を選べます。F3 / Shift+F3 で次・前、Ctrl+Alt+G で行へ移動。検索の欄・補完・波線の一覧の文言は日本語にしています。
- Alt＋ドラッグで矩形選択、Ctrl+D で同じ文字列を選択に足す、Ctrl+Shift+L で同じ文字列をすべて選ぶ、Ctrl+Alt+↑↓ で上下にカーソルを足す。
- Alt+↑↓ で行の移動、Shift+Alt+↑↓ で行の複製、Ctrl+/ でコメントの切り替え（`.s` は `@`、`.string` は `//`）、Ctrl+Shift+S で未保存のファイルをすべて保存。キーの一覧は「[ショートカット](guide.md#ショートカット)」とヘルプのショートカット一覧にあります。

波線（#195）:

- `.s`: 知らない命令（命令表・ARM / Thumb の命令・同じファイルの `.macro` のどれでもない）、組めないマクロ（中から呼ぶマクロをたどった先に定義の無いものがある。例: `giveitem` → `copyvarifnotzero` → `setorcopyvar`。警告で、補完とホバーには出したまま）、必須の引数が足りない（マクロの `:req`）、引数が多すぎる、どこにも定義の無いラベル（命令の引数のうち、ラベル・移動データ・文字列を指すもの）。ラベルは、索引・文字列の索引・`.equ`・リンカのスクリプト（BPRJ.ld の `gStringVar4 = 0x…;` など）・同じ本文の定義を探します。`callasm` などの C の関数を指す引数、`.if 0` の中、マクロの本文は調べません。マクロで作るラベル（`EventScript_X\num:`）は、頭の名前で始まれば定義済みとみなします。
- `.string`: 同じファイルに同じラベルが 2 つ以上（エラー）、別の `.string` に同じラベル（警告）、簡易の幅検査（下）。
- 打つのを止めて 0.5 秒で調べ直します。行番号の横に印、F8 で次の波線、Ctrl+Shift+M で一覧。ND と Chronos の写しの overworld_scripts の `.s` をすべて開いて、誤った波線が出ないことを確かめています。
- ビルドのエラーや保存時の幅検査の結果は、外から波線を足す入口（`extensions/lint.ts` の `setExternalDiagnostics`。ファイルと行で指定）で出します。

文字列のホバーとその場編集（#196）:

- 文字列の参照のホバーに「本文を編集」のボタンがあり、押すと小さな入力欄が出ます。入力中は文字数で幅を検査し（上限は zigzagumap.json の `lineMaxChars`・`linesPerPage`。既定は 1 行 18 字・1 ページ 2 行で ND も同じ）、行ごとの字数と、超えた行の印を出します。Ctrl+Enter か「反映」で `.string` のそのラベルの本文の行だけを書き換えます。その `.string` を開いていなければ裏でタブを開き、未保存にします（Ctrl+S か Ctrl+Shift+S で保存）。
- 入力欄は複数行です（#221）。本文は `\n`・`\p`・`\l`・`\m` のあとで改行した形で出し、その形で書き戻します。Enter で改行し、カーソルの前が制御記号でなければ `\n` を補ってから改行します（`.string` では改行の文字を制御記号のすぐ後ろにしか書けないため。警告にせず補うのは、Enter を押したところでゲームの文も改行したいはずだから）。貼り付けなどで制御記号の無い改行が入ったときも、反映のときに `\n` を補います。字数の表は、つないだ文字列で数えます。
- `.string` を直接開いたときも、本文の行の途中で Enter を押すと、カーソルの前が制御記号でなければ `\n` を補ってから改行します（そのまま改行すると、後ろが別の文字列になるため）。前が制御記号なら字下げせずに改行するだけです。行の終わり（制御記号で終わらない行）と Shift+Enter はふつうの改行です（新しい `#org` を書くときなど）。続きの行には左に線の印を付けます。
- `.string` を直接開いたときも、同じ幅検査の結果を波線で出します。ピクセルで数える幅検査のコマンド（`widthCheck`）があるプロジェクト（Chronos）では、字数の検査は目安なので「情報」の印（青）にします。`[BUFFER1]` を 8 字と数えるなど厳しめに出るため、実際の Chronos の文でも印が付くことがあります（ピクセルの検査は通る）。

保存時の幅検査（#197）:

- `.string` を保存したとき、zigzagumap.json に幅検査のコマンド（`widthCheck`）があれば動かします。Chronos は既定で `python tools/check_text_width.py --source`（作業フォルダは 1 つ上の `Chronos`）、ND は既定で無いので何もしません。動いている間にもう一度保存したら、終わってからもう 1 回だけ動かします。
- 出力の `TEXT WIDTH ERROR: cfru/strings/x.string:21 gText_X (configured) page 1 line 2: 212 px > 208 px (...)` を拾い、`prefix`（Chronos は `cfru/`）を外したパスのファイルのその行に波線を出します。前の結果の波線は消します（直して保存すると消える）。`(configured)` と `(widest)` で同じ中身のものは 1 つにまとめます。ファイルや行の分からない誤りは、保存したファイルの 1 行目に出します。出力は、ビルドの欄のログに「保存時の幅検査: ファイル」の見出しを付けて足します（問題があれば欄を開きます。自動操作では `editor.widthCheck` の `log` と `build.log`）。
- Chronos は、検査するファイル（登録のあるファイル）のすべての `#org` が `tools/check_text_width.py` に登録されていないと、検査もビルドも止まります。そこで、検査の前に登録の一覧（`--list-registry`）を取り、保存した `.string` が登録のあるファイルなら、登録の無い新しい `#org` を追加の登録ファイル（`widthRegistry` の `path`、Chronos は `cfru/strings/text_width_registry.json`）に書き足します。窓は `window`（既定 `field` = 会話の窓）です。本文に `[BUFFER1]`〜`[BUFFER3]` があると入る値の種類が分からないので、`unresolved`（窓の幅を検査しない）で登録します。登録ファイルに書いた名前のうち `.string` から消えた `#org` の分は消します。Python の `REGISTRY` に書いたものには触りません。登録の無いファイル（新しく作った `.string` など）は、今までどおり検査されないので書き足しません。
- 追加の登録ファイルを読む仕組みは Chronos 側（`tools/check_text_width.py`）に入れました（形は Chronos の `docs/TEXT_WIDTH.md`）。登録ファイルが無ければ、検査の結果もビルドも変更前と同じです。

### イベントのラベル（イベントタブのスクリプト欄）

プロジェクトフォルダを開いているとき、人・看板・スクリプトタイルのパネルに「スクリプトのラベル」の欄を出します（#200）。

- 欄にはイベントに付いたラベル名を出し、ラベルが付いていればオフセット（ROM のポインタ）の欄は隠します。ラベルが無い（素の ROM のスクリプトを指す）イベントは、オフセットの欄をそのまま出します。隠しアイテムの看板には欄を出しません。
- 入力すると、マップの `.s`（maps\scripts.json で決まるもの）のラベルのうち、入力を含むものを一覧に出します（↑↓ で選び、Enter か一覧のクリックで決める。Esc で元に戻す。▼ で全部を出す）。フォーカスが外れたときにも決めます。空にして決めるとラベルを外します（出力で eventscripts の行を消す）。ラベルを変えるのはコマンド（`setEventLabel`）なので、Ctrl+Z で元に戻せます。
- マップの `.s` に無いラベルは赤い字にします（ビルドで `Symbol missing` になるため）。使えない名前（半角の英字・数字・`_` `.` `$` 以外、数字で始まる）は決めません。
- `.s` のラベルの一覧は、その `.s` を初めて出すときに読み、エディタで保存したとき・メインウィンドウが前面に戻ったとき・ひな形を書いたときに読み直します（起動とマップの表示には入りません）。
- 「スクリプトを開く」ボタンとイベントのダブルクリックで、ラベルが付いていればエディタのその行を開き、付いていなければ素の ROM のスクリプトを読み取り専用で出します（下の「素の ROM のスクリプトの表示と取り込み」）。
- 自動操作では、欄は `event.person.label`・`event.sign.label`・`event.trap.label` です（`event.<種別>.script` は従来どおりオフセットの欄。比較テストが使うため）。ラベルの一覧は `script.labels` で読みます。

### ラベルの持ち方（maps\BB\scripts_MM.json）

イベントのラベルは、マップごとの別のファイル `maps\BB\scripts_MM.json`（例 `maps\03\scripts_00.json`）に、照合用の座標と一緒に持ちます（#204）。マップの JSON（`MM.json`）・Bochi・`map_project.py` には手を入れません。

- 名前を `MM.scripts.json` にしていないのは、CFRU の `scripts/map_project.py` が `maps/[0-9]*/[0-9]*.json` をすべてマップの JSON として読み、数字で始まる名前のファイルがあるとビルドが止まるためです。
- 形は `{ "Format": 1, "Bank", "Map", "MapScripts", "Table", "Persons": [{ "Index", "X", "Y", "Kind", "Label" }], "Signs": [...], "Traps": [...] }` です。`Kind` は eventscripts の種別（人は `npc` / `trainer` / `item`）、`MapScripts` はマップスクリプトの表のラベル、`Table` は ZigzaguMap が `.s` に書くマップスクリプトの表です。Bochi の maps\ の JSON と同じ整形（2 空白の字下げ、CRLF、ASCII 以外は `\uXXXX`）で書きます。
- ファイルの無いマップは、eventscripts の `#ifdef` の外の行をそのまま読みます。ラベルを変えるまで、ファイルは作りません。`#ifdef` の中の行は読むだけで、ZigzaguMap は変えません。
- 出力（Ctrl+S）のとき、変えたマップとファイルのあるマップについて、ファイル（座標は今のイベントの座標。ただし、マップを開いたときにファイルの座標と合わなかったラベルが同じ番号に付いたままなら、ファイルの座標のまま。付け直すまでずれの知らせを残すため）を書き、eventscripts のそのマップの `#ifdef` の外の行をファイルに合わせます（同じイベントの行はシンボルだけ書き換え、要らない行は消し、無い行は足す）。ファイルもeventscripts も、中身が変わるときだけ書きます。ラベルを全部外したマップのファイルは消します。
- イベントを消すと、後ろのイベントのラベルが 1 つずつ前に詰まります。イベントの数を減らすと、いなくなったイベントのラベルも消えます（どちらも元に戻すと戻る）。
- マップを開いたとき、ファイルに書いた座標と今のイベントの座標が合わないラベルがあれば（Bochi などでイベントの順を変えたとき）、イベントタブの右上に知らせを出します。書いた座標にある同じ種類のイベントが 1 つだけなら、「座標で付け直す」でそのイベントへ付け替えられます（`realignEventLabels`。元に戻せる）。

### ラベルの自動命名とひな形

イベントを置いたとき（イベントマネージャーで数を増やしたとき、`addEvent`）に、ラベルを自動で付け、ひな形をすぐ `.s` と `.string` に書きます（#202）。

- ラベルは規則（zigzagumap.json の `labelTemplate`、既定 `{map}_{kind}{index}`）で付けます。`{map}` は `.s` の名前から作り（`01_moegi.s` → `Moegi`。数字だけの区切りと末尾の `scripts` は外し、区切りごとに頭を大文字にする）、`.s` の名前から作れなければ `Map3_0` のようにバンクとマップの番号にします。`{kind}` は `Npc` / `Sign` / `Tile`、`{index}` はイベントの番号です。プロジェクトのほかのラベルやイベントのラベルと重なれば、番号を 1 つずつ増やします（例 `Moegi_Npc3`、`Moegi_Sign1`、`Map3_0_Tile2`）。
- ひな形は、人が `lock` `faceplayer` `msgbox 文 MSG_FACE` `release` `end`、看板が `msgbox 文 MSG_SIGN` `end`、スクリプトタイルが `lockall` `msgbox 文 MSG_NORMAL` `releaseall` `end` です。文のラベルは `gText_<ラベル>` です。ND は msgbox に漢字のポインタも書き（`msgbox gText_X MSG_FACE gText_X_k`）、`.string` にひらがなと漢字の 2 つ（同じ本文）を足します。Chronos は 1 つです。`useGlobal` が true なら、ラベルの前に `.global` を書きます。
- `.s` の最後に、空行を 1 つはさんで足します（`.string` も同じ）。エディタで開いているファイルなら、エディタの本文へ足し、そのタブに未保存の変更が無ければそのまま保存します（未保存の変更があれば足すだけで、保存はエディタで行う）。
- `.s`・`.string`・幅検査の登録への書き込みは、メインの書き込み（ひな形・取り込み・イベントの削除・マップスクリプトの表）もエディタの書き込み（ラベル名の変更で開いていないファイル・幅検査の登録）も、メインの 1 本の列で 1 つずつ行います（#293）。エディタを閉じるときは、閉じる前の確認と保存が済んでウィンドウが消えるまで次の書き込みを待たせ、消えたあとはディスクへ書きます。書く前にタブやエディタが閉じたら、ディスクの本文に書き直します。
- ひな形を置いている途中（「.s を新しく作る」の入力を待っている間など）に、もう 1 つ置こうとするとエラーになります（自動操作の `template.place`。#294）。
- ひな形を書くのは、イベントを置いたコマンドの一部です。元に戻すと、ラベルを外し、ひな形に手が入っていなければ `.s` と `.string` から除きます（手が入っていれば残して、ステータスバーに出す）。やり直すと同じ名前でもう一度書きます。
- マップの `.s` が maps\scripts.json に無いときは、ファイル名の入力（「scripts.json の編集画面」の「新しい .s を作る」と同じもの）を出し、作ったあとに置いたイベントへラベルとひな形を付けます（`assignEventLabels`。これも元に戻せる）。
- 新しい `.s` はふだん出力のときに作りますが（#201）、ひな形を書くときは、そのときに `.s` と `.string` を作ります（決まった先頭の後ろにひな形を足す）。出力のときは、もうあるので書き換えません。元に戻しても、作った `.s` と `.string` は消しません。

### ラベル名の変更（F2）

エディタで、カーソルのあるラベル名を F2 で変えられます（#203）。

- 新しい名前を聞き、`assembly/overworld_scripts` の下のすべての `.s` の定義と参照（コメントと `"..."` の中は除く）を変えます。開いているタブは本文を書き換え（エディタの元に戻すで戻せる）、開いていないファイルはディスクを書き換えます。
- そのラベルを使っているイベントとマップスクリプトの表があれば、メインでラベルを変えるコマンド（`renameEventLabel`）を実行します（メインの Ctrl+Z で戻せる）。eventscripts は出力のときに書きます。
- 手で名前を書き換えて保存したときも、そのファイルで消えたラベルと増えたラベルが 1 つずつで、消えたラベルをイベントが使っていれば、「イベントのラベルも変えますか？」と聞きます。

### 素の ROM のスクリプトの表示と取り込み

ラベルの付いていないイベントの「スクリプトを開く」（とダブルクリック）、マップスクリプトのパネルの「見る」で、ROM のスクリプトをエディタの読み取り専用のタブ（`ROM:08XXXXXX`）に出します（#206）。プロジェクトが無く ROM だけを開いているときも出せます。そのときは、逆アセンブルと同じ同梱の命令表（0F が 1 ポインタの CFRU の表）で命令の色付けとホバーを出します。「.s に取り込む」はプロジェクトフォルダが要るので押せません（`tests/automation/rom_only_script_check.py` で確かめています）。

- 逆アセンブルはメインウィンドウで行い（ROM はメインだけが持つ）、文字にした結果だけをエディタへ送ります。命令表はプロジェクトの xse_commands.s から作り（素の ROM だけなら同梱の表）、使うたびに作って捨てます。文字列は後ろに `@` のコメントにして付けます。
- タブの上の「.s に取り込む」（#207）で、付けるラベルの一覧（スクリプト・文字列・移動データ・ショップ）を出し、確かめてから（名前は変えられる）マップの `.s` と `.string` に書き足し、イベントのラベルを取り込んだ入口にします。入口はイベントのラベルの規則で付け（`Moegi_Npc3`）、たどった先は `<入口>_1`…、文字列は `gText_<入口>_1`…、移動データは `m_<入口>_1`…、ショップは `<入口>_Mart1`… です。
- 取り込んだまとまりの前には印（`.s` は `@ ZigzaguMap: ROM 0x08XXXXXX から取り込み`、`.string` は `//` の同じ行）を書きます。同じアドレスをもう取り込んであれば、そのラベルを使い、書き直しません（たどった先が取り込み済みなら、そのまとまりは書かずにラベルだけ使う）。
- ND では、漢字のポインタを省いた 0F（ひらがなと同じ文字列）を、同じ本文の `_k` を作って `loadpointer 0x0 X X_k` に指し直します（ND の書き方にそろえる）。
- 取り込みは、イベントのラベルを変えるコマンドに書き足しを結び付けたものです。元に戻すと、ラベルを戻し、手が入っていなければ書き足しも除きます。eventscripts は出力のときに書きます。
- マップスクリプトのパネルの「見る」で開いた、表の行き先のアドレス（`0x0816F58D` のようなもの。条件表の行の行き先も）も取り込めます。入口は「種類を足す」のひな形と同じ `<表のラベル>_<種類>`（`Moegi_MapScripts_OnLoad`、条件表は `_OnFrame` / `_OnWarpInto`。重なれば `2` から番号を付ける）にし、表で行き先がそのアドレスの件をすべて入口のラベルに付け替えます。
- マップにまだ表が無ければ、取り込みと一緒に「表を作る」と同じ表（今のマップスクリプトをアドレスのまま）を作ってから付け替えます。表の行き先ではないアドレス（条件表そのものの位置など）と、ZigzaguMap の表ではない手書きの表を指しているマップは取り込めません。
- マップスクリプトの取り込みは、表を変えるコマンド（`setMapScriptTable`）に書き足しを結び付けたものです。元に戻すと、表を前の形（表が無かったなら表の無い形）に戻し、手が入っていなければ書き足しも除きます。

### マップスクリプトの専用パネル

場所の設定タブの「かんたん（CFRU）」表示のマップスクリプトは、専用のパネルです（#208）。オフセット（ROM のポインタ）の欄は出しません。

- 表は `.s` に書き（`@ ZigzaguMap: マップスクリプトの表 <ラベル>` の行から「ここまで」の行まで。出力のときに書き直す）、eventscripts の `map` の行で指します。表は `mapscript 種類 行き先` を並べて `.byte MAP_SCRIPT_TERMIN` で終え、条件表（種類 02・04）は `.align 1` のあとに `levelscript 変数 値 行き先` を並べて `.hword 0` で終えます。表の中身は scripts_MM.json の `Table` に持ちます。
- まだ表が無いマップでは、今の ROM（か maps\ の JSON）のマップスクリプトを読むだけの一覧と「表を作る」を出します。「表を作る」は今の内容をアドレスのまま表にします（ビルドしても動きは変わらない）。
- 「見る」で開いた ROM のスクリプトは、エディタの「.s に取り込む」で `.s` に取り込めます。行き先はアドレスから取り込んだラベルに変わります（上の「素の ROM のスクリプトの表示と取り込み」）。
- 種類ごとの一覧で、行き先をラベルの欄（イベントタブと同じ。マップの `.s` のラベルから選ぶ。`0x0816F58D` のようなアドレスも書ける）で変えます。条件表は変数・値・行き先の行を並べます。「種類を足す」「条件を足す」は、何もしないスクリプトのひな形（条件表なら、変数を次の値にして繰り返しを止める `setvar`）を `.s` に書いて行き先にします。
- 表の編集はどれも 1 回の操作として元に戻せます（`setMapScriptTable`）。「表をやめる」で、出力のときに `.s` の表と eventscripts の `map` の行を消します。
- プロジェクトフォルダが無いときは、ROM のマップスクリプトを読むだけの一覧にします。

### ビルド

ツール > ビルド（F7）と、スクリプトエディタの下のビルドの欄（Ctrl+B）で、設定（zigzagumap.json の `build`）の手順を上から順に動かします（#198）。

- 先に、エディタの未保存のファイルを保存するか、メインの未出力の変更を出力するかを聞きます（いいえなら、そのままビルドする）。
- 出力（標準出力と標準エラー）は 1 行ずつ欄に出します。手順が終了コード 0 以外で終わったら、そこで止めます。「止める」で子プロセスごと止めます。
- `command` が `copy` の手順は、ZigzaguMap がファイルを写します（`args` の 1 つ目を 2 つ目へ。どちらも `cwd` からの相対パス）。ND の既定は、CFRU のビルド（`python scripts/make.py`）→ `test.gba` を `../NeoDark-DPE-main/BPRJ0.gba` へ写す → DPE のビルド（`../NeoDark-DPE-main` で `python scripts/make.py`）を 1 回で行います。
- 終わったら、ログからエラーの行（GNU as の `ファイル:行: Error:`、`.string` の `Error parsing string on line N`、`Symbol missing: X`、Chronos の `TEXT WIDTH ERROR`、Python の `Traceback` など）を拾って欄の上に並べ、押すとその行を開きます（読み取りは core の `script/build/BuildLog.ts`）。拾ったエラーはエディタの文書に `build-problems` の出来事でも知らせます（波線 #195 の入口）。
- エミュレータの起動は作っていません（#199 は閉じた）。土台にあった Rust の `process_launch` などの入口は、画面から使わないので消しました。

### scripts.json の編集画面

ツール > スクリプトファイルの対応表 で開きます（CFRU-JP のフォルダを開いているときだけ）。開いたままマップを切り替えられます。

- 表の 1 行は、バンク・マップ・マップ名・`.s`・`.string` です。マップを空欄にするとバンク全体の行になります。同じバンク・マップを指す行が複数あると、前の行だけが使われます（後ろの行は灰色にし、下に警告を出します）。「上へ」「下へ」で並びを変えられます。
- `.string` の欄には、`.s` を入れると `strings/overworld_strings_<.s の名前>.string` が自動で入ります。手で書き換えたら、そのまま残します。既定の名前のままなら、scripts.json の `Strings` は省いて書きます（読むときは同じ名前になります）。
- パスはプロジェクトフォルダからの相対パスで、`\` で入れても `/` にそろえます。`..` や絶対パスは使えません。拡張子は `.s` と `.string` です。
- 行の追加・「変更を保存」・削除・並べ替えは、どれもアンドゥできます（Ctrl+Z / Ctrl+Y）。削除しても `.s` と `.string` のファイルは消しません。
- maps\scripts.json に書くのは出力（Ctrl+S）のときだけです。表を変えていなければ、scripts.json には触りません（手で書いた整形もそのまま残ります）。scripts.json の形式が不正なときは、表を出さずに理由を出し、編集も上書きもしません。

`.s` を新しく作る:

- 「新しい .s を作る」を押すと、ファイル名の入力が出ます。ファイル名（例 `03_00_masara`。`.s` は付けても付けなくてもよい）・バンク・マップ・マップ名・`.string` を入れて「作成」を押すと、対応表に行が足されます。マップにスクリプトが要るのに対応する `.s` が無いとき（イベントを置いたときなど）も、同じ入力が出ます。
- 作る場所は `assembly/overworld_scripts/<ファイル名>.s` と、`strings` の下の `.string` です。ファイル名に使えるのは半角の英数字と `_` `-` `.` だけです。
- `.s` の中身は、ND と Chronos の既存の `.s` と同じ先頭（`.text`、`.thumb`、`.align 2`、空行、`.include "../xse_commands.s"`、`.include "../xse_defines.s"`、`.include "../asm_defines.s"`）と空行 1 つです（UTF-8・LF）。`.string` は空のファイルです。
- ファイルを作るのも出力（Ctrl+S）のときです。出力の前にアンドゥで行を消せば、ファイルは作りません。出力のときに同じ名前のファイルが既にあれば、書き換えずにそのまま使います。入力のときに `.s` が既にあれば、作らずに表に足すだけにするかを聞きます。
- ビルド（ND の `python scripts/make.py`、Chronos の `python build.py`）は `assembly/` の `.s` と `strings/` の `.string` をすべて拾うので、作ったファイルはそのままビルドに入ります。

### 外部コマンドの実行（Rust）

ビルドと幅検査に使う、Rust 側の仕組みです（`src-tauri/src/process.rs`。crate は増やさず標準ライブラリだけで作っています）。

- コマンドは、設定（zigzagumap.json）に書いたものを、指定の作業フォルダで起動します。作業フォルダは開いているプロジェクトフォルダからの相対パス（`..` で上へ出てもよい。Chronos は 1 つ上の `Chronos` で動かす）か絶対パスです。黒いコンソールのウィンドウは出しません。
- 標準出力と標準エラーは 1 行ずつ、呼んだウィンドウへイベント `process-output`（`{ id, stream, line }`）で届き、終わると `process-exit`（`{ id, code, killed }`）が届きます。Python の出力が文字化けしないよう、環境変数 `PYTHONUTF8=1` と `PYTHONIOENCODING=utf-8` を付けて起動します。UTF-8 として読めないバイトは置き換えます。
- 途中で止めると、子プロセスごと止めます（Windows は `taskkill /T`）。ZigzaguMap を終了したときも、動いているコマンドを止めます。
- ビルドの手順の `copy` は `process_copy` で写します（作業フォルダの決め方はコマンドと同じ）。エミュレータの起動の入口（`process_launch`）は、#199 を閉じたので消しました。
- ファイルの更新日時と大きさを返す `fs_stat` を足しました（無ければ null）。スクリプトエディタが外部の変更を見つけるのに使います。
- 別ウィンドウは、大きさを変えられるもの（最小の大きさつき、最大化もできる）も開けます。位置と大きさはメインが個人設定に残し、次に開くときに当てます（自動操作のときは使わず、画面外に出します）。

## スクリプトの再生とタイムライン（Phase6）

`applymovement` などの 4F スクリプトを、ゲームと同じ 1 フレーム（約 1/60 秒）の単位で計算して再生します。計算はすべて core（画面なし）にあり、再生の画面を開いたときに初めて読み込みます。数値の根拠は FRLG 日本語版のソースと ROM の表です。エミュレータでの突き合わせはまだしていないので、「ソースの読みだけ」の値はそう書いています。

### 移動コマンドの表（#448）

移動データの 1 バイトごとに、かかるフレーム数、フレームごとに進む画素、ジャンプの高さ、マスが進むフレーム、絵の種類、効き目（向きの固定、見える・見えない、頭の上の印など）を持つ表です（`packages/core/src/script/movement/MovementActionTable.ts`）。再生の計算と、NPC の動き（#13）の両方がこの表を使います。

- 1 マスの歩きの速さ（遅い順）: 160（0x9B〜）・31（`walk_*_very_slow`）・23（`walk_*_slow`）・16（`walk_*`）・11（`slide_left_foot_*`）・8（`run_*`・`slide_right_foot_*`）・6（`slide_*_slow`）・4（`slide_*`）・2（`slide_*_fast`）フレーム。ROM の 1 マスの歩数の表（16・8・6・4・2）とジャンプの高さの表と同じ値です。
- xse の名前と中身が違う命令があります。`run_*` は 2 倍の歩き（走りの絵ではない）、`slide_*_slow`・`slide_*`・`slide_*_fast` は 3・4・8 倍の歩き、`slide_right_foot_*`・`slide_left_foot_*` は走りの絵の 2 倍・1.5 倍です。タイムラインには名前と実際の動きの両方を出します。
- 名前はプロジェクトの `xse_defines.s` を先に見て、無ければ同梱の名前を使います。
- 感情アイコン（0xAA〜0xB9、CFRU）は命令としては 1 フレームで終わり、アイコンが 60 フレーム出ます。
- 長さが絵のアニメで決まる命令（0x45・0x5B・0x68・0x69・0x98〜0x9A・0x9F）は、長さが分からない印を付けて 1 フレームとして扱います。自転車のウィリー（0x70〜0x93）と Chronos の 0xBA〜0xBD は「知らない命令」です。
- ソースの読みだけの値: ワープで上へ消える・上から降りる（0xA4・0xA5）の 22 フレーム、拡大しながらの歩き（0x6E・0x6F）、頭の上の印の 60 フレーム。

### 移動データの読み取りと書き戻し（#449）

`.s` の移動データ（`m_Walk: .byte walk_up, walk_up, end_m`）を、ラベルから `end_m` まで位置つきで読み、書き換えた並びを元の書き方のまま書き戻す部品です（`packages/core/src/script/movement/MovementBlock.ts`）。

- 1 行に並べた形、1 行 1 命令の形、ラベルと同じ行の `.byte`、行の後ろのコメント、CRLF を扱います。変えずに書き戻すと 1 文字も変わりません（ND と Chronos の `assembly/overworld_scripts` のすべての移動データで確かめるテストがあります）。
- 書き戻すときは、変わらない項目の書き方（名前か 16 進）とコメントを残し、足した項目は名前があれば名前、無ければ `0x` の 16 進で書きます。1 行 1 命令の形では、足した項目を前の行の字下げと `.byte` に合わせた新しい行にします。
- 書き戻せない移動データ: `end_m` が無い、`.if` などの中にある・途中に `.if` がある、途中にマクロや `.byte` 以外のディレクティブがある、値の分からない名前がある、同じラベルが 2 か所にある、途中に別のラベルがある、ROM の移動データ（アドレスのまま）。理由を付けて返し、タイムラインでは編集できない印にします。

### スクリプトを実行順にたどる（#450）

ラベルから、スクリプトの命令を実行する順に 1 つずつ返す部品です（`packages/core/src/script/playback/ScriptWalker.ts`）。Phase2 の要約は重なりを省くたどり方で実行順と条件を持たないので、別に作りました。

- 命令名は、プロジェクトの `xse_commands.s` のマクロを中まで展開して、ゲームの命令（命令番号と引数のバイト）に直してから意味を決めます。ND の `cond`、Chronos の `if`、`switch`/`case`（`compare` と `goto_if` の 2 命令になる）、`msgbox`（`loadpointer` と `callstd`）などの書き方の違いは、ここで吸収されます。マクロの定義はいつもプロジェクトのファイルを読むので、`xse_commands.s` を直せばそのまま合います。
- `call` と `return`、`goto`、`goto_if`・`call_if` をたどります。条件分岐の答えは呼び出し元が決めます（再生では、値の分かる比べ方は計算し、分からないものは「飛ばない」を既定にして、タイムラインの分岐の印で選び直します）。分岐は「場所」と「何回目に来たか」で区別します。
- 止まるとき: `end`、呼び出し元の無い `return`、`.byte` などのデータに入った、ファイルの終わり、命令 10,000 個（ループの打ち切り）、飛び先のラベルが無い、飛び先が ROM のアドレス（`goto 0x8192F0E` など）、始めのラベルが `.if 0` の中。`call` の飛び先が ROM のアドレスなら、注意を出して次の行へ進みます。
- `.if`・`.ifdef`・`.ifndef` と `.else`・`.endif` は、値の分かる条件なら外れた側の行を読みません。
- 定義の無いマクロを呼ぶ古い別名（`setobjectxy` → `movesprite`、`turnobject` → `spriteface`）は `moveobject`・`changeface` として読みます。そのほか展開できないマクロは、注意を出してその行を飛ばします。

### 再生の計算とタイムラインのデータ（#451）

たどった命令を、ゲームと同じ順（スクリプト → 移動データを人物に渡す → 人物を動かす → 画面）で 1 フレームずつ進め、最後まで計算してからタイムラインにします（`packages/core/src/script/playback/PlaybackSimulator.ts`・`Timeline.ts`・`PlaybackState.ts`）。コマ送り・戻し・ジャンプは、そのフレームの状態を `stateAt(frame)` で出すだけです。

- フレームの決まり（ソースの読みだけ。エミュレータでの突き合わせはまだ）:
  - `applymovement` を実行したフレームに 1 歩目の 1 画素が動き、論理の位置（マス）は歩き始めで行き先に変わります。命令と命令の間に空きはありません。
  - 移動の合計が T フレームなら、`waitmovement` の次の命令は F+T+2 フレーム目（F は `applymovement` のフレーム）。`wait n` の次の命令は n+1 フレーム後です。
  - 同じフレームの `applymovement` は同時に動きます。まだ動いている人物への `applymovement` はゲームと同じく無視し、印を出します。
- 人物の番号は、0x4000 以上なら変数の中身（`setvar 0x8005 2` の後の `applymovement 0x8005` など）、0xFF は主人公、0x7F はカメラです。
- 変数（`setvar`・`addvar`・`copyvar` など）とフラグは、分かる値だけ計算します。`compare`・`checkflag` の結果が分かる分岐は計算で決め、分からない分岐は「飛ばない」を既定にして、タイムラインの分岐の印で答えを選び直せます（選び直すと最初から計算し直す）。
- 文（`msgbox` など）・はい・いいえ・選択肢は長さ 0 の印です（再生の画面ではそこで止まる）。選択肢は既定の答え（はい・いいえは「はい」、`multichoice2` は既定の項目、ほかの `multichoice` と ND・Chronos の `customchoice` は一番上）を LASTRESULT に入れて最後まで計算し、後の `compare` と分岐は値から決まります。答えを替えると計算し直します。選択肢は「場所」と「何回目に来たか」で区別します。ほかの命令（音、アイテムなど）も長さ 0 で並べます。
- ドアの `opendoor`・`closedoor`・`opendoor2`・`closedoor2` は、フレームとマスを持つ「ドア」の印にします（ドアの絵はタイルアニメの側が印から描く）。`waitdooranim` の長さは、計算の設定 `doorWait` に渡した関数（ドアの表から開き終わるフレームを返す）で決め、渡さなければ待たずに進みます。
- 天候の `setweather`・`doweather`・`resetweather`（0xA4・0xA5・0xA3）は「天候」の印にします（待たないので時間は 0）。絵は天候のプレビュー（表示 > 天候を表示する）が印から描きます（docs/map-editing.md の「天候」）。
- `hidesprite`・`showsprite`（マップのデータの位置に出す）・`moveobject`・`visible`・`invisible`・`faceplayer`・`changeface` を扱います。マップのデータ（イベント）は読むだけで変えません。
- 人物の自分の動き（移動タイプ）は止めます。60 秒（3,600 フレーム）で打ち切ります。
- 計算の時間: 命令 200 個・人物 16 人で中央値 1.8ms（vitest で計った値。命令表と索引を作る時間は入れない）。

### カメラ・画面の揺れ・callasm の再現（#452）

`special` の番号と `callasm` の名前 → 再生での処理、の表です（`packages/core/src/script/playback/handlers/PlaybackHandlers.ts`）。表に 1 行足すと、新しい callasm の処理を登録できます。表に無い special・callasm は何もせずに印を出し、結果を変数で返すものは後の分岐で答えを選びます。

- `special 0x113`（CAMERA_START）: 画面が今追っているマスに見えない人物 0x7F を作り、画面が追う相手をそれに替えます。画面は動きません。
- `applymovement CAMERA`: 普通の人物と同じに動き、画面はその 1 フレームの移動の分だけ動きます。ジャンプの高さでは動きません。
- `special 0x114`（CAMERA_END）: 追う相手を主人公に戻し、0x7F を消します。画面は動かさないので、戻さずに終えると主人公が画面の真ん中から外れたままになります（ゲームと同じ）。
- `special 0x136`（画面を揺らす）: 0x8004 縦の揺れ幅、0x8005 横の揺れ幅、0x8006 回数、0x8007 間隔。間隔ごとに向きを反転し、`waitstate` は「間隔 × 回数」フレームで進みます（長さはソースの読みだけ）。`special 0x111`（エレベーター）は印だけです。
- callasm `MoveCameraToTrainerB`（ND・Chronos）: 0x8005 に 0x7F を入れ、もう 1 人のトレーナーの向き（LASTRESULT）は分からない値にします（後の `case` の分岐で選ぶ）。`HideFollower` は連れ歩きを見えなくします。
- Chronos の `settimeofday` は時間帯の印を出します（画面の側で時間帯の切り替えにつなぐ）。

### 再生の始めの状態（#453）

`packages/core/src/script/playback/StartState.ts`。主人公はマップに置かれていなくても人物 0xFF として出し、絵は男 0（`EVENT_OBJ_GFX_RED_NORMAL`）・女 7（`EVENT_OBJ_GFX_LEAF_NORMAL`）です。

- 踏むスクリプト: そのマスの上で下を向きます。変数の条件は見ずに始め、条件を帯に出します。
- マップスクリプト: 仮の主人公の位置、無ければ最初のワープの上。
- 1 コマ目の主人公の向きは変えられます（`faceplayer` の結果が変わる）。
- マップの人物は全員居るものとし、外した人物だけ居ないことにします。向きは移動タイプの基本の向きです。

### 人物の向きと歩きのコマ（#468）

NPC・再生・仮の主人公で使う共通描画部品があります。ROMのアニメーション表から向き、コマの時間、左右・上下反転を読み、移動途中の位置とジャンプの高さを反映します。仮の主人公と再生はこの部品を使います。NPCの自動移動は後続の作業です。

### 歩きの姿勢の持ち越し（#482）

人物ごとのアニメーション時計で、コマの位置、残り時間、有限ループ、終了、停止を保持します。連続して歩く場合も毎回同じ足から始めず、ROMの歩行・停止対応表に従って左右の足を切り替えます。向きや速度の変更、その場で半分だけ向きを変えるジャンプにも、直前の姿勢を引き継ぎます。

`ANM_CHG_HOLD` は絵の表の変更を禁止するもので、時計の停止とは別に扱います。表を読めない場合は標準値で補わず、診断を返します。

再生ではコマと反転を1人・1フレーム2バイトで記録します。フレームを戻す操作や直接指定でも、順に再生した場合と同じ絵になります。この時計はNPCにも使う共通部品です。

### 再生画面とタイムライン（#454〜#456）

プロジェクトとマップを開き、イベントの右クリック、ツールの「スクリプトを再生」、またはエディタのラベルの上の右クリックから始めます。再生中は人物の自動移動を止め、スクリプトの命令で動かします。エディタで未保存の本文も読みますが、再生によってファイルを書き換えることはありません。

マップの下のバーで再生・一時停止・終了、主人公の男女と向き、居ない人物、速度を選びます。タイムラインは人物ごとの行と全体の印を持ち、箱のクリックで移動前へ、ダブルクリックでスクリプトの行へ移ります。目盛りはドラッグでき、Ctrl＋ホイールで拡大縮小できます。開いているエディタでは、現在の `applymovement` と移動データの値を強調します。

再生バーでは左右キーで動きの前・中・後へ、Shift＋左右キーで1フレームずつ移動します。Home・Endで最初・最後、Spaceで再生・一時停止です。キーは「ショートカットの変更」で変えられます。

文で一時停止し、「続きを読む」で次へ進みます。はい・いいえ・`multichoice`・`customchoice` は既定の答えで最後まで計算します。タイムラインの「選択」の印に今の答えが付き、印を押すとその場面へ移って、バーの下で答えを選び直せます（`multichoice` は項目の表を読まないので 0〜127 の数で選び、127 は B で閉じた場合）。選び直しても今のフレームは変わりません。条件が分からない分岐も、既定の「進まない」で計算し、印から選び直せます。メッセージ枠はROMの絵とパレットを読み、並べ方を確認できたものだけを表示します。読めない枠は中立の枠にします。文字は ROM のフォントで描きます（下の「メッセージの字」）。

### メッセージの字（#497）

窓の字は、実機と同じ字の絵・幅・字間・改行で描きます。

- かな・英数・記号は FR 日本語版のフォントです。看板・ラベルからの再生はフォント 2（システム用）、人物に話しかけたときは、その人物の見た目の性別でフォント 4（男）か 5（女）になります（実機の `FieldBitMapTalkMsgSet` と同じ）。文字は窓の中の x 6・y 2 から、字の幅 + 字間 1 で並び、行の送りは 15 画素、1 行は 208 画素、窓は 2 行です。
- 漢字は、ND・Chronos のベースの ROM に当てている「漢字対応パッチ ver.1.00」の絵です（ROM の 0xE60000〜。文字コードは `FC` ＋ Shift-JIS）。幅は 10 画素です。
- フォントを読む ROM は、プロジェクトのビルドの出力（スクリプトの設定の出力 ROM）→ 開いた ROM → プロジェクトのベースの ROM（ND の `BPRJ0.gba`、Chronos の `../base/BPRJ0.gba`）の順に探し、漢字パッチのある最初のものです。ビルドの出力には CFRU が直した字（数字の 1 など）と ND の空白の幅（6 画素）も入っています。どれにも漢字が無いとき（素の ROM だけのときなど）は、かなを開いた ROM から読み、漢字は補います。
- 字の絵が無い字（charmap.tbl に無い字、ROM の絵が空の字、漢字パッチの無いときの漢字）、ボタンの絵（`[A_BUTTON]` など）、フォント 0・1 への切り替えのあとの字は、確認用のフォントに桃色の点線の枠を付けて補います。ゲームの字ではありません。窓の下の説明（マウスを重ねると出る）に、補った字の一覧が出ます。
- 主人公・ライバルの名前とバッファ（`[PLAYER]`・`[RIVAL]`・`[BUFFER1]` など）は、仮の名前を入れずに、入りうる一番長い名前の幅の点線の箱に名前（主人公・ライバル・BUFFER1 など）を書いて出します。名前の長さで行がはみ出さないかを見るためです。幅は主人公・ライバル 5 字、バッファ 8 字、戦闘のポケモンの名前 11 字です（全角 1 字 11 画素）。
- `\n` で次の行、`\l` でボタンを待ってから 1 行上へ送り、`\p` でボタンを待ってから窓を消して次のページ、`[PAUSE_UNTIL_PRESS]` でボタンを待ちます。どれも再生の「続きを読む」（Space）で次へ進み、最後のページの次で文を読み終えます。窓の下に「ページ / ページ数」を出します。
- `[RED]` などの文字の色、背景・影の色の切り替え、`[SHIFT_TEXT]` などの位置の制御も実機と同じに扱います。窓の右（208 画素）や 3 行目にはみ出した字は実機と同じく描かず、窓の下に知らせます。
- ND の改変 0F（`loadpointer 先 ひらがな 漢字`）と `customchoice` は、漢字の文を出します（実機の漢字の設定のとき）。
- フォントは再生で初めて文を出すときに読み、再生を終えたら捨てます。
- charmap.tbl に同じ字が 2 回ある（ND・Chronos の `D5=a` と `F4=a` など）ときは、ビルドの `scripts/string.py` と同じく後ろの行のコードで出します（#505）。ND・Chronos の表では英字の a・o・u・O・U と ? が後ろの ä・ö・ü・Ö・Ü・▶ の位置のコードになり、ビルドした ROM でも同じコードで書かれるので、ゲームの中でもウムラウト付きで出ます。名前（トレーナー名など）は `scripts/map_project.py` と同じく前の行です。
- 合わせていないもの: スクリプトの命令で変える話し手の性別（`setobjsex`）、見た目が変数で決まる人物（0xF0 以上）の性別（どちらもフォント 2 で出します）、ボタンの絵、フォント 0・1（小さい字）。

Chronosの `settimeofday` は時間帯ビューアと同じ設定を使います。戻す操作でもその時点の色になり、再生を終了すると元の時間帯、イベント表示、スクロールに戻ります。通常の頭上の印5種類はROMから、ND・Chronosの追加の感情アイコン16種類はプロジェクトのPNGから読みます。表示時間、コマの切り替え、浮き上がる動き、人物とは独立した優先順位を反映します。

追加アイコンのパレットは動的に割り当てられます。時間帯の色が全OBJスロットで同じ場合だけ色を確定し、スロットごとの結果が異なる場合は読めなかったデータとして報告します。

### 素の ROM のスクリプトの再生（#459）

スクリプトが ROM のアドレスのままのイベント（素の ROM だけを開いたとき、またはプロジェクトでまだ `.s` に取り込んでいないイベント）も、右クリックの「スクリプトを再生」や仮の主人公から再生できます。

- ROM のスクリプトを逆アセンブルし、エディタの読み取り専用の表示（#206）と同じ本文にしてからたどります。命令の並びは、`.s` に取り込んだ後にたどったものと同じです（素の ROM のマサラタウンの人物と踏むスクリプトで確かめるテストがあります）。
- 命令表と文字の表は、プロジェクトがあればそのもの、無ければ同梱の表を使います。
- 読み取り専用の表示を開いていれば、今の命令と移動データの値の行を強調します。
- タイムラインの箱は編集できない印になり、「.s に取り込む」を案内します。取り込むと編集できます。

### タイムラインからの移動データの編集（#458）

タイムラインの箱を編集すると、`.s` の移動データへ書き戻します。

- 箱の右クリック: 向きを変える（↓↑←→）、別の命令に差し替える（同じ向きで種類・速さの違う命令の一覧から）、同じ命令を前・後ろに足す、続けて同じ命令の回数を変える、消す。
- 箱を押して選ぶと、Delete で消し、Alt＋矢印でその向きに変えます（矢印だけなら今までどおり動きの前後へ移ります）。箱を横にドラッグし、同じ移動データの別の箱の上で離すと並べ替えます。
- 書き戻しは移動データの値だけを変え、書き方（1 行に並べた形・1 行 1 命令の形）、コメント、名前か 16 進かを保ちます。足した値は、プロジェクトに名前があれば名前で書きます。
- エディタで開いているファイルは、エディタの本文に入れます（エディタの Ctrl+Z の履歴にも入ります）。未保存の変更が無ければ保存し、あれば保存しません。開いていないファイルは、再生を計算したときの本文と同じときだけ書きます。外で変わっていたら書かずに知らせ、読み直して計算し直します。
- 1 回の編集は 1 つの操作になり、メインの Ctrl+Z・Ctrl+Y で `.s` を戻せます。戻すとタイムラインも計算し直します。今のフレームは保ちます。
- 同じ移動データを複数の `applymovement` が使っているときは、使っている数を出して聞きます。「はい」でそのまま書き換え（ほかの所も変わります）、「いいえ」で `<元の名前>_2` に写して、このスクリプトの `applymovement` だけ付け替えます。
- 書き戻せない移動データ（ROM のアドレスのまま、`.if` の中、`end_m` が無いなど）の箱は、斜体の薄い表示にし、ホバーと右クリックに理由を出します。ROM のものは「.s に取り込む」と編集できます。

### 道をなぞって移動データを作る（#517・#518）

マップの上をなぞって、`applymovement` の移動データ（命令の列）を作る窓です。メインの画面に浮かぶ小窓で、開いたときに初めて読み込みます。窓はふだん左のマップ一覧の上に出し、始めの位置のまわりを隠すときはマップの表示の右端に寄せて出します。タイトルの帯をドラッグすると動かせます。

開き方は 3 つあります。

- 再生の帯の「道をなぞる…」: 今のフレームで動いている `applymovement` があれば、その人物の動き始めの位置から始め、その移動データを置き換える先にします。無ければ今のフレームの主人公の位置から、新しいラベルとして作ります。ほかの人物の位置は今のフレームのものです。
- イベントタブの人物の右クリック「ここから道をなぞる…」: その人物の位置から、新しいラベルとして作ります。
- スクリプトエディタの `applymovement` の行の右クリック「道をなぞって作り直す…」: その移動データを置き換える先にし、メインの窓に開きます。動かす人物は行の 1 つ目の引数（今のマップの人物でなければ主人公）です。

- 窓では、動かす人物（イベントの人物か主人公）、始めの位置と向き、歩きの速さ（移動コマンドの表にある 1 マス進む歩き）を選びます。人物を選ぶと、始めの位置はその人物の置き場所になります。
- マップの上を左ドラッグすると、通ったマスごとに 1 歩の歩きを足します。斜めや離れたマスへ飛んだときは、横を先に、次に縦に分けます。開いている間は、マップの左ドラッグは道をなぞる操作になり、ブロックを描いたりイベントを動かしたりしません。
- キー: 矢印で 1 歩、Ctrl＋矢印で向きだけ（`look_*`）、Backspace で 1 つ戻す、Shift＋→ でやり直す。窓の「待ちを足す」は、フレーム数を 16・8・4・2・1 の待ちの命令に分けて足します。
- ジャンプは作りません（段差の向きと合わせる必要があり、なぞって作ると間違えやすいため。#507 の Q9）。要るときはタイムラインの差し替えで変えます。
- 通れないマス（マップの外、通れない移動許可、段差、ほかの人物）を通る歩きは、下見の線と一覧の行を赤くし、窓に知らせます。スクリプトの移動データは壁でも通り抜けて歩くので、作るのは止めません。
- 下見は、道の線と向きの矢印、始めの位置の丸、終わりの位置の薄い人物（再生と同じ描き方）です。窓を閉じる・マップを切り替えると消します。マップのデータは変えません。
- 「ここで使う」で `.s` に書きます。書き方は 2 つです。
  - 置き換える: 開いたもとの移動データの値を、なぞった道に置き換えます。書き方（1 行に並べた形・1 行 1 命令の形）とコメントは保ちます。同じ移動データを複数の `applymovement` が使っているときは、タイムラインの編集と同じく、そのまま書き換えるか `<元の名前>_2` に写してこのスクリプトだけ付け替えるかを聞きます。
  - 新しいラベルで足す: `Move_<マップ名>_<番号>`（窓で変えられる）の移動データを、`.s` の最後に空行をはさんで 1 行の形で足し、名前をクリップボードへ写します。足す `.s` は maps\scripts.json のこのマップの行、無ければこのマップのイベントのラベルがある `.s`（マップスクリプト、動かす人物、ほかのイベントの順）です。`useGlobal` が true なら `.global` も書きます。
- 書き込みはタイムラインの編集と同じ部品です。エディタで開いているファイルはエディタの本文に入れ、未保存の変更があれば保存しません。1 回の書き込みは 1 つの操作になり、メインの Ctrl+Z で戻せます。再生中なら、書いた後に計算し直すので、そのまま再生してなぞった道を確かめられます。

### 実機と違う所（再生）

再生は、実機と同じ見た目と動きを目指していますが、確認用です。次の点は実機と同じになりません。

- 乱数: 人物の自分の動き（移動タイプ）の乱数は、実機と同じ式ですが並びは同じではありません。再生の間は人物の自分の動きを止めるので、再生のタイムラインには影響しません。「人物を動かす」では[実機との違い](map-editing.md#実機との違い)に書きました。
- 移動タイプ: 主人公をまねる型と隠れる型は動かしません（[移動タイプの対応表](map-editing.md#移動タイプの対応表)）。
- 連れ歩き: 止まっている間の上下の揺れ、ボールの出入りは描きません（[連れ歩き](map-editing.md#連れ歩き)）。
- メッセージ: 枠はROMの絵とパレットを読みますが、文字は確認用のフォントで描きます。実機のフォントの字形・幅の再現ではないので、行に収まるかの確認には使えません。幅の目安は、エディタの `.string` の簡易の幅検査（「[.string と簡易の幅検査](#string-と簡易の幅検査)」）で見てください。
- 選択肢と分岐: 既定の答えで最後まで計算し、答えはタイムラインの印から選び直します。実機のように、その場で入力を待ちません。

### ソースの読みだけで決めた値（未確認）
