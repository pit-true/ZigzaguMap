# 接続・描画・イベントの操作

## 仮の主人公と実機の画面枠

表示 > 仮の主人公を置く、またはイベントタブの右クリックの「ここに仮の主人公を置く」で、マップに保存しない主人公を置きます。男女と向きは画面上の欄で選べます。男女はスクリプトの再生の帯と同じ個人設定です。主人公をドラッグすると移動し、選んで矢印キーを押すと、その向きに 1 マス歩きます（16 フレームの歩きの絵）。右クリックでも向きを変えられます。

プロジェクトを開いているときは、仮の主人公からスクリプトを再生できます（#457）。

- 歩いて踏むスクリプトのマスに乗ると、そのスクリプトを自動で再生します。変数の条件は見ずに始め、条件を再生の帯に出します。ドラッグや置き直しで乗ったときは始めません。
- 人物か看板の方を向いて Enter か Space を押すと、そのスクリプトを今の位置と向きから再生します。看板は向きの条件を見て、調べられない向きなら知らせます。
- 再生を終えると、仮の主人公は再生を始めた位置と向きに戻ります。

240×160の画面を、人物の足元が左から120px・上から88pxになる位置に重ねます。表示 > プレイヤーの視界の枠（V）で枠と周囲の暗さを切り替えます。人物はROMの方向別の絵で描き、通常ブロックの前景やトリプルレイヤーとの重なり、高さに基づく優先順位、時間帯の色を反映します。「画面をPNGで保存」は、枠と操作の部品を除いた同じ240×160の画像を書きます。

「仮の主人公を終了」で表示と枠の設定を戻します。マップやROMを切り替えたときも配置を捨てます。位置・向き・男女はマップへ書きません。人物を動かす方法は次の節にあります。

### 連れ歩き

連れ歩きのあるプロジェクト（ND）では、仮の主人公の欄に「連れ歩き」が出ます。チェックを入れると、選んだポケモンが主人公の後ろに出て、主人公の歩いた道を追って付いてきます。種族は欄で選び、既定は絵のある最初の種族です。「色違い」「メス」で見た目を変えられます。位置は保存しません。

- 絵はDPEのフォルダの `graphics/ow/32`・`graphics/ow/64`・`graphics/ow/pal` から読みます（`zigzagumap.json` の `dpeDirectory`、無ければNDは隣の NeoDark-DPE-main）。メスの絵が無ければオスの絵、色違いのパレットが無ければ通常のパレットを使います。ヒポポタスなど、メスが別の種族番号の5種は、その番号の絵を使います。
- 有効かは、プロジェクトの `src/follower_mon.c` と DPE の絵で決めます。`#ifdef POKEMON_FOLLOWERS` で囲んだ作りでは、`src/config.h` でこの定義が有効なときだけ使えます。Chronosは無効なので、欄に理由を出して連れ歩きを出しません。
- 主人公が1マス動くと、主人公が居たマスへ歩きます。歩いている間に主人公が続けて動いたときや、ドラッグで何マスも動かしたときは、通った道（横、縦の順）を速い歩きで追います。12マスより遠くへ動かしたときは、主人公のすぐ後ろへ置き直します。道の途中の段差は2マスのジャンプで越えます。
- 重なり順は、32×32の絵はほかの人物と同じく高さで決まります。64×64の絵はゲームと同じく8枚に分け、外の列は前景より上、真ん中の列と下の段は主人公との位置と前のマスの重ね方で変えます。横を向いている間は、はみ出す分だけ主人公と反対側へずらします。
- ゲームとの違い: 止まっている間の上下の揺れ、ボールから出る動き、なみのり・自転車・ワープでボールに戻る動きは描きません。歩いている間だけ時計を回します。

## 人物を動かす（移動タイプの再生）

表示 > 人物を動かすで、表示中のマップの人物を移動タイプのとおりに動かします。既定はオフで、設定には残しません。もう一度選ぶと止まり、人物は元の位置に戻ります。マップやROMを切り替えたときも止まります。人物の位置はマップへ書きません。

- 動く人物はマップの画像の上に描きます。前景のブロック（通常ブロックの上の層、トリプルレイヤーの3枚目）より奥の人物は前景に隠れます。重なり順は高さで決まり、仮の主人公の画面と同じです。
- イベントタブでは、人物の元の位置を箱で示します。動いている絵は箱の下に出ます。
- 仮の主人公を置いている間は、240×160の画面にも動く人物を描きます。主人公のマスには人物が入りません。
- マップの見えないタブ（野生・場所の設定）を開いている間は、時計を止めます。止めている間はCPUを使いません。
- 人物を編集すると、最初の位置から動かし直します。ブロックや移動許可を変えたときは、そのまま続けて描き直します。

### 実機との違い

動きの規則は元の日本語版のソース（`evobjmv.c` の各タイプの関数）をそのまま写しています。待ちの長さは表 {32, 64, 96, 128}（2方向・3方向の見回しは {32, 48, 64, 80}、回るタイプは48）から乱数で選びます。

- 乱数は実機と同じ式ですが、実機ではほかの処理も同じ乱数を使います。そのため、どの人物がいつどちらへ動くかは実機と一致しません。エディタでは毎回同じ種から始めるので、同じ操作なら同じ動きになります。
- 通れるかの判定は実機の順です。移動範囲 → 移動許可の衝突 → マップの外 → 一方通行のブロック（今のマスと行き先）→ 高さ → ほかの人物と主人公。移動範囲の値が0のときは、歩き回るタイプと道のタイプでは1として扱います（実機の補正と同じ）。
- 接続した隣のマップへは入りません（実機では入れる場合があります）。
- 主人公は止まっているものとして扱います。主人公をまねるタイプは動かず、走っている主人公の方を見回すトレーナーが向く動きも起きません。
- クローンの人物は動かしません（元のマップで動かします）。

| 0x02 | MV_ON | 歩き回る（4方向） |

## 人物の移動範囲と視界

表示 > 人物の移動範囲と視界で、人物ごとの移動範囲と、主人公を見つける視界を重ねて表示します。既定はオフです。表示はマップのデータを変えません。

- 移動範囲は青い四角で示します。中心は元のイベントの位置です。人物を動かしている間も、動いた後の位置ではなく元の位置が中心です。範囲の値が0でも、歩き回るタイプと道のタイプは1として扱います。
- 視界は、主人公が立つと見つかるマスを塗ります。トレーナーは赤、主人公を見つける普通の人物は橙の点線です。視界を遮ったマスには×を描きます。
- 視界は人物の今の位置と向きから計算します。人物を動かしている間は、向きや位置が変わると視界も付いてきます。
- イベントタブで選んだ人物は、線を太く描きます。

視界の決め方は元の日本語版のソース（`ev_trai.c` の `TrainerEyeChk`）に合わせています。

- 「トレーナー」の値が1なら今の向きの1方向、3なら4方向を見ます。距離は「視界」の値です。
- 人物のマスから主人公の手前のマスまでに、移動許可の衝突、マップの外、一方通行のブロック、高さの違い、ほかの人物があると見えません。主人公のマス自身も、衝突や高さの違いで入れないマスなら見つかりません。移動範囲は視界に関係しません。
- CFRUのプロジェクトでは、「トレーナー」の値が0でない人物を全部調べます（1なら1方向、ほかの値は4方向）。スクリプトが `trainerbattle` で始まる人物はトレーナーです。始まらない人物は、`src/config.h` で `NON_TRAINER_SPOTTING` が有効なときだけ、普通の人物として主人公を見つけます（NDとChronosは有効）。素のROMだけを開いたときは元の規則で判定します。
- 倒したトレーナーのフラグ、手持ちの数によるダブルバトルの条件、`NON_TRAINER_SPOTTING` の人物の一度きりのフラグは見ません。

### タイルアニメとドア

240×160の画面には、海・花・噴水などのタイルアニメと、ドアの開け閉めを実機と同じ周期で描けます。表示 > タイルアニメを動かすで、人物を動かすと共通の時計を使って動かします（マップに入ってからのフレームを数え、マップを切り替えると0から数え直します）。既定はオフで、止めると元の絵に戻り、時計も使いません。仮の主人公の画面が出ていない間も時計を止めます。ふつうのマップ表示とブロックパレットは動かしません。

スクリプトの再生では、opendoor・closedoor・opendoor2・closedoor2（0xAC・0xAD・0xAF・0xB0）のドアを再生のフレームに合わせて描き、waitdoor（waitdooranim、0xAE）はドアのタスクが終わるまで待ちます（ふつうは20フレーム）。待ちの長さはタイムラインの全体の行に帯で出ます。再生中のタイルアニメは、メニューがオンのときだけ再生のフレームで動きます。

- アニメは、タイルセットヘッダーの関数（+0x10）が素のBPRJと同じ6つのどれかで、その番地のコードも同じときだけ動かします。絵はROMの表から読みます。主は海（16フレームごと・8コマ）・荒海（8フレームごと・8コマ）・花（16フレームごと・5コマ）、副は噴水2種・火山の煙・クチバジムの電線・タマムシジムの草です。関数が0のタイルセット（移植や画像から作ったもの）と、知らない関数は動かしません。
- ドアは、マスの挙動が0x69で、ブロック番号がROMのドアの表（32件）にあるときだけ動きます。開けるのは元の絵と3コマを5フレームずつ、閉めるのはその逆で、どちらも20フレームです。絵は副タイルセットの最後の8タイル（1016〜1023）に一時的に置きます。縦2マスのドアは上のマスも描き替えます。動いている間の次の開け閉めは、実機と同じく何もしません。
- 時間帯の色はアニメの絵にもかかります。元のタイルセットとマップは変えません。

### 天候（#498）

表示 > 天候を表示する で、マップのヘッダーの天候を240×160の画面（仮の主人公と再生）に重ねます。表示 > プレビューする天候 で「マップの天候」のほか、0〜14の天候を一時的に選べます（ヘッダーは変えません。選ぶと表示も始めます）。既定はオフで、ふつうのマップ表示と画像の書き出しの全体図は変えません。仮の主人公の「画像の保存」の PNG には天候も入ります。

- 絵は ROM の天候の関数のリテラルから読みます（雨・雪・霧・霧2・雲・火山灰・砂嵐・泡）。色番号のまま持ち、雷で色が変わっても作り直しません。
- 動きは FR 日本語版の weather.c・wea_*.c を1フレームずつ写したもので、共通の時計で進めます。マップに入ったときと同じく、雨粒や霧が出そろった形から始まります。仮の主人公の画面が出ていない間と、オフの間は時計を使いません。オフにすると読んだ絵と作業用の領域を捨てます。
- 画面の色は段（曇り・雨・雪・雷雨・大雨は段3、雷は段19まで）でパレットにかけます。BG 0〜12 は BG 用の表、人物は OBJ 用の表（曇りでは変わらず、雷では明るくなる）です。霧（6）は、素の ROM では人物の色を (28,31,28) へ 12/16 寄せ、CFRU では寄せません（FADE_NPCS_IN_FOG が無効）。
- 時間帯の色との順は CFRU と同じで、BG は時間帯の色に天候の段を、人物は天候の段に時間帯の色をかけます。
- 半透明の絵（霧・霧2・雲・薄い霧・灰・砂嵐）は、下の画素と BLDALPHA の係数で混ぜます。霧・霧2・雲は同じ優先度の人物より奥、ほかは手前です。
- CFRU の ROM で火山灰（7）が砂嵐の関数に置き換わっていれば、白い砂嵐（HailstormWeatherPal の色）にします。ROM のフックから色を引けないとき（ビルド前の ROM）は、プロジェクトの src/config.h と graphics/Other/Hailstorm/HailstormWeather.png を使います。
- 再生では、setweather（値を覚える）・doweather（切り替える）・resetweather（ヘッダーの値に戻す）を印にし、そのフレームで今の天候を終えてから次の天候へ徐々に切り替えます。戻すと最初から計算し直します。
- 日照り（12）は「この天候はプレビューできません」と出します。FR 日本語版は日照りで色を変えず（weather_fade の負の段は何もしない）、表を作る関数が空のため、マップに入ると処理が終わらず止まります。

実機と違うところ:

- 雪・雷の間隔・泡の位置に使う乱数（pp_rand）は同じ式ですが、種は0から始めます。実機の並びとは同じになりません。雨粒の位置は粒ごとの式で決まるので、実機と同じ並びです。
- マップに入るときの黒からのフェード（fade_field_in）と、日照りの初回の光（HideriFlashEffect）は描きません。
- 雨・雷の音は鳴らしません。
- 雪は ROM どおり、寿命で隠れた雪が戻りません（snow_comeback_timer を増やす処理が無い）。そのため、しばらくすると雪が見えなくなります。ROM のコードを読んだ結果で、mGBA の画面では確かめていません。
- 背景色（バックドロップ）は半透明の第2の対象に入っていませんが、ここでは下の画素と混ぜます（マップのブロックが画面を覆うので、ふつうは違いが出ません）。
- 同じ優先度の人物と天候の絵の前後は、霧・霧2・雲を奥、ほかを手前に決めています。人物の優先度が1（高い所の橋など）のときの細かい重なりは確かめていません。
- 雷の光・時間帯の色は CFRU の動的パレットの番号を決められないので、天候の絵には人物の0番と同じ時間帯の色をかけます。

### 隣のマップと接続

#### 隣のマップの帯

マップタブ・移動エリアタブ・イベントタブで、表示中のマップ（主マップ）のまわりに、上下左右の接続でつながっているマップを並べて描きます。境界のずれ（接続の offset）を、2 枚を見比べながら確かめるためのものです。

- 見せる範囲は 表示 > 隣のマップ で選びます: 「境界から 8 ブロックの帯」（既定）／「マップ全体」／「出さない」。8 ブロックは、実機で主人公が境界に立ったとき向こう側に見える幅です。設定は個人設定の `neighborView`（`band` / `all` / `off`）に残ります。
- 隣のマップは少し暗く描き、主マップには 1px の暗い枠を付けます。移動エリアタブでは隣の移動許可も重ねます。帯の上でダブルクリックするとそのマップを開きます。マップタブ・移動エリアタブでは帯の上の 1 回のクリックで描きますが、ダブルクリックで開くときは、その 2 回のクリックで描いた分を取り消し、履歴にも残しません（#292）。
- 置き場所は接続の向きと offset から決めます（下: 主マップの下に offset だけ右へずらす、上: 主マップの上、左・右も同じ）。帯の幅の外（主マップから 8 ブロックより向こう）は描きません。ダイブ・浮上の接続は並べません（Space で重ねる機能で扱います）。
- 隣のマップは、主マップを出したあとで読みます（マップの切り替えの時間には入りません）。開いて編集していないマップは読み取り専用で読み、編集中のマップの一覧には入れません。帯の画像は 16 枚まで覚えておき、同じ組み合わせに戻ったときは描き直しません。主マップと違うタイルセットの組は、帯を描いたら捨てます。
- 隣のマップを編集したり（2 枚にまたがる操作）、タイルセットを編集したり、主マップの接続や大きさを変えたりすると、帯を描き直します。
- 比較テスト（AdvanceMap との比較）は、AdvanceMap に無い表示なので、帯を「出さない」にして比べます。

#### 接続のずれの調整（角のつまみ）

マップタブの隣の帯の両端（接続の向きと直交する側の端）に、青い枠の小さなつまみ（角のつまみ）を出します。つまみをドラッグすると、帯がブロック単位で動き（下見。ステータスバーに新しいずれを出す）、離すとその接続のずれ（offset）が変わります。

- 相手のマップの、このマップを指す逆向きの接続のずれを、同時に `-offset` にそろえます（境界は両側から見て同じでないと、ゲームの中で行き来したときにずれるため）。相手に逆向きの接続が無ければ、このマップだけを変えて、ステータスバーで知らせます。
- 両方のマップに未出力の印が付き、Ctrl+S で両方とも書きます。1 回の「元に戻す」で両方が戻ります。
- 上下の接続のつまみは横、左右の接続のつまみは縦にだけ動きます。イベントタブ・移動エリアタブには出しません。
- コネクションマネージャーで「調整」（ずれ）だけを変えて「保存」したときも、相手の逆向きの接続をそろえます（設定 > 接続のずれを相手のマップにもそろえる。既定はオン。オフにすると AdvanceMap と同じく自分だけ変える）。方向や相手のマップも一緒に変えたときはそろえません。

#### 接続の追加と削除（辺のつまみ）

マップタブの主マップの 4 辺の中央に、青い丸のつまみ（辺のつまみ）を出します。右クリックすると、その辺の接続のメニューが出ます（隣のマップを「出さない」にしているときは、つまみも出しません）。

- **新しいマップを作ってつなぐ**: 新しいマップを置くバンクを聞きます（既定は今のマップのバンク。いっぱい（255 枚）なら新しいバンク）。バンクの末尾（新しいバンクならマップ 0）に作ります。大きさは、その辺のうち同じ向きの接続で覆われていない区間のいちばん長いところ（4 マス以上。無ければ辺の終わりの 4 マス）の長さ × 奥行き 20 マス（大きさの上限を超えるときは縮める）。ヘッダーは今のマップの写し、タイルセットと境界ブロックは同じ、配置は全部ブロック 0（移動許可 0x0C）です。両側の接続を作ります。
- **既存のマップとつなぐ**: つなぐマップを選びます（上の欄で番号「3.19」か名前の一部で絞り込めます）。ずれは長さの差の半分で、中央にそろえます。相手のマップに逆向きの接続を足します（もうあれば、ずれだけそろえます）。
- **接続を消す（相手のマップ）**: その辺の接続ごとに出ます。確かめてから消し、相手のマップの逆向きの接続も消します。ダイブ・浮上の接続もここから消せます。
- **ダイブ先を作ってつなぐ／ダイブ先をつなぐ／浮上先を作ってつなぐ／浮上先をつなぐ**: ダイブ・浮上の接続は 1 枚に 1 つまでなので、もう持っていれば押せません（相手がもう持っているときはエラーを出します）。作るときは今のマップと同じ大きさ、ずれは 0 です。
- どれも 1 回の「元に戻す」で戻ります（新しいマップも消えます）。両方のマップに未出力の印が付きます。

#### 辺のつまみのドラッグでリサイズ

辺のつまみ（主マップの辺の中央の青い丸）を左ドラッグすると、その辺の向きへ広げる・縮めることができます（外へ引くと広がり、内へ押すと縮みます）。ドラッグ中は新しい大きさを青い点線の枠で見せ（ステータスバーに大きさ）、離したら 1 回の操作で変えます。Esc で取りやめます。

- 大きさの制限は場所の設定タブのリサイズと同じ `(幅+15)×(高さ+14) ≤ 10240` で、幅・高さは 4 より小さくできません（ドラッグはそこで止まります）。
- 増えた行・列は、元の端の行・列の写しで埋めます（同じドラッグの中で縮めてから広げ直すと、元の内容に戻ります）。
- **左・上へ広げた（縮めた）とき**は、見た目の位置関係が変わらないように次も直します: 配置を右・下へずらす、全イベント（人・ワープ・スクリプトタイル・看板）の座標をずらす、直交する辺の接続のずれ（左右なら上下の接続、上下なら左右の接続）を足し、相手のマップの逆向きの接続から引く、フライトポジションがこのマップを指していればずらす、`maps\BB\scripts_MM.json` のラベルの照合用の座標をずらす。縮めて左・上へはみ出したイベントは「マップの外のイベント」の帯に出ます。
- `.s` の中の座標（このマップへ座標つきで来る `warp` などの命令、このマップのイベントのスクリプトの中の `setobjectxy` などの命令）は直しません。見つけたら「直していない座標」のダイアログで、ファイルと行を一覧にして知らせます。
- 右と下では、配置の端を足す・削るだけで、イベントと接続は変えません（場所の設定タブのリサイズと同じ）。
- 1 回の「元に戻す」で全部戻ります。ずれを直した相手のマップにも未出力の印が付きます。

#### 境界をまたぐ描画

マップタブでは隣のマップの帯の上にも描けます。鉛筆（左クリック・左ドラッグ）、スタンプ（複数選択）、矩形塗り（Ctrl＋左ドラッグ）、入れ替え（Alt＋左ドラッグ）、右クリックの拾い、矩形の選択（Ctrl＋右ドラッグ）が境界をまたいで動きます。移動エリアタブの移動許可の書き込みと矩形塗りも同じです。

- 帯で見えていない部分（主マップから 8 ブロックより向こう、隣のマップの無いところ）には描きません。表示 > 隣のマップ を「マップ全体」にすると、隣のマップ全体に描けます。
- 1 回の操作が 2 枚のマップにまたがるときは、マップごとの書き込みをまとめて 1 回の操作にします（1 回の「元に戻す」で両方戻ります）。ドラッグの途中で境界をまたいでも 1 回です。
- 隣のマップへ初めて書くときに、そのマップを編集用に読み込みます（読み込むまでの間に描いた分は、読み込んでから順に書きます）。書いたマップには未出力の印が付き、帯も描き直します。Ctrl+S で両方とも出力します。
- 矩形塗りの下見は、主マップのタイルセットで描きます（隣のマップのタイルセットが違うときは、書いたあとの帯の見た目が正しい絵です）。

#### Space でダイブ先・浮上先を重ねる

マップタブとイベントタブで Space を押している間、ダイブ・浮上の接続先のマップを主マップに重ね、マウスのまわり（半径 4 ブロックの丸）だけを透かして見せます。海の上の岩や浅瀬と、潜った先の地形の位置を合わせるためのものです。

- 重ねている間にダブルクリックすると、相手のマップを開きます（主マップには描きません。#292）。Space を離すと消えます。
- ダイブと浮上の両方があるときはダイブ先を重ねます。どちらも無ければステータスバーで知らせます。
- 相手のマップは、主マップと同じ大きさなので全体を読みます（読み取り専用。編集中のマップの一覧には入れません）。画像は Space を離したあとも 1 枚だけ持ち、同じマップでもう一度押したときはすぐ出します。

#### クローン（表示 > クローン）

表示 > クローン に印を付けている間だけ、イベントタブで人を、上下左右の接続の相手（隣のマップ）の境界から 8 マス以内に置くと、隣のマップに同じ見た目のクローンを作ります（HexManiacAdvance と同じ。境界を越える前から隣の人が見えるようにするため）。既定は印なし（作らない）です。

- クローンは人の種類 1 で、高さの欄に参照先の人の番号、トレーナーの種類の欄に参照先のマップ、視界の欄に参照先のバンク、見た目とフラグは元の人と同じです（FR の `ObjectEventTemplate` のクローンの形）。位置は隣のマップの座標で、隣のマップの外（境界ブロックの所）になります。
- 合わせるのは、人をドラッグで動かしたとき、座標・見た目・フラグなどの欄を入力したとき、イベントマネージャーで数を変えたとき、ひな形で置いたとき、イベントを削除したときです（どれも同じ規則）。元の人を近いまま動かすとクローンも動き、8 マスより外へ出す・元の人を消すとクローンを消します。元の人の操作とクローンの変更は 1 回の「元に戻す」で戻り、隣のマップにも未出力の印が付きます。
- 印を付けている間は、イベントタブの隣の帯の上に、そのマップのクローン（隣のマップの人の写しで、このマップの外に置かれたもの）も描きます。帯といっしょに少し暗くします。
- クローンの見た目はほかの人と同じです（#298）。ふだんは人の文字の箱（P）、表示 > オブジェクトの表示 がオンなら元の人の OW の画像で描きます。マップの中にあるクローンも、帯の上のクローンも同じ規則です。画像は、クローン自身の見た目の欄ではなく元の人（参照先のマップの、番号が同じ人）の見た目の欄から引きます（ゲームの中でもクローンは元の人の見た目になるため）。向きはほかの人と同じく 1 コマ目（下向き）です。元のマップをまだ読んでいなければ読み込んでから描き直し、読めない・元の人がいないときはクローン自身の見た目の欄で描きます。
- クローンには、マスの右上に白い縁の水色の小さな三角を付けます（画面だけ。マップ&イベント画像の保存とマップの画像のコピーには付けません）。クローンの吹き出しには「クローン（元: マップ 3.19 の人 2）」のように元の人を出し、続けて元の人のスクリプトの要約（セリフ・アイテムなど。主マップの人と同じ形）を出します（元のマップを読んでいなければ読み込んでから。読めなければ「番号 3 の人」のように参照先の番号だけ）。マップの中のクローンも、帯の上のクローンも同じです（帯の上は、表示 > クローン がオンで描いているときだけ。#345）。
- 印が無いときは、作りも消しもしません。すでにあるクローンは、普通のイベント（種類 1 の人）として上と同じ見た目で見えます（帯の上には描きません）。
- マップのリサイズやずれの調整ではクローンを動かしません（HMA と同じ。手で直す）。
- クローンはマップの外に置くものなので、「イベントがマップの外に配置されています」の知らせには数えません。
- 作った・動かした・消したことはステータスバーの補助の欄で知らせます。比較テストはクローンを作らない（印なし）で比べます。
- 自動操作: `event.state` の `clones`（クローンの人の番号と参照先、元の人の番号 `originIndex`、描く画像番号 `graphicsId`）、`neighbors.state` の `clones`（位置・人の番号・描く画像番号）・`clonesShown`、`action` の `view.clones`（個人設定 `showClones`）。

### 描く

#### 複数選択の移動許可と、コピー・貼り付け

マップから Ctrl＋右ドラッグで矩形を拾うと、ブロックと一緒に移動許可も拾います。左クリックで貼ると、マップタブの右の欄（境界ブロックの下）の「移動許可も貼る」がオン（既定）なら移動許可ごと、オフならブロックだけを貼ります（AdvanceMap はブロックだけ）。ブロックパレットから選んだものは移動許可を持たないので、今までどおりブロックだけを貼ります。

- Ctrl+C で今の選択をコピーし、Ctrl+V でマウスが乗っているマスを左上にして貼ります（どちらもマップタブ。アプリの中だけのクリップボードで、OS のクリップボードは使いません。後ろを覆うダイアログを開いている間と、入力欄の中では反応しません）。
- 貼るのは 1 回の操作です（1 回の「元に戻す」で戻ります）。「移動許可も貼る」は個人設定 `pasteMovements` に残ります。

#### 矩形塗りと 2 マスの入れ替え

- **矩形塗り（Ctrl＋左ドラッグ）**: マップタブで、押したマスと今のマスを角にした矩形を、選んでいるブロックで埋めます。ドラッグ中は矩形にブロックを半透明で重ねて見せ（下見）、離したら 1 回の操作で書きます。複数選択（スタンプ）は矩形の左上を基準にくり返して敷き詰めます（右端・下端で切れる分は切ります）。移動許可を持つ選択は「移動許可も貼る」に従います。移動エリアタブでも同じ操作で、選んでいる移動許可を矩形に塗ります（ブロックは変えません）。
- **2 マスの入れ替え（Alt＋左ドラッグ）**: 押したマスと離したマスのブロックと移動許可を入れ替えます（HMA は何も選んでいないときのドラッグですが、ZigzaguMap はいつも何かを選んでいるので Alt を使います）。
- **取りやめ（Esc）**: 矩形塗り・入れ替え・矩形の選択（Ctrl＋右ドラッグ）のドラッグ中に Esc を押すと、離しても何もしません。
- どれも 1 回の「元に戻す」で戻ります。修飾キーなしの左クリック・左ドラッグ・右クリック、Ctrl＋右ドラッグは今までどおりです。Ctrl を押したままの左クリック（ドラッグしない）は 1 マスの矩形塗りになるので、スタンプは左上の 1 ブロックだけ置きます。

#### ミキシングバッグ

ブロックパレットで Ctrl＋左クリックすると、そのブロックを袋（ミキシングバッグ）に出し入れします（もう一度押すと出します）。袋の中身はパレットの下に並びます（空なら出ません）。袋の欄を Ctrl＋クリックすると空にします。

- 袋に 2 つ以上入っていて、選んでいるブロック（1 つ）が袋の中にあるとき、鉛筆（左クリック・左ドラッグ）と矩形塗り（Ctrl＋左ドラッグ）は、マスごとに袋の中から乱数で選んで描きます。境界をまたぐ描画でも同じです。袋を使うときは袋の欄に青い枠が付きます。
- 移動許可は、マップタブの「移動許可を自動で選ぶ」（#235）がオンなら、描いたブロックにいちばん多い移動許可も書きます（オフならブロックだけ）。
- 選んだ結果は操作（コマンドの引数）にマスごとのブロックとして残るので、やり直しでも同じ絵に戻ります。袋の中身はファイルに残しません（ROM を開き直すと空）。

#### 移動許可の自動選択・ブロックの使用回数・移動許可だけ違うマスの強調

- ROM を開いたあと、少し待ってから全マップの配置を 1 回なめて、タイルセットの組ごとにブロックの使用回数と、ブロックごとの移動許可の数を数えます（マップの表示を遅らせない）。描いたり取り消したりすると、そのマップの分だけ数え直します。主タイルセットのブロック（0x000〜0x27F）は主タイルセットが同じマップ全部、副のブロックは主と副の組が同じマップ全部で数えます。ベース ROM で配置を共有しているマップ（ポケモンセンターの中など）は 1 回だけ数えます。Phase5（#395）から、境界ブロック（ボーダー）に置いたブロックも数えます（移動許可の数には入れません）。
- マップタブの右の欄の「移動許可を自動で選ぶ」（既定オン。個人設定 `autoMovement`）: ブロックを 1 つ選ぶと（パレット・マップの右クリック・境界ブロック）、全マップでそのブロックにいちばん多い移動許可を選びます（移動エリアタブで描く値。ステータスバーの補助の欄で知らせる）。移動許可を持つ選択（マップから拾った複数選択・スタンプ）には当てません。マップタブで描くのはこれまでどおりブロックだけです。
- 同じ欄に「使用回数: N（このマップ M）」と「多い移動許可」を出します。
- 表示 > 移動許可の強調（既定オン。個人設定 `usageMarks`）: マップタブでブロックを 1 つ選んでいるとき、同じブロックなのに移動許可がいちばん多い値と違うマスを黄色の枠で囲みます。移動エリアタブでは、選んでいる移動許可の値のマスを桃色の枠で囲みます。Ctrl を押している間は描きません。画像の保存と `canvasPng` には入りません。
- 比較テスト（AdvanceMap との比較）は、AdvanceMap に無い動きなので、自動選択と強調を切って比べます。
- 自動操作: `blockUsage`（`block`。省略で選んでいるブロック）、部品の ID `map.autoMovement`（チェック）・`map.blockUsage`・`map.blockUsageMost`、`action` の `view.usageMarks`。

#### スタンプ（マップタブ）

マップから拾った複数選択（Ctrl＋右ドラッグ。ブロックと移動許可）やブロックパレットで選んだ複数のブロックを、名前を付けて `maps\stamps\` に保存し、あとで一覧から選んで貼れます。

- マップタブの右の欄の「スタンプ」の「選択を保存」で、今の選択に名前を付けて保存します。同じ名前があれば上書きするか聞きます。
- 一覧には、今のマップに貼れるものだけを名前順にサムネイルつきで出します。主タイルセットのブロックだけのスタンプは主タイルセットが同じマップ、副タイルセットのブロック（0x280 以上）を含むスタンプは主と副の両方が同じマップに出ます。出していない数は一覧の下に出します。サムネイルは今のタイルセットで描きます（保存しない）。
- 項目を押すとそれが選択になり、左クリックで貼ります（今の複数選択と同じ。Ctrl+V の貼り付けとも同じ）。移動許可は「移動許可も貼る」がオンなら一緒に貼ります（ブロックパレットから作ったスタンプは移動許可を持たないので、ブロックだけ）。選んだあとでタイルセットの組が違うマップへ移ると、ステータスバーで知らせます。
- 項目の右クリックで「名前の変更」「今の選択で上書き」「削除」。
- 保存・名前の変更・上書き・削除はすぐファイルに書き、出力（Ctrl+S）を待ちません。元に戻すの対象にもしません。書く前に `maps\project.json` が無ければ作ります。
- 素の ROM だけで開いているときはメモリだけに持ち、出力先を選んで出力したときに書きます。出力先を指定して別のフォルダへ出力したときも、今のスタンプをその先へ書きます。
- 形が四角でないスタンプ（`cells` に貼らないマス `null` を含むもの。ファイルを手で書いて作る）も貼れます。`null` のマスは、鉛筆・矩形塗りの敷き詰め・境界ブロック・境界をまたぐ描画のどれでも書かず、元のブロックを残します。コピー（Ctrl+C）と「選択を保存」でも穴を保ちます。
- 自動操作: `stamps.list`・`stamps.save`・`stamps.select`・`stamps.rename`・`stamps.remove`。

### 表示と移動

#### Ctrl で重ね描きを隠す・座標と選択範囲の表示

- 移動エリアタブとイベントタブで Ctrl を押している間、移動許可の重ね描きとイベントの箱を描きません（下のブロックを見るため）。離す・ウィンドウからフォーカスが外れると戻ります。Ctrl＋ドラッグの間も隠れたままです。マップタブの重ね描きは矩形選択の枠だけなので、隠しません。
- イベントタブで Ctrl を押している間は、イベントをつかまず、吹き出しも出しません。Ctrl＋右クリックで、イベントの下のブロックを拾います（マップタブで描くブロックになる。メニューは出ない）。
- ステータスバーに補助の欄を足しました（AdvanceMap と同じ左の欄はそのまま）。マップタブではカーソルのブロックの番号・移動許可（値と名前）・挙動、Ctrl＋右ドラッグ（矩形選択）の間は「X・Y と W×H」、どのタブでも隣のマップの帯の上では「バンク.マップ 名前 (X, Y)」（隣のマップの中の座標）を出します。何も無ければ欄を隠します。
- 自動操作: `key` に `type: "down"` / `"up"`（押すだけ・離すだけ）。Ctrl を押している間の `canvasPng` は重ね描きを含みません。補助の欄は `getField` の `status.info`。

#### マップの履歴（戻る・進む）とマップ名で探す

- 開いたマップの履歴を 50 枚まで持ち、戻る・進むで行き来します。マップ一覧・ワープのダブルクリック・隣のマップのダブルクリック・マップを指定して開く・配置の共有の一覧など、どの開き方でも履歴に積みます。戻ってから別のマップを開くと、進むの履歴は消えます。消したマップ（取り消した作業用のマップなど）は飛ばします。
- 戻る: ツール > 直前のマップを開く（Alt+BkSp）、マウスの戻るボタン。進む: ツール > 次のマップへ進む（Alt+Shift+BkSp）、マウスの進むボタン。
- AdvanceMap の「直前のマップを開く」は直前の 2 枚を行き来しますが、ZigzaguMap では履歴を 1 つずつ戻ります（2 回押すと 2 つ前のマップ）。
- ツール > マップ名で探して開く（Ctrl+F）: マップ名の一部か「バンク.マップ」を入れると候補を出し、↑↓で選んで Enter かダブルクリックで開きます。名前は一覧と同じく「ポケセン」「ジム」などの補足も含めて探し、カタカナとひらがな・全角と半角を区別しません。空白で区切るとどの語も合うものだけを出します（「ときわ ぽけせん」）。HMA は Ctrl+G ですが、ZigzaguMap の Ctrl+G はグリッドの表示（AdvanceMap と同じ）なので Ctrl+F にしました。
- マップ一覧の上の欄に入れると、一覧を絞り込みます（合う項目とその親だけを出し、枝は全部開く。グループの名前が合えば中身を全部）。Esc か × で消すと、元の開き方に戻ります。↓か Enter で一覧へ移ります。
- 自動操作: `history.state`、`action` の `view.back`・`view.forward`・`map.find`、`mapFind`（`query`、`open`）、`tree.filter`（`text`）、`mouse` の `button: "back"` / `"forward"`。

#### 配置の共有（場所の設定タブ）

素の ROM には、同じ配置（ブロックの並び。フッター）を複数のマップで使っているものがあります（素の BPRJ では 18 組。ポケモンセンターの中は 17 枚など）。場所の設定タブに「この配置（ブロックの並び）は N 枚のマップで使われています」と、使っているマップの一覧を出します。一覧のマップを押すとそのマップを開きます。共有していないマップでは出しません。

- かんたん表示では「大きさ」の下の「配置の共有」の枠、くわしく表示では AdvanceMap の部品の枠の下に出します。
- 数えるのはベース ROM のマップのうち、`maps\` に JSON が無いものです。ヘッダーの先頭のフッターのポインタが同じものを同じ配置とみなします。
- `maps\` の JSON のマップは数えません。BochiBochiEditor 改造版と `map_project.py` は、JSON のマップごとにフッター・配置・境界を別の場所に置き直すので、ビルドした ROM でもほかと共有しません（ヘッダーの配置の番号は残りますが、データはつながりません）。
- そのため、ZigzaguMap で共有している配置のマップに描いて出力すると、そのマップだけが別の配置になり、ほかのマップは変わりません（HMA は同じ配置を使う全マップが変わります）。
- 自動操作: `getField` の `easy.layoutShared`・`header.layoutShared`（文。共有していなければ `visible` が false）、一覧のボタン `easy.layoutShared.map:<バンク>.<マップ>`（`click` で開く）。

### イベント

#### イベントのホバーの吹き出し（イベントタブ）

イベントタブでイベントの上にカーソルを 0.4 秒止めると、吹き出しで中身を出します。ボタンを押す・マップから出る・ホイールを回す・タブやマップを替えると消えます。ステータスバーの座標とオフセットは今までどおりです。

- 人・看板・スクリプトタイル: スクリプトをたどって、セリフ（1 件 60 字まで、5 件まで）、トレーナー（番号と戦闘前の文）、ショップの品物（5 品まで）、もらえるアイテム（`giveitem`・`additem`・`copyvarifnotzero`）、もらえるポケモン（`givepokemon`）、野生戦（`setwildbattle`）を並べます。同じものは 1 回だけ出します。絵は出さず名前だけです。
  - ラベルが付いていれば（`scripts_MM.json`・eventscripts）、`.s` のラベルからたどります。`call`・`goto` などの行き先も、同じファイルの中だけたどります（深さ 4、16 か所まで）。文字列は `strings\` の `.string` から引き、定数（`.equ`）は値に直して名前を引きます。ND の 2 ポインタの `msgbox` は先の方（ひらがな）を出します。
  - ラベルが無ければ、素の ROM のスクリプトを逆アセンブルしてたどります（Phase2 の逆アセンブラ）。
  - ラベルが `.s` に無いときは「ラベル … が .s に見つかりません」と出し、ROM のポインタがあれば ROM のスクリプトを出します。スクリプトが無ければ「スクリプトなし」。
  - 種族や道具を変数で渡す命令（`givepokemon 0x4001 …`）は「変数 0x4001」と出します。素の FR の数（412）を超える種族の番号（CFRU で増やした種族）は、ベース ROM の名前の表では引けないので番号で出します。
- 人: トレーナーなら視界、クローンなら元の人（マップと人の番号。#298）と元の人のスクリプトの要約（#345）も出します。看板の隠しアイテムは道具の名前と数、スクリプトタイルは条件の変数と値、ワープは行き先のマップ名とワープの番号です。
- 同じマスに複数のイベントがあれば、線で区切って並べます。
- ワープ（#240）: 行き先のマップ名とワープの番号に加えて、行き先のワープのまわり 7×7 ブロックの画像を出します（行き先のマスを赤い枠で示す。マップの外は境界ブロック）。行き先のマップは読み取り専用で読み（開いたマップの一覧や未出力の判定に入れない）、画像は最近の 8 枚を覚えます。行き先のマップやワープが無ければ文で知らせます。
- ワープできないブロックの上のワープ（#240）: ワープが乗っているブロックの挙動が、ワープとして働くもの（洞窟の出入り口 0x60、はしご 0x61、矢印 0x62〜0x65、落とし穴 0x66、ワープ床 0x67・0x68、ドア 0x69、エスカレーター 0x6A・0x6B、階段 0x6C〜0x6F、ユニオンルーム 0x71。FR の値、`packages/core/src/map/behaviors.ts`）でなければ、イベントタブのワープの箱の右上に黄色の印を付け、吹き出しの先頭に「このブロックではワープできません（挙動 0xNN）」と出します。マップの外のワープは調べません。オブジェクトの表示（人を OW 画像で描く）のときはワープの箱を描かないので、印も出しません。行き先として着くだけのワープ（スクリプトのワープの着き先）にも印が付きます。
- 要約は最近の 64 件を覚えます。編集したとき・メインのウィンドウが前面に戻ったときに作り直します（`.s` と `.string` をエディタで保存したあとも合う）。ラベルの索引と文字列の索引は初めてホバーしたときに作ります（Chronos で 1 秒弱）。
- 隣のマップの帯の上では、帯に描いているこのマップのクローンにだけ吹き出しを出します（#345）。隣のマップ自身のイベント（人・看板・ワープなど）は帯に描いていないので、吹き出しも出しません。見えない物の吹き出しは、どこに何があるのか分からず紛らわしいためです。隣のマップのイベントを見るときは、帯をダブルクリックしてそのマップを開きます。
- 自動操作: `event.hover`（`kind`・`index` か `cell`。その場で出して文を返す）、`event.hover.state`、`event.hover.hide`。マウスの `hover` でも 0.4 秒止まれば出ます。

#### ワープの右クリックから行き先のマップを作る

イベントタブでワープを右クリックし、「行き先のマップを作る」を選ぶと、新しいマップを作ってワープを向け合います（1 回の「元に戻す」で新しいマップもワープも戻ります）。

- 見本を探します: 今のマップと主・副のタイルセットが同じマップのうち、同じブロックの上にあるほかのワープの行き先（行き先のマップとワープがあるもの。行き先のマップごとに 1 つ、8 枚まで）。窓に名前・大きさ・サムネイル（戻りのワープを置く位置を赤い枠）を並べるので、1 つ選びます。
- 見本を選ぶと、見本のマップの大きさ・タイルセット・ヘッダー・境界を写します。「見本の配置をそのまま写す」を外すと、配置はブロック 0（移動許可 0x0C）で埋めます。見本を使わないとき（見本が無いときも）は、9×9 で今のマップのタイルセット・ヘッダー・境界、ブロック 0 で作ります。
- 新しいマップを置くバンクを聞きます（既定は今のマップのバンク。満杯なら新しいバンク。マップのコネクションの「新しいマップを作ってつなぐ」と同じ）。
- 新しいマップのワープ 0 を元のワープへ向けて置きます（見本を選んだときは見本の行き先のワープの位置、そうでなければ下の辺の中央）。元のワープは新しいマップのワープ 0 へ向けます。作ったあと新しいマップを開きます。
- 自動操作: 右クリックのメニューの項目 `createWarpMap`（`contextMenu.press`）、`warp.samples`（`index`）、`warp.createMap`（`index`・`sample`（見本の番号か null）・`copyLayout`・`bank`。窓を出さない。ワープが無いなどのエラーはダイアログを出さずにエラーで返す。#380）。

#### 使われている番号の索引と「未使用」ボタン

フラグ・変数・隠しアイテムの番号・トレーナーの番号のうち、どれが使われているかの索引を作り、使われていない番号を選べるようにしました。

- 使われているとみなすもの:
  - 素の ROM の全マップのスクリプト（人・看板・スクリプトタイル・マップスクリプトの入口から、Phase2 の逆アセンブラで `call`・`goto`・`trainerbattle` の続きまでたどる）の、フラグと変数の引数（`setflag`・`clearflag`・`checkflag`・`setvar`・`compare` など。命令表の引数の種類で決める）と、`trainerbattle` の相手の番号。
  - `assembly\` の `.s` の同じ命令（数と `.equ` の名前。ほかの `.s` と `xse_defines.s` などの `.equ` も引く）と、`trainer`・`trainerbattle*` の番号。
  - 全マップ（`maps\` の JSON と ROM）の人のフラグ、スクリプトタイルの変数、マップスクリプトの条件表の変数、看板の隠しアイテムの番号。
  - C のソース（`src\`・`include\`）に出てくる `FLAG_*`・`VAR_*` の名前を、`#define` で番号にしたもの。`include\constants\flags.h`・`vars.h` に定義があるだけの名前は数えません。`src\config.h` の `#define FLAG_INVERSE 0x900` のように、ほかのファイルで定義しているものは使っているとみなします。
  - `maps\trainers.json` のトレーナーの番号（#245）。
- 隠しアイテムの番号はフラグ（0x3E8 + 番号）と同じものなので、どちらで使っていても使用中とみなします。変数は 0x4000 以上（0x8000 台の特別な変数まで）だけを数えます。
- 索引は、イベントタブを開いてから 1.2 秒後に、画面を止めないよう少しずつ作ります（ND の写しで約 1.2〜4 秒、Chronos で約 4 秒。起動からマップの表示には入りません）。マップタブなどだけを使う間は作りません（待機時のメモリを増やさないため）。ほかのタブでも、「未使用」ボタン・ひな形・自動操作で要ったときはその場で作ります。作り終えたら、全マップと C のソースを読んだごみを片付け、命令表も持ち続けません（直すときに作り直す）。作ったあとは、イベントの編集（取り消し・やり直しも）と、`.s` の書き換え（エディタでの保存、ひな形・取り込み）でその分だけ直します。
- 探す範囲は、プロジェクトの `zigzagumap.json` の `"usage"` の節で変えられます（ZigzaguMap はこの節を書きません）。

  ```json
  { "usage": { "flags": { "from": "0x21", "to": "0x3E7", "exclude": ["0x100-0x11F", "0x200"] },
               "vars": { "from": "0x4034", "to": "0x40FF" }, "hiddenItems": { "from": 1, "to": 255 },
               "trainers": { "from": 1, "to": 742 } } }
  ```

  | 種類 | 既定の範囲 | 理由 |
  |---|---|---|
  | フラグ `flags` | 0x21〜0x3E7 | 起点は HMA と同じ。0x3E8 からは隠しアイテムのフラグ |
  | 変数 `vars` | 0x4034〜0x40FF | 起点は HMA と同じ。0x40FF までが保存される変数 |
  | 隠しアイテム `hiddenItems` | 1〜255 | 看板の 1 バイト |
  | トレーナー `trainers` | 1〜742 | 素の FR の表（0 は「無し」） |

  数は 10 進の数か `"0x"` の 16 進の文字列です。`exclude` に、範囲の中で使わない番号（`"a-b"` の区間か 1 つの番号）を書けます。ND と Chronos で取り置きの範囲が決まったら、ここに書いてください。
- 画面: プロジェクトフォルダを開いているとき、イベントタブの人のフラグ、スクリプトタイルの変数、看板の隠し ID の欄の横に「未使用」ボタンを出します。押すと、範囲の中で使われていない最小の番号を入れます（欄を変えるコマンドなので、Ctrl+Z で戻せます）。素の ROM だけのときは出しません（AdvanceMap との比較の画面を変えないため）。
- 処理は core の `script/usage/`（`UsageIndex`・`UsageProject` と、出どころごとの `romUsage`・`asmUsage`・`eventUsage`・`cUsage`）、範囲の読み取りは `script/config/UsageConfig.ts`、画面側は `app/UsageService.ts` です。
- 自動操作: `usage.state`・`usage.next`・`usage.find`（[docs/automation.md](automation.md)）。

#### イベントのひな形

イベントタブのマップを右クリックして「ここにひな形を置く」を選ぶと、種類を選ぶ窓が出ます。種類と入力を決めて「置く」を押すと、押したマスにイベントを置き、スクリプトを `.s` と `.string` に書きます。プロジェクトフォルダを開いているときだけ使えます（イベントの上で右クリックしたときも、メニューの最後に出ます）。

- 置くと、イベントの追加・欄の値・ラベル（Phase2 の自動命名。`{kind}` はひな形ごとの名前）・`.s` と `.string` の書き足し・（落とし物のボールなら落とし物の設定）・（新しいトレーナーなら `maps\trainers.json`）を 1 回の操作にまとめます。1 回の Ctrl+Z で全部戻り、Ctrl+Y で同じ名前のままもう一度書きます。
- マップの `.s` が `maps\scripts.json` に無ければ、先に「.s を新しく作る」の入力を出します。
- フラグ・変数・隠しアイテムの番号は、索引（#227）の未使用の最小を既定に入れます（窓の「未使用」ボタンでも入れ直せます）。
- 文は窓で直せます。置く前に簡易の幅検査（`zigzagumap.json` の `lineMaxChars`・`linesPerPage`。既定 1 行 18 字・2 行）を通し、超えていれば置きません。既定の文はどれも収まります。
- ND は msgbox に漢字のポインタも書き（`msgbox X MSG_… X_k`）、`.string` に同じ本文の `_k` も足します。Chronos は 1 ポインタで、ラベルの前に `.global` を書きます。Chronos は、足した `#org` を幅検査の登録ファイル（`strings/text_width_registry.json`）にも足します（エディタで保存したときと同じ規則。`check_text_width.py` の REGISTRY に載っている `.string` だけ）。取り消すと登録も戻ります。
- 組み込みの 7 種類だけです（利用者が足す仕組みは作っていません）。技教えなど SPEC に無いひな形は入れていません。

|---|---|---|---|
| 人 | 人（見た目） | 見た目、文 | `Moegi_Npc3` |
| 看板 | 看板 | 文 | `Moegi_Sign1` |
| スクリプトタイル | スクリプトタイル（変数は未使用の最小、値 0） | 変数、文 | `Moegi_Tile0` |
| 落とし物 | 看板の隠しアイテム（種類 7。番号は未使用の最小）。「見えるボール（人）で置く」なら見た目 92 の人と落とし物（Bochi の ItemBalls。拾うスクリプトは出力のときに `HiddenItem.s` に書く）。フラグは未使用の最小 | 隠しアイテムの番号、アイテム、数、ボールで置くか、フラグ | （スクリプトなし） |
| アイテムをくれる人 | 人（見た目 30、下向き固定） | 見た目、フラグ、アイテム、数、渡す前と渡したあとの文 | `Moegi_Giver4` |
| ショップ | 人（見た目 68 の店員、下向き固定） | 見た目、品物（複数） | `Moegi_Mart5` |
| トレーナー | 人（見た目 18、トレーナーの種類 1、視界 5、向き固定、フラグ 0） | トレーナー（一覧から選ぶ。#245 の新しいトレーナーも）、見た目、視界、向き、戦闘前・負けたとき・戦闘後の文 | `EventScript_Moegi_Trainer6` |

#### トレーナー（maps\trainers.json）・直す窓・チームの自動生成

- ひな形「トレーナー」の窓で「新しいトレーナーを作る」に印を付けると、番号・名前・クラス・絵・手持ちを入れて、新しいトレーナーとして置けます。一覧で選んだトレーナーを見本にして、クラス・絵・BGM・性別・AI を写します。置くと `maps\trainers.json` に書き（出力のとき）、スクリプトはその番号で書きます。イベント・スクリプトと一緒に 1 回の Ctrl+Z で戻ります。
- 番号の既定は、索引（#227）で使われていない既存の枠の最小です（素の ROM のスクリプトと `.s` と trainers.json のどれにも出てこない番号）。743〜767 の番号を入れると、ビルドが表を広げます（768 から先は、戦ったかどうかのフラグ `0x500 + 番号` がシステムのフラグと重なるので使えません）。
- 「自動で作る」（乱数の種を入れて押す）: このマップと、接続している隣のマップの野生（全時間帯・全区分）から種族を選びます。数は 1〜3 匹、レベルはその野生の最高レベル + 0〜2、手持ちの形式は 0（技と持ち物を書かない。技はゲームがレベルアップの表から決める）、個体値は 0 です。同じ種なら同じ結果になります。マップに野生がいなければ、ワープの行き先のマップの野生を使います。それでも無ければ、手持ちの欄に「種族 レベル」を自分で書いてください（例 `0x10 9, 0x13 8`）。作った手持ちは窓で直してから置けます。
- **トレーナーを直す窓**: イベントタブで人を右クリックし、「トレーナーを編集」を選ぶと、その人のスクリプトが使うトレーナー（`trainer`・`trainerbattle*` の番号。イベントのホバーの吹き出しと同じたどり方）の窓が開きます。番号が見つからなければ番号を聞きます。窓では名前・クラス・絵・BGM・女性・持ち物 4 つ・ダブルバトル・AI・手持ち（「種族 レベル」をカンマで区切る）を直せます。手持ちの個体値・持ち物・技（形式が持つとき）は、同じ並びの元の値を残します。
  - 「OK」で `maps\trainers.json` に書きます（出力のとき。1 回の Ctrl+Z で戻ります）。ROM の表と同じ値に戻したときは trainers.json から消します。trainers.json にあるトレーナーなら「ROM の値に戻す」（ROM の表に無い 743 番以上は「trainers.json から消す」）も出ます。
  - プロジェクトフォルダを開いているときだけ使えます（trainers.json を `maps\` に書くため）。
- trainers.json の編集は、コマンド `setTrainer`（同じ番号が無ければ足す。あれば置き換える）・`removeTrainer` です（元に戻せます。自動操作の `command` からも使えます）。
- trainers.json を消す（全部の行を消す）と、ビルドした ROM のトレーナーの表は元に戻ります。

`maps\trainers.json` の形式（Bochi の maps\ の JSON と同じ整形。2 空白の字下げ、CRLF、ASCII 以外は `\uXXXX`）:

```json
{
  "Format": 1,
  "Trainers": [
    {
      "Id": 1,
      "PartyFlags": 0,
      "Class": 2,
      "Music": 6,
      "Female": false,
      "Pic": 7,
      "Name": "タロウ",
      "Items": [0, 0, 0, 0],
      "DoubleBattle": false,
      "AiFlags": 1,
      "Party": [
        { "Iv": 0, "Level": 9, "Species": 16 },
        { "Iv": 0, "Level": 8, "Species": 19 }
      ]
    }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `Id` | 表の番号（1〜767）。同じ番号は 1 つだけ。743 以上はビルドが表を広げる |
| `PartyFlags` | 手持ちの形式。bit0 が技あり（手持ちに `Moves` の 4 つ）、bit1 が持ち物あり（`HeldItem`） |
| `Class`・`Pic` | クラスと絵の番号 |
| `Music`・`Female` | BGM（0〜127）と女性か（1 バイトの最上位ビット） |
| `Name` | 名前（5 文字まで。ビルドが `charmap.tbl` で変える） |
| `Items` | 持ち物 4 つ |
| `DoubleBattle`・`AiFlags` | ダブルバトルか、AI |
| `Party` | 手持ち 1〜6 匹（`Iv`・`Level`・`Species`、形式によって `HeldItem`・`Moves`） |
| `Label` | 記録用（省略可）。ビルドは使わない |

- 形式の読み書きは core の `project/TrainersJson.ts` だけで行い、知らない項目は残します。1 件も無くなったらファイルを消します。
- ビルドで当てるのは build-support のパッチを当てた `scripts/map_project.py` です（「[ビルド側の変更（build-support）](script-editor.md#ビルド側の変更build-support)」）。trainers.json が無いか `Trainers` が空なら、パッチを当てる前と ROM がバイト単位で同じです。
- ビルドした ROM で確かめるには、ビルドした ROM を ZigzaguMap で開いて自動操作の `trainer.get`（その番号の名前・手持ち）を見るか、`*(0x0800F5C0)` の表の `番号 × 0x20` の位置を読みます。写しのテスト（`tests/realcopy/run.py --template`）がこれを確かめます。

### 描く道具（#388〜#390）

マップタブと移動エリアタブの右の欄のいちばん上に、道具の帯（「鉛筆」「塗り」「シフト」のボタン）を置きました。AdvanceMap と比べるマップ表示の領域にはかけていません。左ボタンで何をするかを選びます。右クリックで拾う・Ctrl＋右ドラッグで矩形を選ぶ・中ボタンでスクロール・Ctrl＋ホイールで拡大は、道具に関係なく今までどおりです。今の道具は個人設定（`paintTool`）に覚え、両方のタブで同じ道具を使います。

| 道具（キー） | 左ボタン | 修飾キー |
|---|---|---|
| 鉛筆（N。既定） | 今までと同じ（クリックで置く、ドラッグで通ったマスに置く） | Ctrl＋ドラッグで矩形塗り、Alt＋ドラッグで入れ替え（今までと同じ）。Shift を押しながらで直線 |
| 塗りつぶし（B） | 押したマスと上下左右につながった同じマスを塗る | Ctrl＋クリックでマジック塗り（つながっていなくても、マップの中の同じマスを全部置き換える）。Alt＋ドラッグの入れ替えはそのまま |
| マップシフト（S） | ドラッグした量だけマップ全体をずらす | Shift を押しながらで横か縦だけ。Esc でやめる。Ctrl＋ドラッグの矩形塗りと Alt＋ドラッグの入れ替えはそのまま |

塗りつぶしとマジック塗り（#388）:

- 「同じ」とみなすもの（Q2）: マップタブはブロックだけ、移動エリアタブは移動許可だけを見ます。同じブロックで移動許可だけ違う所も一度に塗れます。
- 選択が複数マス（スタンプ）のときは、押したマスを左上にして柄をくり返します（矩形塗りと同じ揃え方。穴のマスは書きません）。ミキシングバッグを使う選択のときは、マスごとに袋から選びます。移動許可は鉛筆の矩形塗りと同じく「移動許可も貼る」「移動許可を自動で選ぶ」に従います。
- 範囲は押したマスのマップの中だけです。隣のマップの帯の上で押したときは、そのマップの中の、帯で見えている所だけを塗ります（隣のマップへは広げません）。
- トリプルレイヤーのブロックの次の番号（N+1）は、ほかの描き方と同じく書きません。
- 1 回の塗りは 1 回の「元に戻す」で戻ります。塗ったマスの数はステータスバーに出ます。

直線とスマートパス（#389）:

- 直線（Q3）: 鉛筆・移動エリアの鉛筆で、Shift を押しながら描くと、描き始め（か Shift を押したマス）から最初に動いた向きで横か縦を決め、その線の上だけに描きます。速く動かして飛んだマスは線の上でつなぎます。Shift を離すとふつうの描き方に戻り、押し直すとその位置から続けます。1 回のドラッグは 1 回の「元に戻す」です。Shift を押していないときは、今までどおり通ったマスだけに描きます。
- スマートパス（Q4）: マップタブの道具の帯の「スマートパス」をオンにして、ちょうど 3×3 の選択（道や池の縁の見本。左上・上・右上・左・中・右・左下・下・右下）で描くと、周りに合わせて角・辺・中を選んで描きます。9 マスをオートペンの「縁つき」の一時的なパーツにして、オートペンと同じ解き方で描きます（パーツはファイルに残しません）。内角の絵は持たないので、凹んだ所の角は中のブロックになります。鉛筆と塗りつぶしで使えます。選択が 3×3 でないとき（チェックの文字が灰色）は、ふつうの鉛筆です。オートペン（P）がオンでパーツのブロックを選んでいるときは、オートペンが先です。移動エリアタブでは使えません。
- スマートパスの移動許可は、マップから拾った 3×3（移動許可を持つ選択）で「移動許可も貼る」がオンなら、見本のマスのものを書きます。

マップシフトと対話式リサイズ（#390）:

- マップシフト（Q5）: マップ全体のブロックと移動許可を、ドラッグした量だけずらします。はみ出た行と列は反対側に出ます。ドラッグ中はずらした絵を下見に出し、ステータスバーにずらす量を出します。離すと 1 回の操作（コマンド `shiftMap`）になります。イベント・接続・境界ブロック・大きさは変えません（イベントはイベントタブで動かします）。隣の帯の上で押しても、表示中のマップをずらします。
- 対話式リサイズ（Q6）: 場所の設定タブのかんたん表示の「大きさと位置を変える…」か、辺のつまみ（主マップの辺の中央）の右クリックのメニューの「大きさと位置を変える…」で、窓「マップの大きさと位置」を開きます。
  - 幅・高さの数値と、新しい枠の中で今のマップを置く位置（「左に足す」「上に足す」の数値か、図のマップのドラッグ）を決めます。負の値は、その分を削ります。図には新しい枠（赤）と今のマップを出し、下に 4 辺の変わる量と、その幅での高さの上限を出します。
  - 広げた所を埋めるもの: 端の写し（既定。辺のつまみと同じ）、境界ブロック、選んでいるブロック（スタンプは柄）。境界ブロックと選んだブロックの柄は、できあがりのマップの左上にそろえてくり返します。
  - 中身は辺のつまみのリサイズ（`resizeMapEdge`）を 4 辺分まとめたもので、1 回の「元に戻す」で戻ります。左と上へ広げた・縮めたときは、辺のつまみと同じくイベント・接続（相手の逆向きの接続も）・フライトポジション・ラベルの照合用の座標をずらします。
  - 大きさの上限と下限は辺のつまみと同じです（幅・高さ 4 以上、`(幅+15)×(高さ+14) ≤ 10240`）。超えるときは OK を押しても変えず、窓の下に理由を出します。場所の設定タブの「マップサイズの変更」（右と下へ伸縮し、増えた所はブロック 0）は AdvanceMap と同じまま残しています。

### 表示の補助（#391）

表示メニューに 3 つの項目を足し、移動エリアタブに数値の欄を足しました。既定はどれもオフか今までの見た目なので、AdvanceMap と同じ画面のままです。設定は個人設定（`cursorFrame`・`playerView`・`gridStyle`）に残り、次の起動でもそのままです。

- 表示 > カーソルの枠（C）: マウスのマスに白い枠を出します。マップタブで道具が鉛筆なら、塗る予定の大きさ（スタンプは選択の大きさ）の枠です。マップ・移動エリア・イベントタブで出ます。
- 表示 > プレイヤーの視界の枠（V）: マウスのマスを主人公の位置にして、ゲームの画面に映る範囲（240×160画素）を黄色の枠で出し、枠の外を暗くします。主人公のマスの左上は枠の左から112px・上から72pxです。仮の主人公を置いている間は、その主人公の位置を追います。
- 表示 > グリッドの設定…: グリッドの線の間（横・縦のマス数。1〜64）、ずらし（マス）、色、線の形（実線・破線・点）を決める窓です。入れている間もマップの上のグリッドに当てて見せ、OK でグリッドを出してその形を覚えます。キャンセルで元の形に戻します。「既定に戻す」は今までの見た目（1 マスごと・黒・実線）です。出す・隠すは今までどおり 表示 > グリッドの表示（Ctrl+G）です。画像の保存とコピーにも同じ形で入ります。
- 移動エリアタブの右の欄（道具の帯の下）の「値」: 移動許可の値を 16 進 2 桁（00〜3F）で入れると、選択とパレットの位置が動きます。打っている途中の 1 桁（「4F」の「4」）では選ばず、2 桁そろったときか、1 桁のまま Enter を押したとき・欄を離れたときに選びます。パレットで選ぶと欄の値も変わります。範囲の外の値は赤い字になり、選択は変えません。
- 2 つの枠は、マップ表示の上に置いた枠だけで描きます（マップの大きさの画像を持たないので、メモリは増えません）。グリッドは今までと同じ所（表示の大きさのグリッドの Canvas）に描きます。

### イベントの複数選択・まとめての移動・削除・複製（#399）

イベントタブのマップで、いくつかのイベントを選んで一度に動かす・消す・写すことができます。1 つだけ選んでいるときの動き（クリックで選ぶ、ドラッグで動かす、右クリックのメニュー、Ctrl を押している間イベントを隠す）は今までと同じです。

- 選び方（Q10）: Shift＋クリックで、そのイベントを選びに足す・外す。空いた所から Shift＋ドラッグすると、矩形の中のイベントを全部足す。空いた所を（Shift なしで）押すと、複数の選択をやめる。欄には最後に押したイベントを出し、赤い枠を付ける。ほかに選んでいるものは橙の枠。人・看板・スクリプトタイル・ワープ・フライトポジションを混ぜて選べる。
- まとめての移動: 選んでいるイベントのどれかをドラッグすると、全部が同じだけ動く。マップの中にあるイベントは、マップの外へは出ない（端で止まる）。元からマップの外にあるもの（クローンなど）は一緒に動く。1 回の「元に戻す」で全部戻る。人を動かしたときは、隣のマップのクローンも合わせる（表示 > クローンがオンのとき）。
- まとめての削除: Delete キーか、右クリックの「選んだ N 個を削除」。確認のダイアログは 1 回で、イベントごとに消すもの（スクリプトの記述・文字列・`maps\rom_erase.json` に記録する ROM の範囲）を並べる。一緒に消すイベントは互いに「ほかから使われている」とは数えないので、2 つが同じスクリプトを使っていれば両方を消すときにそのスクリプトも消す。フライトポジションは消さない（20 件の表のため）。1 回の「元に戻す」で全部戻る。
- 複製: Ctrl+D か、右クリックの「複製」。写しは 1 マス右下に置く（ほかのイベントがある・マップの外になるときは、近くの空いたマス）。番号は種類ごとの末尾に足し、人の番号（`localId`）は足した位置の番号にする。フラグ・スクリプト・見た目などの欄は全部写す（Porymap と同じく聞かない）。スクリプトのラベル（Phase2）があるイベントは、写しにも同じラベルを付ける（新しいひな形は作らない）。落とし物の人は落とし物も写す。フライトポジションとクローンは写さない。写したあとは写しを選ぶ。1 回の「元に戻す」で全部消える。
- 画像の保存（マップ&イベント画像）に重ねる枠は、今までどおり欄の 1 つだけです。

自動操作の命令は `event.selectMany`・`event.duplicate`・`event.deleteSelected` と、`event.state` の `selected`（docs/automation.md）。

### ルーラーと人の数の上限の警告（#400）

- ルーラー（Q11）: イベントタブのマップで Shift＋右ドラッグしている間だけ、押したマスから今のマスへ線を引き、両端のマスと 2 つを囲む矩形に水色の枠を付けます。横と縦のマス数（離れているマスの数）をステータスバーに「ルーラー: 横 5 マス・縦 3 マス」のように出します。離すと線は消え、文はステータスバーに残ります。イベントはつかみません。伸ばして離したときは右クリックのメニューを出しません（同じマスで離したときは今までどおり出す）。人の視界やワープの間の距離を測るのに使います。
- 人の数の上限: 開いているマップの人が 64 個を超えると、ステータスバーに赤い「注意: 人が N 個（上限 64）」（押すと説明）を、イベント数の設定の欄の下に赤い文を出します。数を変えることは止めません（今までどおり 255 個まで置けます）。
  - 理由: ゲームはマップに入るときに人の表をセーブデータの 64 個分の場所（`SvSxyObj[64]`。CFRU の `gSaveBlock1->eventObjectTemplates[64]`、0x08E0〜0x0EDF）へ数の分だけ写し、64 で止めません（FRLG の日本語版 `fld_tool.c` の `SxyObjDataSet`、BPRJ の 0x08054828）。65 個目からは後ろのイベントのフラグ（0x0EE0〜）を書きつぶします。
  - CFRU が置き換えていないことは、ND と Chronos のソース（この処理を置き換える関数も `hooks` などの登録も無い）と、ビルドした ROM（ND の `test.gba`、Chronos の `build\Chronos.gba`）の 0x08054828 からの命令が素の BPRJ と同じことで確かめました。ゲームを動かしての確認はしていません。
  - 看板・スクリプトタイル・ワープは、ゲームがマップのデータを直接読むので、表の数（255）のほかに上限はありません。警告は出しません。

### ブロックエディタ: タイルの矩形の選択・反転・パレットだけ塗る（#393）

AdvanceMap と同じ部品の配置はそのままで、窓の下に 1 行（ホバーの情報と案内）を足しました（窓の高さが 18 ピクセル増えます）。

| 操作 | 動作 |
|---|---|
| タイル一覧のドラッグ | 押した位置と離した位置を角にした矩形のタイルを選ぶ（2 枚以上なら赤い枠が出る）。1 回押すだけなら今までどおり 1 枚 |
| 8 マスの左クリック | 選んだ矩形を、押したマスを左上にして置く。8 マスは「下のレイヤー 2 列＋上のレイヤー 2 列」の 4 × 2 の並びとして扱い、はみ出た分は置かない。3枚目のレイヤーの 4 マスは 2 × 2 で、8 マスとは別に置く |
| X反転・Y反転 | 選んだ矩形全体に当てる（並びの順と、各タイルの反転の両方） |
| 8 マスの右ドラッグ | 押したマスから離したマスまでの矩形を、反転とパレットごと拾う（反転の欄は外れる。置くと拾ったときと同じ値になる）。1 マスの右クリックは今までどおり（タイル・反転・パレットの欄をそのマスの値にする） |
| 8 マスの Ctrl＋左クリック | タイルと反転は変えずに、パレットだけを今のパレットにする（選んでいる矩形の大きさの範囲） |
| タイル一覧・8 マスにマウスを乗せる | 窓の下に、タイル番号・パレット・反転を出す（8 マスは場所の名前も） |

どれもブロックエディタの中の編集で、メインの履歴に入るのは今までどおり「変更」を押したときです（1 回の Ctrl+Z で戻る）。

### ブロックエディタ: ブロックのコピー・貼り付けと入れ替え（#394）

AdvanceMap の 3 つのメニューの後ろに「編集(E)」を足しました。キーは入力欄の中とダイアログを出している間は反応しません。

| 項目 | キー | 動作 |
|---|---|---|
| 編集 > ブロックのコピー | Ctrl+C | 選んでいるブロックの、いま画面に見えている中身（8 タイルと属性。トリプルレイヤーなら3枚目のレイヤーの 4 タイルも）を窓の中に持つ。マップを切り替えて、別のタイルセットへも貼れる（タイル番号はそのまま） |
| 編集 > ブロックの切り取り | Ctrl+X | コピーしてから、選んでいるブロックを空（タイル 0、属性 0）にする。トリプルレイヤーのブロックは次の番号（3枚目のレイヤーに使っていたもの）も空にする |
| 編集 > ブロックの貼り付け | Ctrl+V | 選んでいるブロックへすぐ確定する。トリプルレイヤーのブロックは「変更」と同じく次の番号の下のレイヤーに3枚目のレイヤーを書き、属性と上のレイヤーを消す（消える値があれば確かめる）。次の番号が無い・次の番号もトリプルレイヤーのときは貼れない |
| 編集 > ブロックの入れ替え | X | オン・オフ（チェックが付く）。オンの間にブロック一覧で 2 つを順に押すと、中身（8 タイルと属性）を入れ替える |

入れ替えの決まり（#407 の Q8 の推奨）:

- 2 つ目を押すと、そのタイルセットを使うマップ（ROM と `maps\` の両方。主なら主、副なら副が同じもの）の数を出して聞きます。「はい」でマップの配置とボーダーの番号も付け替え（マップの見た目は変わらない）、「いいえ」でタイルセットの中だけ入れ替え、「キャンセル」でやめます。主のタイルセットでは、付け替えたマップがどれも次の出力で `maps\BB\MM.json` に書かれます。
- 入れ替えと付け替えは 1 つのコマンド（`swapBlocks`）で、1 回の Ctrl+Z で全部戻ります。付け替えるマップは実行の前に読み込みます（読み込んだマップは開いている間メモリに残ります）。
- トリプルレイヤーのブロックは N と N+1 の組で動かします。トリプルレイヤーのブロックどうしでだけ入れ替えられ、トリプルレイヤーの次の番号を選んだとき・トリプルレイヤーとそうでないブロック・組が重なるときは止めて理由を出します。主と副のブロックどうしは入れ替えられません。
- 作業用のマップ（新規作成・.map から開いたもの）は付け替えません。

### ブロックエディタ: 使用回数・未使用のブロックとタイル・ブロック一覧の画像（#395）

AdvanceMap の 3 つのメニューと「編集」の後ろに「表示(V)」を足し、「画像」メニューの最後に書き出しを足しました。表示の 3 つはどれも既定オフで、オンの間だけ数えます。

| 項目 | 動作 |
|---|---|
| 表示 > 使用回数 | ブロック一覧の各ブロックの右下に、全マップでの使用回数を出す（マップタブの「使用回数」と同じ数え方。配置と境界ブロックを数え、配置を共有しているマップは 1 回）。0 回は赤い数字 |
| 表示 > 未使用のブロック | 使用回数が 0 のブロックに赤い枠と斜線 |
| 表示 > 未使用のタイル | どのブロックからも使われていないタイルに、タイル一覧で赤い枠と斜線。主のタイルは、同じ主を使う全部の組（副タイルセット）のブロックからも数える |
| 画像 > ブロック一覧の画像の書き出し… | タイルセット（1・2）、範囲（はじめと終わりの番号。16 進）、レイヤー（下・上・3枚目）、幅（1 行のブロック数）、透明の扱い（そのまま・黒・パレット 0 の色 0）を選び、プレビューを見て PNG に書く。3枚目のレイヤーはトリプルレイヤーのブロックだけに描く |

- 数えるのはメインのウィンドウで、結果をブロックエディタへ送ります。表示の項目をオンにしたときと、ブロックエディタの中身が変わったとき（変更・貼り付け・入れ替え・マップの切り替えなど）に数え直します。3 つともオフにするか窓を閉じると、結果を捨てます。
- 数えるのは表示中のマップの組（主と副）です。未使用のブロックは、その組での使用回数が 0 のものです（主のブロックは同じ主を使う全部のマップで数えるので、ほかの組で使っていれば 0 にはなりません）。
- 窓の下の 1 行に、未使用のブロックとタイルの数と、数えるのにかかった時間を出します。

### ブロックエディタ: 新しいタイルセット（#397）

ブロックエディタの「画像」メニューの最後に「新しいタイルセット…」を足しました（#407 の Q9 の推奨）。屋内の新しい建物などで、ほかのマップに影響しないタイルセットを作れます。

| 欄 | 内容 |
|---|---|
| 種類 | タイルセット1（主）かタイルセット2（副）。既定はタイルセット2 |

- 「作る」で、新しいタイルセットを加え、表示中のマップの組をそれに付け替えます。2 つは 1 回の操作で、1 回の Ctrl+Z で戻ります。ほかのマップは元のタイルセットのままです。

### パレットエディタ: 16 進の欄・未使用の色・色の使用箇所・読み込める形式（#396）

パレットエディタの上にメニュー（表示・ツール）を、下に 16 進の RGB の行を足しました（窓の高さが 50 ピクセル増えます）。AdvanceMap と同じ部品の配置はそのままです。

### 野生: 枠ごとの割合・グラフ・種族の全マップ検索（#398）

| 場所 | 動作 |
|---|---|
| 野生ポケモンタブの各枠の右 | その枠の出現の割合（%）。ゲームの処理で決まる値で、草むら 20,20,10,10,10,10,5,5,4,4,1,1、水と岩砕き 60,30,5,4,1、釣りは竿ごとにボロ 70,30・いい 60,20,20・すごい 40,40,15,4,1（ND と Chronos の `src/dexnav.c` の表と同じ） |
| 野生ポケモンタブの「グラフ…」 | 表示中のタイプの、種族ごとの合計の割合（棒）と、レベルの分布を出す窓。レベルの分布は全部の種族か、選んだ種族だけ。釣りは竿を選ぶ。棒にマウスを乗せると値を窓の下に出す。保存してある表で描く |
| ツール > 野生ポケモンの検索… | 種族を打って選び、「検索」を押すと、全マップ（ROM と `maps\` の両方）からその種族が出る枠を表にする（マップ・種類・枠・レベル・割合）。列の見出しを押すと並べ替え（もう一度押すと逆順）、行をダブルクリックするとそのマップを開いて野生ポケモンタブにする |

- レベルの分布は、枠の割合をその枠の最低〜最高のレベルに等しく分けた値です（ゲームは範囲の中から一様に選ぶ）。
- 今の表は昼だけです（時間帯ごとの表は Phase6）。検索とグラフも、野生ポケモンタブで見えている表を使います。
- 検索は「検索」を押したときに全マップの野生を読み、窓を閉じたら捨てます。グラフはライブラリを足さず Canvas で描いています。
- 種族の欄（#447）: 名前の頭を打つと、下に候補が出ます。カタカナ・ひらがな・ローマ字のどれで打っても当たります（「ふし」「フシ」「fushi」→ フシギダネ・フシギソウ・フシギバナ）。ローマ字はヘボン式と訓令式のどちらでもよく（shi / si、chi / ti、tsu / tu、fu / hu、ji / zi、sha / sya など）、長音「ー」は母音を重ねても「-」でも打たなくても（rizaadon・riza-don・rizadon）、促音「ッ」は子音を重ねても xtu でも、ニドランの ♀・♂ は f・m（mesu・osu）でも当たります。番号（`16`、`No.16`、16 進の `0x10`）でも当たります。
  - 欄を押すと全部の候補が出ます。候補を押すか、↑↓で選んで Enter で決まります。Esc で候補を閉じます。
  - 名前が 1 つに決まる文字（「poppo」「ぽっぽ」「16」など）を打って Enter を押すと、候補を選ばなくても決まります。候補を閉じているときに Enter を押すと検索します。
  - 当たる候補が無いときは「当たる種族がありません。」と出します。決まらないまま欄から離れると、欄の文字は今の種族に戻ります。
  - ひらがなとローマ字の読みは、ROM（とプロジェクト）から読んだ種族名のカタカナから計算で作ります（読みのデータは持ちません）。読みの表は検索の窓を開いたときに作り、閉じたら捨てます。野生ポケモンタブの種族の欄は今までどおり一覧から選びます。

### マップ一覧の状態の印と右クリック（#401）

- 印: マップの名前の前に小さな印を付けます。橙の三角は開いているマップ、青い丸は未出力の変更があるマップ、赤い丸に白い × は読み込めなかったマップです（1 つのマップには、読み込めなかった・未出力・開いているの順に 1 つだけ）。名前の後ろの ` *`（未出力）は今までどおり残します。読み込めなかった印は、開き直せたときと、ROM を開き直したときに消えます。印にマウスを乗せると説明が出ます。
- 右クリックのメニュー（マップの項目だけ）: 「開く」「名前をコピー」（一覧と同じ書き方の名前。番号と並び替えの補足は付けない）「番号（バンク.マップ）をコピー」（`3.0` の形）「このマップを複製」。
- 複製: 「マップの追加/挿入」の追加と同じく、同じバンクの最後に新しい番号で写して開きます。1 回の「元に戻す」で消え、出力すると `maps\` に書きます。ND の写しで、複製したマップを出力してビルドが通り、できた ROM のそのマップの配置と大きさが元と同じことを確かめています（`tests/realcopy/run.py --maplist`）。

自動操作の命令は `tree.rightClick`・`clipboard.last` と、`tree.list` の `mark`（docs/automation.md）。

### 履歴の窓（#402）

表示 > 履歴の窓（Ctrl+E）で、メインの画面に浮かぶ小窓（ドラッグで動かせる）に、元に戻す・やり直すの履歴を出します。もう一度押すか × で閉じます。

- 新しい操作ほど上に並びます。各行は「ブロックを塗る（3.0）」のように、操作の名前と対象のマップ（バンク.マップ）です。いくつかの変更を 1 回で戻す操作は「ブロックを置く × 3」「イベントの削除 ほか 2 件」のように出します。
- 今いる位置の行を選んだ色で出し、その上の、やり直せる操作は薄く出します。いちばん下は「（最初の状態）」です。
- 行を押すと、その操作の後まで戻す・進めます（Ctrl+Z・Ctrl+Y を何回か押したのと同じ）。「（最初の状態）」を押すと全部戻します。戻したあとで新しい操作をすると、薄い行は消えます（今までどおり）。
- 操作をした・戻した・進めたとき、ROM を開き直したときに、一覧を直します。
- 操作の名前の表は `apps/desktop/src/i18n/ja.commands.ts` です。表に無い操作は、コマンドの名前（英語）のまま出ます。

自動操作の命令は `editHistory.state`・`editHistory.goTo`（docs/automation.md）。窓を開く・閉じるは `action` の `view.history`。

### マップの画像の書き出しとタイムラプス（#403）

ファイル > マップの画像を書き出す… で窓を開きます。今までの ツール > マップ画像の保存（24 ビットの BMP）と、画像のコピーはそのまま残しています。

- 範囲: 「このマップ」か「接続している全マップ（つなぎ合わせ）」。つなぎ合わせは「接続している全マップの画像をコピー」と同じ並べ方で、辺が 16,384 画素を超えるときは 1/2・1/4 に縮めるか聞きます。
- 含めるもの: イベントの種類ごと（人・ワープ・スクリプトタイル・看板）、移動許可（濃さは移動エリアタブと同じ）、グリッド（表示 > グリッドの設定 の形。マップごとにマップの左上にそろえる）、境界ブロック（周り）、隣のマップの帯（周り。「このマップ」のときだけ）。周りは、ゲームの画面で主人公の周りに見える分として、左右 7 マス・上下 5 マス広げます。境界ブロックはマップの左上にそろえて並べ、隣のマップはその上に描きます。
- 形式: PNG（既定）か BMP（24 ビット）。ファイルに保存するか、クリップボードへコピーします。プレビューに大きさと描くマップの数が出ます。
- タイムラプス（GIF）: このマップの、起動してからの変更を最初の変更の前からたどり、変更ごとに 1 コマにして GIF に書きます。コマの間（ミリ秒）と、とばすコマ数を選べます（最後のコマはいつも今の状態）。範囲と含めるものは上の選択と同じで、大きさは今の状態に合わせます。作る間は履歴を戻して進め、終わると元の位置に戻します。コマは 1 枚ずつ作ってすぐ GIF に書くので、全部を同時には持ちません。GIF は自前で書いていて（`packages/core/src/image/GifWriter.ts`）、色が 256 を超えるコマは固定の 252 色に寄せます。
- メモリ: マサラタウン（3.0）を 100×75（FR の大きさの上限で、幅 100 での最大の高さ）に広げて 12 回描き、15 コマ・1600×1200 のタイムラプスを作ったとき、JavaScript のヒープは作る前 64.9 MB、作った後 66.6 MB でした。

自動操作の命令は `mapExport.state`・`mapExport.run`（docs/automation.md）。窓を開くのは `action` の `image.export`。

### ショートカットの変更（#392）

設定 > ショートカットの変更… で、メニューと道具のキーを変えられます。既定のキーは今までと同じなので、変えなければ何も変わりません。

- 窓には変えられる操作が並びます（メニューのショートカットを持つ項目（履歴の窓の Ctrl+E など）、元に戻す・やり直す、イベントの削除と複製、スタンプのコピーと貼り付け、ドラッグの取りやめ（Esc）、ダイブ先の重ね表示（Space）、オートペン（P）、道具の切り替え（N・B・S）、ブロックエディタの 編集 メニュー（コピー・切り取り・貼り付け・入れ替え））。キーの欄を押してから決めたいキーを押します。1 つの操作に 2 つまで決められ、「×」で外せます。
- ほかの操作と重なるときは、どちらに残すか聞きます。重なりは、キーを受ける場所が重なる操作どうしだけで調べます（たとえばイベントタブだけの Ctrl+D と、マップタブだけの Ctrl+C の操作は重なりません）。
- 「既定に戻す」で全部を既定のキーにします。OK で決めるとすぐ使え、メニューの表記とヘルプ > ショートカット一覧も変わります。
- 別ウィンドウ（ブロックエディタ・パレットエディタ・ワールドマップエディターなど）の元に戻す・やり直す・出力も、同じキーになります。スクリプトエディタのキーは変えられません（Q16）。
- 変えたキーは個人設定の `shortcuts`（既定と違う操作だけ）に残り、次の起動でもそのままです。
- 入力欄の中では、今までどおりショートカットに反応しません。Esc（ダイアログを閉じる）、メニューやマップ一覧の中の矢印、マウスと組み合わせる修飾キーは変えられません。

### すべての設定の窓（#404）

設定 > すべての設定… で、表示と設定のメニューの項目を 1 つの窓に並べます（メニューはそのまま残しています）。

- 上の欄は個人の設定（AppData の `settings.json`）です。メニューの並びのまま、サブメニューごとに枠で分けます。チェックの付く項目はチェックの欄で、変えるとメニューを押したのと同じになり、メニューのチェックもそろいます（メニューで変えたときも窓がそろいます）。窓を開く項目（グリッドの設定・ショートカットの変更・スクリプトの管理など）は「開く…」のボタンです。項目はメニューの定義から作るので、Phase5 で足した道具・グリッド・カーソルの枠・視界・監視の設定も並びます。
- 下の欄はプロジェクトの設定（`zigzagumap.json` の `script` の節）です。ビルドしてできる ROM・イベントのラベルの名前の形・`.global` にするか・1 行の文字数の上限・1 ページの行数を変えて「プロジェクトの設定を保存」で書きます。空の欄は既定の値（欄に薄く出る）に戻します。ほかの項目と節（`userScripts` など）は残します。保存した `zigzagumap.json` は、外で変わったファイルとは数えません。

自動操作の命令は `allSettings.state`・`allSettings.save`（docs/automation.md）。窓を開くのは `action` の `opt.allSettings`。

### ファイルの変化の監視（#404）

プロジェクトフォルダを開いているとき、メインのウィンドウに戻るたびに、次のファイルの更新日時と大きさを開いたときと比べます。`maps\BB\MM.json`・`maps\BB\scripts_MM.json`・`maps\tilesets\` の下・`maps\project.json`・`maps\regionmap.json`・`maps\trainers.json`・`maps\scripts.json`・`zigzagumap.json`。

- 外（Bochi・git・テキストエディタなど）で変わっていれば、変わったファイルの一覧（変更・追加・削除）を出して、読み直すか聞きます。
- 未出力の変更があるマップがあれば、読み直すとその変更を捨てることを書いて、もう一度聞きます。
- 読み直すときは、ROM とプロジェクトを開き直し（F5 の再読み込みと同じ読み込み）、開いていたマップを開き直します。元に戻す・やり直すの履歴は空になります。
- 「いいえ」を選んだ変化は、次からは聞きません。ZigzaguMap が出力で書いたファイルは数えません。
- 監視の部品（Rust）は足していません。戻ったときに調べるだけです。
- 設定 > 外で変わったファイルを調べる（既定オン）を外すと、戻ったときに調べません。

自動操作の命令は `projectWatch.check`・`projectWatch.state`（docs/automation.md）。

### JavaScript のスクリプト（#405）

プロジェクトフォルダの `zigzagumap-scripts\` に置いた `.js` を、設定 > スクリプトの管理… でチェックすると動きます。チェックしたものは `zigzagumap.json` の `userScripts.enabled` に書きます（プロジェクトで共有できます）。例は `docs/userscripts/` にあります（`grass.js`: 草むらを置くと移動許可を 0C にする、`count.js`: 全マップのブロックを数える）。

- スクリプトは 1 つの Web Worker で動きます。使えるのは `zz`（下の API）と `console` だけで、fetch・XMLHttpRequest・WebSocket・importScripts・IndexedDB などは読み込む前に消しています。Tauri の命令も届かないので、ファイルや外部コマンドは使えません。有効なスクリプトが無ければ Worker を作りません。
- API（どれも Promise を返す）: `zz.map.current()`・`getBlock(x, y)`・`setBlock(x, y, block)`・`getMovement`・`setMovement`・`getCells()`・`getBorder`・`setBorder`・`getHeader()`・`getTilesets()`・`fill(x, y, value, { magic, movement })`（塗りつぶし。`magic: true` でマジック塗り、`movement: true` で移動許可を塗る。塗ったマスの数を返す）・`shift(dx, dy)`（マップシフト。はみ出た分は反対側へ回る）、`zz.maps.list()`・`zz.maps.getCells(bank, map)`（ほかのマップは読むだけ）、`zz.names.list("maps" | "species")`、`zz.ui.message(text)`・`zz.ui.input(prompt, initial)`・`zz.ui.status(text)`、`zz.view.setGrid(show)`、`zz.registerAction(id, label, run)`、`zz.log(...)`。
- コールバック（`zz.on(名前, 関数)`）: `projectOpened`・`projectClosed`・`mapOpened`・`blocksChanged`（`bank`・`map`・`cells`・`kind`（`execute` / `undo` / `redo`））・`mapResized`・`mapShifted`（`dx`・`dy`。戻すときは逆向き）・`hoverChanged`（`tab`・`x`・`y`。マスが変わったときだけ。外へ出たら `x` が null）・`tabChanged`。スクリプトが書いた変更では `blocksChanged` を呼びません。
- 書き込みは、1 回のコールバック・登録した操作の分を 1 つの操作にまとめます（Ctrl+Z 1 回で全部戻る）。書き込みはコールバックか登録した操作の中だけで使えます。
- 登録した操作は、ツール > ユーザースクリプト か、スクリプトの管理の窓の「実行」で動かします。窓には読み込めなかった理由とログも出ます。「止める」で Worker を終わらせます（長く止まったスクリプトも止まります）。「読み直し」でファイルを読み直します。
- 起動の時間とメモリ: スクリプトが無いときは Worker を作らないので変わりません（素の ROM での起動からマップ表示まで、同じときに測って中央値 1106 ms と、入れる前の 1173 ms。ほかの作業でぶれがあります）。確認用を含めた 4 つを有効にしたときの JavaScript のヒープは 40.4 MB から 42.0 MB でした。
- 登録した操作は ツール > ユーザースクリプト に登録した順に並びます（スクリプトの管理… もここから開けます）。上から 9 つまでは、設定 > ショートカットの変更… の「ツール > ユーザースクリプト > N 番目の操作」でキーを決められます（既定のキーは無し）。

自動操作の命令は `userScripts.state`・`userScripts.run`・`userScripts.reload`・`userScripts.stop`（docs/automation.md）。
