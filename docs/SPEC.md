# ZigzaguMap 仕様

AdvanceMap 風の、CFRU-JP 用マップエディタ。2026-11-13 の聞き取りで決めた内容をまとめる。作業の細目は GitHub の issue を参照する。

## 対象と前提

- 対象ROMは、ファイアレッド日本語版（BPRJ）の素のROMと、バイナリ改造から CFRU 方式へ移った BPRJ（NeoDark のベースROM）。
- 開くのは「ベースROM」と「CFRU-JP のフォルダ」。ベースROMは読み取り専用で、ROMへは書き込まない。
- 対応プロジェクトは Chronos（PokemonChrnos）と NeoDark（ND）。違いはプロジェクト設定で持つ。
- 素のROMだけを開いた場合は、閲覧と編集ができ、出力先フォルダを選んで同じ形式で書き出す。
- Windows 用。全Phaseの完了後に macOS と Linux へ対応する。
- 画面は日本語のみ。文言は言語ファイルに分け、AdvanceMap 1.92 日本語化パックの `Japanese.ini` の表記を使う。

## 技術

- TypeScript + Tauri 2。UIフレームワークは使わず、素の TypeScript と Canvas で組む。依存は最小限にする。
- ROMの解析と出力は TypeScript のコアライブラリ（`packages/core`）に置く。Node でも動かし、テストとMCPサーバーから画面なしで呼ぶ。Rust 側はファイル入出力とウィンドウ管理だけ。
- 画面の操作はすべて「操作コマンド」を通す。同じコマンドを、JSON の操作列の再生、MCPサーバー（stdio）、JavaScript のスクリプト機能から呼ぶ。全操作をアンドゥ・リドゥできる（Ctrl+Z / Ctrl+Y）。
- ブロックエディタ、ワールドマップエディタ、スクリプトエディタは本物の別ウィンドウにし、開いたときに初めて読み込む。
- スクリプトエディタは CodeMirror 6。
- 機能ごとにクラスとモジュールを分ける。Phaseの区切りでリファクタリングを行う。
- `maps\` の形式は将来変わる前提で、読み書きを1つのモジュールにまとめる。

### 軽さの目標

| 項目 | 目標 |
|---|---|
| 起動からマップ表示まで | 1秒以内 |
| 待機時メモリ（WebView2 込み） | 150MB 以下 |
| 配布物 | 10MB 以下 |
| マップの切り替え | 100ms 以内 |

## 出力

- 形式は ND の `scripts/map_project.py` が読む `maps\BB\MM.json`（BochiBochiEditor 改造版の `SaveCfruProject` と同じ）。ベースROMと違うマップだけを書き、同じに戻ったらファイルを消す。
- タイルセットは `maps\tilesets\<id>\tileset.json` と `tiles.png`。
- Ctrl+S で、変更のあったマップだけを書き出す。自動出力はしない。未出力のマップには印を付け、閉じるときに確認する。
- 落とし物は Bochi と同じく `assembly/overworld_scripts/HiddenItem.s` の `@ BBE-BEGIN`〜`@ BBE-END` の範囲に書く。
- スクリプトの紐づけは `eventscripts`（`種別 バンク マップ [番号] ラベル`）に書く。Phase2 でイベントを項目ごとの JSON にし、ラベル名を直接持たせる。
- バンクと `.s` の対応は `maps\scripts.json` に持つ。項目は、バンク番号、マップ番号（省略するとバンク全体）、マップ名、`.s` のファイル名、`.string` のファイル名。`.string` は `overworld_strings_<.s の名前>.string` の規則で自動入力する。
- Bochi 改造版と同じ `maps\` を読み書きでき、どちらで編集しても崩れないこと。Bochi 側には手を入れない。
- ビルド側（`map_project.py`）の正本は本リポジトリの `build-support/` に置き、Chronos と ND へ配る。マップ名、タウンマップ、ブロック、パレット、深夜の野生に対応するよう拡張する。

## 設定の置き場所

- プロジェクトの設定（パス、機能の有無、対応表）はプロジェクトフォルダの `zigzagumap.json`。
- 個人の設定（ウィンドウ位置、テーマ、最近開いたもの）は AppData。

## Phase1: AdvanceMap 1.92 の再現

- 日本語化した AdvanceMap 1.92 の全機能と外観を再現する。ピクセル単位の一致は求めない。起動時のタイトルロゴは作らない。
- 「ROMの保存」は「出力」に置き換える。エメラルド主人公のOWを使うアイコンは、ファイアレッド主人公のOWに差し替える（アプリに同梱する）。
- 追加するもの: アンドゥ、ROMのドラッグ＆ドロップ。
- 1.95 だけの機能は入れない。
- 「スクリプトエディターの選択」の設定と、外部エディタの起動を再現する。
- 終了条件: AdvanceMap と ZigzaguMap で同じ操作をし、途中の状態が同じになること。スクリーンショット（マップ表示領域）、各入力欄の値、ダイアログの有無で比べる。出力まで進めることは確かめるが、出力物の中身は AdvanceMap と比べない。
- 別途、出力した `maps\` を読み直して編集前と同じ状態に戻るかを自動テストで確かめる。

## Phase2: スクリプト連携と内蔵エディタ

- 人・看板・スクリプトタイルのスクリプト欄に、ラベル名の表示、対応する `.s` 内のラベルの一覧、選択、補完を出す。素のROMのスクリプトはアドレスのまま表示する。
- イベントを新規に置くと、ラベル名を自動で付け（既定 `EventScript_<マップ名>_<種別><番号>`）、種別ごとのひな形を `.s` に書く。`.s` を新しく作るときはファイル名の入力欄を出す。エディタでラベル名を変えたら `eventscripts` とマップ側の表示も追従する。
- 素のROMにあるスクリプトは、`xse_commands.s` の記法で読み取り専用で表示する。「.s に取り込む」で、ラベルを付けて対応する `.s` へ書き、文字列と移動データも取り込む。
- マップスクリプトの専用パネル（種類ごとの一覧、条件表、ラベルの選択）。
- オブジェクトのダブルクリックで、別ウィンドウのエディタが開く。
  - 改造済みの Gen3 Script Assistant 拡張（`pokehack\tool\gen3-script-assistant-main`）と同じ補完・ホバー・色付け。命令の定義は CSV と `xse_commands.s` のマクロの両方から読む。
  - 定義ジャンプ（ラベル、`strings` の該当行）。
  - 検索と置換（正規表現）、Alt＋ドラッグの矩形選択、複数カーソル、行の移動と複製、コメント切り替え、複数ファイルのタブ、Ctrl+S、外部変更の再読み込み、エラー箇所の波線。
  - 開けるのはイベント用フォルダ（`assembly\overworld_scripts`）と `strings` のファイルだけ。
  - テーマは Dark+ 風、Light+ 風、Monokai 風、Solarized Dark 風の4つ。マップエディタ本体は明るい標準色とダークの2つ。
- 文字列: ホバーで本文を表示、その場で編集して `.string` へ書き戻す。入力中は文字数による簡易の幅検査、保存時は `check_text_width.py` があれば実行する。ND の2ポインタ版（ひらがなと漢字）と Chronos の1ポインタ版の両方を扱う。
- ビルドの実行ボタンとログ表示、エラー行へのジャンプ、ビルド後のエミュレータ起動。

## Phase3: HexManiacAdvance の機能とスタンプ

- マップ接続の調整: 隣接マップの同時表示、角のつまみのドラッグでずれを変える（相手側も同時に直す）、境界をまたぐ描画・矩形塗り・スタンプ、辺のつまみの右クリックから接続の追加と削除と新規マップ作成、辺のつまみのドラッグでリサイズ（左と上へ広げたときは接続とイベントを補正）、Space でダイブ先と浮上先を重ねる、クローンの自動作成（設定で切れる）。
- スタンプ: 矩形の複数選択、コピーと貼り付け、名前つきで `maps\stamps\` に保存、サムネイルつき一覧から貼り付け。内容はブロック番号と移動許可。作ったときのタイルセットの組を記録し、いまのマップに貼れるものだけを一覧に出す。主タイルセットのブロックだけのスタンプは、主が同じマップに貼れる。
- 表示: Ctrl を押している間イベントと移動許可を隠す、サイドボタンで前のマップへ戻る、マップ名で絞り込んで移動、座標と選択範囲の表示。
- 描画: 移動許可の自動選択、ブロックの使用回数、移動許可だけ違うマスの強調、2マスの入れ替え、ミキシングバッグ、Ctrl＋ドラッグの矩形塗り。
- イベント: ワープのホバーで行き先の周辺画像、スクリプトの要約のホバー、ワープの右クリックから行き先マップの作成と戻りのワープ、ワープできないブロック上のワープの警告、未使用フラグと変数の自動選択、ひな形（人、看板、スクリプトタイル、落とし物、トレーナー、ショップ、アイテムをくれる人）。トレーナーのチーム自動生成は、書き込み先を調べてから仕様を決める。
- ヘッダー: 配置を共有しているマップの数の表示。
- 出力: 接続している全マップの画像をクリップボードへ。
- 外すもの: ランダム自動生成、データの付け替えと拡張、マップ以外の機能。

## Phase4: BochiBochiEditor の機能

- トリプルレイヤー: 属性4バイト目が `0x30` のブロックを3層とし、3層目に次の番号のブロックの下層4タイルを使う。ブロックエディタで3層を編集でき、3層目に使われているブロックは単独で置けない。
- 自動ペン（岸・段差・木・建物）、左と上へのマップ拡張、別ROMからのタイルセット移植、ポインタの参照元検索（ベースROMの調査用）、落とし物と隠しアイテムの自動作成、マップ作成補助。
- 外すもの: ランダムマップ生成。

## Phase5: Porymap の機能

- 描画: 直線塗り、スマートパス、マジック塗り、マップシフト、スポイト、対話式リサイズ。
- 移動許可: 濃さのスライダー、数値での直接指定。
- イベント: 複数選択とまとめての移動、Ctrl+D で複製、ルーラー、ワープ位置の警告、イベント数の上限警告。
- 接続: 相手側の自動修正、ダイブ先と浮上先の重ね表示。
- 野生: 種族の全マップ検索、出現率とレベル分布のグラフ。
- ブロック編集: コピーと貼り付け、入れ替え、使用回数、パレットの未使用色と色の使用箇所、画面からの色拾い。
- 一覧: 絞り込み、状態アイコン、戻る・進む、マップの複製。
- 履歴の一覧、つなぎ合わせ画像、タイムラプスGIF、ショートカットの変更、ステータスバー、JavaScript のスクリプト機能（操作コマンドを呼ぶ）。
- 外すもの: レイアウトの切り替え、重ね描き、名前付きID、カスタム属性、Poryscript、野生の区分追加、プレハブ（スタンプと同じ）。

## Phase6: 新機能

- 4Fスクリプトの再生: スクリプトをラベルから `end` までたどり、複数人物の同時移動、`waitmovement`、`pause`、カメラの開始と終了、表示と非表示、位置変更を再現する。条件分岐は画面で選ぶ。`applymovement CAMERA` は完全に再現する。`callasm` の中のカメラ移動は、C ソースを読んで関数ごとに再現処理を登録する。再生後は元の位置に戻る。
- 主人公（男女）はマップに置かれていなくても動かせる。開始位置は、話しかけるスクリプトなら下から、踏むスクリプトならそのタイルの上。仮の主人公を先に置いてあれば、その位置から話しかけたものとして向きを合わせる。1コマ目では向きを変えられる。踏むスクリプトは自動で再生を始める。
- タイムライン: 人物ごとの移動コマンドを時間順に並べ、現在のコマンドとエディタの該当行を強調する。コマ送りは1コマンドを「移動前・移動中・移動後」の3コマとする。コマ戻し、速度変更、任意位置へのジャンプ。タイムライン上の編集は `.s` の移動データへ書き戻す。
- アニメーション再生: NPCの移動タイプを実機と同じ規則で動かし、移動範囲とトレーナーの視界を表示する。花・水・滝などのタイルアニメとドアを動かす。
- 240×160 の枠: ROMのカメラ処理と同じ位置に出し、外側を暗くする。オンとオフを切り替えられる。
- 時間帯ビューア: `dns_data.h` の係数表から実機と同じ計算で色を変える。区分はプロジェクトから読む（Chronos は5区分、ND は4区分）。
- 時間帯別の野生: 野生の編集画面に時間帯のタブを足し、`Wild[].Time` に書く。Chronos の深夜に対応するよう、ビルド側と `wild_encounter.c` を広げる。
- 連れ歩きの仮配置: 主人公をつまんで動かすと連れ歩きが付いてくる。絵は DPE の `graphics\ow` から読み、実機と同じ重なり順で描く。表示と非表示を切り替えられる。位置は保存しない。連れ歩きが有効なプロジェクトでだけ出す。
- タイルの自動分割: 任意のPNG（16の倍数。層ごとのPNGも可）を 8×8 に分け、反転を含む重複を除き、パレットを自動で割り当て、16×16 のブロックも作る。既存タイルセットへの追加か新規作成を選ぶ。取り込み前に使用数と上限を表示する。
- 移動の速さとコマ数は ROM の解析から求める。資料は `C:\Users\korok\Documents\src\gen3\address_map_viewer.html` と `Documents\src` を優先する。

## 運用

- issue は日本語。Phase1 は細かく分け、Phase2 以降は親 issue を先に作って着手時に分ける。テストで落ちた箇所も issue に書く。ユーザーのFBは会話で受け、issue に書き写す。
- 各Phaseがテスト込みで終わったら、exe を作り、全動作のまとめ動画と作業時間を Discord へ送る。ユーザーが「次へ」と言うまで次のPhaseへは進まない。
- テストは、コアの単体テスト、操作列の再生テスト、AdvanceMap との比較テストの3層。ROMが要るテストはローカルだけで実行し、ROMはリポジトリに入れない。
- 配布はインストール不要の exe（GitHub のリリース）。自動更新は作らない。ライセンスは MIT。
