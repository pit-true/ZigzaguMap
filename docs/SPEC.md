# ZigzaguMap 仕様

AdvanceMap 風の、CFRU-JP 用マップエディタ。2026-11-13 の聞き取りで決めた内容をまとめる。作業の細目は GitHub の issue を参照する。

## 対象と前提

- 対象ROMは、ファイアレッド日本語バージョン（BPRJ）の素のROMと、バイナリ改造から CFRU 方式へ移った BPRJ（NeoDark のベースROM）。
- 開くのは「ベースROM」と「CFRU-JP のフォルダ」。ベースROMは読み取り専用で、ROMへは書き込まない。
- 対応プロジェクトは Chronos（PokemonChrnos）と NeoDark（ND）。違いはプロジェクト設定で持つ。
- 素のROMだけを開いた場合は、閲覧と編集ができ、出力先フォルダを選んで同じ形式で書き出す。
- Windows 用。全Phaseの完了後に macOS と Linux へ対応する。
- 画面は日本語のみ。文言は言語ファイルに分け、AdvanceMap 1.95 の言語ファイルをもとに改訂した `Japanese.ini`（リポジトリの `apps/desktop/src/i18n/source/Japanese.ini`）の表記を使う。値の中の AdvanceMap 1.95 向けの注記は表示しない。改訂バージョンに無い番号は旧バージョン（AdvanceMap 1.92 日本語化パック）の表記を使う。

## 技術

- TypeScript + Tauri 2。UIフレームワークは使わず、素の TypeScript と Canvas で組む。依存は最小限にする。
- ROMの解析と出力は TypeScript のコアライブラリ（`packages/core`）に置く。Node でも動かし、テストとMCPサーバーから画面なしで呼ぶ。Rust 側はファイル入出力とウィンドウ管理だけ。
- 画面の操作はすべて「操作コマンド」を通す。同じコマンドを、JSON の操作列の再生、MCPサーバー（stdio）、JavaScript のスクリプト機能から呼ぶ。全操作をアンドゥ・リドゥできる（Ctrl+Z / Ctrl+Y）。
- ブロックエディタ、ワールドマップエディタ、スクリプトエディタは本物の別ウィンドウにし、開いたときに初めて読み込む。
- スクリプトエディタは CodeMirror 6。
- 機能ごとにクラスとモジュールを分ける。Phaseの区切りでリファクタリングを行う。
- `maps\` の形式は将来変わる前提で、読み書きを1つのモジュールにまとめる。

### 軽さの目標

| 項目 | 目標 |
|---|---|
| 起動からマップ表示まで | 1秒以内 |
| 待機時メモリ（WebView2 込み） | 150MB 以下 |
| 配布物 | 10MB 以下 |
| マップの切り替え | 100ms 以内 |

## 出力

- 形式は ND の `scripts/map_project.py` が読む `maps\BB\MM.json`（BochiBochiEditor 改造バージョンの `SaveCfruProject` と同じ）。ベースROMと違うマップだけを書き、同じに戻ったらファイルを消す。
- タイルセットは `maps\tilesets\<id>\tileset.json` と `tiles.png`。
- Ctrl+S で、変更のあったマップだけを書き出す。自動出力はしない。未出力のマップには印を付け、閉じるときに確認する。
- 落とし物は Bochi と同じく `assembly/overworld_scripts/HiddenItem.s` の `@ BBE-BEGIN`〜`@ BBE-END` の範囲に書く。
- スクリプトの紐づけは `eventscripts`（`種別 バンク マップ [番号] ラベル`）に書く。Phase2 でイベントを項目ごとの JSON にし、ラベル名を直接持たせる。
- バンクと `.s` の対応は `maps\scripts.json` に持つ。項目は、バンク番号、マップ番号（省略するとバンク全体）、マップ名、`.s` のファイル名、`.string` のファイル名。`.string` は `overworld_strings_<.s の名前>.string` の規則で自動入力する。
- Bochi 改造バージョンと同じ `maps\` を読み書きでき、どちらで編集しても崩れないこと。Bochi 側には手を入れない。
- ビルド側（`map_project.py`）の見本は本リポジトリの `build-support/` に置き、Chronos と ND へ配る。マップ名、タウンマップ、ブロック、パレット、深夜の野生に対応するよう拡張する。

## 設定の置き場所

- プロジェクトの設定（パス、機能の有無、対応表）はプロジェクトフォルダの `zigzagumap.json`。
- 個人の設定（ウィンドウ位置、テーマ、最近開いたもの）は AppData。

## Phase1: AdvanceMap 1.92 の再現

- 日本語化した AdvanceMap 1.92 の全機能と外観を再現する。ピクセル単位の一致は求めない。起動時のタイトルロゴは作らない。
- 「ROMの保存」は「出力」に置き換える。エメラルド主人公のOWを使うアイコンは、ファイアレッド主人公のOWに差し替える（アプリに同梱する）。
- 追加するもの: アンドゥ、ROMのドラッグ＆ドロップ。
- 1.95 だけの機能は入れない。
- 「スクリプトエディタの選択」の設定と、外部エディタの起動を再現する。
- 終了条件: AdvanceMap と ZigzaguMap で同じ操作をし、途中の状態が同じになること。スクリーンショット（マップ表示領域）、各入力欄の値、ダイアログの有無で比べる。出力まで進めることは確かめるが、出力物の中身は AdvanceMap と比べない。
- 別途、出力した `maps\` を読み直して編集前と同じ状態に戻るかを自動テストで確かめる。

## Phase2: スクリプト連携と内蔵エディタ

- 人・看板・スクリプトタイルのスクリプト欄に、ラベル名の表示、対応する `.s` 内のラベルの一覧、選択、補完を出す。素のROMのスクリプトはアドレスのまま表示する。
- イベントを新規に置くと、ラベル名を自動で付け（既定 `EventScript_<マップ名>_<種別><番号>`）、種別ごとのひな形を `.s` に書く。`.s` を新しく作るときはファイル名の入力欄を出す。エディタでラベル名を変えたら `eventscripts` とマップ側の表示も追従する。
- 素のROMにあるスクリプトは、`xse_commands.s` の記法で読み取り専用で表示する。「.s に取り込む」で、ラベルを付けて対応する `.s` へ書き、文字列と移動データも取り込む。
- マップスクリプトの専用パネル（種類ごとの一覧、条件表、ラベルの選択）。
- オブジェクトのダブルクリックで、別ウィンドウのエディタが開く。
  - 改造済みの Gen3 Script Assistant 拡張（`pokehack\tool\gen3-script-assistant-main`）と同じ補完・ホバー・色付け。命令の定義は CSV と `xse_commands.s` のマクロの両方から読む。
  - 定義ジャンプ（ラベル、`strings` の該当行）。
  - 検索と置換（正規表現）、Alt＋ドラッグの矩形選択、複数カーソル、行の移動と複製、コメント切り替え、複数ファイルのタブ、Ctrl+S、外部変更の再読み込み、エラー箇所の波線。
  - 開けるのはイベント用フォルダ（`assembly\overworld_scripts`）と `strings` のファイルだけ。
  - テーマは Dark+ 風、Light+ 風、Monokai 風、Solarized Dark 風の4つ。マップエディタ本体は明るい標準色とダークの2つ。
- 文字列: ホバーで本文を表示、その場で編集して `.string` へ書き戻す。入力中は文字数による簡易の幅検査、保存時は `check_text_width.py` があれば実行する。ND の2ポインタのバージョン（ひらがなと漢字）と Chronos の1ポインタのバージョンの両方を扱う。
- ビルドの実行ボタンとログ表示、エラー行へのジャンプ、ビルド後のエミュレータ起動。

## Phase3: HexManiacAdvance の機能とスタンプ

- マップ接続の調整: 隣接マップの同時表示、角のつまみのドラッグでずれを変える（相手側も同時に直す）、境界をまたぐ描画・矩形塗り・スタンプ、辺のつまみの右クリックから接続の追加と削除と新規マップ作成、辺のつまみのドラッグでリサイズ（左と上へ広げたときは接続とイベントを補正）、Space でダイブ先と浮上先を重ねる、クローンの自動作成（設定で切れる）。
- スタンプ: 矩形の複数選択、コピーと貼り付け、名前つきで `maps\stamps\` に保存、サムネイルつき一覧から貼り付け。内容はブロック番号と移動許可。作ったときのタイルセットの組を記録し、いまのマップに貼れるものだけを一覧に出す。主タイルセットのブロックだけのスタンプは、主が同じマップに貼れる。
- 表示: Ctrl を押している間イベントと移動許可を隠す、サイドボタンで前のマップへ戻る、マップ名で絞り込んで移動、座標と選択範囲の表示。
- 描画: 移動許可の自動選択、ブロックの使用回数、移動許可だけ違うマスの強調、2マスの入れ替え、ミキシングバッグ、Ctrl＋ドラッグの矩形塗り。
- イベント: ワープのホバーで行き先の周辺画像、スクリプトの要約のホバー、ワープの右クリックから行き先マップの作成と戻りのワープ、ワープできないブロック上のワープの警告、未使用フラグと変数の自動選択、ひな形（人、看板、スクリプトタイル、落とし物、トレーナー、ショップ、アイテムをくれる人）。トレーナーのチーム自動生成は、書き込み先を調べてから仕様を決める。
- ヘッダー: 配置を共有しているマップの数の表示。
- 出力: 接続している全マップの画像をクリップボードへ。
- 外すもの: ランダム自動生成、データの付け替えと拡張、マップ以外の機能。

## Phase4: BochiBochiEditor の機能

2026-11-15 の調査（issue #9・#10、子 issue #299〜#317）と、#319 の Q1〜Q18（どれも推奨の案で確定）で決めた内容。動きの説明は README の「BochiBochiEditor の機能（Phase4）」。

- トリプルレイヤー: 属性のビット 28〜30 の値が 3（4バイト目で `0x30`〜`0x3F`・`0xB0`〜`0xBF`）のブロックをトリプルレイヤーとし、3枚目のレイヤーに次の番号のブロック（N+1）の下のレイヤーの4タイルを使う。判定と描き方は Bochi ではなく実機に合わせる（主の 639 番の次は副の 640 番ではない）。
  - ブロックエディタでトリプルレイヤーを編集できる。表の最後のブロックはトリプルレイヤーにできない（Q1）。トリプルレイヤーにしたとき N+1 の属性と上のレイヤーは 0 にする（Q2）。
  - N+1 は単独で置けない。描く道具はどれも N+1 を書かない。すでに置かれている N+1 は実機どおりに描き、枠の印を付ける（既定オン。Q3）。パレットとブロック一覧では N+1 を薄くして斜線を引く（Q4）。
  - 出力の形は変えない（`tileset.json` の `Behaviors` と次のブロックの `Blocks`）。
- オートペン（面・縁つき（HexManiacAdvance の 9 グリッドに当たる）・部品・くり返し、重なって並ぶ木）とマップ作成補助（パーツを作る・直す別ウィンドウ、範囲を塗る・整える）。
  - パーツは `maps\autopen\` に ZigzaguMap の JSON で置き、プロジェクトで共有する。Bochi の `mapassist\*.txt` は読み込みだけ（Q6）。
  - 素の BPRJ の主タイルセットには既定のパーツ（岸・段差・木・建物）を同梱し、ほかのタイルセットはマップから候補を作る（Q7）。
  - マップ作成補助は本物の別ウィンドウ（Q9）。
- 別ROMからのタイルセット移植: FR・LG・エメラルドの日本語バージョンと英語バージョンを読む（Q8）。新しいタイルセットとして足し、今のマップの組を付け替える（Q10）。アニメ処理は、取り込み先のベースROMの同じアドレスに同じ処理があるときだけ残す（Q11）。
- ポインタ一覧と参照元の検索（ベースROMの調査用）。探すROMは、開いているベースROMか、ほかのROMのファイル（Q16）。
- 落とし物と隠しアイテムの自動作成: Phase3 のひな形に加えて、イベントタブの右クリックの「ここに○○を追加」と、落とし物の見た目の既定（ROM でいちばん多いもの）。
- 左と上へのマップ拡張は Phase3 で済み。
- 表示と一覧: イベントの種類ごとの表示とイベントの濃さ、接続先のタイルセットが違うときの境目の警告、一覧の「場所:」「地形:」の絞り込み、タウンマップのウィンドウ、パレットのブロック情報と TS1/TS2 の境目（境目は #545 で外した）、最近使ったブロック、移動許可の説明、マップ一覧のサムネイル（既定オフ。Q13）、Ctrl＋ホイールでの 1〜8 倍の拡大と中ボタンのスクロール（Q14）。
- 後の Phase へ回すもの（Q5・Q12）:
  - 主人公より手前に出るレイヤー（トリプルレイヤーの3枚目、通常のブロックの上のレイヤー）をイベントの絵の上に描く表示は、Phase6 の連れ歩きの仮配置（実機と同じ重なり順）でまとめて作る。
  - チップ取り込み（画像からタイルとブロックを作るウィザード）と下地ブロックを選ぶウィンドウは、Phase6 の「タイルの自動分割」とまとめる。
  - タイルアニメの再生は Phase6（アニメーション再生）。
  - 塗りつぶしとブロックエディタのタイルの矩形のコピーと貼り付けは Phase5。
- 外すもの: ランダムマップ生成、ツール欄の分離と並べ替え（Q15）、Bochi の書き出し形式（`map_B_N_名前\` の PNG と `map_info.txt`。Q17）、ROM へ書く前提の機能（地形データの表を合わせる、データ作成タブの手順ガイド、マップスクリプトの表の終端の修復、拡張形式、表の自動検出、大きさを変えるときに埋めるブロックの指定。Q18。埋めるブロックの指定は、要れば Phase5 の対話式リサイズで足す）。

## Phase5: Porymap の機能

2026-11-15 の調査（issue #11、子 issue #388〜#406）と、#407 の Q1〜Q20（どれも推奨の案で確定）で決めた内容。作ったものの説明は `docs/` の各文書（[編集機能](map-editing.md)・[タイルセットとブロック](tilesets.md)）。

- 先に作ってあったもの: 接続の相手側の自動修正、ダイブ先と浮上先の重ね表示、マップの使用回数、戻る・進む、一覧の絞り込み、ワープ位置の警告（ワープできないブロックの上のワープの印）、画面からの色拾い、スポイト（右クリック、Ctrl＋右ドラッグで矩形）、移動許可の濃さのスライダー、ステータスバーのブロックと移動許可の情報は、Phase3 と Phase4 で作ってある（Phase3 の Q14）。Phase5 では足していない。

- 描画: 塗りつぶし（Phase4 の Q12 で回した。Phase3 の Q16 でも決めた）、直線塗り、スマートパス、マジック塗り、マップシフト、スポイト、対話式リサイズ。
  - 道具の切り替えは、マップタブと移動エリアタブの中に置く小さな道具の帯（鉛筆・塗りつぶし・シフト）と、N・B・S のキー。今のボタンと修飾キーの操作は、鉛筆のときにそのまま使える。帯は AdvanceMap と比べるマップ表示の領域にかけない（Q1）。
  - 塗りつぶしとマジック塗りで「同じ」とみなすのは、マップタブではブロックだけ、移動エリアタブでは移動許可だけ。塗った所の移動許可は「移動許可も貼る」「移動許可を自動で選ぶ」に従う（Q2）。範囲は 1 枚のマップの中だけ。
  - 直線は Shift を押しながら描く（Q3）。
  - スマートパスは、選択が 3×3 のときだけ帯のチェックで切り替え、Phase4 のオートペンの縁つきの解き方で描く（Q4）。
  - マップシフトで動かすのはブロックと移動許可だけ。イベントは複数選択のまとめての移動で動かす（Q5）。
  - 対話式リサイズのウィンドウでは、幅と高さの数値、新しい枠の中で今のマップを置く位置（ドラッグ）、広げた所を埋めるブロック（既定は今と同じ端の写し。ほかに境界ブロック、選んだブロック）を選ぶ（Q6）。
- 移動許可: 濃さのスライダー、数値での直接指定。
- プレイヤーの視界の枠（240×160 画素、15×10 マス）: Phase5 ではカーソルのマスを主人公の位置にした枠を V で切り替える（主人公は枠の左から 8 マス目・上から 5 マス目に仮に置く）。ROM のカメラに合わせた位置の計算と、外側を暗くする表示は Phase6（Q7）。
- イベント: 複数選択とまとめての移動、Ctrl+D で複製、ルーラー、ワープ位置の警告、イベント数の上限警告（人は 64 まで）。
  - 複数選択は、Shift＋クリックで足す・外す、空いた所からの Shift＋ドラッグで矩形の中を選ぶ。「Ctrl を押している間イベントを隠す」は変えない（Q10）。
  - ルーラーは、イベントタブで Shift＋右ドラッグの間だけ出し、距離をステータスバーに出す（Q11）。
- 接続: 相手側の自動修正、ダイブ先と浮上先の重ね表示。
- 野生: 種族の全マップ検索、出現率とレベル分布のグラフ。
- ブロック編集: コピーと貼り付け（タイルの矩形も。Phase4 の Q12 で回した）、入れ替え、使用回数、パレットの未使用色と色の使用箇所、画面からの色拾い。
  - ブロックの入れ替えでは、マップの番号も付け替える。そのタイルセットを使うマップの数を出して確かめ、付け替えないことも選べる（Q8）。
  - 新しいタイルセットを作れる（`New: true` の `tileset.json`。Q9）。初めの中身は、空か今のタイルセットの写しを選ぶ。表示中のマップの組だけを付け替える。
- 一覧: 絞り込み、状態アイコン、戻る・進む、マップの複製。
- 履歴の一覧、つなぎ合わせ画像、タイムラプスGIF、ショートカットの変更、ステータスバー、JavaScript のスクリプト機能（操作コマンドを呼ぶ）。
  - タイムラプスGIFは、開いているマップの、起動してからの履歴から作る（Q12）。
  - 画像の書き出しのウィンドウは PNG を既定にする。今の「画像を保存」（24 ビットの BMP）はそのまま残す（Q13）。
  - ショートカットを変えられるのは、メインのウィンドウと、ブロックエディタなどの別ウィンドウ（メニューと道具のキー）。スクリプトエディタは今のまま（Q16）。
  - JavaScript のスクリプトは、プロジェクトフォルダの `zigzagumap-scripts\*.js` に置き、`zigzagumap.json` で有効にするものを選ぶ。Web Worker で動かし、使えるのは決めた API だけ（ファイルや外部コマンドは使えない。Q17）。
- 設定のウィンドウ: 設定 > すべての設定… で画面内のウィンドウを開き、表示と設定のメニューの項目と Phase5 の新しい設定を種類ごとに並べる。メニューは今のまま残す（Q14）。
  - 並べ方は、メニューの並び（サブメニューごとの枠）にした。項目はメニューの定義から作る。下の欄に、プロジェクトの設定（`zigzagumap.json` の `script` の節）を置いた（#404）。

## Phase6: 新機能

2026-11-16 の調査（issue #12〜#16、子 issue #432〜#477・#482。調査の記録は作業フォルダの `phase6\research_A.md`・`research_B.md`・`research_C.md`）と、ユーザーの返事（各 issue のコメントの「ユーザーの返事」）で決めた内容。返事の無かった点は、各 issue に書いた推奨の案で確定した。作ったものの説明は `docs/` の各文書（[スクリプト編集と再生](script-editor.md)・[編集機能](map-editing.md)・[タイルセットとブロック](tilesets.md)・[時間帯と野生ポケモン](time-and-wild.md)）。

- 4Fスクリプトの再生（#448〜#459、#468、#482）: スクリプトをラベルから `end` までたどり、ゲームと同じ 1 フレームの単位で計算する。複数人物の同時移動、`waitmovement`、`pause`、カメラの開始と終了、画面の揺れ、表示と非表示、位置変更、ドアの開け閉めを再現する。`applymovement CAMERA` は完全に再現する。`callasm` の中のカメラ移動は、C ソースを読んで関数ごとに再現処理を登録する。再生後は元の位置に戻り、マップのデータは変えない。
  - 再生はメインのマップの上に重ね、マップの下に再生の帯を出す（A-1）。人物の自分の動き（移動タイプ）は再生の間は止める（A-5）。マップの人物は全員居るものとし、帯のチェックで外せる（A-6）。
  - 条件分岐と選択肢は、既定の答えで最後まで計算し、タイムラインの印から答えを選び直すと計算し直す（A-2）。`msgbox` などの文は出し、再生はそこで止まる。タイムラインでは長さ 0 の印にする（A-3）。メッセージの枠は ROM の絵とパレットを読み、読めなければ中立の枠にする。文字は確認用のフォントで、実機の字形・幅の再現ではない。
  - 主人公（男女）はマップに置かれていなくても動かせる。開始位置は、話しかけるスクリプトなら人物の下から、踏むスクリプトならそのタイルの上。仮の主人公を先に置いてあれば、その位置から話しかけたものとして向きを合わせる。1 コマ目の向きは変えられる。踏むスクリプトは変数の条件を見ずに始め、条件を帯に出す（A-7）。仮の主人公を矢印キーで歩かせて踏むスクリプトのマスに乗ると、自動で再生する（ドラッグや置き直しで乗ったときは始めない）。人物か看板の方を向いて Enter か Space を押すと、そのスクリプトを今の位置から再生する（#457）。
  - ROM のアドレスのままのスクリプト（素の ROM、まだ取り込んでいないイベント）も、逆アセンブルして再生できる。編集は「.s に取り込む」の後（A-9）。
  - タイムライン: 人物ごとの移動コマンドを時間順に並べ、現在のコマンドとエディタの該当行を強調する。コマ送りは 1 コマンドを「移動前・移動中・移動後」の 3 コマとし、全員の命令を時間順に合わせる（A-4）。コマ戻し、速度変更、任意位置へのジャンプ。
  - タイムライン上の編集（向き・種類・速さの差し替え、足す、消す、並べ替え、回数。A-11）は `.s` の移動データへ書き戻す。共用の移動データは、使っている数を出して「そのまま書き換える」か「`<元の名前>_2` に写して、このスクリプトだけ付け替える」を選ばせる（A-8）。エディタで開いているファイルは本文に入れ、未保存の変更があれば保存しない。メインの Ctrl+Z で戻せる。
  - ND・Chronos の `xse_commands.s` の不具合（`setobjectxy`・`turnobject` が定義の無いマクロを呼ぶ）は、直さずに ZigzaguMap が `moveobject`・`changeface` として読む（ビルド側の直しは本体へ書かず、ユーザーに案を渡す。A-12）。
- アニメーション再生（#471〜#474、#470）: NPC の移動タイプを元の日本語バージョンのソースの規則で動かし、移動範囲とトレーナーの視界を表示する。花・海・噴水などのタイルアニメとドアを、実機と同じ周期で動かす（タイルアニメは Phase4 の Q12 でここへ回した）。どれも表示メニューで切り替え、既定はオフ。止めている間は CPU を使わない。

## 運用

- issue は日本語。Phase1 は細かく分け、Phase2 以降は親 issue を先に作って着手時に分ける。テストで落ちた箇所も issue に書く。ユーザーのFBは会話で受け、issue に書き写す。
