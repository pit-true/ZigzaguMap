# ZigzaguMap

CFRU-JP 用のマップエディタです。AdvanceMap 1.92 日本語版と同じ画面と操作で、ファイアレッド日本語版（BPRJ）のマップを編集し、`maps\` の JSON として書き出します。ベース ROM には書き込みません。

- 対象: 素の BPRJ と、CFRU 方式へ移った BPRJ（NeoDark のベース ROM）。開くのは「ベース ROM」と「CFRU-JP のフォルダ」で、ベース ROM は読むだけです。素の ROM だけでも閲覧と編集ができ、出力のときに出力先のフォルダを選びます。
- Windows 用です（WebView2 が要ります）。インストールは不要で、exe 1 つで動きます。
- 仕様はこの README にまとめています。長い節は `docs/` に分けました: [自動操作の入口](docs/automation.md)、[比較テスト](docs/compare-test.md)。

## 使い方

- **ROM を開く**: ファイル > ROMを開く（Ctrl+O）か、`.gba` をウィンドウにドラッグ＆ドロップします。素の ROM だけでも閲覧と編集ができます。
- **ROM の再読み込み**: ファイル > ROMの再読み込み（F5）。未出力の変更があれば確かめてから、ROM（とプロジェクト）を読み直します。AdvanceMap と同じく、読み直したあとはマップを開きません（「最後に選択したものを覚える」がオンでも）。
- **プロジェクトを開く**: ファイル > CFRU-JPのフォルダを開く で CFRU-JP のフォルダを選びます。ベース ROM は、開いている ROM か、以前そのフォルダと組で開いた ROM を使い、どちらも無ければ選ぶよう求めます。フォルダのドラッグ＆ドロップでも開けます。`maps\BB\MM.json` があるマップはそちらを読みます。
- **最近開いたもの**: ファイルメニューの下に出ます（ROM とフォルダの組で覚えます）。個人設定は `%APPDATA%\io.github.pit-true.zigzagumap\settings.json` に保存します。
- 起動引数で開くこともできます: `zigzagumap.exe [--project <フォルダ>] <ROM>`。「最後に選択したものを覚える」がオンなら、前回のマップとタブを開きます。
- `--profile <フォルダ>` を付けると、個人設定（`settings.json`）と WebView2 のデータ（`EBWebView`）をそのフォルダに置きます（無ければ作ります）。通常の個人設定には触れません。
- **マップを開く**: 左の一覧の項目をダブルクリックか Enter（AdvanceMap と同じく、選ぶだけでは開きません）。ツール > マップを指定して開く（Ctrl+M）、以前開いたマップを開く（Alt+BkSp）も使えます。
- **元に戻す・やり直す**: Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z も可）。AdvanceMap の「オブジェクトの表示」の Ctrl+Z は、アンドゥに使うため外しています。
- **出力**: ファイル > 出力（Ctrl+S）。素の ROM だけを開いているときは、最初に出力先のフォルダを選びます。ファイル > 出力先を指定して出力 で別のフォルダへ書くこともできます。ファイル > バックアップの作成 も「出力先を指定して出力」と同じです。
- **ROM でないファイル**を開くと、AdvanceMap と同じ「AdvanceMapError(12): Unknown Rom Type! …」を出し、開いていたものはそのまま残します。
- **画像の保存**: ツール > マップ画像の保存／マップ&イベント画像の保存／パレット画像の保存。AdvanceMap と同じ 24 ビットの DIB（BMP と同じ形式）で書きます。マップ画像はブロックだけ（境界ブロックとイベントは含まない）、マップ&イベント画像はイベントタブと同じ印（フライトポジションの F と、カーソルの表示がオンなら選択中のイベントの赤い枠を含む。オブジェクトの表示がオンなら OW 画像）を重ねたもの、パレット画像はブロックパレット全体（今の横幅、等倍）です。拡張子を付けなければ `.DIB` を足します。AdvanceMap はイベントタブ以外でマップ&イベント画像を保存すると 0 バイトのファイルになりますが、ZigzaguMap はどのタブでもイベントを重ねた画像を書きます。
- **ヘルプ**: ZigzaguMapについて（F1、ツールバーの「?」）、エンドユーザー規約（F2。ZigzaguMap のライセンス）、Read me（この README）。

### マップタブ（マップの設定）

| 操作 | 動作 |
|---|---|
| 左クリック | 選択中のブロックを置く（移動許可は変えない）。スタンプなら押したマスを左上にして全体を置く |
| 左ドラッグ | 通ったマスに置く（1 回の操作にまとまり、1 回のアンドゥで戻る）。スタンプはドラッグしても 1 回だけ置く |
| 右クリック／右ドラッグ | 離したマスのブロックを拾う（パレットが追従してスクロール） |
| Ctrl＋右ドラッグ | 矩形を複数ブロック（スタンプ）として選ぶ。パレット上でも同じ |
| パレットの左・右クリック | ブロックを選ぶ |
| 境界ブロックの左クリック／右クリック | 置く／拾う |

Ctrl＋右ドラッグ（Ctrl＋右クリック）でスタンプを選ぶと、選んだ範囲を等倍で出す小さな窓「Grosser Block」が開きます（× で閉じる。題名の帯をつかんで動かせます）。

設定 > グリッドの表示（Ctrl+G）、設定 > 表示サイズ で 2 倍表示、設定 > ブロックパレットの横幅（Ctrl+P）でパレットの 1 行の数を変えられます。

### 移動エリアタブ（移動エリアの設定）

移動許可の値を色つきで重ね、値を 16 進で描きます。右のパレットで値を選び、左クリック・左ドラッグで書き、右クリックで拾います。設定 > 移動エリアの設定の透明度 の値は AdvanceMap と同じく「マップ側の重み」です（既定 0.3 で、色 70%・マップ 30%）。

### イベントタブ（イベントの設定）

マップのイベントを文字の箱（P=人、橙の S=看板、W=ワープ、緑の S=スクリプト、F=フライトポジション。AdvanceMap と同じく 50% の不透明度でマップに重ねる）で描き、右のパネルで選んで編集します。どの編集も Ctrl+Z / Ctrl+Y で戻せます。

| 操作 | 動作 |
|---|---|
| 箱をクリック（左右どちらのボタンでも） | そのイベントを選ぶ。同じマスに重なっていれば、フライトポジション > 看板 > スクリプト > ワープ > 人 の順に上のものを選ぶ |
| 箱をドラッグ | イベントを動かす（1 回のドラッグが 1 回のアンドゥ）。マップの外へも動かせる |
| 箱をダブルクリック | ワープは「マップの移動」、看板・スクリプト・人は「スクリプトを開く」と同じ |
| 種別コンボ・イベント番号 | 選ぶイベントを変える。種別はマップを切り替えても保ち、番号は 0 に戻る |
| 選択カーソルの表示 | 選択中のイベントの赤い枠を出す・消す |
| イベントの削除 | 選択中のイベントを消す（後ろが前に詰まる） |
| イベント数の設定: | 人・看板・ワープ・スクリプトの数を変えて「イベント数の変更」。増やした分は値が全部 0 のイベントを末尾に足し、減らした分は末尾から消す。イベントの無いマップにも作れる |
| マップの移動（ワープ） | 行き先のマップを開き、行き先のワープを選ぶ。無いマップなら「指定したマップは存在しません！」 |
| スクリプトを開く | 設定 > スクリプトエディタの選択 のエディターを `"<エディター>" "<ROM>" 16F884` の形で起動する（ROM とオフセットの区切りは設定により空白か「:」。起動のしかたは場所の設定タブと同じで、「:」のときは `"<ROM>:16F884"` になる）。未設定なら「スクリプトエディタが定義されていません！」 |

- 欄の値は入力のたびに反映します（確定ボタンはありません）。同じ欄に続けて入力した分は、1 回のアンドゥでまとめて戻ります。
- 16 進の欄は AdvanceMap と同じく `$` を前に付けて読みます。空欄は 0、あふれた桁は切り捨てます（4 桁の欄の 10000 は 0）。読めない文字を入れると `'$ZZ' is not a valid integer value.` を出し、値は変えません。10 進のスピンは範囲の端に丸めます（300 は 255）。
- スクリプトのオフセットは下位 3 バイトだけを書き、上位 1 バイトは元のままです。
- 看板のイベントタイプが 05〜08 のときは、オフセットの代わりにアイテム ID・隠し ID・個数を出します。
- フライトポジションの表は、タウンマップの飛び先（回復地点）と同じ ROM の表です。編集は `maps\regionmap.json` の `HealLocations` に出力します（ワールドマップエディターを開いていなくても書きます）。ワールドマップエディターで飛び先を変えても、同じ値になります。
- 人の落とし物（ItemBalls）は画面では変えません。ほかの欄を編集しても、落とし物は保ったまま出力します。
- マップの外にイベントがあると、ステータスバーの右欄に「ノート:イベントがマップの外に配置されています」を出します。
- 設定 > オブジェクトの表示（ツールバーの主人公のボタン）をオンにすると、AdvanceMap と同じく人を ROM の OW 画像（下向きの 1 コマ目）で描き、人以外の箱は描きません。

AdvanceMap と違う点は「[AdvanceMap と違う点](#advancemap-と違う点)」にまとめています。

### 「保存」ボタンの読み替え

AdvanceMap で ROM へすぐ書き込む「保存」ボタン類（マップ名の変更を保存、マップスクリプトの変更、タイルセットの変更、保存してマップの再読み込み、コネクションの保存、設定の保存など）は、同じ場所に置き、押すと**編集中の状態へ反映**します。ROM には書かず、ファイル > 出力（Ctrl+S）でまとめて `maps\` へ書き出します。反映はどれも 1 回の操作として Ctrl+Z / Ctrl+Y で戻せます（1 回押して複数の項目が変わるときも 1 回のアンドゥで戻ります）。

### 場所の設定タブ

設定 > 高度なヘッダーを表示（Ctrl+H、初期はオン）で、通常表示と高度な表示を切り替えます（個人設定に残ります）。

通常表示:

| 枠 | 動作 |
|---|---|
| 名前: | 左のコンボは名前表（地名番号 0x58〜0xC4）の一覧。選ぶと右の欄に名前が入ります（このマップの地名番号は変えません）。「マップ名の変更を保存」は、コンボで選んでいる名前表の項目を書き換えます（同じ地名番号の全マップの名前が変わり、出力ではそれらの JSON を全部書きます）。文字はプロジェクトの `charmap.tbl`（無ければ同梱の表）で変換します。「新しい名前の作成」は AdvanceMap と同じく無効です |
| マップ名の表示/タイプ | ヘッダーの 0x19（名前表示・ダッシュ・穴抜け）。選ぶとすぐ反映します |
| マップオプション: | BGM（コンボと 16 進 4 桁の「No.」が連動。一覧に無い値ではコンボが空）、フラッシュ、天候、タイプ、戦闘背景の強制上書き。選ぶ・入れるとすぐ反映します。選択肢は改訂版 Japanese.ini と `Musik_jap.ini` の [Musik_BPR] のとおりで、表に無い番号は「0n ???」 |
| マップスクリプト | スクリプトNo. の上下で切り替え、種類・オフセットを変えます。種類 02・04（条件表）では、表の先頭の行を「イベント変数・イベント変数の値・スクリプトオフセット2」に出します（オフセット欄は無効。読み込んだときから条件表のものは表の位置、種類を条件表に変えたものは `$000000`。「00 スクリプト未設定」でもオフセット欄は無効）。追加・削除（確認なし）・欄の変更はメモリ上の表に対して行い、「マップスクリプトの変更」で反映します。種類「00 スクリプト未設定」のまま保存するとエラーです（一覧の終端と同じ値で保存できないため） |
| 使用するタイルセット: | 番号（AdvanceMap のタイルセット番号 0〜67）を入れて「タイルセットの変更」。確認なしで差し替えてマップを描き直します（合わないタイルセットでは絵が崩れるのも同じ） |
| マップのサイズ: | 横幅・高さを入れて「マップサイズの変更」。左上を基準に伸縮します。0 と空欄は無視します |

高度な表示:

| 枠 | 動作 |
|---|---|
| マップヘッダーの設定: | マップバンクテーブル、バンク番号、マップ番号、バンクの一覧、マップヘッダーの位置（すべて読み取り専用） |
| マップヘッダーデータ: | マップヘッダー 28 バイトの 16 進と、フッター・イベント・マップスクリプト・コネクションの位置。16 進を書き換えると「保存してマップの再読み込み」が押せ、0x10 以降の設定を反映します |
| マップフッターデータ: | フッター 28 バイトの 16 進と、横幅・高さ・タイルセット番号・境界ブロックの大きさの欄が連動します（タイルセット番号を変えるとタイルセットのオフセットも変わります）。横幅・高さを変えて保存すると、AdvanceMap と同じく配置のデータはそのままで新しい横幅で折り返して読みます（足りないマスは 0。「マップサイズの変更」の左上基準の伸縮とは違う） |
| 境界データ: | 境界のブロックの値（16 進）。変えると画像がすぐ変わります。「マップフッターデータ」の保存で一緒に反映します |
| タイルセットデータ: | 主・副タイルセットのヘッダー 24 バイトの 16 進。保存で圧縮フラグ・副フラグ・アニメーション関数などを反映します |

**オフセット欄の表示**: ZigzaguMap は ROM へ書かないので、ROM 上の位置が意味を持つのは「ベース ROM から読み、`maps\` の JSON が無いマップ」だけです。そのマップではベース ROM 上の位置を出します。JSON から読んだマップや新しく作ったマップでは、ヘッダー・フッターとその先のデータの位置を、AdvanceMap が未設定の位置に使う書式 `$000000` で出します（16 進欄のポインタ部分も 0）。バンク表とバンクの一覧は、ベース ROM にあるバンクなら出します。ポインタと位置は表示だけで、保存しても読み捨てます（出力時に作り直すため）。

### マップコネクション

ツール > マップコネクション（Ctrl+A）かツールバーの矢印アイコンで開きます（常に手前に出るダイアログで、メインの画面も操作できます）。

- コネクションNo. の上下で切り替え、方向（無し・下・上・左・右・ダイビング・浮上）、調整、バンク番号、マップ番号、不明（16 進）を変えます。
- 「追加」は方向 無し・調整 0・バンク 0・マップ 0 を末尾に足します（確認なし）。「削除」は「コネクションNo.nを削除しますか？」と聞きます。ここまではメモリ上の表に対して行い、「保存」で反映します。保存せずに閉じる・別のマップへ移ると変更は捨てます。
- 左の矢印ボタンは、その方向の 1〜3 番目のコネクションがあるときだけ押せます（2・3 番目の帯はあるときだけ出ます）。押すと相手のマップを開き、ダイアログも開いたマップのコネクションに切り替わります。
- 範囲は確かめず、書くときに切り詰めます（バンク・マップは 1 バイト、不明は 2 バイト。AdvanceMap と同じく -3 や 300 も入ります）。

### 野生ポケモンの設定タブ

- タイプ（草むら・水上・岩砕き・釣り）を選ぶと、そのタイプのエンカウント率と各枠（草むら 12、水上 5、岩砕き 5、釣り 10）を出します。データの無いタイプでは部品を隠し、「設定の保存」は押せません。タイプを切り替えると保存していない編集は捨てます。
- エンカウント率の欄・トラックバー・百分率（値÷255 の切り捨て）が連動します。0〜255 に丸め（300 → 255、-5 → 0）、`0x10` や `$10` の 16 進も受け付けます。トラックバーは矢印キーで 1、PageUp / PageDown で 25、Home / End で両端へ動きます。
- 最小・最大 Lv は検査せず、反映するときに 1 バイトに切り詰めます（300 → 44）。空欄は元の値のままです。種族はコンボから選びます（0 番は「選択してください」）。
- 「設定の保存」で、表示中のタイプのエンカウント率と各枠を反映します。
- 野生データの無いマップでは、野生データが無いという文言（[Allgemein] 941）と「野生ポケモンの追加」を出します。「野生ポケモンの追加」「タイプの追加」のダイアログで使うタイプにチェックを入れて OK を押すと、そのタイプを初期値（確率 0、全枠 Lv 1/1、「選択してください」）で作ります。何もチェックせずに OK を押すと「野生ポケモン設定の追加/変更を中止しました！」と出します。チェックを外したタイプのデータは消えます。
- 種族名は ROM の種族名表から読みます。読めない間は `No.番号` で出します。

### 入力エラー

数値欄に整数として読めない文字を入れると、AdvanceMap と同じ「'abc' is not a valid integer value.」（`$` を付けて読む 16 進欄は `'$zzzz' is …`）を出し、値は変えません。確かめるタイミングは AdvanceMap の欄ごとの動作に合わせ、どのタブも共通の部品（`ui/form/integerInput.ts`）で決めています。

| タイミング | 欄 |
|---|---|
| 1 文字入れるたび | イベントタブの全欄、音楽No.、マップスクリプトのオフセット・フラグ・フラグの値・フラグのオフセット、高度な表示の横幅・高さ・タイルセット番号、出現確率と最小・最大 Lv、コネクションの調整・バンク・マップ・不明 |
| ボタンを押したとき | 使用するタイルセット、マップの大きさ（通常表示） |

オフセットの欄（`$16F884` のように `$` が文字に入っている欄）は、AdvanceMap と同じく文字のまま読みます（`zz` なら `'zz' is …`）。10 進の欄の空欄は何もしません。ほかのエラーの文言は改訂版 Japanese.ini（ini に無いものは AdvanceMap）に合わせています（タイルセット番号が表に無い: 「AdvanceMapError(1): Try to read at pos 0! …」、大きすぎるマップ: 「マップの横幅200の時のマップの高さの最大サイズは33です」、フッターの 16 進が不正: 「マップフッターに無効なポインタが設定されています！」）。

### 新規マップ・作成したマップ（.map / .evt）

ファイル > マップ の 4 項目と、ツールバーの「新規マップの作成」「マップの追加/挿入」です。

- **新規マップの作成**: 「新規マップの作成」ダイアログに、ファイル名・マップの横幅・マップの高さ・タイルセット1/2（AdvanceMap のタイルセット番号 0〜67）を入れて「作成」。初期値は今のマップの名前（一覧の項目の文字列）と大きさで、タイルセットは未選択です。作成したマップは全マス 0x3001（ブロック 1・移動許可 0x0C）、境界ブロックは 2×2 の 0、イベント・接続・マップスクリプトは無し、ヘッダー（音楽など）は作成時に開いていたマップのものです。
- 入力は「作成」を押したときに確かめます（AdvanceMap と同じく 1 文字ごとには確かめません）。順番も AdvanceMap と同じで、横幅・高さが整数でなければ「'abc' is not a valid integer value.」、名前が空・横幅や高さが空か 0 以下・タイルセットが未選択なら「全て記入してください」、大きすぎれば「マップの横幅200の時のマップの高さの最大サイズは33です」です。エラーのときはダイアログを閉じません。
- 作成したマップと `.map` から開いたマップは**作業用のマップ**です。プロジェクトのバンクには入らず、出力（Ctrl+S）でも書きません。編集はほかのマップと同じようにでき、Ctrl+Z / Ctrl+Y も使えます（作成・読み込み自体も取り消せます）。プロジェクトへ入れるには「マップの追加/挿入」を使います。AdvanceMap と同じく、作成しても題名・一覧の選択・ステータスバーは変えません（`.map` から開いたときだけ、題名を「ZigzaguMap - <拡張子を除いたパス>」にします）。
- **作成したマップに名前を付けて保存**: 今のマップ（作業用のマップでも、プロジェクトのマップでも）を `.map` と `.evt` に書きます。既定のファイル名は「<今のマップの名前>.map」、初期フォルダは前回のフォルダ（最初は ROM のフォルダ）です。保存したファイルはマップ一覧の「マップファイル」の下に名前で並びます（AdvanceMap の `Ini\MapDateien.ini` と同じく、同じ名前なら上書き。個人設定の `mapFiles` に残ります）。
- **作成したマップを開く**: `.map` を選ぶと、同じ名前の `.evt` も読みます（無ければイベント無し）。「マップファイル」の項目をダブルクリック・Enter しても開けます。項目のファイルが無いときは「作成したマップのファイル"map\*.evt と map\*.map"が存在しません！」を出し、その項目を一覧から外します。
- **マップの追加/挿入**: 今のマップをプロジェクトへ写します。AdvanceMap は押すとすぐ ROM へ書きますが、ZigzaguMap は編集中のプロジェクトへ反映し、出力で `maps\BB\MM.json` と（無ければ）`maps\project.json` を書きます。どれも 1 回の操作として Ctrl+Z で取り消せます。成功すると「現在表示中のマップデータをコピーし、(B.M)にマップデータをインポートしました！」を出し、ダイアログを閉じてそのマップを開きます。× で閉じると「マップは挿入されていません！」です（ダイアログの題名は「マップの挿入」）。
  - 差し替え（既存のマップを差し替える）: 選んだ既存のマップの中身（ヘッダー、配置、境界ブロック、タイルセット、イベント、接続、マップスクリプト）を今のマップで差し替えます。番号と野生はそのままで、落とし物は消えます。
  - 追加/挿入（新規バンクの追加/既存バンクの拡張）: 選んだバンクの末尾に今のマップを写して加えます。「新規バンクの追加」を選ぶと、新しいバンクのマップ 0 に加えます。マップの追加数の欄は 1 以上ならいくつでも 1 つだけ加え、0 以下なら何もしません（AdvanceMap と同じく何も出しません）。追加数の欄は 1 文字入れるたびに整数か確かめます（AdvanceMap と同じ）。
  - 挿入（既存のバンクに挿入する）: ZigzaguMap はダミーマップ（予約した空きの番号）を作らないので、残量はいつも 0 で押せません。
- **マップバンクヘッダーの管理**（ツール > ダミーデータへ移す/ヘッダー管理、マップの追加/挿入の「マップバンクヘッダーの表示」）: 全バンクの番号、マップ一覧の位置（ベース ROM に無いバンクは `$000000`）、マップ数（「格納マップ数:」。追加したマップを含む）、ダミーマップの残量（いつも 0）を出します。「新バンク番号」で足した行は、「変更の適用」で新しいバンクとして作ります。ビルド側で空のバンクは作れないので、各バンクにマップ 0 を 1 つ置きます（中身は新規マップの作成と同じ初期値で、大きさ・タイルセット・ヘッダーは今のマップのもの）。ダミーマップの残量と「ダミーマップバンクの追加数」「ダミーマップの追加数」を 0 以外にして適用すると「ZigzaguMap は ROM へ書き込まないため、この機能は不要です」と案内します（その値は使いません）。「キャンセル」と × は何もしません。
- **マップタブの「新規マップ作成」「マップバンクの作成」**: AdvanceMap では一覧の「保留したダミーマップデータ」「保留したダミーバンク番号」を開いたときにマップの代わりに出るボタンです。ZigzaguMap にはダミーマップ・ダミーバンクが無いので、いつも隠れています（押せば、新規マップ作成は「新規マップの作成」、マップバンクの作成は不要の案内）。

置ける番号の制約: 新しいマップは**既存のバンクの末尾**か、**最後のバンクの次の新しいバンクのマップ 0**にだけ加えられます（ビルド側の `map_project.py` の制約）。操作列（`createMap` / `insertMap`）で途中の番号を指定したときは「バンク B に新しいマップを加えられるのは末尾（マップ番号 N）だけです。ZigzaguMap ではマップの配置をビルドが行うため、途中の番号へは挿入できません。」、バンクを飛ばしたときは「新しいバンクは N 番にだけ作れます（バンク番号を飛ばすことはできません）。」を出します。

#### .map / .evt の形式

AdvanceMap 1.92 に実際に書かせて確かめた形式です。ZigzaguMap はこの形で書き、AdvanceMap で開けることを確かめています。

| ファイル | 中身（数値はリトルエンディアン） |
|---|---|
| `.map` | u32 横幅、u32 高さ、u32 タイルセット１の番号、u32 タイルセット２の番号、u8 境界の横幅、u8 境界の高さ、2 バイト（AdvanceMap はいつも `C0 00` を書く。読むときは見ない）、境界ブロック（u16 × 境界の横幅 × 高さ）、配置（u16 × 横幅 × 高さ。1 マスはブロック番号と移動許可） |
| `.map`（古い版） | 境界ブロック 2×2（8 バイト）、配置、末尾に u32 横幅・高さ・タイルセット１・タイルセット２。AdvanceMap 同梱の `Maps\*.map` がこの形。ZigzaguMap は読めるが、書くのは上の形 |
| `.evt` | 人（24 バイト）、ワープ（8 バイト）、スクリプト（16 バイト）、看板（12 バイト）の一覧を ROM と同じ並びで続け、末尾に件数 4 バイト（人・ワープ・スクリプト・看板） |

タイルセットはポインタではなく AdvanceMap のタイルセット番号（ベース ROM のタイルセット表の何番目か）で書きます。表に無いタイルセット（`maps\tilesets` で新しく作ったものなど）を使うマップは `.map` に書けず、エラーになります。ヘッダー・接続・マップスクリプト・野生はどちらのファイルにも入りません。

### ブロックエディタ（ツール > ブロックエディタ、Ctrl+B）

マップを開いているときに、別ウィンドウで開きます（題名は「ブロックエディタ     タイルセット1: N  タイルセット2: M」）。左から、ブロック一覧（主の 640 個のあとに副）、ブロックの編集面とタイル一覧（1024 タイル。主 0x000〜、副 0x280〜）、マップデータです。

| 操作 | 動作 |
|---|---|
| ブロック一覧の左・右クリック | ブロックを選ぶ。8 マス（左が下層、右が上層）と属性 4 バイト、ブロック（16 進 3 桁）、オフセット（ベース ROM でのブロック定義の位置）を出す |
| タイル一覧の左・右クリック、ドラッグ | タイルを選ぶ（離した位置）。タイル欄とプレビューに出す |
| 8 マスの左クリック | 選んでいるタイル・X反転・Y反転・パレットを置く |
| 8 マスの右クリック | そのマスのタイル・X反転・Y反転・パレットを拾う |
| Palette0〜12 | タイル一覧とプレビューの色。置くタイルのパレット番号にもなる。パレットエディタと連動する |
| マップデータ | 上の 2 欄が属性の 0・1 バイト目、下の 2 欄が 2・3 バイト目（16 進）。0 バイト目は挙動のコンボ、3 バイト目は背景のコンボと連動する。16 進でない文字は「'$zz' is not a valid integer value.」 |
| 変更 | 選んでいるブロックの 8 タイルと属性を、編集中の状態へ確定する（AdvanceMap は ROM へ書く）。メインのマップ表示とブロックパレットがすぐ描き直される |

メニュー:

- 画像 > タイルセット1/2をファイルに保存する: 選んでいるパレットの色で 24 ビットの DIB（横 128、主 640 タイル・副 384 タイル）と、同じ名前の `.pal` を書きます（AdvanceMap と同じバイト列）。パレットに同じ色が 2 つ以上あると「Export of this palette not possible; …」を出して書きません。
- 画像 > タイルセット1/2にファイルから読み込む: DIB・BMP（1/4/8/24/32 ビット）と、インデックス PNG を読みます。色番号が 15 以下のインデックス画像は番号をそのまま、24 ビットの画像は選んでいるパレットの同じ色（無ければ一番近い色）にします。上限を超えるタイルは捨てます。
- 画像 > ブロックの再読み込み: メインから写しを取り直し、選んでいるブロックの編集中の値を捨てます。
- ブロック > タイルセット1/2をファイルに保存する・ファイルから読み込む: `.bvd`（ブロック数 u32、ブロック定義 16 バイト × 数、属性 4 バイト × 数、末尾 `FRLG`。Porymap の AdvanceMap 1.92 用の読み込みと同じ形式。末尾が `RSE ` の 2 バイト属性も読める）。開くとブロック数も `.bvd` の数になります。
- ブロック > ブロック数の追加/変更: タイルセット 2 のブロック数（上限 384 に丸める）。
- パレット > パレットエディタの表示／ブロックのパレット参照先の一括変更: それぞれ別ウィンドウで開きます。
- パレット > パレットの変更を反映する: パレットエディタの「変更」で一時適用した色を、編集中の状態へ確定します（AdvanceMap の「パレットの変更をROMに上書きする」）。
- パレット > 現在のパレットをファイルに保存する・ファイルから読み込む: `.pal`（16 色 × `R, G, B, 0`）。開いた色は一時適用の扱いで、「パレットの変更を反映する」で確定します。

### パレットエディタ

16 色の見本を押して色を選び、赤・緑・青のスライダー（0〜31。右の数字は 8 倍）で変えます。15 ビットの値（`青<<10 | 緑<<5 | 赤`）を入れて「15bit to RGB」でも変えられます（最上位ビットは無視、16 進でなければ「'$ZZZZ' is not a valid integer value.」）。「変更」でブロックエディタのタイル一覧・8 マス・プレビューに出ます（ブロック一覧とメインは確定するまで変わりません）。「色の選択」を押すと、100ms ごとにマウスカーソルの下の画面の色を拾い、左ボタンを押したところで止めます（Esc かもう一度押しても止まる）。

### ブロックパレット一括変更

タイルセット 1 か 2 を選び、右の欄にパレットの変更先を入れて「変更を保存する」を押すと、そのタイルセットの全ブロックのパレット番号を置き換えて閉じます（確認なし）。

### 別ウィンドウと編集中の状態

- 別ウィンドウ（ブロックエディタ・パレットエディタ・ブロックパレット一括変更）は Tauri の本物のウィンドウで、ワールドマップエディタと同じく中身は別ウィンドウ用の入口 `tool.html`（`src/tool.ts`。メインの画面のコードは読み込まない）から、ウィンドウのラベルを見て組み立てます。エディタのコードは開いたときに初めて読み込み、閉じると WebView ごと破棄します。メインの起動では読み込みません（メイン側の窓口 `windows/ToolWindowHost.ts` も初めて開くときに読み込みます）。
- 編集中の状態（CommandBus とタイルセット）はメインウィンドウだけが持ちます。別ウィンドウはイベント `tool-request` で操作（コマンドの JSON）を送り、メインがそれを CommandBus で実行します。アンドゥ・リドゥはメインと同じ履歴に入り、どのウィンドウでも Ctrl+Z / Ctrl+Y（Ctrl+S は出力）で戻せます。
- タイルセットが変わると（どのウィンドウの操作でも、アンドゥでも）、メインは開いている別ウィンドウへイベント `tool-message` でタイルセットの写しを送り直します。選んでいるパレットと一時適用した色も、メインが持ってウィンドウどうしで共有します。
- マップを切り替えると、別ウィンドウはそのマップのタイルセットに追従します。ROM を開き直したときとマップを閉じたときは閉じます。
- 未出力のタイルセットの変更があるときも、閉じる・別の ROM を開くときに「変更を出力しますか？」と聞きます。

| 言語 | 画面は日本語だけなので Japanese の 1 項目（AdvanceMap と同じく、選んでいる言語にもチェックは付けない） |
| 最後に選択したものを覚える | 次の起動で前回のマップとタブを開く |
| イベントパネルの非表示／自動的にオフセットを検索する／高度なヘッダーを表示 | チェックを覚えるだけ（AdvanceMap でもイベントパネルの非表示は見た目が変わらない。後の 2 つは今の画面では使わない） |
| 開いたときにバックアップを作成、ツール > ダミーデータへ移す/ヘッダー管理（マップバンクヘッダーの管理を除く）、空き領域の検索 | 「ZigzaguMap は ROM へ書き込まないため、この機能は不要です」と案内する |
| スクリプトエディタの選択 | exe を選び、「:」区切りか「 」区切りかを聞く（AdvanceMap と同じ文言）。.exe 以外はエラー |
| 最後に開いたROMのショートカットを作成する | オンにするときに確認する。オンの間は ROM を開くたびに exe と同じフォルダに `Most recently used ROM.gba.lnk` を作る（既定はオフ） |
| コンテキストメニューにAM context menuを追加する | 確認してから、エクスプローラーの .gba の右クリックに「ZigzaguMapで開く」を登録する（現在のユーザーのレジストリ）。もう一度押すと外す |
| ツール > デスクトップにショートカットを作成 | 確認してから、デスクトップに `ZigzaguMap.lnk` を作る |

## AdvanceMap と違う点

AdvanceMap 1.92 との違いのうち、意図して残しているものの一覧です。比較テスト（[docs/compare-test.md](docs/compare-test.md)）では、これらを「仕様上の違い」として理由つきで除外しています。

### 全体

- ROM へは書き込みません。「ROMの保存」は「出力」（Ctrl+S、`maps\` へ書く）、「ROMに名前を付けて保存」は「出力先を指定して出力」です。ROM へすぐ書く「保存」ボタン類は、編集中の状態への反映に読み替えます（「[「保存」ボタンの読み替え](#保存ボタンの読み替え)」）。
- AdvanceMap に無いものを足しています: 元に戻す・やり直す（Ctrl+Z / Ctrl+Y）、ROM とフォルダのドラッグ＆ドロップ、「CFRU-JPのフォルダを開く」。起動時のタイトルロゴはありません。
- 未出力の変更があっても、別のマップへ移るとき（「マップの移動」を含む）に確認しません。マップごとの変更を持ったまま切り替え、一覧の名前に ` *` を付け、閉じる・別の ROM を開くときにだけ「変更を出力しますか？」と聞きます。
- 画面は日本語だけです（言語メニューは Japanese の 1 項目）。アプリ名は ZigzaguMap です（「Advance Mapについて」は「ZigzaguMapについて」、ダイアログの題名も ZigzaguMap）。
- ROM へ書かないので意味の無い機能（開いたときにバックアップを作成、ダミーデータ系、空き領域の検索、ワールドマップのルーチンの変更）は、「ZigzaguMap は ROM へ書き込まないため、この機能は不要です」と案内します。「バックアップの作成」は「出力先を指定して出力」と同じです。
- 確認・エラー・入力のダイアログは画面内に出します（Windows 標準のメッセージボックスは使わない。並びと文言は同じ）。
- 「オブジェクトの表示」の Ctrl+Z は、アンドゥに使うため外しています。
- マップ&イベント画像の保存は、どのタブでもイベントを重ねた画像を書きます（AdvanceMap はイベントタブ以外では 0 バイトのファイル）。
- 1×1 のマップ（3.50、3.51）は、AdvanceMap では黒く表示されますが、ZigzaguMap はブロックを描きます（#115。AdvanceMap の不具合とみなす）。

### 比較テストで決めた違い

| 項目 | AdvanceMap | ZigzaguMap | 理由 |
|---|---|---|---|
| ファイルメニューの最近開いたファイル（#161） | 最大数の行をいつも出す（履歴の無い行は空） | 履歴にあるものだけ出す | 空の行は何の情報も持たないため |
| 設定 >「最後に開いたROMのショートカットを作成する」の初期状態（#162） | オン | オフ | ユーザーが頼んでいないファイルを exe のフォルダに作らないため |
| 「タイルセット番号で並び替え」の最後のグループ（#163） | 「Tileset 67」のあとに名前が空のグループを 1 つ出す | 出さない | AdvanceMap の不具合とみなす |
| 合わないタイルセットの組（#164） | ブロック表の外のデータもブロックとして描く | ブロック表の長さだけ読み、それより後ろのブロック番号は背景色で描く | ブロック数はブロックエディタと出力（`maps\tilesets`）にも使うので、表の外を読むとその中身まで出力に混ざるため |
| マップを指定して開く（Ctrl+M）を取り消したあと（#166） | Cancel で閉じたり整数でない値を入れたりすると、「以前開いたマップを開く」が動かなくなる | いつも前のマップを開く | AdvanceMap の不具合とみなす |

### イベントタブ

- 「マップの移動」で、行き先のマップの、ワープ No. のワープを選びます（AdvanceMap は番号 0 を選ぶ）。
- アイテム ID の名前は ROM の文字コード表で読みます（AdvanceMap では一部が文字化けする）。
- ポインタが 0 のイベントにスクリプトのオフセットを入れたときは、上位 1 バイトを 08 にします。

### 場所の設定・マップコネクション・野生ポケモンの設定

- 「保存」は ROM ではなく編集中の状態へ反映します（「[「保存」ボタンの読み替え](#保存ボタンの読み替え)」）。
- タイルセット番号に表に無い番号（9999 など）を入れたときは、AdvanceMap は受け付けて崩れた絵を出しますが、ZigzaguMap は指せるタイルセットが無いのでエラーにします。マップの横幅に -1 を入れたとき、AdvanceMap は落ちますが ZigzaguMap はエラーにします。
- 高度なヘッダーの位置・ポインタは表示だけです。不正な 16 進を保存したとき、AdvanceMap は続けて「AdvanceMapError(1)」も出してヘッダーを壊しますが、ZigzaguMap は最初のエラーだけを出して何も変えません。
- マップコネクションの矢印ボタンの有効・無効は、下書きの表の方向から決めます（AdvanceMap は方向を変えたときに表と合わない状態になることがあります）。
- 「スクリプトを開く」は、設定 > スクリプトエディタの選択 で選んだ exe に、ベース ROM のパスとオフセットを渡します（maps\ の JSON から読んだマップでは、ベース ROM 上のオフセットと一致しないことがあります）。選んでいなければステータスバーにオフセットを出します。
- タイルセット番号に -1 を入れたとき、AdvanceMap は同じエラー（AdvanceMapError(1)）を 2 回続けて出しますが、ZigzaguMap は 1 回です（AdvanceMap の不具合とみなす）。

### 新規マップ・作成したマップ・追加/挿入

- AdvanceMap は新規作成したマップを `.map` に保存すると、直前に開いていたマップのイベントを `.evt` に書きます。ZigzaguMap は作業用のマップのイベント（新規作成なら無し = 件数 0 の 4 バイト）を書きます。
- 名前に `/` などファイル名に使えない文字があるとき、AdvanceMap は保存ダイアログを開けませんが、ZigzaguMap はその文字を `_` にしたファイル名を初期値にします。
- マップの追加/挿入は、野生と落とし物（Bochi の ItemBalls。HiddenItem.s のラベルが重なるため）を写しません。
- 「マップの追加数」は、加えるマップの数ではありません（いつも 1 つ）。
- マップバンクヘッダーの「変更の適用」で作るバンクには、空のバンクの代わりにマップ 0 を置きます。

### ブロックエディタ・パレットエディタ・一括変更

- 「変更」「パレットの変更をROMに上書きする」「変更を保存する」「ブロック数の追加/変更」は ROM へ書かず、編集中の状態へ反映します（出力で `maps\tilesets\` に書く）。メニューの文言は「パレットの変更を反映する」にしました。
- 8 マスに置くタイルのパレット番号は、選んでいるパレットにします（AdvanceMap では反映されない場合があり、条件は分かっていません）。右クリックで拾うとパレットも拾います。
- タイルセット画像・`.bvd` の読み込みは、AdvanceMap では「Invalid filename.」で失敗しますが、ZigzaguMap では読み込めます。
- 一括変更の右の欄は 10 進で読みます（表の初期値が 10 進のため。数でなければ AdvanceMap と同じエラー）。

### ワールドマップエディタ

- AdvanceMap は素の BPRJ ではワールドマップエディタを開けません（エラーが続けて出て窓が出ない）が、ZigzaguMap では地図の絵と全ての表を読めます。
- 「保存」は編集中の状態への確定です。「ルーチンの変更」は ROM を書き換えないので、質問だけを出して何もしません。

## ワールドマップエディタ

ツール > ワールドマップエディタ（Ctrl+W、ツールバーの緑のアイコン）で、タウンマップ（空を飛ぶの地図）を別ウィンドウで開きます。初めて開いたときにベース ROM と `maps\regionmap.json` を読みます。画面の構成は AdvanceMap 1.92 の TWeltkarteForm と同じです（AdvanceMap は素の BPRJ では開けず、地図も黒いままですが、ZigzaguMap では地図の絵と全ての表を読めます）。

| 部分 | 動作 |
|---|---|
| 世界地図 | 左クリック（ドラッグしたときは離したマス）で位置を選び、そのマスの値を基本レイヤー・トップレイヤーの欄に読み込む。開いたときは、メインで開いているマップの地名の位置を選ぶ |
| エディットレイヤーの表示 / フライトポジション/人IDの表示 / トップレイヤーの座標を読み込む | 地名のあるマスの色、地名の位置の白い点、トップレイヤー（洞窟）のマスを重ねて描く。3 つ目を外すとトップレイヤーの欄は「未設定/非表示」 |
| マップ（16 進）・地名の一覧 | 地名を選んで、名前のオフセット・名前・座標・幅/高さ・人ID・フライトポジションを表示する。16 進でない入力は「'$zz' is not a valid integer value.」 |
| ポジションの保存 | 座標・幅/高さ・名前（基本レイヤーはフライトポジションも）を確定する。名前はマップ名表の書き換えなので、同じ地名番号の全マップの名前が変わる |
| フラグの保存 | 人ID（訪問フラグ。無しは FFFF）を確定する |
| マップの保存 | 選んでいるマスに、欄のマップの値を置く。置いていない値があるままタウンマップNo を切り替えると「ワールドマップの変更を保存しますか？」 |
| フライトポジション マップ/座標、このマップを開く | 左は空を飛ぶの行き先 3 バイト（バンク・マップ・飛び先の番号）、右は飛び先 6 バイト（バンク・マップ・X・Y）を ROM の並びの 16 進で出す。ボタンで行き先のマップをメインウィンドウで開く |
| タウンマップNo | 1: カントー、2: 1〜3のしま、3: 4〜5のしま、4: 6〜7のしま。「ワールドマップ番号の管理」は AdvanceMap と同じく押せない |
| ルーチンの変更 | ROM を書き換えないので、AdvanceMap の書き換え済みのときと同じ質問だけを出して何もしない |
| 再読み込み | 編集中の状態を読み直し、欄の入力を捨てる |

表の部分の名前は旧版の日本語訳です。改訂版 Japanese.ini の [WorldMapEditor] は英語のままなので、画面の文言は overrides.ini で旧版の日本語訳にしています（座標の見出しは、旧版の「縦座標」「横座標」が X と Y で逆なので入れ替えています）。

AdvanceMap の「保存」は、ZigzaguMap では編集中の状態への確定です。確定した操作はメインの履歴に積まれ、エディターの中でも Ctrl+Z / Ctrl+Y（入力欄の外）で取り消し・やり直し、Ctrl+S で出力できます。

### maps\regionmap.json

タウンマップの変更は `maps\regionmap.json` に書きます。ベース ROM と違う表だけを、項目ごとの読める形（base64 ではない）で書き、全部ベース ROM と同じに戻ったらファイルを消します。字下げは 2 空白、改行は CRLF です。

| キー | 中身 | ROM の表（BPRJ。括弧は表を指すポインタの位置） |
|---|---|---|
| `Format` | 1 | |
| `Layouts` | 変えた面・レイヤーだけ。`Page`（`kanto` / `sevii123` / `sevii45` / `sevii67`）、`Layer`（`map` = 基本レイヤー / `dungeon` = トップレイヤー）、`Rows`（15 行、各行は地名番号の 16 進 2 桁を空白区切りで 22 個） | u8[2][15][22] を 4 面: 0x3B9018・0x3B92AC・0x3B9540・0x3B97D4（0xC5378・0xC5380・0xC5388・0xC53B0、GetMapNo） |
| `Positions` | 地名 0x58〜0xC5 の全 110 件。`Id`（`"0x58"`）、`X`、`Y` | s16[n][2]: 0x3B89E8（0xC4F20、SetMapNo_and_Pos） |
| `Sizes` | 同じ 110 件。`Id`、`Width`、`Height` | u16[n][2]: 0x3B8D00（0xC4F1C） |
| `FlyDestinations` | 地名 0x58〜0xC3 の全 108 件。`Id`、`Bank`、`Map`、`HealLocation`（0 なら飛び先を使わずマップの真ん中へ） | u8[108][3]: 0x3B9A68（0xC648C、FlyDestination） |
| `HealLocations` | 飛び先 1〜20 の全件。`Index`、`Bank`、`Map`、`X`、`Y`、`Unknown`（末尾 2 バイト。AdvanceMap の「不明:」。無い古いファイルはベース ROM の値）。イベントタブのフライトポジション（AdvanceMap の FlugposHeader の表）と同じ表 | 8 バイト × 20: 0x3B5944（0xC0E94 の値 + 8、GetWarpPosByNo。0xC0E44 も同じ表を指す） |
| `MapVisitFlags` / `DungeonVisitFlags` | 地名 0x58〜0xC5 の全 110 件。`Id`、`Flag`（`"0x0890"`、無ければ null） | 表ではなく GetMapState（0x0C47C0）/ GetCaveState（0x0C4A5C）の switch 文。取り込むには表を引く命令への書き換えが要る |

名前は `regionmap.json` には書かず、ほかのマップ名の変更と同じく、その地名番号を使うマップの `maps\BB\MM.json` に入ります。地図の絵（タイル・パレット・タイルマップ）は読むだけで編集しません。

## 出力の仕様

出力（Ctrl+S）は、変更のあったものだけをプロジェクトフォルダへ書きます。自動では出力しません。ベース ROM には書き込みません。読み書きの処理は `packages/core/src/project/`（パスは `paths.ts`、全体の流れは `CfruProject.save`）にまとめ、`maps\` の形式が変わってもここだけを直せばよいようにしています。

| ファイル | いつ書くか | 形式 |
|---|---|---|
| `maps\BB\MM.json`（バンク・マップは 2 桁） | ベース ROM と内容が違い、既存のファイルとも違うマップ。ベース ROM と同じに戻ったら消す。マップ名を変えたときは、同じ地名番号の全マップ | ND の `scripts/map_project.py` と BochiBochiEditor 改造版（`SaveCfruProject`）と同じ形式。下の表 |
| `maps\project.json` | 何か書くときに無ければ作る | `{"Format":1,"BaseBankCounts":[…]}`（ベース ROM のバンクごとのマップ数。字下げなし） |
| `maps\tilesets\<primary\|secondary>_<ヘッダーの位置 6 桁>\tileset.json` と `tiles.png` | ブロックエディタなどで変えたタイルセット。ベース ROM と同じに戻ったら消す | Bochi と同じ。`tileset.json` は `Format`・`HeaderAddress`・`Secondary`・`New`・`Header`・`TileCount`・`BlockCount`・`BlockBytes`・`BehaviorBytes`・`Compressed`・`ImageSha256`・`Palettes`・`Blocks`・`Behaviors`、`tiles.png` はタイルのインデックス PNG |
| `assembly\overworld_scripts\HiddenItem.s` | 落とし物（人の ItemBalls）が変わったとき | `@ BBE-BEGIN <識別子>`〜`@ BBE-END <識別子>` の生成範囲だけを作り直す（手書き部分は残す。Bochi と同じ）。ラベルは `HiddenItem_BB_MM_<識別子>` |
| `maps\regionmap.json` | タウンマップ・フライトポジションを変えたとき。全部ベース ROM と同じに戻ったら消す | 「[maps\regionmap.json](#mapsregionmapjson)」 |

JSON はどれも Bochi（.NET の System.Text.Json）と同じ整形です。2 空白の字下げ、改行は CRLF、末尾に改行 1 つ、バイト列は base64、文字列は ASCII の表示文字以外と `"` `&` `'` `+` `<` `>` と逆引用符を `\uXXXX` にします（`\` は `\\`）。同じタイルセットを使うマップはどれも、次に開いたときから `maps\tilesets` の内容で読みます。

`maps\BB\MM.json` の項目は次のとおりです（Bochi の `CfruMapSource` と同じ並び）。

| キー | 中身 |
|---|---|
| `Format`・`Bank`・`Number` | 1、バンク番号、マップ番号 |
| `Header` | マップヘッダー 28 バイト（0x00〜0x0F のポインタは 0） |
| `Footer` | マップフッター 28 バイト（0x08〜0x17 のポインタは 0） |
| `Layout`・`Border` | 配置と境界ブロック（1 マス 2 バイト。ブロック番号と移動許可） |
| `PrimaryTileset`・`SecondaryTileset` | タイルセットのヘッダーのポインタ値 |
| `MapName` | 地名の文字列（ROM の文字コード） |
| `EventHeader`・`Persons`・`Warps`・`Traps`・`Signs` | イベントの見出し（一覧のポインタは 0）と 4 種類の一覧（落とし物の人のスクリプトのポインタは 0） |
| `ConnectionsHeader`・`Connections` | コネクションの見出しと一覧 |
| `MapScripts`・`MapScriptLists` | マップスクリプトと、種類 2・4 の条件表（`TableOffset`・`Data`。表を指すポインタは 0） |
| `ItemBalls` | 落とし物（`Id`・`PersonIndex`・`ItemId`・`Label`） |
| `Wild` | 野生（`Time` と `Areas`。各エリアは `Rate` と `Slots`） |

構造体どうしをつなぐポインタはすべて 0 にして書き、ビルド（`map_project.py`）が作り直します。新しいマップは既存のバンクの末尾か、最後のバンクの次の新しいバンクにだけ置けます（[新規マップ・作成したマップ](#新規マップ作成したマップmap--evt)）。`.map` / `.evt` は出力ではなく、AdvanceMap と同じ作業用のファイルです（[.map / .evt の形式](#map--evt-の形式)）。

## 構成

pnpm の workspace です。

- `packages/core`: ROM の解析・描画・操作コマンド・出力（TypeScript。Node とブラウザの両方で動き、画面なしでテストできる）
  - `rom/`・`binary/`: ROM とバイト列の読み書き、LZ77、base64、16 進の表記（`formatHex`）
  - `map/`・`event/`・`connection/`・`mapscript/`・`wild/`・`fly/`・`name/`・`sprite/`・`regionmap/`: ROM の各データの読み書き（`*Codec` が構造体、`*Reader`・`*Table` が表）
  - `model/`: 編集中のマップ（`MapDocument`）とベース ROM からの読み込み
  - `tileset/`・`render/`: タイルセットの編集用データと描画（`BlockRenderer`、`renderBlocks`、`MapRenderer`）
  - `command/`: 操作コマンド（`commands/` に種類ごと）、`CommandBus`（実行・アンドゥ・リドゥ・履歴）、`CommandRegistry`（JSON の記録からコマンドを作る）、`CommandGroup`（複数のコマンドを 1 回の操作にまとめる。記録から作り直せる）、`DocumentStore`（編集中の状態）
  - `project/`: `maps\` の読み書き（出力の形式は全部ここ）。`amfile/` は AdvanceMap の `.map` / `.evt`
- `apps/desktop`: デスクトップアプリ（Tauri 2 + Vite + 素の TypeScript）
  - `src/app/`: アプリ全体（`App`）、状態（`EditorState`）、ROM とプロジェクト（`ProjectSession`、`TauriProjectFs`）、マップ一覧（`MapCatalog`、`MapTreeModel`）、メニューの定義とアクション（`menuDefinition`、`Actions`、`Shortcuts`）、設定（`Settings`、`SettingPrompts`、`SystemSettings`）、ファイル（`FileDialogs`）、自動操作（`automation/`）
  - `src/ui/`: メニューバー、ツールバー、マップ一覧、タブ、ステータスバー、画面内のダイアログ（`Dialog`、`MessageBox`、`InputDialog`）、Canvas の共通処理（`canvas.ts`）、`map/`（マップ表示・パレット・重ね描き）、`tabs/`・`event/`・`header/`・`wild/`・`connection/`・`newmap/`（タブとダイアログ）、`form/`（16 進欄・スピン・コンボなどの入力部品と入力エラー）
  - `src/input/`: マウス操作（ブロック・移動許可の配置）
  - `src/windows/`: 別ウィンドウ。入口は `tool.html`（`src/tool.ts` → `startToolWindow.ts` の表でラベルから中身を選ぶ）。`block-editor/`・`palette-editor/`・`block-adjust/`（メインとの同期は `ToolWindowHost`・`ToolClient`・`protocol`）、`world-map/`（`WorldMapHost`・`WorldMapClient`）
  - `src/i18n/`: 文言、`src/styles/`: 部品ごとの CSS、`src/util/`: 小さな共通処理
  - `src-tauri/`: Rust 側。ファイルの入出力、ウィンドウの管理、自動操作の入口（HTTP）、画面の撮影だけを受け持つ
- `scripts/`: ビルド・文言の生成と確認・計測、`tests/`: 自動操作の確認と比較テスト、`tools/`: AdvanceMap を動かすハーネスなど

編集はすべて `packages/core` の操作コマンドを CommandBus で実行します（別ウィンドウもコマンドの JSON をメインへ送り、メインが実行する）。ダイアログの中の下書き（コネクション・マップスクリプトの表など）は写しを編集し、「保存」でコマンドにします。例外は、作成したマップを `.map` に保存したときの名前とパスの記録（保存の結果で、取り消す対象ではない）です。

別ウィンドウを足すとき（Phase2 のスクリプトエディタなど）は、`src/windows/startToolWindow.ts` の表と `src-tauri/capabilities/default.json` の `windows` に足します。

## 開発

Node.js 22 以降、pnpm、Rust（1.96 以降）、WebView2 が必要です。

```sh
pnpm install
pnpm typecheck   # 型チェック（使っていない変数・引数もエラーにする）
pnpm test        # 単体テスト
pnpm lint        # 型チェック + 文言の生成物の確認 + 文言の突き合わせ
scripts\build.cmd clippy   # Rust の lint（警告もエラーにする）
```

単体テスト（`packages/core/test`）には、出力の往復テストを含みます: マップを JSON にして読み直すと同じになること（`project.test.ts`。素の ROM では `realRomProject.test.ts` が全マップ）、全種類のコマンドを実行して出力し、開き直すと同じで、全部取り消すと JSON が消えること（`realRomEdit.test.ts`）、タイルセット・落とし物・新しいマップ・マップ名の出力（`editSave.test.ts`）。

画面の文言は、改訂版 `apps/desktop/src/i18n/source/Japanese.ini`（UTF-8）に、補正 `apps/desktop/src/i18n/source/overrides.ini`（同じ書式、UTF-8）を重ねたものです。`scripts/gen-i18n.mjs` が「Japanese.ini → overrides.ini」の順にキー（節と番号）ごとに値を重ね、文言のモジュール `apps/desktop/src/i18n/ini.generated.ts` を作ります。`ja*.ts` は生成物の値を `ini.節["番号"]` で引いています。

- Japanese.ini はユーザーが用意した改訂版の写しなので、書き換えずにそのまま置きます。英語のまま・文字化け・機械翻訳のような値は overrides.ini で直します。各項目の上のコメントに、出どころ（旧版 = AdvanceMap 1.92 の日本語化パックの同じ番号の値／新規の案）と改訂版の値を書きます。
- overrides.ini には Japanese.ini にある節・番号だけを書けます（無い番号を書くと生成でエラーになります）。
- 言い回しを変えたいときは、overrides.ini を直すか（改訂版を差し替えるときは Japanese.ini を差し替えて）、生成し直し、生成物と一緒にコミットします。

```sh
node scripts/gen-i18n.mjs          # ini.generated.ts を作り直す
node scripts/gen-i18n.mjs --check  # ini・overrides.ini と生成物が合っているか確かめる
node scripts/check-i18n.mjs        # 文言の突き合わせ（下記）
```

`scripts/check-i18n.mjs` は、改訂版 Japanese.ini に overrides.ini を重ねた値を基準に、ini に無い番号の参照と、ini の値と同じなのに ini から引かず直接書いた文字列と、画面で使っている文言に残った英語だけの値・文字化け・タブ文字を探します（画面で使ってよい英語「OK」「BGM:」などは、スクリプトの `ALLOWED_ENGLISH` に理由を付けて書きます）。`--inventory <inventory のフォルダ> --old-ini <AdvanceMap 1.92 の Japanese.ini>` を付けると、AdvanceMap の画面を調べた部品表の文字列（1.92 の表記）を旧版の ini で番号に直し、アプリに対応が無いものも探します。意図した違いと番号の読み替え（改訂版で並びが変わったツールバーなど）は、スクリプトの `INTENTIONAL`・`RENAMED` に理由を付けて書きます（`--verbose` で一覧）。

- 値の中の AdvanceMap 1.95 向けの注記（「(AM1.95未使用)」「(※AM1.95使用不可)」）は外します。外し方は `scripts/gen-i18n.mjs` の `stripNote` だけで決めています。行末の空白も外します。
- 注記を外して空になった番号と、ini に無い番号は生成物に入りません。`ja*.ts` がそれを引いていると型チェック（`pnpm typecheck`）で止まるので、旧版の文言を直接書くか、ini に足してください。
- ルビー・サファイア・エメラルドの挙動や季節など、ZigzaguMap に該当する機能の無い節は出しません（`EXCLUDED_SECTIONS`）。

ROM が要るテストは、環境変数 `ZIGZAGU_TEST_ROM` に素の BPRJ のパスを入れたときだけ実行されます。ROM はリポジトリに入れません。

```powershell
$env:ZIGZAGU_TEST_ROM = "C:\path\to\BPRJ.gba"; pnpm test
```

ND のベース ROM と NeoDark-CFRU のフォルダを `ZIGZAGU_TEST_ND_ROM` と `ZIGZAGU_TEST_ND_PROJECT` に入れると、`maps\` の JSON を読むテストも実行されます（フォルダには書き込みません）。

コアライブラリを Node から使うときは `pnpm --filter @zigzagumap/core build` で `dist` を作ります（`@zigzagumap/core` と `@zigzagumap/core/node`）。マップを PNG に書いて確かめるには次のようにします。

```sh
pnpm --filter @zigzagumap/core dump-map -- <rom> 3 0 out.png --events
pnpm --filter @zigzagumap/core dump-map -- <rom> 3 0 out.png --project <CFRU-JP のフォルダ>
```

全マップの描画を AdvanceMap の「マップ画像の保存」と画素で比べるには、`tools/am-harness/export_map_images.py <フォルダ>` で AdvanceMap に全マップの画像（`m<バンク>_<マップ>.DIB`）を書かせてから、次を実行します（色は 5 ビットに落として比べ、違うマップとマスを出します）。

```sh
pnpm --filter @zigzagumap/core compare-map-images -- <rom> <フォルダ> [--json out.json]
```

アプリの起動とビルド:

```sh
cd apps/desktop
pnpm tauri dev     # 開発用に起動（自動操作の入口がポート 17890 で有効になる）
```

リリース用の exe は `scripts\build.cmd` で作ります（`apps/desktop/src-tauri/target/release/zigzagumap.exe`）。Visual Studio Build Tools の `vcvars64.bat` を読んでから `pnpm tauri build` を実行するので、cmd・PowerShell・Git Bash のどれからでも動きます（Git Bash だけで `pnpm tauri build` を実行すると、Git 付属の `link.exe` が先に見つかって失敗します）。

```sh
scripts\build.cmd          # リリースビルド
scripts\build.cmd debug    # デバッグビルド
scripts\build.cmd check    # cargo check だけ
scripts\build.cmd clippy   # cargo clippy（Rust の lint）
```

出力先を変えたいときは、環境変数 `CARGO_TARGET_DIR` を設定してから実行します（exe は `<CARGO_TARGET_DIR>\release\zigzagumap.exe` にできます）。

自動操作の入口（テスト用の HTTP の命令）は [docs/automation.md](docs/automation.md)、AdvanceMap との比較テストの回し方は [docs/compare-test.md](docs/compare-test.md) にあります。

## 性能

| 項目 | 目標 | 測り方 |
|---|---|---|
| 起動からマップ表示まで | 1 秒以内 | `scripts/measure-startup.mjs` |
| マップの切り替え | 100ms 以内 | `scripts/measure-startup.mjs`（`scripts\measure-memory.ps1` も出す） |
| 待機時メモリ（WebView2 込み） | 150MB 以下 | `scripts\measure-memory.ps1` の専用ワーキングセットの合計 |
| 配布物 | 10MB 以下 | `zigzagumap.exe` の大きさ |

Phase1 の終わり（2026-11-14、素の BPRJ）に測った値: 起動からマップ表示まで 中央値 750ms（5 回の最大 767ms）、マップの切り替え 中央値 27ms（50 回の最大 58ms）、メモリ（専用ワーキングセットの合計）は起動直後 75MB・ROM を開いた後 105MB・マップを 10 枚切り替えた後 114MB・ブロックエディタを開いた後 146MB・閉じた後 116MB、exe 3.6MB です。

### 起動とマップ切り替えの時間

`scripts/measure-startup.mjs` で測ります。毎回、一時フォルダの `--profile` に前回のマップ（3.0）を覚えた設定を置き、`zigzagumap.exe --automation <ポート> --profile <一時フォルダ> <ROM>` で起動して（画面外・非アクティブ。通常の設定には触れない）、exe を起動してからマップを描き終えるまで（画面側の記録 `mapShown`）を測ります。続けてマップを 10 枚切り替え、自動操作の `selectMap` の返事の `switchMs`（読み込み・描画・一覧の更新まで）を集めます。

```sh
node scripts/measure-startup.mjs --exe <zigzagumap.exe> --rom <素の BPRJ> [--port 17996] [--runs 5]
```

### メモリ

待機時メモリ（目標 150MB 以下、WebView2 込み）は `scripts\measure-memory.ps1` で測ります。exe を `--automation` と一時フォルダの `--profile` で起動し（画面外・非アクティブ。通常の設定には触れない）、起動直後／ROM を開いた後（3.0）／マップを 10 枚切り替えた後／ブロックエディタを開いた後／閉じた後の 5 場面で、それぞれ 10 秒待ってから測ります。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\measure-memory.ps1 -Exe <zigzagumap.exe> -Rom <素の BPRJ> [-Port 17995] [-Out result.json]
```

- exe とその子孫（WebView2 のブラウザ・レンダラー・GPU・ユーティリティ・crashpad）を、種類ごとに「専用ワーキングセット」「プライベート（コミット）」「ワーキングセット」で出します。目標は **専用ワーキングセットの合計** で判定します（タスクマネージャーの「メモリ」の列と同じ値。ワーキングセットは共有ページを二重に数えるので合計に向かない）。メインの JavaScript のヒープ（`state` の `jsHeap`）、入口が応答するまでの時間、マップ切り替えの時間も出します。
- `-Baseline -Exe <webview-baseline.exe> -BrowserArgs "<引数>"` で、WebView2 の空のウィンドウだけの値（下限）を同じ方法で測ります（`tools\webview-baseline` を `CARGO_TARGET_DIR` を設定してから `build.cmd` でビルド）。
- `-BrowserArgs` を付けると、WebView2 に引数を足して試せます（環境変数 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`）。

WebView2 には、計測で効果のあった引数だけを付けています（`src-tauri/src/lib.rs` の `BROWSER_ARGS`）: `--disable-gpu`（GPU プロセスの約 50MB が無くなる。Canvas 2D と合成はソフトウェアで行い、描画とマップ切り替えの速さは変わらない）、`--enable-features=NetworkServiceInProcess2`（ネットワークのプロセスをまとめる。約 5MB）。

### 配布物

配布物は `zigzagumap.exe` 1 つです（画面のコードと文言は exe に入っています。WebView2 は Windows のものを使う）。大きさは `scripts\build.cmd` で作った exe のファイルの大きさで判定します。
