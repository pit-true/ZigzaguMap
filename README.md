# ZigzaguMap

CFRU-JP 用のマップエディタです。AdvanceMap 1.92 日本語版をもとにした画面と操作で、ファイアレッド日本語版（BPRJ）のマップを編集し、`maps\` の JSON として書き出します。ベース ROM には書き込みません。

- 対象: 素の BPRJ と、CFRU 方式へ移った BPRJ（NeoDark のベース ROM）。開くのは「ベース ROM」と「CFRU-JP のフォルダ」で、ベース ROM は読むだけです。素の ROM だけでも閲覧と編集ができ、出力のときに出力先のフォルダを選びます。
- Windows 用です（WebView2 が要ります）。インストールは不要で、exe 1 つで動きます。
- Phase1 では AdvanceMap 1.92 と同じ動きを目指しました。そのあとユーザーの要望で変えたところ（表示メニュー、場所の設定のかんたん表示など）は「[AdvanceMap と違う点](#advancemap-と違う点)」にまとめています。
- 仕様はこの README にまとめています。長い節は `docs/` に分けました: [自動操作の入口](docs/automation.md)、[比較テスト](docs/compare-test.md)。

## 使い方

- **ROM を開く**: ファイル > ROMを開く（Ctrl+O）、ツールバーの左端のボタン、`.gba` のドラッグ＆ドロップのどれかで ROM を選ぶと、続けて「ROM と組にする CFRU-JP のフォルダ」を選ぶダイアログが出ます。フォルダを選ぶと組で開き、キャンセルすると ROM だけで開きます（素の ROM だけでも閲覧と編集ができます）。ROM でないファイルなら、フォルダを聞く前にエラーを出します。最近開いたものから開くときと起動引数の ROM は、組のフォルダが記録されていればそれを使い、ダイアログは出しません（最近開いたもので組のフォルダが無いものは、ダイアログを出します）。
- **ROM の再読み込み**: ファイル > ROMの再読み込み（F5）。未出力の変更があれば確かめてから、ROM（とプロジェクト）を読み直します。AdvanceMap と同じく、読み直したあとはマップを開きません（「最後に選択したものを覚える」がオンでも）。
- **プロジェクトを開く**: ファイル > CFRU-JPのフォルダを開く で CFRU-JP のフォルダを選びます。ベース ROM は、開いている ROM か、以前そのフォルダと組で開いた ROM を使い、どちらも無ければ選ぶよう求めます。フォルダのドラッグ＆ドロップでも開けます。`maps\BB\MM.json` があるマップはそちらを読みます。
- **最近開いたもの**: ファイルメニューの下に出ます（ROM とフォルダの組で覚えます）。個人設定は `%APPDATA%\io.github.pit-true.zigzagumap\settings.json` に保存します。
- 起動引数で開くこともできます: `zigzagumap.exe [--project <フォルダ>] <ROM>`。「最後に選択したものを覚える」がオンなら、前回のマップとタブを開きます。
- `--profile <フォルダ>` を付けると、個人設定（`settings.json`）と WebView2 のデータ（`EBWebView`）をそのフォルダに置きます（無ければ作ります）。通常の個人設定には触れません。
- **マップを開く**: 左の一覧の項目をダブルクリックか Enter（AdvanceMap と同じく、選ぶだけでは開きません）。ツール > マップを指定して開く（Ctrl+M）、以前開いたマップを開く（Alt+BkSp）も使えます。
- **元に戻す・やり直す**: Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z も可）。AdvanceMap の「オブジェクトの表示」の Ctrl+Z は、アンドゥに使うため外しています。
- **出力**: ファイル > 出力（Ctrl+S）。素の ROM だけを開いているときは、最初に出力先のフォルダを選びます。ファイル > 出力先を指定して出力 で別のフォルダへ書くこともできます。ファイル > バックアップの作成 も「出力先を指定して出力」と同じです。
- **ROM でないファイル**を開くと、AdvanceMap と同じ「AdvanceMapError(12): Unknown Rom Type! …」を出し、開いていたものはそのまま残します。
- **画像の保存**: ツール > マップ画像の保存／マップ&イベント画像の保存／パレット画像の保存。AdvanceMap と同じ 24 ビットの DIB（BMP と同じ形式）で書きます。マップ画像はブロックだけ（境界ブロックとイベントは含まない）、マップ&イベント画像はイベントタブと同じ印（フライトポジションの F と、カーソルの表示がオンなら選択中のイベントの赤い枠を含む。オブジェクトの表示がオンなら OW 画像）を重ねたもの、パレット画像はブロックパレット全体（今の横幅、等倍）です。拡張子を付けなければ `.DIB` を足します。AdvanceMap はイベントタブ以外でマップ&イベント画像を保存すると 0 バイトのファイルになりますが、ZigzaguMap はどのタブでもイベントを重ねた画像を書きます。
- **ヘルプ**: Read me（この README を、見出し・箇条書き・表・コード・リンクとして描いて出す。`docs/` へのリンクもヘルプの中で開き、「戻る」で戻る。http・https のリンクは既定のブラウザで開く。本文の HTML はそのまま文字で出すので、スクリプトは動かない）、ショートカット一覧（「[ショートカット](#ショートカット)」と同じ表）、ZigzaguMapについて（F1、ツールバーの「?」。アプリ名・バージョン・GitHub のリポジトリへのリンクだけ）、エンドユーザー規約（F2。ZigzaguMap のライセンス）。

### マップタブ（マップの設定）

| 操作 | 動作 |
|---|---|
| 左クリック | 選択中のブロックを置く（移動許可は変えない）。スタンプなら押したマスを左上にして全体を置く |
| 左ドラッグ | 通ったマスに置く（1 回の操作にまとまり、1 回のアンドゥで戻る）。スタンプはドラッグしても 1 回だけ置く |
| 右クリック／右ドラッグ | 離したマスのブロックを拾う（パレットが追従してスクロール） |
| Ctrl＋右ドラッグ | 矩形を複数ブロック（スタンプ）として選ぶ。パレット上でも同じ |
| パレットの左・右クリック | ブロックを選ぶ |
| 境界ブロックの左クリック／右クリック | 置く／拾う |

Ctrl＋右ドラッグ（Ctrl＋右クリック）でスタンプを選ぶと、選んだ範囲を等倍で出す小さな窓「Grosser Block」が開きます（× で閉じる。題名の帯をつかんで動かせます）。

表示 > グリッドの表示（Ctrl+G）、表示 > 表示サイズ で 2 倍表示、表示 > ブロックパレットの横幅（Ctrl+P）でパレットの 1 行の数を変えられます。

### 移動エリアタブ（移動エリアの設定）

移動許可の値を色つきで重ね、値を 16 進で描きます。右のパレットで値を選び、左クリック・左ドラッグで書き、右クリックで拾います。表示 > 移動エリアの設定の透明度 で小さな窓を開き、スライダーで変えます（動かすとすぐ描き直し、離したときに個人設定へ保存。値は 0〜100% で数字も出す）。値の意味は AdvanceMap と同じく「マップ側の重み」です（既定 30% で、色 70%・マップ 30%。左端が色だけ、右端がマップだけ）。小窓を開いたままほかの操作もでき、「閉じる」か × で閉じます。

### イベントタブ（イベントの設定）

マップのイベントを文字の箱（P=人、橙の S=看板、W=ワープ、緑の S=スクリプト、F=フライトポジション。AdvanceMap と同じく 50% の不透明度でマップに重ねる）で描き、右のパネルで選んで編集します。どの編集も Ctrl+Z / Ctrl+Y で戻せます。

| 操作 | 動作 |
|---|---|
| 箱をクリック（左右どちらのボタンでも） | そのイベントを選ぶ。同じマスに重なっていれば、フライトポジション > 看板 > スクリプト > ワープ > 人 の順に上のものを選ぶ |
| 箱をドラッグ | イベントを動かす（1 回のドラッグが 1 回のアンドゥ）。マップの外へも動かせる |
| 箱をダブルクリック | ワープは「マップの移動」。看板（スクリプトの看板だけ）・スクリプト・人は、プロジェクトフォルダを開いていればスクリプトエディタでそのスクリプトを開く（「スクリプトエディタ（別ウィンドウ）」の節）。素の ROM だけのときは何もしない |
| 種別コンボ・イベント番号 | 選ぶイベントを変える。種別はマップを切り替えても保ち、番号は 0 に戻る |
| 選択カーソルの表示 | 選択中のイベントの赤い枠を出す・消す |
| イベントの削除 | 選択中のイベントを消す（後ろが前に詰まる） |
| イベント数の設定: | 人・看板・ワープ・スクリプトの数を変えて「イベント数の変更」。増やした分は値が全部 0 のイベントを末尾に足し、減らした分は末尾から消す。イベントの無いマップにも作れる |
| マップの移動（ワープ） | 行き先のマップを開き、行き先のワープを選ぶ。無いマップなら「指定したマップは存在しません！」 |

- 欄の値は入力のたびに反映します（確定ボタンはありません）。同じ欄に続けて入力した分は、1 回のアンドゥでまとめて戻ります。
- 16 進の欄は AdvanceMap と同じく `$` を前に付けて読みます。空欄は 0、あふれた桁は切り捨てます（4 桁の欄の 10000 は 0）。読めない文字を入れると `'$ZZ' is not a valid integer value.` を出し、値は変えません。10 進のスピンは範囲の端に丸めます（300 は 255）。
- スクリプトのオフセットは下位 3 バイトだけを書き、上位 1 バイトは元のままです。
- 看板のイベントタイプが 05〜08 のときは、オフセットの代わりにアイテム ID・隠し ID・個数を出します。
- フライトポジションの表は、タウンマップの飛び先（回復地点）と同じ ROM の表です。編集は `maps\regionmap.json` の `HealLocations` に出力します（ワールドマップエディターを開いていなくても書きます）。ワールドマップエディターで飛び先を変えても、同じ値になります。
- 人の落とし物（ItemBalls）は画面では変えません。ほかの欄を編集しても、落とし物は保ったまま出力します。
- マップの外にイベントがあると、ステータスバーの右欄に「ノート:イベントがマップの外に配置されています」を出します。どのタブでも、ツールバーの下に同じ文言の帯と「マップの内側に戻す」ボタンを出します（マップを開いたとき、イベントを動かしたとき、マップを縮めたとき、元に戻したときに調べ直す）。ボタンを押すと、外にある全イベント（人・看板・ワープ・スクリプトとフライトポジション）を、いちばん近いマップの内側のマスへ寄せます（右・下へはみ出したものは端のマス、16 ビットで負に回った座標（0x8000 以上）は 0）。1 回の操作なので、1 回の Ctrl+Z で全部戻ります。外のイベントが無くなると帯は消えます。
- 「スクリプトを開く」ボタンは隠しています（外部のスクリプトエディタとの連携は外しました。ボタンは今はポインタしか渡せないので、イベントタブのスクリプト欄（#200）で出し方を決めます）。ダブルクリックからは内蔵のスクリプトエディタを開けます。
- 表示 > オブジェクトの表示（ツールバーの主人公のボタン）をオンにすると、AdvanceMap と同じく人を ROM の OW 画像（下向きの 1 コマ目）で描き、人以外の箱は描きません。

AdvanceMap と違う点は「[AdvanceMap と違う点](#advancemap-と違う点)」にまとめています。

### 「保存」ボタンの読み替え

AdvanceMap で ROM へすぐ書き込む「保存」ボタン類（マップ名の変更を保存、マップスクリプトの変更、タイルセットの変更、保存してマップの再読み込み、コネクションの保存、設定の保存など）は、同じ場所に置き、押すと**編集中の状態へ反映**します。ROM には書かず、ファイル > 出力（Ctrl+S）でまとめて `maps\` へ書き出します。反映はどれも 1 回の操作として Ctrl+Z / Ctrl+Y で戻せます（1 回押して複数の項目が変わるときも 1 回のアンドゥで戻ります）。

### 場所の設定タブ

タブの上のラジオボタンで「かんたん（CFRU）」（初期）と「くわしく（従来）」を切り替えます（個人設定の `headerView` に残ります）。

#### かんたん（CFRU）

CFRU の開発で実際に変える項目だけを、まとまりごとに並べます。ROM のアドレス（ヘッダー・フッターの位置やポインタ）は出しません（CFRU ではビルドが決めるため）。選ぶ・チェックする欄はすぐ反映し、数を入れる欄はボタンで反映します。どれも 1 回の操作として Ctrl+Z / Ctrl+Y で戻せます。項目は ND・Chronos の `map_project.py` が出力から読む項目（ヘッダー、レイアウト、イベント、コネクション、マップスクリプト、マップ名）を基準に選びました。

| まとまり | 欄 | 動作 |
|---|---|---|
| マップ名 | 地名 | このマップの地名番号（名前表の 0x58〜。選ぶとすぐ反映） |
| | 名前の書き換え | このマップの地名の名前を書き換える（同じ地名のマップすべての名前が変わる） |
| | マップに入ったときに名前を表示する | ヘッダー 0x19 の名前表示 |
| 音楽と見た目 | 音楽（と 16 進の番号）、天候、マップのタイプ、戦闘背景、明るさ（洞窟） | 選ぶ・入れるとすぐ反映 |
| できること | 自転車に乗れる、走れる（ランニングシューズ）、あなぬけのひも・テレポートで外へ出られる | ヘッダー 0x18 と 0x19 のビット |
| タイルセット | 主・副 | AdvanceMap のタイルセット番号を選び、「タイルセットを変更」で反映（表に無いタイルセットはそのまま出す） |
| 大きさ | マップ（横×高さ） | 「大きさを変更」で、左上を基準に伸び縮みする |
| | 境界ブロック（横×高さ） | 「大きさを変更」で、左上を基準に伸び縮みする（足りないマスは 0） |
| マップスクリプト | | 「くわしく」の通常表示と同じ部品（下の表） |
| マップコネクション | | つながっているマップの一覧（方向と相手）と、「マップコネクションを開く」 |

#### くわしく（従来）

AdvanceMap と同じ画面です。タブの上の「高度なヘッダーを表示」（表示メニューと Ctrl+H でも同じ。初期はオン）で、通常表示と高度な表示を切り替えます（個人設定に残ります）。

通常表示:

| 枠 | 動作 |
|---|---|
| 名前: | 左のコンボは名前表（地名番号 0x58〜0xC4）の一覧。選ぶと右の欄に名前が入ります（このマップの地名番号は変えません）。「マップ名の変更を保存」は、コンボで選んでいる名前表の項目を書き換えます（同じ地名番号の全マップの名前が変わり、出力ではそれらの JSON を全部書きます）。文字はプロジェクトの `charmap.tbl`（無ければ同梱の表）で変換します。「新しい名前の作成」は AdvanceMap と同じく無効です |
| マップ名の表示/タイプ | ヘッダーの 0x19（名前表示・ダッシュ・穴抜け）。選ぶとすぐ反映します |
| マップオプション: | BGM（コンボと 16 進 4 桁の「No.」が連動。一覧に無い値ではコンボが空）、フラッシュ、天候、タイプ、戦闘背景の強制上書き。選ぶ・入れるとすぐ反映します。選択肢は改訂版 Japanese.ini と `Musik_jap.ini` の [Musik_BPR] のとおりで、表に無い番号は「0n ???」 |
| マップスクリプト | スクリプトNo. の上下で切り替え、種類・オフセットを変えます。種類 02・04（条件表）では、表の先頭の行を「イベント変数・イベント変数の値・スクリプトオフセット2」に出します（オフセット欄は無効。読み込んだときから条件表のものは表の位置、種類を条件表に変えたものは `$000000`。「00 スクリプト未設定」でもオフセット欄は無効）。追加・削除（確認なし）・欄の変更はメモリ上の表に対して行い、「マップスクリプトの変更」で反映します。種類「00 スクリプト未設定」のまま保存するとエラーです（一覧の終端と同じ値で保存できないため） |
| 使用するタイルセット: | 番号（AdvanceMap のタイルセット番号 0〜67）を入れて「タイルセットの変更」。確認なしで差し替えてマップを描き直します（合わないタイルセットでは絵が崩れるのも同じ） |
| マップのサイズ: | 横幅・高さを入れて「マップサイズの変更」。左上を基準に伸縮します。0 と空欄は無視します |

高度な表示:

| 枠 | 動作 |
|---|---|
| マップヘッダーの設定: | マップバンクテーブル、バンク番号、マップ番号、バンクの一覧、マップヘッダーの位置（すべて読み取り専用） |
| マップヘッダーデータ: | マップヘッダー 28 バイトの 16 進と、フッター・イベント・マップスクリプト・コネクションの位置。16 進を書き換えると「保存してマップの再読み込み」が押せ、0x10 以降の設定を反映します |
| マップフッターデータ: | フッター 28 バイトの 16 進と、横幅・高さ・タイルセット番号・境界ブロックの大きさの欄が連動します（タイルセット番号を変えるとタイルセットのオフセットも変わります）。横幅・高さを変えて保存すると、AdvanceMap と同じく配置のデータはそのままで新しい横幅で折り返して読みます（足りないマスは 0。「マップサイズの変更」の左上基準の伸縮とは違う） |
| 境界データ: | 境界のブロックの値（16 進）。変えると画像がすぐ変わります。「マップフッターデータ」の保存で一緒に反映します |
| タイルセットデータ: | 主・副タイルセットのヘッダー 24 バイトの 16 進。保存で圧縮フラグ・副フラグ・アニメーション関数などを反映します |

**オフセット欄の表示**: ZigzaguMap は ROM へ書かないので、ROM 上の位置が意味を持つのは「ベース ROM から読み、`maps\` の JSON が無いマップ」だけです。そのマップではベース ROM 上の位置を出します。JSON から読んだマップや新しく作ったマップでは、ヘッダー・フッターとその先のデータの位置を、AdvanceMap が未設定の位置に使う書式 `$000000` で出します（16 進欄のポインタ部分も 0）。バンク表とバンクの一覧は、ベース ROM にあるバンクなら出します。ポインタと位置は表示だけで、保存しても読み捨てます（出力時に作り直すため）。

### マップコネクション

ツール > マップコネクション（Ctrl+A）かツールバーの矢印アイコンで開きます（常に手前に出るダイアログで、メインの画面も操作できます）。

- コネクションNo. の上下で切り替え、方向（無し・下・上・左・右・ダイビング・浮上）、調整、バンク番号、マップ番号、不明（16 進）を変えます。
- 「追加」は方向 無し・調整 0・バンク 0・マップ 0 を末尾に足します（確認なし）。「削除」は「コネクションNo.nを削除しますか？」と聞きます。ここまではメモリ上の表に対して行い、「保存」で反映します。保存せずに閉じる・別のマップへ移ると変更は捨てます。
- 左の矢印ボタンは、その方向の 1〜3 番目のコネクションがあるときだけ押せます（2・3 番目の帯はあるときだけ出ます）。押すと相手のマップを開き、ダイアログも開いたマップのコネクションに切り替わります。
- 範囲は確かめず、書くときに切り詰めます（バンク・マップは 1 バイト、不明は 2 バイト。AdvanceMap と同じく -3 や 300 も入ります）。

### 野生ポケモンの設定タブ

- タイプ（草むら・水上・岩砕き・釣り）を選ぶと、そのタイプのエンカウント率と各枠（草むら 12、水上 5、岩砕き 5、釣り 10）を出します。データの無いタイプでは部品を隠し、「設定の保存」は押せません。タイプを切り替えると保存していない編集は捨てます。
- エンカウント率の欄・トラックバー・百分率（値÷255 の切り捨て）が連動します。0〜255 に丸め（300 → 255、-5 → 0）、`0x10` や `$10` の 16 進も受け付けます。トラックバーは矢印キーで 1、PageUp / PageDown で 25、Home / End で両端へ動きます。
- 最小・最大 Lv は検査せず、反映するときに 1 バイトに切り詰めます（300 → 44）。空欄は元の値のままです。種族はコンボから選びます（0 番は「選択してください」）。
- 「設定の保存」で、表示中のタイプのエンカウント率と各枠を反映します。
- 野生データの無いマップでは、野生データが無いという文言（[Allgemein] 941）と「野生ポケモンの追加」を出します。「野生ポケモンの追加」「タイプの追加」のダイアログで使うタイプにチェックを入れて OK を押すと、そのタイプを初期値（確率 0、全枠 Lv 1/1、「選択してください」）で作ります。何もチェックせずに OK を押すと「野生ポケモン設定の追加/変更を中止しました！」と出します。チェックを外したタイプのデータは消えます。
- 種族名は ROM の種族名表から読みます。読めない間は `No.番号` で出します。

### 入力エラー

数値欄に整数として読めない文字を入れると、AdvanceMap と同じ「'abc' is not a valid integer value.」（`$` を付けて読む 16 進欄は `'$zzzz' is …`）を出し、値は変えません。確かめるタイミングは AdvanceMap の欄ごとの動作に合わせ、どのタブも共通の部品（`ui/form/integerInput.ts`）で決めています。

| タイミング | 欄 |
|---|---|
| 1 文字入れるたび | イベントタブの全欄、音楽No.、マップスクリプトのオフセット・フラグ・フラグの値・フラグのオフセット、高度な表示の横幅・高さ・タイルセット番号、出現確率と最小・最大 Lv、コネクションの調整・バンク・マップ・不明 |
| ボタンを押したとき | 使用するタイルセット、マップの大きさ（通常表示） |

オフセットの欄（`$16F884` のように `$` が文字に入っている欄）は、AdvanceMap と同じく文字のまま読みます（`zz` なら `'zz' is …`）。10 進の欄の空欄は何もしません。ほかのエラーの文言は改訂版 Japanese.ini（ini に無いものは AdvanceMap）に合わせています（タイルセット番号が表に無い: 「AdvanceMapError(1): Try to read at pos 0! …」、大きすぎるマップ: 「マップの横幅200の時のマップの高さの最大サイズは33です」、フッターの 16 進が不正: 「マップフッターに無効なポインタが設定されています！」）。

### 新規マップ・作成したマップ（.map / .evt）

ファイル > マップ の 4 項目と、ツールバーの「新規マップの作成」「マップの追加/挿入」です。

- **新規マップの作成**: 「新規マップの作成」ダイアログに、ファイル名・マップの横幅・マップの高さ・タイルセット1/2（AdvanceMap のタイルセット番号 0〜67）を入れて「作成」。初期値は今のマップの名前（一覧の項目の文字列）と大きさで、タイルセットは未選択です。作成したマップは全マス 0x3001（ブロック 1・移動許可 0x0C）、境界ブロックは 2×2 の 0、イベント・接続・マップスクリプトは無し、ヘッダー（音楽など）は作成時に開いていたマップのものです。
- 入力は「作成」を押したときに確かめます（AdvanceMap と同じく 1 文字ごとには確かめません）。順番も AdvanceMap と同じで、横幅・高さが整数でなければ「'abc' is not a valid integer value.」、名前が空・横幅や高さが空か 0 以下・タイルセットが未選択なら「全て記入してください」、大きすぎれば「マップの横幅200の時のマップの高さの最大サイズは33です」です。エラーのときはダイアログを閉じません。
- 作成したマップと `.map` から開いたマップは**作業用のマップ**です。プロジェクトのバンクには入らず、出力（Ctrl+S）でも書きません。編集はほかのマップと同じようにでき、Ctrl+Z / Ctrl+Y も使えます（作成・読み込み自体も取り消せます）。プロジェクトへ入れるには「マップの追加/挿入」を使います。AdvanceMap と同じく、作成しても題名・一覧の選択・ステータスバーは変えません（`.map` から開いたときだけ、題名を「ZigzaguMap - <拡張子を除いたパス>」にします）。
- **作成したマップに名前を付けて保存**: 今のマップ（作業用のマップでも、プロジェクトのマップでも）を `.map` と `.evt` に書きます。既定のファイル名は「<今のマップの名前>.map」、初期フォルダは前回のフォルダ（最初は ROM のフォルダ）です。保存したファイルはマップ一覧の「マップファイル」の下に名前で並びます（AdvanceMap の `Ini\MapDateien.ini` と同じく、同じ名前なら上書き。個人設定の `mapFiles` に残ります）。
- **作成したマップを開く**: `.map` を選ぶと、同じ名前の `.evt` も読みます（無ければイベント無し）。「マップファイル」の項目をダブルクリック・Enter しても開けます。項目のファイルが無いときは「作成したマップのファイル"map\*.evt と map\*.map"が存在しません！」を出し、その項目を一覧から外します。
- **マップの追加/挿入**: 今のマップをプロジェクトへ写します。AdvanceMap は押すとすぐ ROM へ書きますが、ZigzaguMap は編集中のプロジェクトへ反映し、出力で `maps\BB\MM.json` と（無ければ）`maps\project.json` を書きます。どれも 1 回の操作として Ctrl+Z で取り消せます。成功すると「現在表示中のマップデータをコピーし、(B.M)にマップデータをインポートしました！」を出し、ダイアログを閉じてそのマップを開きます。× で閉じると「マップは挿入されていません！」です（ダイアログの題名は「マップの挿入」）。
  - 差し替え（既存のマップを差し替える）: 選んだ既存のマップの中身（ヘッダー、配置、境界ブロック、タイルセット、イベント、接続、マップスクリプト）を今のマップで差し替えます。番号と野生はそのままで、落とし物は消えます。
  - 追加/挿入（新規バンクの追加/既存バンクの拡張）: 選んだバンクの末尾に今のマップを写して加えます。「新規バンクの追加」を選ぶと、新しいバンクのマップ 0 に加えます。マップの追加数の欄は 1 以上ならいくつでも 1 つだけ加え、0 以下なら何もしません（AdvanceMap と同じく何も出しません）。追加数の欄は 1 文字入れるたびに整数か確かめます（AdvanceMap と同じ）。
  - 挿入（既存のバンクに挿入する）: ZigzaguMap はダミーマップ（予約した空きの番号）を作らないので、残量はいつも 0 で押せません。
- **マップバンクヘッダーの管理**（ツール > ダミーデータへ移す/ヘッダー管理、マップの追加/挿入の「マップバンクヘッダーの表示」）: 全バンクの番号、マップ一覧の位置（ベース ROM に無いバンクは `$000000`）、マップ数（「格納マップ数:」。追加したマップを含む）、ダミーマップの残量（いつも 0）を出します。「新バンク番号」で足した行は、「変更の適用」で新しいバンクとして作ります。ビルド側で空のバンクは作れないので、各バンクにマップ 0 を 1 つ置きます（中身は新規マップの作成と同じ初期値で、大きさ・タイルセット・ヘッダーは今のマップのもの）。ダミーマップの残量と「ダミーマップバンクの追加数」「ダミーマップの追加数」を 0 以外にして適用すると「ZigzaguMap は ROM へ書き込まないため、この機能は不要です」と案内します（その値は使いません）。「キャンセル」と × は何もしません。
- **マップタブの「新規マップ作成」「マップバンクの作成」**: AdvanceMap では一覧の「保留したダミーマップデータ」「保留したダミーバンク番号」を開いたときにマップの代わりに出るボタンです。ZigzaguMap にはダミーマップ・ダミーバンクが無いので、いつも隠れています（押せば、新規マップ作成は「新規マップの作成」、マップバンクの作成は不要の案内）。

置ける番号の制約: 新しいマップは**既存のバンクの末尾**か、**最後のバンクの次の新しいバンクのマップ 0**にだけ加えられます（ビルド側の `map_project.py` の制約）。操作列（`createMap` / `insertMap`）で途中の番号を指定したときは「バンク B に新しいマップを加えられるのは末尾（マップ番号 N）だけです。ZigzaguMap ではマップの配置をビルドが行うため、途中の番号へは挿入できません。」、バンクを飛ばしたときは「新しいバンクは N 番にだけ作れます（バンク番号を飛ばすことはできません）。」を出します。

#### .map / .evt の形式

AdvanceMap 1.92 に実際に書かせて確かめた形式です。ZigzaguMap はこの形で書き、AdvanceMap で開けることを確かめています。

| ファイル | 中身（数値はリトルエンディアン） |
|---|---|
| `.map` | u32 横幅、u32 高さ、u32 タイルセット１の番号、u32 タイルセット２の番号、u8 境界の横幅、u8 境界の高さ、2 バイト（AdvanceMap はいつも `C0 00` を書く。読むときは見ない）、境界ブロック（u16 × 境界の横幅 × 高さ）、配置（u16 × 横幅 × 高さ。1 マスはブロック番号と移動許可） |
| `.map`（古い版） | 境界ブロック 2×2（8 バイト）、配置、末尾に u32 横幅・高さ・タイルセット１・タイルセット２。AdvanceMap 同梱の `Maps\*.map` がこの形。ZigzaguMap は読めるが、書くのは上の形 |
| `.evt` | 人（24 バイト）、ワープ（8 バイト）、スクリプト（16 バイト）、看板（12 バイト）の一覧を ROM と同じ並びで続け、末尾に件数 4 バイト（人・ワープ・スクリプト・看板） |

タイルセットはポインタではなく AdvanceMap のタイルセット番号（ベース ROM のタイルセット表の何番目か）で書きます。表に無いタイルセット（`maps\tilesets` で新しく作ったものなど）を使うマップは `.map` に書けず、エラーになります。ヘッダー・接続・マップスクリプト・野生はどちらのファイルにも入りません。

### ブロックエディタ（ツール > ブロックエディタ、Ctrl+B）

マップを開いているときに、別ウィンドウで開きます（題名は「ブロックエディタ     タイルセット1: N  タイルセット2: M」）。左から、ブロック一覧（主の 640 個のあとに副）、ブロックの編集面とタイル一覧（1024 タイル。主 0x000〜、副 0x280〜）、マップデータです。

| 操作 | 動作 |
|---|---|
| ブロック一覧の左・右クリック | ブロックを選ぶ。8 マス（左が下層、右が上層）と属性 4 バイト、ブロック（16 進 3 桁）、オフセット（ベース ROM でのブロック定義の位置）を出す |
| タイル一覧の左・右クリック、ドラッグ | タイルを選ぶ（離した位置）。タイル欄とプレビューに出す |
| 8 マスの左クリック | 選んでいるタイル・X反転・Y反転・パレットを置く |
| 8 マスの右クリック | そのマスのタイル・X反転・Y反転・パレットを拾う |
| Palette0〜12 | タイル一覧とプレビューの色。置くタイルのパレット番号にもなる。パレットエディタと連動する |
| マップデータ | 上の 2 欄が属性の 0・1 バイト目、下の 2 欄が 2・3 バイト目（16 進）。0 バイト目は挙動のコンボ、3 バイト目は背景のコンボと連動する。16 進でない文字は「'$zz' is not a valid integer value.」 |
| 変更 | 選んでいるブロックの 8 タイルと属性を、編集中の状態へ確定する（AdvanceMap は ROM へ書く）。メインのマップ表示とブロックパレットがすぐ描き直される |

メニュー:

- 画像 > タイルセット1/2をファイルに保存する: 選んでいるパレットの色で 24 ビットの DIB（横 128、主 640 タイル・副 384 タイル）と、同じ名前の `.pal` を書きます（AdvanceMap と同じバイト列）。パレットに同じ色が 2 つ以上あると「Export of this palette not possible; …」を出して書きません。
- 画像 > タイルセット1/2にファイルから読み込む: DIB・BMP（1/4/8/24/32 ビット）と、インデックス PNG を読みます。色番号が 15 以下のインデックス画像は番号をそのまま、24 ビットの画像は選んでいるパレットの同じ色（無ければ一番近い色）にします。上限を超えるタイルは捨てます。
- 画像 > ブロックの再読み込み: メインから写しを取り直し、選んでいるブロックの編集中の値を捨てます。
- ブロック > タイルセット1/2をファイルに保存する・ファイルから読み込む: `.bvd`（ブロック数 u32、ブロック定義 16 バイト × 数、属性 4 バイト × 数、末尾 `FRLG`。Porymap の AdvanceMap 1.92 用の読み込みと同じ形式。末尾が `RSE ` の 2 バイト属性も読める）。開くとブロック数も `.bvd` の数になります。
- ブロック > ブロック数の追加/変更: タイルセット 2 のブロック数（上限 384 に丸める）。
- パレット > パレットエディタの表示／ブロックのパレット参照先の一括変更: それぞれ別ウィンドウで開きます。
- パレット > パレットの変更を反映する: パレットエディタの「変更」で一時適用した色を、編集中の状態へ確定します（AdvanceMap の「パレットの変更をROMに上書きする」）。
- パレット > 現在のパレットをファイルに保存する・ファイルから読み込む: `.pal`（16 色 × `R, G, B, 0`）。開いた色は一時適用の扱いで、「パレットの変更を反映する」で確定します。

### パレットエディタ

16 色の見本を押して色を選び、赤・緑・青のスライダー（0〜31。右の数字は 8 倍）で変えます。15 ビットの値（`青<<10 | 緑<<5 | 赤`）を入れて「15bit to RGB」でも変えられます（最上位ビットは無視、16 進でなければ「'$ZZZZ' is not a valid integer value.」）。「変更」でブロックエディタのタイル一覧・8 マス・プレビューに出ます（ブロック一覧とメインは確定するまで変わりません）。「色の選択」を押すと、100ms ごとにマウスカーソルの下の画面の色を拾い、左ボタンを押したところで止めます（Esc かもう一度押しても止まる）。

### ブロックパレット一括変更

タイルセット 1 か 2 を選び、右の欄にパレットの変更先を入れて「変更を保存する」を押すと、そのタイルセットの全ブロックのパレット番号を置き換えて閉じます（確認なし）。

### 別ウィンドウと編集中の状態

- 別ウィンドウ（ブロックエディタ・パレットエディタ・ブロックパレット一括変更）は Tauri の本物のウィンドウで、ワールドマップエディタと同じく中身は別ウィンドウ用の入口 `tool.html`（`src/tool.ts`。メインの画面のコードは読み込まない）から、ウィンドウのラベルを見て組み立てます。エディタのコードは開いたときに初めて読み込み、閉じると WebView ごと破棄します。メインの起動では読み込みません（メイン側の窓口 `windows/ToolWindowHost.ts` も初めて開くときに読み込みます）。
- 編集中の状態（CommandBus とタイルセット）はメインウィンドウだけが持ちます。別ウィンドウはイベント `tool-request` で操作（コマンドの JSON）を送り、メインがそれを CommandBus で実行します。アンドゥ・リドゥはメインと同じ履歴に入り、どのウィンドウでも Ctrl+Z / Ctrl+Y（Ctrl+S は出力）で戻せます。
- タイルセットが変わると（どのウィンドウの操作でも、アンドゥでも）、メインは開いている別ウィンドウへイベント `tool-message` でタイルセットの写しを送り直します。選んでいるパレットと一時適用した色も、メインが持ってウィンドウどうしで共有します。
- マップを切り替えると、別ウィンドウはそのマップのタイルセットに追従します。ROM を開き直したときとマップを閉じたときは閉じます。
- 未出力のタイルセットの変更があるときも、閉じる・別の ROM を開くときに「変更を出力しますか？」と聞きます。
- スクリプトエディタは例外で、テキストファイルの編集中のバッファをエディタのウィンドウが持ち、保存もエディタが直接ファイルへ書きます（CommandBus を通さない。「スクリプトエディタ（別ウィンドウ）」の節）。

## スクリプト連携と内蔵スクリプトエディタ（Phase2）

Phase2 で作っている途中の機能です。実装した分の仕様をここに書きます。

### スクリプトの設定（zigzagumap.json）

- 設定はプロジェクトフォルダ（ZigzaguMap で開く CFRU-JP のフォルダ）の `zigzagumap.json` の `"script"` の節に書きます。ファイルや節が無いとき、項目を省いたときは、方言ごとの既定値を使います。読み書きは core の `ScriptConfigJson`（`packages/core/src/script/config/`）だけで行い、知らない項目はファイルの最上位と節の中のどちらも、書き戻しても残します。
- パスはプロジェクトフォルダからの相対パスで、区切りは `/` です。`..` で上のフォルダも指せます。`\` で書いてあっても、読むときに `/` にそろえます。
- 項目は次のとおりです。

| 項目 | 内容 | ND の既定値 | Chronos の既定値 |
|---|---|---|---|
| `dialect` | 方言。`nd`・`chronos`・`auto` | `auto` | `auto` |
| `build` | ビルドの手順の列。1 つの手順は `{ "command", "args", "cwd" }`。上から順に動かす。`command` が `copy` なら、`args` の 1 つ目のファイルを 2 つ目へ写す | CFRU の `python scripts/make.py`（`cwd` は `.`）→ `copy test.gba ../NeoDark-DPE-main/BPRJ0.gba` → DPE の `python scripts/make.py`（`cwd` は `../NeoDark-DPE-main`） | `python build.py`（`cwd` は `..`） |
| `outputRom` | ビルドで出来る ROM | `../NeoDark-DPE-main/test.gba` | `../build/Chronos.gba` |
| `widthCheck` | `.string` の幅検査のコマンド（形は `build` の 1 手順と同じ）。`null` なら無し | `null` | `python tools/check_text_width.py --source`（`cwd` は `..`） |
| `labelTemplate` | ラベルの規則。`{map}`（`.s` の名前から作った名前）・`{kind}`（`Npc` / `Sign` / `Tile`）・`{index}`（番号）を置き換える | `{map}_{kind}{index}` | 同じ |
| `useGlobal` | 新しいラベルに `.global` を付けるか | `false` | `true` |
| `lineMaxChars` / `linesPerPage` | 簡易の幅検査の、1 行の字数と 1 ページの行数 | 18 / 2 | 18 / 2 |
| `commandsCsv` | 命令の説明を足す commands.csv。`null` なら使わない | `null` | `null` |
| `widthRegistry` | 幅検査の追加の登録ファイル（`path`・`.string` のパスの頭 `prefix`・足すときの窓 `window`）。`null` なら書き足さない | `null` | `{ "path": "strings/text_width_registry.json", "prefix": "cfru/", "window": "field" }` |

- `auto` のときは、プロジェクトフォルダの `xse_commands.s` の `loadpointer` マクロを見ます。引数が 3 つ（`destination, value, value_kanji`）なら ND、2 つなら Chronos です。`xse_commands.s` が無いときや `loadpointer` が見つからないときは、Chronos（素の CFRU と同じ 1 ポインタ）として扱います。
- ND の既定のビルドは、CFRU のビルド → DPE へのコピー → DPE のビルドまでを 1 回で行います（#198 で決めた）。エミュレータの起動は作りません（#199 は閉じた）。前の版にあった `emulator` の項目は読まず、書いてあれば知らない項目として残します。

### 命令表（xse_commands.s と commands.csv）

- 命令表は、開いたプロジェクトの `xse_commands.s` のマクロから毎回作ります。ND と Chronos では 0F（`loadpointer`）などの長さが違うため（ND は 2 ポインタで 10 バイト、Chronos は 1 ポインタで 6 バイト）、決まった表は持ちません。
- マクロの名前、引数（`:req` は必須、`=値` は既定値、無印は省略可）、直前のコメント行（説明）を読みます。本文の `.byte`・`.hword`・`.2byte`・`.4byte`・`.word` と、ほかのマクロの呼び出しを中まで展開し、命令のバイトの並びを作ります。先頭の 1 バイトが決まった値なら、それを命令番号とします。
- `.ifb` / `.ifnb` の分岐は、「どの引数を省いたか」ごとの並びに分けて持ちます（例: ND の `applymovement` は、マップを省くと 0x4F の 7 バイト、書くと 0x50 の 9 バイト）。`.equ` の定数は `xse_commands.s`・`xse_defines.s`・`asm_defines.s` から求めます。`/* */` の中は読みません。
- 読めないマクロ（呼び先のマクロが無い、自分を呼ぶ、対応していない書き方）は、理由を付けて一覧に出します。ほかのマクロは続けて読みます。
- `commands.csv`（列は name, detail, hover, opcode, args。BOM 付き UTF-8、`#` で始まる行と空行は飛ばす）があれば、同じ名前の命令に説明（detail と hover）を付けます。同じ名前の行が複数あれば、命令番号の合う行を使います。CSV にだけある名前（`#Org` など）も命令として引けます。
- 引数の種類は、文字列・ラベル・移動・変数・フラグ・定数に分けます。Gen3 Script Assistant 改造版の規則（命令ごとの上書きと、引数の名前の規則）を使い、文字列は本文で 4 バイトのまま書く引数から求めます。このため `msgbox` の文字列の引数は ND で 2 つ、Chronos で 1 つ、`customchoice` は ND で 4 つ、Chronos で 2 つになります。

### .s の解析とラベルの索引

- `.s` の 1 行を、ラベル定義・命令（マクロ）かディレクティブ・引数・コメントに分け、それぞれの桁の範囲を返します。エディタの色付けと索引は、同じ解析を使います。
- ラベルは、行頭（空白の後）の `名前:` です。同じ行に `.byte` などを続けて書けます（`m_Walk: .byte walk_up, end_m`）。
- 引数は空白とカンマで区切ります。`"..."` と括弧の中では区切りません。`VAR + 1` のように演算子をはさんだ並びは 1 つの式として扱います。`.equ` は、名前とその後ろ全部（値）の 2 つに分けます。
- コメントは `@`（行の途中からも）、行頭の `#`、`/* */` です。`/* */` は複数の行にまたがってよく、中にあるラベルのような行は拾いません。`"..."` の中の `@` はコメントにしません。
- 索引に入れるのは、`assembly/` の下のすべての `.s` と、プロジェクトフォルダ直下の `xse_commands.s`・`xse_defines.s`・`asm_defines.s` です。
- ラベルごとに、ファイル・行・桁・`.global` の有無と、続く最大 4 行（1 行 80 字まで。コメントは除く）を持ちます。`.equ` は値と、同じ行の `@` コメント（説明）を持ちます。移動の名前は、`xse_defines.s` の `look_down` から `end_m` までの `.equ` です。
- 名前は大文字と小文字を区別します。同じ名前が複数あれば、すべてを持ちます。
- 索引はファイルごとに持ちます。1 ファイルを読み直すと、そのファイルの分だけが入れ替わります。
- ファイルごとに改行（LF / CRLF）を覚え、書き戻すときは同じ改行にそろえます。
- ND の全ファイルの索引は、JSON にして 1MB 未満（約 840KB）です。

### .string と簡易の幅検査

`strings\*.string` の読み方は、CFRU の `scripts/string.py` に合わせています。

- `#org @ラベル` の次の行が本文です。本文の 1 行が 1 つの文字列になります。続く行は前の行につながらず、ラベルの無い別の文字列として直後に置かれます。
- `#org` が続いて本文の無いラベルは、次のラベルと同じ文字列を指します。
- 空白だけの行（全角の空白だけの行も）は空行、行頭が `//` の行はコメントです。
- `#include "…"`、`#ifdef` / `#ifndef` / `#else` / `#endif` の行は指定として読みます。`#ifdef` の中のラベルも読み、どの条件の中にあるかを覚えます（条件が成り立つかは判断しません）。
- 最初の `#org` より前の `MAX_LENGTH=` と `FILL_FF=` は設定として読みます。
- 改行の形（LF・CRLF・CR、最後の改行の有無）と BOM は行ごとに残します。読んで書き戻すと 1 バイトも変わりません。

書き戻し:

- 本文の差し替えでは、そのラベルの最初の本文の行だけを書き換えます。本文は 1 行で書き、`\n` `\p` `\l` は文字のまま書きます。改行の文字、空の本文、`//` や `#org` で始まる本文は書けません（エラーにします）。
- 本文の無いラベルを差し替えると、`#org` の直後に本文の行を 1 行足します。次のラベルとの共有はなくなります。
- 新しいラベルはファイルの最後に足します。前に空行を 1 つはさみ、改行はファイルでいちばん多い形にそろえます。

本文の見せ方: `\p` で次のページ、`\n` `\l` `\m` で次の行にします。`[PLAYER]`、`{Lv}`、`<FF 09>`、`[FD]` などは書かれたまま見せます。

簡易の幅検査は、ピクセルではなく字数で数えます。

| 字 | 字数 |
|---|---|
| 全角の字 | 1 |
| 半角の英数字・記号、半角カナ | 0.5（設定で変えられる） |
| 空白（半角も全角も） | 1（ゲームでは半角の空白も全角と同じ幅） |
| `[PLAYER]` `[RIVAL]` | 5 |
| `[BUFFER1]` などの `[BUFFER…]` | 8（道具・技の名前の長さ） |
| `[ATTACKER]` `[TARGET]` など戦闘のポケモン | 11（「あいての 」と名前） |
| 矢印・ボタンの絵、`{Lv}` などの `{…}`、`\$` | 1 |
| 色・待ちなどの制御（`[RED]` など）、`[XX]`、`<XX YY>` | 0 |

1 行の字数の上限は 18、1 ページの行数の上限は 2 です（Chronos の窓の幅 208px に全角 10px の字が 18 字入る）。`\l` も 1 行と数えます。上限、半角の重み、プレースホルダの字数は検査を呼ぶ側から変えられます。上限を超えた行は、ページと行の番号、ファイルの中の位置（行の始まり・終わりと、超え始めた字の位置）を返します。ピクセルの検査（Chronos の `tools/check_text_width.py`）とは結果が違うことがあります。全角の `！`（5px）や小さい字（9px）も 1 字と数えるので、そこは厳しめに出ます。半角の数字（8px）は 0.5 字と数えるので、そこは甘めに出ます。

### eventscripts と maps\scripts.json

読み書きは core の `script/project/` にあります。scripts.json の画面は「[scripts.json の編集画面](#scriptsjson-の編集画面)」です。

- eventscripts は 1 行 1 件で `種別 バンク マップ [番号] シンボル` と書きます。種別は `map` / `npc` / `trainer` / `item` / `tile` / `sign` で、大文字小文字は区別しません。行の見分け方は CFRU の `scripts/insert.py` に合わせています。トークンの数が違う行や、`npc` などで番号が無い行は「読めない行」として残します（insert.py も使いません）。
- コメント（`#` で始まる行）、空行、`#include` / `#define` / `#ifdef` / `#ifndef` / `#else` / `#endif` の行、読めない行は、どれも元の位置にそのまま残します。改行（LF / CRLF / CR）も行ごとに覚えるので、読んで書き戻すと 1 バイトも変わりません。編集で変わるのは、足す・変える・消す行だけです。
- `#ifdef` の中の行は、どの条件の下にあるかを覚えます。insert.py は eventscripts の中の `#define` を読まず、`#include` 先の `#define` だけを使います。
- `trainer` はシンボルの頭に `EventScript_`、`item` は `ItemFindScript_` を付けた名前がラベル名です（insert.py と同じ）。ラベル名からシンボルに戻すときは、この頭の文字列を外します。
- 番号はイベントの並びの中の位置（0 から）です。人（`npc` / `trainer` / `item` は同じ番号を使う）、看板（`sign`）、スクリプトタイル（`tile`）でそれぞれ数えます。`map` は番号を使いません。
- イベントを消すと、そのイベントの行を消し、同じマップの同じ並びで後ろにある番号を 1 つずつ減らします。入れ替えと移動でも、同じ並びの番号を付け直します。`#ifdef` の中の行も同じように付け直します（どの条件でビルドしても、番号は同じ並びを指すためです）。番号を `05` のように 0 で桁をそろえて書いた行は、同じ桁数で書き直します。
- 行を足すときは、同じバンク・マップの項目のうち `#ifdef` の外にある最後の項目の次に入れます。無ければファイルの末尾に足します。区切りは空白 1 つで、改行はファイルで最初に出てくる改行に合わせます。
- `maps\scripts.json` は `{ "Format": 1, "Entries": [{ "Bank", "Map", "Name", "Script", "Strings" }] }` です。`Map` を省くとバンク全体の項目になり、マップを指定した項目のほうが優先されます。`Strings` を省くと `strings/overworld_strings_<.s の名前（拡張子なし）>.string` を使います（ND の名前の付け方）。
- `scripts.json` は Bochi の maps\ の JSON と同じ整形（2 空白の字下げ、CRLF、ASCII 以外の文字は `\uXXXX`）で書きます。知らない項目は消さずに書き戻します（決まった項目の後ろに、読んだときの順で並べます）。

### ROM のスクリプトの逆アセンブル

ROM のスクリプトのバイト列を、`xse_commands.s` の書き方の文に戻します。処理は core の `script/disasm/` にあります（画面はまだありません。読み取り専用の表示は #206、`.s` への取り込みは #207 で作ります）。

命令表:

- プロジェクトを開いているときは、そのプロジェクトの `xse_commands.s` から作った命令表を使います。ND のベース ROM は 0F が 2 ポインタ（10 バイト）なので、素の FR の長さで読むと壊れます。
- プロジェクトの無い素の ROM では、同梱の表を使います。同梱の表は Chronos の cfru の `xse_commands.s` と `xse_defines.s`（0F が 1 ポインタ）から、命令番号・名前・バイトの並び・引数の名前と種類と、移動の名前だけを抜き出したものです。0x2C・0x2D・0x74 は Chronos と ND が自分で変えた命令なので入れていません。作り直すときは `packages/core/scripts/gen-disasm-commands.ts` に、`xse_commands.s` のあるフォルダを渡します。
- 使うのは、`.byte` などだけで書いたマクロです。別名のマクロと、`msgbox` のように複数の命令をまとめたマクロは使いません（`msgbox` は `loadpointer` と `callstd` の 2 行に戻ります）。
- 同じ命令番号のマクロがいくつかあるときは、決まった値（trainerbattle の種類など）の多いもの、ファイルで先に書いたもの、省ける引数を書いた型、の順に試します。ND の 0F は、2 つのポインタが同じなら漢字を省いた形（`loadpointer 0x0 X`）、違えば `loadpointer 0x0 X X_kanji` にします。

読み方:

- 入口から順に読み、`end`・`return`・`goto`・`gotostd`・`jumpram`・`killscript`・0x5D・0x5E・`virtualgoto` で止めます。
- たどる分岐先は、0x04〜0x07（`call`・`goto`・`goto_if`・`ifcall`）の行き先と、trainerbattle の続きのスクリプト（種類 1・2 は 3 つ目、6・8 は 4 つ目のポインタ）です。trainerbattle のほかのポインタは文字列として読みます。
- 引数の種類が文字列の 4 バイトは文字列、移動の引数は移動データ（`end_m` の 0xFE まで）、`mart`・`mart2`・`mart3` の引数はショップの一覧（2 バイトずつ、0 まで）として読みます。`callasm` などのほかのポインタはたどらず、数のまま書きます。
- たどった先、文字列、移動データ、ショップの一覧には `ROM_08XXXXXX`（ポインタの値、大文字の 16 進 8 桁）のラベルを付けます。入口には呼ぶ側で名前を付けられます。
- どの型にも合わない命令は `.byte 0xXX` を 1 つ書いて、その道は止めます。命令の途中を指す分岐や ROM の外を指す分岐は、数のまま書いて問題の一覧に出します。読んだ行に戻る分岐（輪）は、2 回目からは読みません。
- 上限は、命令が全体で 20000 個、文字列が 1024 バイト、移動データとショップの一覧が 256 個です。超えたら止めて問題の一覧に出します。

書き方:

- `.s` は、ラベルの行の後に命令をタブで字下げして書き、まとまりの間に空行を入れます。引数は空白で区切り、数は `0x` の 16 進です。
- 省いた引数（`.ifb` で空の側の引数、本文で使わない既定値の引数）は書きません。途中の引数を省くときだけ、カンマで区切って空のまま書きます。本文で使わない必須の引数（`trainerbattle1` の `type` など）には、命令番号の次の決まった値を書きます。
- 移動データは `.byte walk_up, exclaim, end_m`、ショップの一覧は `.align 1` の後に `.hword 0xD, 0x0` と書きます。名前の無い移動の値は 16 進で書きます。
- 文字列は `.string` の形（`#org @ラベル` と 1 行の本文）で別に書きます。
- 結果は、まとまり・行・引数・文字列・移動データ・ショップの一覧・問題を構造のまま返し、文字にした行にはそれぞれ ROM の位置を付けます。

文字列の戻し方は、CFRU の `scripts/string.py` の読み方に合わせています。

- string.py は charmap.tbl の右辺を書いたまま使い、同じ字が何度も出るときは最後の定義を使います。そのため、string.py で同じバイトに戻る定義だけを使います。たとえば ND の charmap では `?` が AC と EF の 2 つにあり、string.py は `?` を EF にするので、AC は全角の `？` で書きます。
- FD 01・02・03・04・06 は `[PLAYER]`・`[BUFFER1]`・`[BUFFER2]`・`[BUFFER3]`・`[RIVAL]` にします。表に無い 1 バイトは `[F7]`、表に無い FC xx yy は `<FC 88 9F>` にします。
- 書いた本文を string.py の読み方で戻して元のバイト列にならないときは、本文をすべて `[XX]` で書きます。
- 文字コード表は、プロジェクトの charmap.tbl を渡せます。渡さなければ同梱のもの（ND の charmap.tbl）を使います。

確かめたこと:

- 素の BPRJ のマサラタウン（バンク 3・マップ 0）の人と看板の入口 7 つから、14 のまとまりと移動データ 5 つ、文字列 13 個に戻りました。これを `arm-none-eabi-as` でアセンブルし直すと、どのまとまりも元のバイト列と一致しました（まとまりごとに元の位置へ `.org` で置き、文字列のラベルは元の位置の `.equ` にして比べました）。
- 素の BPRJ の全マップの人・看板・スクリプトタイルを読むと、知らない命令は 1 か所（0xD1）だけでした。そこで拾った 3453 個の文字列は、ND の string.py で書き戻すとすべて元のバイト列になりました。
- ND のベース ROM のいあいぎり・なみのりのスクリプトは、0F を 2 ポインタで読み、ひらがなと漢字の文字列を戻せました。アセンブルし直しても一致しました。

### スクリプトエディタ（別ウィンドウ）

スクリプトの `.s` と `.string` を編集する別ウィンドウです（CodeMirror 6）。色付け・補完・検索などの機能は「[スクリプトエディタの機能](#スクリプトエディタの機能)」に書きます。

開き方:

- イベントタブでイベント（人・看板・スクリプト）をダブルクリックすると、そのイベントのスクリプトを開きます。プロジェクトフォルダを開いていないとき（素の ROM だけ）は何もしません。
- 開く場所の求め方: eventscripts からそのイベント（バンク・マップ・種別・番号。スクリプトはスクリプトタイルの `tile`）の行を探し、ラベル名にしてから、ラベルの索引（「.s の解析とラベルの索引」）で `.s` と行を引きます。`#ifdef` で同じイベントの行がいくつもあるときは、`#include` 先の `#define` で条件が成り立つ行を使います（無ければ最初の行）。
- ラベルが見つからないとき（eventscripts に行が無い、ラベルが assembly に無い、開けないフォルダにある）は、maps\scripts.json のそのマップの `.s` を 1 行目から開きます。それも無ければ、ステータスバーに「このイベントのスクリプトが見つかりません」と出して開きません。
- ラベルの索引はメインウィンドウが持ちます（名前・ファイル・行だけ）。初めてスクリプトを開くときに作り、エディタで保存したファイルの分だけ読み直します。メインウィンドウが前面に戻ったとき（外のエディタで書き換えたかもしれないので）は捨てて、次に開くときに作り直します。

開けるファイル:

- プロジェクトフォルダの `assembly/overworld_scripts/` と `strings/` の中のファイルだけです（大文字小文字は区別しません）。ほかのパスはエディタではエラーのダイアログ、メインからはステータスバーで断ります。
- 読み書きは、メインがプロジェクトフォルダを開いたときに決めたフォルダからの相対パスで行います（Rust 側の許可はウィンドウどうしで共通）。別のプロジェクトフォルダを開くと、エディタは閉じます（同じフォルダで ROM を開き直したときは残します）。

画面と操作:

- 上にタブの帯、真ん中に本文、下にカーソルの位置（行・桁）・改行の形・BOM の有無と、保存などのお知らせを出します。タブはファイルごとに 1 つで、同じファイルを開き直すとそのタブへ切り替えます。未保存のタブには ● を付け、ウィンドウの題名の前にも ● を付けます。
- キー: Ctrl+S で表示中のファイルを保存（メインの「出力」は動きません）、Ctrl+W で表示中のタブを閉じる、Ctrl+Tab / Ctrl+Shift+Tab でタブの切り替え、Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z）で元に戻す・やり直す（履歴はファイルごと）、Tab で字下げ（タブ文字）。タブの × かホイールのクリックでもタブを閉じます。
- 未保存のタブを閉じるとき、未保存のままウィンドウを閉じるときは「保存しますか？」と聞きます（はい = 保存して閉じる、いいえ = 保存せずに閉じる、キャンセル = 閉じない）。メインウィンドウを閉じるとき、別のプロジェクトフォルダを開くときも、エディタに未保存のファイルがあればメインで同じように聞きます。ダイアログはどれも画面内のもので、Windows の標準のダイアログは使いません。
- ウィンドウは大きさを変えられ、最大化もできます（最小 420×260）。位置と大きさは個人設定の `toolWindows` に覚え、次に開くときに同じ場所に出します（自動操作で起動したときは覚えず、画面外に出します）。

保存と外部の変更:

- 保存は、読んだときの改行の形（LF / CRLF / CR）と BOM の有無を保ちます。改行が混ざっているファイルは、いちばん多い形にそろえて保存します。書き込みは一時ファイルに書いてから置き換えます。
- 開いているファイルの更新日時と大きさを 1 秒ごとと、ウィンドウが前面に戻ったときに調べます。外で変わっていて、未保存の変更が無ければ黙って読み直します（変わった範囲だけを置き換えるので、カーソルと選択はそのまま残ります）。未保存の変更があれば「読み直しますか？」と聞きます（いいえなら編集中の内容を残し、同じ変更では二度聞きません）。読み直しも元に戻す履歴に入ります。ファイルが消えたときはタブの名前に取り消し線を引き、保存すると作り直します。

マップの編集との違い: マップとイベントの編集は CommandBus で実行し、メインの履歴に入ります。テキストファイル（`.s`・`.string`）の正本はディスクと、エディタが開いている間の編集中のバッファです。エディタの編集は CommandBus を通さず、元に戻す履歴もエディタのファイルごとに持ちます（Ctrl+Z はメインの履歴を戻しません）。

読み込みとメモリ: CodeMirror とエディタのコードは、エディタのウィンドウ（`tool.html`）を開いたときに初めて読み込みます。メインの `index.html` の束には入れません（`apps/desktop/test/bundle.test.ts` が `vite build` の出力を調べて確かめます）。メイン側の窓口 `ui/script/ScriptHost.ts` も、初めてスクリプトを開くときに読み込みます。

作りの決まり（後の issue で機能を足すとき）:

- エディタの機能は `apps/desktop/src/windows/script-editor/extensions/` に 1 機能 1 ファイルで書き、`extensions/index.ts` の一覧に 1 行足します。拡張はファイル（タブ）ごとに作るので、`.s` と `.string` で違うものを返せます（`EditorFileContext` の `path`・`kind`、保存 `save()`、別のファイルを開く `openFile()` を受け取る）。
- メインとのやり取りは `windows/script-editor/protocol.ts` にまとめています。エディタ → メインは `script-editor:request`（返事は `script-editor:reply`）で、今は `hello`（準備ができた。待っている開く指示を受け取る）と `saved`（保存した）です。メイン → エディタは `script-editor:open`（ファイルと行）と、`script-editor:query`（`dirty` = 未保存のファイル、`saveAll` = 全部保存。答えは `script-editor:answer`）です。
- エディタ → メインの `setting` は、エディタの個人設定（今はテーマ `scriptEditorTheme`）を変えたときに送ります。settings.json はメインが書くので、エディタは読むだけです。

### スクリプトエディタの機能

Gen3 Script Assistant 改造版（VS Code の拡張）の色付け・ホバー・補完を再現し、拡張に無い定義へ移動・波線・文字列の編集・テーマなどを足しています。命令表・ラベルと `.equ` の索引・文字列のラベルの索引は、エディタのウィンドウを開いたときに裏で読みます（ND で 1 秒前後。メインのウィンドウのメモリは使いません）。索引は、開いているタブの編集中の本文で置き換えるので、保存前に足したラベルも補完や定義へ移動に出ます（保存せずにタブを閉じるとディスクの内容に戻ります）。ウィンドウが前面に戻ったときに、外で書き換えたファイルを読み直します。処理は core の `script/assist/`（DOM なし）と、エディタの `windows/script-editor/extensions/` の 1 機能 1 ファイルにあります。

- 読み込みとメモリ: CodeMirror と補助の機能はエディタの束（`ScriptEditorWindow-*.js`）だけに入り、メインの束は変わりません（エディタの束は 296KB から 465KB、gzip で 152KB）。ND の写しで、エディタを開いている間のエディタのウィンドウの専用ワーキングセットは約 82MB（機能を足す前は約 20MB。索引などの知識は Node で測って約 12MB、残りは読み込みのときの一時的なものと CodeMirror）。閉じるとメインだけの値に戻ります。メインのウィンドウの値は、機能を足す前と同じです。

色付けとテーマ（#191）:

- `.s` は、コメント（`@`、行頭の `#`、`/* */`）・ラベル定義・ディレクティブ・数・文字列・マクロの引数参照（`\引数`）を字句で色分けします。命令名と引数の種類は命令表と索引で決め、見えている行にだけ色を付けます（拡張の semantic token と同じ役目）。種類は、命令（xse_commands.s のマクロと、同じファイルの `.macro`）、ARM / Thumb の命令（`callasm` で呼ぶ関数の行）、文字列の参照（`.string` のラベル。斜体）、ラベルの参照、変数、定数です。知らない命令は色を付けません。
- `.string` は、`#org @ラベル`、`//` のコメント、`#include` などの指定、本文の制御（`\n` `\p` `\l`、`[PLAYER]`、`{...}`、`<FF 09>` と `[XX]`）を色分けします。
- テーマは Dark+ 風・Light+ 風（既定）・Monokai 風・Solarized Dark 風の 4 つで、下の帯の右端で選びます。選んだテーマは個人設定（settings.json の `scriptEditorTheme`）に残します。テーマのパッケージは使わず、色の表は `extensions/themes.ts` に書いています。
- 4,584 行の `.s` で 1 字打ってから画面が描き直されるまで、平均 16.5 ms（次のフレームを待つ時間を含む）でした。

ホバーと補完（#192）:

- ホバーは拡張と同じ順で決めます。命令は commands.csv の hover（無ければマクロの引数の並びと直前のコメント）と、マクロの場所。文字列の参照は `.string` の本文（`\p` は空行、`\n` `\l` は改行にして見せ、700 字で切る）。ND の `msgbox` と `loadpointer` は、ひらがなと漢字の両方を出します（漢字を省いた行は「省略。ひらがなと同じ文字列」）。Chronos は 1 つです。そのほかの引数は、役割（`代入先イベント変数` など）、必須か省略時の値、`.equ` の値と説明、10 進と 16 進、変数の説明（0x800D は LASTRESULT など）、数と同じ値の名前（最大 8）、ラベルの定義の先頭の行（最大 3 か所）です。拡張では英語だった見出し（Signature・Source・Decimal・Hex・Known names）は日本語にしました。
- 補完は Ctrl+Space か、名前を打ったとき、引数の区切りの空白を打ったときに出ます。命令名の位置では命令とディレクティブ、引数の位置では引数の種類に合わせて、文字列のラベル・ラベル・移動の名前（`.byte` の行も）・変数・フラグ・定数を出します。`msgbox` の種類の引数は拡張と同じ `MSG_*` の 8 つです（値は xse_defines.s の `.equ` があればそちら）。ラベル・フラグ・変数の補完は拡張に無かったものです。
- commands.csv の hover の Markdown は、ヘルプの `markdown.ts` の行の中の変換（太字・コード）を使い、段落と改行はホバー用に自前で扱います（ヘルプの変換は段落の中の改行を空白にするため）。

定義へ移動（#193）:

- F12 か Ctrl+クリックで、カーソルの名前の定義へ移ります。引く順は、ラベル（assembly の `.s`）、文字列のラベル（`.string` の `#org` の行）、`.equ` です。同じファイルの定義が先に選ばれます。別のファイルならタブを開きます。Alt+←（マウスの「戻る」ボタンでも）で、移る前の位置へ戻ります。
- 見つからないときと、エディタで開けないファイル（xse_commands.s など）にある定義は、下の帯に場所を出します。
- Ctrl+クリックは、定義のある名前の上では定義へ移動、それ以外ではカーソルを足します（#194 の複数カーソルと同じキーのため、こう分けました）。

編集の操作（#194）:

- 検索と置換（Ctrl+F、Ctrl+H）。正規表現・大文字小文字の区別・単語単位を選べます。F3 / Shift+F3 で次・前、Ctrl+Alt+G で行へ移動。検索の欄・補完・波線の一覧の文言は日本語にしています。
- Alt＋ドラッグで矩形選択、Ctrl+D で同じ文字列を選択に足す、Ctrl+Shift+L で同じ文字列をすべて選ぶ、Ctrl+Alt+↑↓ で上下にカーソルを足す。
- Alt+↑↓ で行の移動、Shift+Alt+↑↓ で行の複製、Ctrl+/ でコメントの切り替え（`.s` は `@`、`.string` は `//`）、Ctrl+Shift+S で未保存のファイルをすべて保存。キーの一覧は「[ショートカット](#ショートカット)」とヘルプのショートカット一覧にあります。

波線（#195）:

- `.s`: 知らない命令（命令表・ARM / Thumb の命令・同じファイルの `.macro` のどれでもない）、必須の引数が足りない（マクロの `:req`）、引数が多すぎる、どこにも定義の無いラベル（命令の引数のうち、ラベル・移動データ・文字列を指すもの）。ラベルは、索引・文字列の索引・`.equ`・リンカのスクリプト（BPRJ.ld の `gStringVar4 = 0x…;` など）・同じ本文の定義を探します。`callasm` などの C の関数を指す引数、`.if 0` の中、マクロの本文は調べません。マクロで作るラベル（`EventScript_X\num:`）は、頭の名前で始まれば定義済みとみなします。
- `.string`: 同じファイルに同じラベルが 2 つ以上（エラー）、別の `.string` に同じラベル（警告）、簡易の幅検査（下）。
- 打つのを止めて 0.5 秒で調べ直します。行番号の横に印、F8 で次の波線、Ctrl+Shift+M で一覧。ND と Chronos の写しの overworld_scripts の `.s` をすべて開いて、誤った波線が出ないことを確かめています。
- ビルドのエラーや保存時の幅検査の結果は、外から波線を足す入口（`extensions/lint.ts` の `setExternalDiagnostics`。ファイルと行で指定）で出します。

文字列のホバーとその場編集（#196）:

- 文字列の参照のホバーに「本文を編集」のボタンがあり、押すと小さな入力欄が出ます。入力中は文字数で幅を検査し（上限は zigzagumap.json の `lineMaxChars`・`linesPerPage`。既定は 1 行 18 字・1 ページ 2 行で ND も同じ）、行ごとの字数と、超えた行の印を出します。Enter か「反映」で `.string` のそのラベルの本文の行だけを書き換えます。その `.string` を開いていなければ裏でタブを開き、未保存にします（Ctrl+S か Ctrl+Shift+S で保存）。改行の文字は書けないので、改行は `\n`、改ページは `\p` と書きます。
- `.string` を直接開いたときも、同じ幅検査の結果を波線で出します。ピクセルで数える幅検査のコマンド（`widthCheck`）があるプロジェクト（Chronos）では、字数の検査は目安なので「情報」の印（青）にします。`[BUFFER1]` を 8 字と数えるなど厳しめに出るため、実際の Chronos の文でも印が付くことがあります（ピクセルの検査は通る）。

保存時の幅検査（#197）:

- `.string` を保存したとき、zigzagumap.json に幅検査のコマンド（`widthCheck`）があれば動かします。Chronos は既定で `python tools/check_text_width.py --source`（作業フォルダは 1 つ上の `Chronos`）、ND は既定で無いので何もしません。動いている間にもう一度保存したら、終わってからもう 1 回だけ動かします。
- 出力の `TEXT WIDTH ERROR: cfru/strings/x.string:21 gText_X (configured) page 1 line 2: 212 px > 208 px (...)` を拾い、`prefix`（Chronos は `cfru/`）を外したパスのファイルのその行に波線を出します。前の結果の波線は消します（直して保存すると消える）。`(configured)` と `(widest)` で同じ中身のものは 1 つにまとめます。ファイルや行の分からない誤りは、保存したファイルの 1 行目に出します。出力はエディタのウィンドウに覚えておきます（自動操作の `editor.widthCheck` の `log`。ビルドのログの欄ができたらそこに出します）。
- Chronos は、検査するファイル（登録のあるファイル）のすべての `#org` が `tools/check_text_width.py` に登録されていないと、検査もビルドも止まります。そこで、検査の前に登録の一覧（`--list-registry`）を取り、保存した `.string` が登録のあるファイルなら、登録の無い新しい `#org` を追加の登録ファイル（`widthRegistry` の `path`、Chronos は `cfru/strings/text_width_registry.json`）に書き足します。窓は `window`（既定 `field` = 会話の窓）です。本文に `[BUFFER1]`〜`[BUFFER3]` があると入る値の種類が分からないので、`unresolved`（窓の幅を検査しない）で登録します。登録ファイルに書いた名前のうち `.string` から消えた `#org` の分は消します。Python の `REGISTRY` に書いたものには触りません。登録の無いファイル（新しく作った `.string` など）は、今までどおり検査されないので書き足しません。
- 追加の登録ファイルを読む仕組みは Chronos 側（`tools/check_text_width.py`）に入れました（形は Chronos の `docs/TEXT_WIDTH.md`）。登録ファイルが無ければ、検査の結果もビルドも変更前と同じです。

### イベントのラベル（イベントタブのスクリプト欄）

プロジェクトフォルダを開いているとき、人・看板・スクリプトタイルのパネルに「スクリプトのラベル」の欄を出します（#200）。

- 欄にはイベントに付いたラベル名を出し、ラベルが付いていればオフセット（ROM のポインタ）の欄は隠します。ラベルが無い（素の ROM のスクリプトを指す）イベントは、オフセットの欄をそのまま出します。隠しアイテムの看板には欄を出しません。
- 入力すると、マップの `.s`（maps\scripts.json で決まるもの）のラベルのうち、入力を含むものを一覧に出します（↑↓ で選び、Enter か一覧のクリックで決める。Esc で元に戻す。▼ で全部を出す）。フォーカスが外れたときにも決めます。空にして決めるとラベルを外します（出力で eventscripts の行を消す）。ラベルを変えるのはコマンド（`setEventLabel`）なので、Ctrl+Z で元に戻せます。
- マップの `.s` に無いラベルは赤い字にします（ビルドで `Symbol missing` になるため）。使えない名前（半角の英字・数字・`_` `.` `$` 以外、数字で始まる）は決めません。
- `.s` のラベルの一覧は、その `.s` を初めて出すときに読み、エディタで保存したとき・メインウィンドウが前面に戻ったとき・ひな形を書いたときに読み直します（起動とマップの表示には入りません）。
- 「スクリプトを開く」ボタンとイベントのダブルクリックで、ラベルが付いていればエディタのその行を開き、付いていなければ素の ROM のスクリプトを読み取り専用で出します（下の「素の ROM のスクリプトの表示と取り込み」）。
- 自動操作では、欄は `event.person.label`・`event.sign.label`・`event.trap.label` です（`event.<種別>.script` は従来どおりオフセットの欄。比較テストが使うため）。ラベルの一覧は `script.labels` で読みます。

### ラベルの持ち方（maps\BB\scripts_MM.json）

イベントのラベルは、マップごとの別のファイル `maps\BB\scripts_MM.json`（例 `maps\03\scripts_00.json`）に、照合用の座標と一緒に持ちます（#204）。マップの JSON（`MM.json`）・Bochi・`map_project.py` には手を入れません。

- 名前を `MM.scripts.json` にしていないのは、CFRU の `scripts/map_project.py` が `maps/[0-9]*/[0-9]*.json` をすべてマップの JSON として読み、数字で始まる名前のファイルがあるとビルドが止まるためです。
- 形は `{ "Format": 1, "Bank", "Map", "MapScripts", "Table", "Persons": [{ "Index", "X", "Y", "Kind", "Label" }], "Signs": [...], "Traps": [...] }` です。`Kind` は eventscripts の種別（人は `npc` / `trainer` / `item`）、`MapScripts` はマップスクリプトの表のラベル、`Table` は ZigzaguMap が `.s` に書くマップスクリプトの表です。Bochi の maps\ の JSON と同じ整形（2 空白の字下げ、CRLF、ASCII 以外は `\uXXXX`）で書きます。
- ファイルの無いマップは、eventscripts の `#ifdef` の外の行をそのまま読みます。ラベルを変えるまで、ファイルは作りません。`#ifdef` の中の行は読むだけで、ZigzaguMap は変えません。
- 出力（Ctrl+S）のとき、変えたマップとファイルのあるマップについて、ファイル（座標は今のイベントの座標）を書き、eventscripts のそのマップの `#ifdef` の外の行をファイルに合わせます（同じイベントの行はシンボルだけ書き換え、要らない行は消し、無い行は足す）。ファイルもeventscripts も、中身が変わるときだけ書きます。ラベルを全部外したマップのファイルは消します。
- イベントを消すと、後ろのイベントのラベルが 1 つずつ前に詰まります。イベントの数を減らすと、いなくなったイベントのラベルも消えます（どちらも元に戻すと戻る）。
- マップを開いたとき、ファイルに書いた座標と今のイベントの座標が合わないラベルがあれば（Bochi などでイベントの順を変えたとき）、イベントタブの右上に知らせを出します。書いた座標にある同じ種類のイベントが 1 つだけなら、「座標で付け直す」でそのイベントへ付け替えられます（`realignEventLabels`。元に戻せる）。

### ラベルの自動命名とひな形

イベントを置いたとき（イベントマネージャーで数を増やしたとき、`addEvent`）に、ラベルを自動で付け、ひな形をすぐ `.s` と `.string` に書きます（#202）。

- ラベルは規則（zigzagumap.json の `labelTemplate`、既定 `{map}_{kind}{index}`）で付けます。`{map}` は `.s` の名前から作り（`01_moegi.s` → `Moegi`。数字だけの区切りと末尾の `scripts` は外し、区切りごとに頭を大文字にする）、`.s` の名前から作れなければ `Map3_0` のようにバンクとマップの番号にします。`{kind}` は `Npc` / `Sign` / `Tile`、`{index}` はイベントの番号です。プロジェクトのほかのラベルやイベントのラベルと重なれば、番号を 1 つずつ増やします（例 `Moegi_Npc3`、`Moegi_Sign1`、`Map3_0_Tile2`）。
- ひな形は、人が `lock` `faceplayer` `msgbox 文 MSG_FACE` `release` `end`、看板が `msgbox 文 MSG_SIGN` `end`、スクリプトタイルが `lockall` `msgbox 文 MSG_NORMAL` `releaseall` `end` です。文のラベルは `gText_<ラベル>` です。ND は msgbox に漢字のポインタも書き（`msgbox gText_X MSG_FACE gText_X_k`）、`.string` にひらがなと漢字の 2 つ（同じ本文）を足します。Chronos は 1 つです。`useGlobal` が true なら、ラベルの前に `.global` を書きます。
- `.s` の最後に、空行を 1 つはさんで足します（`.string` も同じ）。エディタで開いているファイルなら、エディタの本文へ足します（ディスクへは直接書かない。保存はエディタで行う）。
- ひな形を書くのは、イベントを置いたコマンドの一部です。元に戻すと、ラベルを外し、ひな形に手が入っていなければ `.s` と `.string` から除きます（手が入っていれば残して、ステータスバーに出す）。やり直すと同じ名前でもう一度書きます。
- マップの `.s` が maps\scripts.json に無いときは、ファイル名の入力（「scripts.json の編集画面」の「新しい .s を作る」と同じもの）を出し、作ったあとに置いたイベントへラベルとひな形を付けます（`assignEventLabels`。これも元に戻せる）。
- 新しい `.s` はふだん出力のときに作りますが（#201）、ひな形を書くときは、そのときに `.s` と `.string` を作ります（決まった先頭の後ろにひな形を足す）。出力のときは、もうあるので書き換えません。元に戻しても、作った `.s` と `.string` は消しません。

### ラベル名の変更（F2）

エディタで、カーソルのあるラベル名を F2 で変えられます（#203）。

- 新しい名前を聞き、`assembly/overworld_scripts` の下のすべての `.s` の定義と参照（コメントと `"..."` の中は除く）を変えます。開いているタブは本文を書き換え（エディタの元に戻すで戻せる）、開いていないファイルはディスクを書き換えます。
- そのラベルを使っているイベントとマップスクリプトの表があれば、メインでラベルを変えるコマンド（`renameEventLabel`）を実行します（メインの Ctrl+Z で戻せる）。eventscripts は出力のときに書きます。
- 手で名前を書き換えて保存したときも、そのファイルで消えたラベルと増えたラベルが 1 つずつで、消えたラベルをイベントが使っていれば、「イベントのラベルも変えますか？」と聞きます。

### 素の ROM のスクリプトの表示と取り込み

ラベルの付いていないイベントの「スクリプトを開く」（とダブルクリック）、マップスクリプトのパネルの「見る」で、ROM のスクリプトをエディタの読み取り専用のタブ（`ROM:08XXXXXX`）に出します（#206）。プロジェクトが無く ROM だけを開いているときも出せます。

- 逆アセンブルはメインウィンドウで行い（ROM はメインだけが持つ）、文字にした結果だけをエディタへ送ります。命令表はプロジェクトの xse_commands.s から作り（素の ROM だけなら同梱の表）、使うたびに作って捨てます。文字列は後ろに `@` のコメントにして付けます。
- タブの上の「.s に取り込む」（#207）で、付けるラベルの一覧（スクリプト・文字列・移動データ・ショップ）を出し、確かめてから（名前は変えられる）マップの `.s` と `.string` に書き足し、イベントのラベルを取り込んだ入口にします。入口はイベントのラベルの規則で付け（`Moegi_Npc3`）、たどった先は `<入口>_1`…、文字列は `gText_<入口>_1`…、移動データは `m_<入口>_1`…、ショップは `<入口>_Mart1`… です。
- 取り込んだまとまりの前には印（`.s` は `@ ZigzaguMap: ROM 0x08XXXXXX から取り込み`、`.string` は `//` の同じ行）を書きます。同じアドレスをもう取り込んであれば、そのラベルを使い、書き直しません（たどった先が取り込み済みなら、そのまとまりは書かずにラベルだけ使う）。
- ND では、漢字のポインタを省いた 0F（ひらがなと同じ文字列）を、同じ本文の `_k` を作って `loadpointer 0x0 X X_k` に指し直します（ND の書き方にそろえる）。
- 取り込みは、イベントのラベルを変えるコマンドに書き足しを結び付けたものです。元に戻すと、ラベルを戻し、手が入っていなければ書き足しも除きます。eventscripts は出力のときに書きます。

### マップスクリプトの専用パネル

場所の設定タブの「かんたん（CFRU）」表示のマップスクリプトは、専用のパネルです（#208）。オフセット（ROM のポインタ）の欄は出しません。

- 表は `.s` に書き（`@ ZigzaguMap: マップスクリプトの表 <ラベル>` の行から「ここまで」の行まで。出力のときに書き直す）、eventscripts の `map` の行で指します。表は `mapscript 種類 行き先` を並べて `.byte MAP_SCRIPT_TERMIN` で終え、条件表（種類 02・04）は `.align 1` のあとに `levelscript 変数 値 行き先` を並べて `.hword 0` で終えます。表の中身は scripts_MM.json の `Table` に持ちます。
- まだ表が無いマップでは、今の ROM（か maps\ の JSON）のマップスクリプトを読むだけの一覧と「表を作る」を出します。「表を作る」は今の内容をアドレスのまま表にします（ビルドしても動きは変わらない）。
- 種類ごとの一覧で、行き先をラベルの欄（イベントタブと同じ。マップの `.s` のラベルから選ぶ。`0x0816F58D` のようなアドレスも書ける）で変えます。条件表は変数・値・行き先の行を並べます。「種類を足す」「条件を足す」は、何もしないスクリプトのひな形（条件表なら、変数を次の値にして繰り返しを止める `setvar`）を `.s` に書いて行き先にします。
- 表の編集はどれも 1 回の操作として元に戻せます（`setMapScriptTable`）。「表をやめる」で、出力のときに `.s` の表と eventscripts の `map` の行を消します。
- プロジェクトフォルダが無いときは、ROM のマップスクリプトを読むだけの一覧にします。

### ビルド

ツール > ビルド（F7）と、スクリプトエディタの下のビルドの欄（Ctrl+B）で、設定（zigzagumap.json の `build`）の手順を上から順に動かします（#198）。

- 先に、エディタの未保存のファイルを保存するか、メインの未出力の変更を出力するかを聞きます（いいえなら、そのままビルドする）。
- 出力（標準出力と標準エラー）は 1 行ずつ欄に出します。手順が終了コード 0 以外で終わったら、そこで止めます。「止める」で子プロセスごと止めます。
- `command` が `copy` の手順は、ZigzaguMap がファイルを写します（`args` の 1 つ目を 2 つ目へ。どちらも `cwd` からの相対パス）。ND の既定は、CFRU のビルド（`python scripts/make.py`）→ `test.gba` を `../NeoDark-DPE-main/BPRJ0.gba` へ写す → DPE のビルド（`../NeoDark-DPE-main` で `python scripts/make.py`）を 1 回で行います。
- 終わったら、ログからエラーの行（GNU as の `ファイル:行: Error:`、`.string` の `Error parsing string on line N`、`Symbol missing: X`、Chronos の `TEXT WIDTH ERROR`、Python の `Traceback` など）を拾って欄の上に並べ、押すとその行を開きます（読み取りは core の `script/build/BuildLog.ts`）。拾ったエラーはエディタの文書に `build-problems` の出来事でも知らせます（波線 #195 の入口）。
- エミュレータの起動は作っていません（#199 は閉じた）。土台にあった Rust の `process_launch` などの入口は、画面から使わないので消しました。

### scripts.json の編集画面

ツール > スクリプトファイルの対応表 で開きます（CFRU-JP のフォルダを開いているときだけ）。開いたままマップを切り替えられます。

- 表の 1 行は、バンク・マップ・マップ名・`.s`・`.string` です。マップを空欄にするとバンク全体の行になります。同じバンク・マップを指す行が複数あると、前の行だけが使われます（後ろの行は灰色にし、下に警告を出します）。「上へ」「下へ」で並びを変えられます。
- `.string` の欄には、`.s` を入れると `strings/overworld_strings_<.s の名前>.string` が自動で入ります。手で書き換えたら、そのまま残します。既定の名前のままなら、scripts.json の `Strings` は省いて書きます（読むときは同じ名前になります）。
- パスはプロジェクトフォルダからの相対パスで、`\` で入れても `/` にそろえます。`..` や絶対パスは使えません。拡張子は `.s` と `.string` です。
- 行の追加・「変更を保存」・削除・並べ替えは、どれもアンドゥできます（Ctrl+Z / Ctrl+Y）。削除しても `.s` と `.string` のファイルは消しません。
- maps\scripts.json に書くのは出力（Ctrl+S）のときだけです。表を変えていなければ、scripts.json には触りません（手で書いた整形もそのまま残ります）。scripts.json の形式が不正なときは、表を出さずに理由を出し、編集も上書きもしません。

`.s` を新しく作る:

- 「新しい .s を作る」を押すと、ファイル名の入力が出ます。ファイル名（例 `03_00_masara`。`.s` は付けても付けなくてもよい）・バンク・マップ・マップ名・`.string` を入れて「作成」を押すと、対応表に行が足されます。マップにスクリプトが要るのに対応する `.s` が無いとき（イベントを置いたときなど）も、同じ入力が出ます。
- 作る場所は `assembly/overworld_scripts/<ファイル名>.s` と、`strings` の下の `.string` です。ファイル名に使えるのは半角の英数字と `_` `-` `.` だけです。
- `.s` の中身は、ND と Chronos の既存の `.s` と同じ先頭（`.text`、`.thumb`、`.align 2`、空行、`.include "../xse_commands.s"`、`.include "../xse_defines.s"`、`.include "../asm_defines.s"`）と空行 1 つです（UTF-8・LF）。`.string` は空のファイルです。
- ファイルを作るのも出力（Ctrl+S）のときです。出力の前にアンドゥで行を消せば、ファイルは作りません。出力のときに同じ名前のファイルが既にあれば、書き換えずにそのまま使います。入力のときに `.s` が既にあれば、作らずに表に足すだけにするかを聞きます。
- ビルド（ND の `python scripts/make.py`、Chronos の `python build.py`）は `assembly/` の `.s` と `strings/` の `.string` をすべて拾うので、作ったファイルはそのままビルドに入ります。

### 外部コマンドの実行（Rust）

ビルド・幅検査・エミュレータの起動に使う、Rust 側の仕組みです（`src-tauri/src/process.rs`。crate は増やさず標準ライブラリだけで作っています）。

- コマンドは、設定（zigzagumap.json）に書いたものを、指定の作業フォルダで起動します。作業フォルダは開いているプロジェクトフォルダからの相対パス（`..` で上へ出てもよい。Chronos は 1 つ上の `Chronos` で動かす）か絶対パスです。黒いコンソールのウィンドウは出しません。
- 標準出力と標準エラーは 1 行ずつ、呼んだウィンドウへイベント `process-output`（`{ id, stream, line }`）で届き、終わると `process-exit`（`{ id, code, killed }`）が届きます。Python の出力が文字化けしないよう、環境変数 `PYTHONUTF8=1` と `PYTHONIOENCODING=utf-8` を付けて起動します。UTF-8 として読めないバイトは置き換えます。
- 途中で止めると、子プロセスごと止めます（Windows は `taskkill /T`）。ZigzaguMap を終了したときも、動いているコマンドを止めます。
- ビルドの手順の `copy` は `process_copy` で写します（作業フォルダの決め方はコマンドと同じ）。エミュレータの起動の入口（`process_launch`）は、#199 を閉じたので消しました。
- ファイルの更新日時と大きさを返す `fs_stat` を足しました（無ければ null）。スクリプトエディタが外部の変更を見つけるのに使います。
- 別ウィンドウは、大きさを変えられるもの（最小の大きさつき、最大化もできる）も開けます。位置と大きさはメインが個人設定に残し、次に開くときに当てます（自動操作のときは使わず、画面外に出します）。

## AdvanceMap と違う点

AdvanceMap 1.92 との違いのうち、意図して残しているものの一覧です。比較テスト（[docs/compare-test.md](docs/compare-test.md)）では、これらを「仕様上の違い」として理由つきで除外しています。

### 全体

- ROM へは書き込みません。「ROMの保存」は「出力」（Ctrl+S、`maps\` へ書く）、「ROMに名前を付けて保存」は「出力先を指定して出力」です。ROM へすぐ書く「保存」ボタン類は、編集中の状態への反映に読み替えます（「[「保存」ボタンの読み替え](#保存ボタンの読み替え)」）。
- AdvanceMap に無いものを足しています: 元に戻す・やり直す（Ctrl+Z / Ctrl+Y）、ROM とフォルダのドラッグ＆ドロップ、「CFRU-JPのフォルダを開く」。起動時のタイトルロゴはありません。
- 未出力の変更があっても、別のマップへ移るとき（「マップの移動」を含む）に確認しません。マップごとの変更を持ったまま切り替え、一覧の名前に ` *` を付け、閉じる・別の ROM を開くときにだけ「変更を出力しますか？」と聞きます。
- 画面は日本語だけです（言語メニューはありません）。アプリ名は ZigzaguMap です（「Advance Mapについて」は「ZigzaguMapについて」、ダイアログの題名も ZigzaguMap）。
- ROM へ書かないので意味の無い機能（開いたときにバックアップを作成、ダミーデータ系、空き領域の検索、ワールドマップのルーチンの変更）は、「ZigzaguMap は ROM へ書き込まないため、この機能は不要です」と案内します。「バックアップの作成」は「出力先を指定して出力」と同じです。
- 確認・エラー・入力のダイアログは画面内に出します（Windows 標準のメッセージボックスは使わない。並びと文言は同じ）。
- 「オブジェクトの表示」の Ctrl+Z は、アンドゥに使うため外しています。
- マップ&イベント画像の保存は、どのタブでもイベントを重ねた画像を書きます（AdvanceMap はイベントタブ以外では 0 バイトのファイル）。
- 1×1 のマップ（3.50、3.51）は、AdvanceMap では黒く表示されますが、ZigzaguMap はブロックを描きます（#115。AdvanceMap の不具合とみなす）。

### ユーザーの要望で変えた点（Phase1 のフィードバック）

Phase1 を触ったユーザーの要望（issue #169〜#181）で、AdvanceMap と違う動きにしたものです。比較テストでは理由「ユーザーの要望（Phase1 のフィードバック）」を付けて除外しています。

### 比較テストで決めた違い

| 項目 | AdvanceMap | ZigzaguMap | 理由 |
|---|---|---|---|
| ファイルメニューの最近開いたファイル（#161） | 最大数の行をいつも出す（履歴の無い行は空） | 履歴にあるものだけ出す | 空の行は何の情報も持たないため |
| 設定 >「最後に開いたROMのショートカットを作成する」の初期状態（#162） | オン | オフ | ユーザーが頼んでいないファイルを exe のフォルダに作らないため |
| 「タイルセット番号で並び替え」の最後のグループ（#163） | 「Tileset 67」のあとに名前が空のグループを 1 つ出す | 出さない | AdvanceMap の不具合とみなす |
| 合わないタイルセットの組（#164） | ブロック表の外のデータもブロックとして描く | ブロック表の長さだけ読み、それより後ろのブロック番号は背景色で描く | ブロック数はブロックエディタと出力（`maps\tilesets`）にも使うので、表の外を読むとその中身まで出力に混ざるため |
| マップを指定して開く（Ctrl+M）を取り消したあと（#166） | Cancel で閉じたり整数でない値を入れたりすると、「以前開いたマップを開く」が動かなくなる | いつも前のマップを開く | AdvanceMap の不具合とみなす |

### イベントタブ

- 「マップの移動」で、行き先のマップの、ワープ No. のワープを選びます（AdvanceMap は番号 0 を選ぶ）。
- アイテム ID の名前は ROM の文字コード表で読みます（AdvanceMap では一部が文字化けする）。
- ポインタが 0 のイベントにスクリプトのオフセットを入れたときは、上位 1 バイトを 08 にします。

### 場所の設定・マップコネクション・野生ポケモンの設定

- 「保存」は ROM ではなく編集中の状態へ反映します（「[「保存」ボタンの読み替え](#保存ボタンの読み替え)」）。
- タイルセット番号に表に無い番号（9999 など）を入れたときは、AdvanceMap は受け付けて崩れた絵を出しますが、ZigzaguMap は指せるタイルセットが無いのでエラーにします。マップの横幅に -1 を入れたとき、AdvanceMap は落ちますが ZigzaguMap はエラーにします。
- 高度なヘッダーの位置・ポインタは表示だけです。不正な 16 進を保存したとき、AdvanceMap は続けて「AdvanceMapError(1)」も出してヘッダーを壊しますが、ZigzaguMap は最初のエラーだけを出して何も変えません。
- マップコネクションの矢印ボタンの有効・無効は、下書きの表の方向から決めます（AdvanceMap は方向を変えたときに表と合わない状態になることがあります）。
- タイルセット番号に -1 を入れたとき、AdvanceMap は同じエラー（AdvanceMapError(1)）を 2 回続けて出しますが、ZigzaguMap は 1 回です（AdvanceMap の不具合とみなす）。

### 新規マップ・作成したマップ・追加/挿入

- AdvanceMap は新規作成したマップを `.map` に保存すると、直前に開いていたマップのイベントを `.evt` に書きます。ZigzaguMap は作業用のマップのイベント（新規作成なら無し = 件数 0 の 4 バイト）を書きます。
- 名前に `/` などファイル名に使えない文字があるとき、AdvanceMap は保存ダイアログを開けませんが、ZigzaguMap はその文字を `_` にしたファイル名を初期値にします。
- マップの追加/挿入は、野生と落とし物（Bochi の ItemBalls。HiddenItem.s のラベルが重なるため）を写しません。
- 「マップの追加数」は、加えるマップの数ではありません（いつも 1 つ）。
- マップバンクヘッダーの「変更の適用」で作るバンクには、空のバンクの代わりにマップ 0 を置きます。

### ブロックエディタ・パレットエディタ・一括変更

- 「変更」「パレットの変更をROMに上書きする」「変更を保存する」「ブロック数の追加/変更」は ROM へ書かず、編集中の状態へ反映します（出力で `maps\tilesets\` に書く）。メニューの文言は「パレットの変更を反映する」にしました。
- 8 マスに置くタイルのパレット番号は、選んでいるパレットにします（AdvanceMap では反映されない場合があり、条件は分かっていません）。右クリックで拾うとパレットも拾います。
- タイルセット画像・`.bvd` の読み込みは、AdvanceMap では「Invalid filename.」で失敗しますが、ZigzaguMap では読み込めます。
- 一括変更の右の欄は 10 進で読みます（表の初期値が 10 進のため。数でなければ AdvanceMap と同じエラー）。

### ワールドマップエディタ

- AdvanceMap は素の BPRJ ではワールドマップエディタを開けません（エラーが続けて出て窓が出ない）が、ZigzaguMap では地図の絵と全ての表を読めます。
- 「保存」は編集中の状態への確定です。「ルーチンの変更」は ROM を書き換えないので、質問だけを出して何もしません。

## ワールドマップエディタ

ツール > ワールドマップエディタ（Ctrl+W、ツールバーの緑のアイコン）で、タウンマップ（空を飛ぶの地図）を別ウィンドウで開きます。初めて開いたときにベース ROM と `maps\regionmap.json` を読みます。画面の構成は AdvanceMap 1.92 の TWeltkarteForm と同じです（AdvanceMap は素の BPRJ では開けず、地図も黒いままですが、ZigzaguMap では地図の絵と全ての表を読めます）。

| 部分 | 動作 |
|---|---|
| 世界地図 | 左クリック（ドラッグしたときは離したマス）で位置を選び、そのマスの値を基本レイヤー・トップレイヤーの欄に読み込む。開いたときは、メインで開いているマップの地名の位置を選ぶ |
| エディットレイヤーの表示 / フライトポジション/人IDの表示 / トップレイヤーの座標を読み込む | 地名のあるマスの色、地名の位置の白い点、トップレイヤー（洞窟）のマスを重ねて描く。3 つ目を外すとトップレイヤーの欄は「未設定/非表示」 |
| マップ（16 進）・地名の一覧 | 地名を選んで、名前のオフセット・名前・座標・幅/高さ・人ID・フライトポジションを表示する。16 進でない入力は「'$zz' is not a valid integer value.」 |
| ポジションの保存 | 座標・幅/高さ・名前（基本レイヤーはフライトポジションも）を確定する。名前はマップ名表の書き換えなので、同じ地名番号の全マップの名前が変わる |
| フラグの保存 | 人ID（訪問フラグ。無しは FFFF）を確定する |
| マップの保存 | 選んでいるマスに、欄のマップの値を置く。置いていない値があるままタウンマップNo を切り替えると「ワールドマップの変更を保存しますか？」 |
| フライトポジション マップ/座標、このマップを開く | 左は空を飛ぶの行き先 3 バイト（バンク・マップ・飛び先の番号）、右は飛び先 6 バイト（バンク・マップ・X・Y）を ROM の並びの 16 進で出す。ボタンで行き先のマップをメインウィンドウで開く |
| タウンマップNo | 1: カントー、2: 1〜3のしま、3: 4〜5のしま、4: 6〜7のしま。「ワールドマップ番号の管理」は AdvanceMap と同じく押せない |
| ルーチンの変更 | ROM を書き換えないので、AdvanceMap の書き換え済みのときと同じ質問だけを出して何もしない |
| 再読み込み | 編集中の状態を読み直し、欄の入力を捨てる |

表の部分の名前は旧版の日本語訳です。改訂版 Japanese.ini の [WorldMapEditor] は英語のままなので、画面の文言は overrides.ini で旧版の日本語訳にしています（座標の見出しは、旧版の「縦座標」「横座標」が X と Y で逆なので入れ替えています）。

AdvanceMap の「保存」は、ZigzaguMap では編集中の状態への確定です。確定した操作はメインの履歴に積まれ、エディターの中でも Ctrl+Z / Ctrl+Y（入力欄の外）で取り消し・やり直し、Ctrl+S で出力できます。

### maps\regionmap.json

タウンマップの変更は `maps\regionmap.json` に書きます。ベース ROM と違う表だけを、項目ごとの読める形（base64 ではない）で書き、全部ベース ROM と同じに戻ったらファイルを消します。字下げは 2 空白、改行は CRLF です。

| キー | 中身 | ROM の表（BPRJ。括弧は表を指すポインタの位置） |
|---|---|---|
| `Format` | 1 | |
| `Layouts` | 変えた面・レイヤーだけ。`Page`（`kanto` / `sevii123` / `sevii45` / `sevii67`）、`Layer`（`map` = 基本レイヤー / `dungeon` = トップレイヤー）、`Rows`（15 行、各行は地名番号の 16 進 2 桁を空白区切りで 22 個） | u8[2][15][22] を 4 面: 0x3B9018・0x3B92AC・0x3B9540・0x3B97D4（0xC5378・0xC5380・0xC5388・0xC53B0、GetMapNo） |
| `Positions` | 地名 0x58〜0xC5 の全 110 件。`Id`（`"0x58"`）、`X`、`Y` | s16[n][2]: 0x3B89E8（0xC4F20、SetMapNo_and_Pos） |
| `Sizes` | 同じ 110 件。`Id`、`Width`、`Height` | u16[n][2]: 0x3B8D00（0xC4F1C） |
| `FlyDestinations` | 地名 0x58〜0xC3 の全 108 件。`Id`、`Bank`、`Map`、`HealLocation`（0 なら飛び先を使わずマップの真ん中へ） | u8[108][3]: 0x3B9A68（0xC648C、FlyDestination） |
| `HealLocations` | 飛び先 1〜20 の全件。`Index`、`Bank`、`Map`、`X`、`Y`、`Unknown`（末尾 2 バイト。AdvanceMap の「不明:」。無い古いファイルはベース ROM の値）。イベントタブのフライトポジション（AdvanceMap の FlugposHeader の表）と同じ表 | 8 バイト × 20: 0x3B5944（0xC0E94 の値 + 8、GetWarpPosByNo。0xC0E44 も同じ表を指す） |
| `MapVisitFlags` / `DungeonVisitFlags` | 地名 0x58〜0xC5 の全 110 件。`Id`、`Flag`（`"0x0890"`、無ければ null） | 表ではなく GetMapState（0x0C47C0）/ GetCaveState（0x0C4A5C）の switch 文。取り込むには表を引く命令への書き換えが要る |

名前は `regionmap.json` には書かず、ほかのマップ名の変更と同じく、その地名番号を使うマップの `maps\BB\MM.json` に入ります。地図の絵（タイル・パレット・タイルマップ）は読むだけで編集しません。

## 出力の仕様

出力（Ctrl+S）は、変更のあったものだけをプロジェクトフォルダへ書きます。自動では出力しません。ベース ROM には書き込みません。読み書きの処理は `packages/core/src/project/`（パスは `paths.ts`、全体の流れは `CfruProject.save`）にまとめ、`maps\` の形式が変わってもここだけを直せばよいようにしています。

| ファイル | いつ書くか | 形式 |
|---|---|---|
| `maps\BB\MM.json`（バンク・マップは 2 桁） | ベース ROM と内容が違い、既存のファイルとも違うマップ。ベース ROM と同じに戻ったら消す。マップ名を変えたときは、同じ地名番号の全マップ | ND の `scripts/map_project.py` と BochiBochiEditor 改造版（`SaveCfruProject`）と同じ形式。下の表 |
| `maps\project.json` | 何か書くときに無ければ作る | `{"Format":1,"BaseBankCounts":[…]}`（ベース ROM のバンクごとのマップ数。字下げなし） |
| `maps\tilesets\<primary\|secondary>_<ヘッダーの位置 6 桁>\tileset.json` と `tiles.png` | ブロックエディタなどで変えたタイルセット。ベース ROM と同じに戻ったら消す | Bochi と同じ。`tileset.json` は `Format`・`HeaderAddress`・`Secondary`・`New`・`Header`・`TileCount`・`BlockCount`・`BlockBytes`・`BehaviorBytes`・`Compressed`・`ImageSha256`・`Palettes`・`Blocks`・`Behaviors`、`tiles.png` はタイルのインデックス PNG |
| `assembly\overworld_scripts\HiddenItem.s` | 落とし物（人の ItemBalls）が変わったとき | `@ BBE-BEGIN <識別子>`〜`@ BBE-END <識別子>` の生成範囲だけを作り直す（手書き部分は残す。Bochi と同じ）。ラベルは `HiddenItem_BB_MM_<識別子>` |
| `maps\scripts.json` | ツール > スクリプトファイルの対応表で表を変えたとき（変えていなければ触らない） | 「[eventscripts と maps\scripts.json](#eventscripts-と-mapsscriptsjson)」 |
| `assembly\overworld_scripts\<名前>.s` と `strings\<名前>.string` | 対応表の「新しい .s を作る」で足した行があるとき。既にあるファイルは書き換えない | `.s` は決まった先頭（「[scripts.json の編集画面](#scriptsjson-の編集画面)」）、`.string` は空 |
| `maps\regionmap.json` | タウンマップ・フライトポジションを変えたとき。全部ベース ROM と同じに戻ったら消す | 「[maps\regionmap.json](#mapsregionmapjson)」 |

JSON はどれも Bochi（.NET の System.Text.Json）と同じ整形です。2 空白の字下げ、改行は CRLF、末尾に改行 1 つ、バイト列は base64、文字列は ASCII の表示文字以外と `"` `&` `'` `+` `<` `>` と逆引用符を `\uXXXX` にします（`\` は `\\`）。同じタイルセットを使うマップはどれも、次に開いたときから `maps\tilesets` の内容で読みます。

`maps\BB\MM.json` の項目は次のとおりです（Bochi の `CfruMapSource` と同じ並び）。

| キー | 中身 |
|---|---|
| `Format`・`Bank`・`Number` | 1、バンク番号、マップ番号 |
| `Header` | マップヘッダー 28 バイト（0x00〜0x0F のポインタは 0） |
| `Footer` | マップフッター 28 バイト（0x08〜0x17 のポインタは 0） |
| `Layout`・`Border` | 配置と境界ブロック（1 マス 2 バイト。ブロック番号と移動許可） |
| `PrimaryTileset`・`SecondaryTileset` | タイルセットのヘッダーのポインタ値 |
| `MapName` | 地名の文字列（ROM の文字コード） |
| `EventHeader`・`Persons`・`Warps`・`Traps`・`Signs` | イベントの見出し（一覧のポインタは 0）と 4 種類の一覧（落とし物の人のスクリプトのポインタは 0） |
| `ConnectionsHeader`・`Connections` | コネクションの見出しと一覧 |
| `MapScripts`・`MapScriptLists` | マップスクリプトと、種類 2・4 の条件表（`TableOffset`・`Data`。表を指すポインタは 0） |
| `ItemBalls` | 落とし物（`Id`・`PersonIndex`・`ItemId`・`Label`） |
| `Wild` | 野生（`Time` と `Areas`。各エリアは `Rate` と `Slots`） |

構造体どうしをつなぐポインタはすべて 0 にして書き、ビルド（`map_project.py`）が作り直します。新しいマップは既存のバンクの末尾か、最後のバンクの次の新しいバンクにだけ置けます（[新規マップ・作成したマップ](#新規マップ作成したマップmap--evt)）。`.map` / `.evt` は出力ではなく、AdvanceMap と同じ作業用のファイルです（[.map / .evt の形式](#map--evt-の形式)）。

## 構成

pnpm の workspace です。

- `packages/core`: ROM の解析・描画・操作コマンド・出力（TypeScript。Node とブラウザの両方で動き、画面なしでテストできる）
  - `rom/`・`binary/`: ROM とバイト列の読み書き、LZ77、base64、16 進の表記（`formatHex`）
  - `map/`・`event/`・`connection/`・`mapscript/`・`wild/`・`fly/`・`name/`・`sprite/`・`regionmap/`: ROM の各データの読み書き（`*Codec` が構造体、`*Reader`・`*Table` が表）
  - `model/`: 編集中のマップ（`MapDocument`）とベース ROM からの読み込み
  - `tileset/`・`render/`: タイルセットの編集用データと描画（`BlockRenderer`、`renderBlocks`、`MapRenderer`）
  - `command/`: 操作コマンド（`commands/` に種類ごと）、`CommandBus`（実行・アンドゥ・リドゥ・履歴）、`CommandRegistry`（JSON の記録からコマンドを作る）、`CommandGroup`（複数のコマンドを 1 回の操作にまとめる。記録から作り直せる）、`DocumentStore`（編集中の状態）
  - `project/`: `maps\` の読み書き（出力の形式は全部ここ）。`amfile/` は AdvanceMap の `.map` / `.evt`
- `apps/desktop`: デスクトップアプリ（Tauri 2 + Vite + 素の TypeScript）
  - `src/app/`: アプリ全体（`App`）、状態（`EditorState`）、ROM とプロジェクト（`ProjectSession`、`TauriProjectFs`）、マップ一覧（`MapCatalog`、`MapTreeModel`）、メニューの定義とアクション（`menuDefinition`、`Actions`、`Shortcuts`）、設定（`Settings`、`SettingPrompts`、`SystemSettings`）、ファイル（`FileDialogs`）、自動操作（`automation/`）
  - `src/ui/`: メニューバー、ツールバー、マップ一覧、タブ、ステータスバー、画面内のダイアログ（`Dialog`、`MessageBox`、`InputDialog`）、Canvas の共通処理（`canvas.ts`）、`map/`（マップ表示・パレット・重ね描き）、`tabs/`・`event/`・`header/`・`wild/`・`connection/`・`newmap/`（タブとダイアログ。マップの外のイベントの帯は `event/OutsideEventsBar`、場所の設定のかんたん表示は `header/SimpleHeaderView`）、`form/`（16 進欄・スピン・コンボなどの入力部品と入力エラー）、`view/`（表示メニューの小窓。透明度のスライダー）、`help/`（ヘルプの窓。Markdown の変換 `markdown.ts` と文書の窓 `HelpViewer`）、`script/`（「スクリプトを開く」の入口 `ScriptEntry` と、スクリプトエディタのメイン側の窓口 `ScriptHost`）
  - `src/input/`: マウス操作（ブロック・移動許可の配置）
  - `src/windows/`: 別ウィンドウ。入口は `tool.html`（`src/tool.ts` → `startToolWindow.ts` の表でラベルから中身を選ぶ）。`block-editor/`・`palette-editor/`・`block-adjust/`（メインとの同期は `ToolWindowHost`・`ToolClient`・`protocol`）、`world-map/`（`WorldMapHost`・`WorldMapClient`）、`script-editor/`（スクリプトエディタ。機能ごとの拡張は `extensions/`）
  - `src/i18n/`: 文言、`src/styles/`: 部品ごとの CSS、`src/util/`: 小さな共通処理（外部のリンクを開く `externalLinks` など）、`src/assets/`: 画像（ツールバーの主人公のドット絵）
  - `test/`: 画面のうち DOM を使わない部分（メニューの構成、ショートカットの一覧、Markdown の変換、透明度の目盛り）の単体テスト
  - `src-tauri/`: Rust 側。ファイルの入出力、ウィンドウの管理、自動操作の入口（HTTP）、画面の撮影だけを受け持つ
- `scripts/`: ビルド・文言の生成と確認・計測、`tests/`: 自動操作の確認と比較テスト、`tools/`: AdvanceMap を動かすハーネスなど

編集はすべて `packages/core` の操作コマンドを CommandBus で実行します（別ウィンドウもコマンドの JSON をメインへ送り、メインが実行する）。ダイアログの中の下書き（コネクション・マップスクリプトの表など）は写しを編集し、「保存」でコマンドにします。例外は、作成したマップを `.map` に保存したときの名前とパスの記録（保存の結果で、取り消す対象ではない）です。

別ウィンドウを足すとき（Phase2 のスクリプトエディタなど）は、`src/windows/startToolWindow.ts` の表と `src-tauri/capabilities/default.json` の `windows` に足します。

## 開発

Node.js 22 以降、pnpm、Rust（1.96 以降）、WebView2 が必要です。

```sh
pnpm install
pnpm typecheck   # 型チェック（使っていない変数・引数もエラーにする）
pnpm test        # 単体テスト（core と、画面の DOM を使わない部分）
pnpm lint        # 型チェック + 文言の生成物の確認 + 文言の突き合わせ
scripts\build.cmd clippy   # Rust の lint（警告もエラーにする）
```

単体テスト（`packages/core/test`）には、出力の往復テストを含みます: マップを JSON にして読み直すと同じになること（`project.test.ts`。素の ROM では `realRomProject.test.ts` が全マップ）、全種類のコマンドを実行して出力し、開き直すと同じで、全部取り消すと JSON が消えること（`realRomEdit.test.ts`）、タイルセット・落とし物・新しいマップ・マップ名の出力（`editSave.test.ts`。漢字を含むマップ名（ND の `charmap.tbl` で漢字は `FC xx yy` の 3 バイト）を出力して読み直すテストも含む。`ZIGZAGU_TEST_ND_PROJECT` を入れると、NeoDark-CFRU の `charmap.tbl` そのもので確かめる）。

画面の文言は、改訂版 `apps/desktop/src/i18n/source/Japanese.ini`（UTF-8）に、補正 `apps/desktop/src/i18n/source/overrides.ini`（同じ書式、UTF-8）を重ねたものです。`scripts/gen-i18n.mjs` が「Japanese.ini → overrides.ini」の順にキー（節と番号）ごとに値を重ね、文言のモジュール `apps/desktop/src/i18n/ini.generated.ts` を作ります。`ja*.ts` は生成物の値を `ini.節["番号"]` で引いています。

- Japanese.ini はユーザーが用意した改訂版の写しなので、書き換えずにそのまま置きます。英語のまま・文字化け・機械翻訳のような値は overrides.ini で直します。各項目の上のコメントに、出どころ（旧版 = AdvanceMap 1.92 の日本語化パックの同じ番号の値／新規の案）と改訂版の値を書きます。
- overrides.ini には Japanese.ini にある節・番号だけを書けます（無い番号を書くと生成でエラーになります）。
- 言い回しを変えたいときは、overrides.ini を直すか（改訂版を差し替えるときは Japanese.ini を差し替えて）、生成し直し、生成物と一緒にコミットします。

```sh
node scripts/gen-i18n.mjs          # ini.generated.ts を作り直す
node scripts/gen-i18n.mjs --check  # ini・overrides.ini と生成物が合っているか確かめる
node scripts/check-i18n.mjs        # 文言の突き合わせ（下記）
```

`scripts/check-i18n.mjs` は、改訂版 Japanese.ini に overrides.ini を重ねた値を基準に、ini に無い番号の参照と、ini の値と同じなのに ini から引かず直接書いた文字列と、画面で使っている文言に残った英語だけの値・文字化け・タブ文字を探します（画面で使ってよい英語「OK」「BGM:」などは、スクリプトの `ALLOWED_ENGLISH` に理由を付けて書きます）。`--inventory <inventory のフォルダ> --old-ini <AdvanceMap 1.92 の Japanese.ini>` を付けると、AdvanceMap の画面を調べた部品表の文字列（1.92 の表記）を旧版の ini で番号に直し、アプリに対応が無いものも探します。意図した違いと番号の読み替え（改訂版で並びが変わったツールバーなど）は、スクリプトの `INTENTIONAL`・`RENAMED` に理由を付けて書きます（`--verbose` で一覧）。

- 値の中の AdvanceMap 1.95 向けの注記（「(AM1.95未使用)」「(※AM1.95使用不可)」）は外します。外し方は `scripts/gen-i18n.mjs` の `stripNote` だけで決めています。行末の空白も外します。
- 注記を外して空になった番号と、ini に無い番号は生成物に入りません。`ja*.ts` がそれを引いていると型チェック（`pnpm typecheck`）で止まるので、旧版の文言を直接書くか、ini に足してください。
- ルビー・サファイア・エメラルドの挙動や季節など、ZigzaguMap に該当する機能の無い節は出しません（`EXCLUDED_SECTIONS`）。

ROM が要るテストは、環境変数 `ZIGZAGU_TEST_ROM` に素の BPRJ のパスを入れたときだけ実行されます。ROM はリポジトリに入れません。

```powershell
$env:ZIGZAGU_TEST_ROM = "C:\path\to\BPRJ.gba"; pnpm test
```

ND のベース ROM と NeoDark-CFRU のフォルダを `ZIGZAGU_TEST_ND_ROM` と `ZIGZAGU_TEST_ND_PROJECT` に入れると、`maps\` の JSON を読むテストも実行されます（フォルダには書き込みません）。

ND と Chronos の実フォルダの写しを使うテストは `tests/realcopy` にあります（ローカルだけで動かす）。実フォルダと写し先のパスを `tests/realcopy/local.config.json`（コミットしない。見本は `local.config.example.json`）に書いて、`python tests/realcopy/run.py --smoke` を実行します。実フォルダを写し先へ写し（`build/`・`.git`・ベース ROM 以外の `.gba` などは除く）、ZigzaguMap（`--automation`）で写しを開いて何もせずに出力し、写しでビルドします（ND は CFRU の `python scripts/make.py`、Chronos はルートの `python build.py`）。実行の前後で実フォルダのファイルの更新日時が 1 つも変わらないことも確かめます。`--reuse` で前の写しをそのまま使い、`--dpe` で ND の DPE のビルドまで動かします。写し・起動・出力・ビルドの部品（`tests/realcopy/lib`）は、ほかのテストからも使えます。

コアライブラリを Node から使うときは `pnpm --filter @zigzagumap/core build` で `dist` を作ります（`@zigzagumap/core` と `@zigzagumap/core/node`）。マップを PNG に書いて確かめるには次のようにします。

```sh
pnpm --filter @zigzagumap/core dump-map -- <rom> 3 0 out.png --events
pnpm --filter @zigzagumap/core dump-map -- <rom> 3 0 out.png --project <CFRU-JP のフォルダ>
```

全マップの描画を AdvanceMap の「マップ画像の保存」と画素で比べるには、`tools/am-harness/export_map_images.py <フォルダ>` で AdvanceMap に全マップの画像（`m<バンク>_<マップ>.DIB`）を書かせてから、次を実行します（色は 5 ビットに落として比べ、違うマップとマスを出します）。

```sh
pnpm --filter @zigzagumap/core compare-map-images -- <rom> <フォルダ> [--json out.json]
```

アプリの起動とビルド:

```sh
cd apps/desktop
pnpm tauri dev     # 開発用に起動（自動操作の入口がポート 17890 で有効になる）
```

リリース用の exe は `scripts\build.cmd` で作ります（`apps/desktop/src-tauri/target/release/zigzagumap.exe`）。Visual Studio Build Tools の `vcvars64.bat` を読んでから `pnpm tauri build` を実行するので、cmd・PowerShell・Git Bash のどれからでも動きます（Git Bash だけで `pnpm tauri build` を実行すると、Git 付属の `link.exe` が先に見つかって失敗します）。

```sh
scripts\build.cmd          # リリースビルド
scripts\build.cmd debug    # デバッグビルド
scripts\build.cmd check    # cargo check だけ
scripts\build.cmd clippy   # cargo clippy（Rust の lint）
```

出力先を変えたいときは、環境変数 `CARGO_TARGET_DIR` を設定してから実行します（exe は `<CARGO_TARGET_DIR>\release\zigzagumap.exe` にできます）。

自動操作の入口（テスト用の HTTP の命令）は [docs/automation.md](docs/automation.md)、AdvanceMap との比較テストの回し方は [docs/compare-test.md](docs/compare-test.md) にあります。

## 性能

| 項目 | 目標 | 測り方 |
|---|---|---|
| 起動からマップ表示まで | 1 秒以内 | `scripts/measure-startup.mjs` |
| マップの切り替え | 100ms 以内 | `scripts/measure-startup.mjs`（`scripts\measure-memory.ps1` も出す） |
| 待機時メモリ（WebView2 込み） | 150MB 以下 | `scripts\measure-memory.ps1` の専用ワーキングセットの合計 |
| 配布物 | 10MB 以下 | `zigzagumap.exe` の大きさ |

Phase1 の終わり（2026-11-14、素の BPRJ）に測った値: 起動からマップ表示まで 中央値 750ms（5 回の最大 767ms）、マップの切り替え 中央値 27ms（50 回の最大 58ms）、メモリ（専用ワーキングセットの合計）は起動直後 75MB・ROM を開いた後 105MB・マップを 10 枚切り替えた後 114MB・ブロックエディタを開いた後 146MB・閉じた後 116MB、exe 3.6MB です。

Phase1 のフィードバックを入れたあと（2026-11-14、素の BPRJ）に測り直した値: 起動からマップ表示まで 中央値 867ms（9 回の最大 948ms）、マップの切り替え 中央値 28ms（90 回の最大 55ms）、メモリ（専用ワーキングセットの合計）は起動直後 77MB・ROM を開いた後 104MB・マップを 10 枚切り替えた後 134MB・ブロックエディタを開いた後 149MB・閉じた後 116MB、exe 3.6MB です。同じ時に Phase1 の終わりの exe を測ると起動は中央値 842ms だったので、起動の差は PC の混み具合によるものです。

スクリプトエディタ（CodeMirror 6）を入れたあと（2026-11-14、素の BPRJ と ND のプロジェクトフォルダの写し）: 起動からマップ表示まで 中央値 889ms（5 回の最大 970ms）、マップの切り替え 中央値 29ms（50 回の最大 49ms）、メモリ（専用ワーキングセットの合計）は ROM とプロジェクトを開いた後 106MB・マップを 10 枚切り替えた後 140MB・ブロックエディタを開いた後 149.5MB・閉じた後 119MB・スクリプトエディタを開いた後 136MB・閉じた後 114MB、exe 3.8MB（3,963,904 バイト）です。エディタの束は minify 後 296KB（gzip 96KB）で、エディタのウィンドウを開いたときだけ読み込みます。

### 起動とマップ切り替えの時間

`scripts/measure-startup.mjs` で測ります。毎回、一時フォルダの `--profile` に前回のマップ（3.0）を覚えた設定を置き、`zigzagumap.exe --automation <ポート> --profile <一時フォルダ> <ROM>` で起動して（画面外・非アクティブ。通常の設定には触れない）、exe を起動してからマップを描き終えるまで（画面側の記録 `mapShown`）を測ります。続けてマップを 10 枚切り替え、自動操作の `selectMap` の返事の `switchMs`（読み込み・描画・一覧の更新まで）を集めます。

```sh
node scripts/measure-startup.mjs --exe <zigzagumap.exe> --rom <素の BPRJ> [--port 17996] [--runs 5]
```

### メモリ

待機時メモリ（目標 150MB 以下、WebView2 込み）は `scripts\measure-memory.ps1` で測ります。exe を `--automation` と一時フォルダの `--profile` で起動し（画面外・非アクティブ。通常の設定には触れない）、起動直後／ROM を開いた後（3.0）／マップを 10 枚切り替えた後／ブロックエディタを開いた後／閉じた後の 5 場面で、それぞれ 10 秒待ってから測ります。`-Project <CFRU-JP のフォルダの写し>` を付けると ROM と一緒に開き、スクリプトエディタを開いた後／閉じた後の 2 場面も測ります（開くファイルは `-ScriptFile`、省略で `assembly\overworld_scripts` の最初の `.s`。フォルダには書き込みません）。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\measure-memory.ps1 -Exe <zigzagumap.exe> -Rom <素の BPRJ> [-Port 17995] [-Out result.json]
```

- exe とその子孫（WebView2 のブラウザ・レンダラー・GPU・ユーティリティ・crashpad）を、種類ごとに「専用ワーキングセット」「プライベート（コミット）」「ワーキングセット」で出します。目標は **専用ワーキングセットの合計** で判定します（タスクマネージャーの「メモリ」の列と同じ値。ワーキングセットは共有ページを二重に数えるので合計に向かない）。メインの JavaScript のヒープ（`state` の `jsHeap`）、入口が応答するまでの時間、マップ切り替えの時間も出します。
- `-Baseline -Exe <webview-baseline.exe> -BrowserArgs "<引数>"` で、WebView2 の空のウィンドウだけの値（下限）を同じ方法で測ります（`tools\webview-baseline` を `CARGO_TARGET_DIR` を設定してから `build.cmd` でビルド）。
- `-BrowserArgs` を付けると、WebView2 に引数を足して試せます（環境変数 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`）。

WebView2 には、計測で効果のあった引数だけを付けています（`src-tauri/src/lib.rs` の `BROWSER_ARGS`）: `--disable-gpu`（GPU プロセスの約 50MB が無くなる。Canvas 2D と合成はソフトウェアで行い、描画とマップ切り替えの速さは変わらない）、`--enable-features=NetworkServiceInProcess2`（ネットワークのプロセスをまとめる。約 5MB）。

### 配布物

配布物は `zigzagumap.exe` 1 つです（画面のコードと文言は exe に入っています。WebView2 は Windows のものを使う）。大きさは `scripts\build.cmd` で作った exe のファイルの大きさで判定します。
