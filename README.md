# ZigzaguMap

CFRU-JP 用のマップエディタです。AdvanceMap 風の操作で、ファイアレッド日本語版（BPRJ）のマップを編集し、`maps\` の JSON として書き出します。ベースROMには書き込みません。仕様は [docs/SPEC.md](docs/SPEC.md) を参照してください。

## 使い方

- **ROM を開く**: ファイル > ROMを開く（Ctrl+O）か、`.gba` をウィンドウにドラッグ＆ドロップします。素の ROM だけでも閲覧と編集ができます。
- **プロジェクトを開く**: ファイル > CFRU-JPのフォルダを開く で CFRU-JP のフォルダを選びます。ベース ROM は、開いている ROM か、以前そのフォルダと組で開いた ROM を使い、どちらも無ければ選ぶよう求めます。フォルダのドラッグ＆ドロップでも開けます。`maps\BB\MM.json` があるマップはそちらを読みます。
- **最近開いたもの**: ファイルメニューの下に出ます（ROM とフォルダの組で覚えます）。個人設定は `%APPDATA%\io.github.pit-true.zigzagumap\settings.json` に保存します。
- 起動引数で開くこともできます: `zigzagumap.exe [--project <フォルダ>] <ROM>`。「最後に選択したものを覚える」がオンなら、前回のマップとタブを開きます。
- **マップを開く**: 左の一覧の項目をダブルクリックか Enter（AdvanceMap と同じく、選ぶだけでは開きません）。ツール > マップを指定して開く（Ctrl+M）、以前開いたマップを開く（Alt+BkSp）も使えます。
- **元に戻す・やり直す**: Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z も可）。AdvanceMap の「オブジェクトの表示」の Ctrl+Z は、アンドゥに使うため外しています。
- **出力**: ファイル > 出力（Ctrl+S）。素の ROM だけを開いているときは、最初に出力先のフォルダを選びます。ファイル > 出力先を指定して出力 で別のフォルダへ書くこともできます。ファイル > バックアップの作成 も「出力先を指定して出力」と同じです。
- **ROM でないファイル**を開くと、AdvanceMap と同じ「AdvanceMapError(12): Unknown Rom Type! …」を出し、開いていたものはそのまま残します。
- **画像の保存**: ツール > マップ画像の保存／マップ&イベント画像の保存／パレット画像の保存。AdvanceMap と同じ 24 ビットの DIB（BMP と同じ形式）で書きます。マップ画像はブロックだけ（境界ブロックとイベントは含まない）、マップ&イベント画像はイベントの印（オブジェクトの表示がオンなら OW 画像）を重ねたもの、パレット画像はブロックパレット全体（今の横幅、等倍）です。拡張子を付けなければ `.DIB` を足します。AdvanceMap はイベントタブ以外でマップ&イベント画像を保存すると 0 バイトのファイルになりますが、ZigzaguMap はどのタブでもイベントを重ねた画像を書きます。
- **ヘルプ**: ZigzaguMapについて（F1、ツールバーの「?」）、エンドユーザー規約（F2。ZigzaguMap のライセンス）、Read me（この README）。

### マップタブ（マップの設定）

| 操作 | 動作 |
|---|---|
| 左クリック | 選択中のブロックを置く（移動許可は変えない）。スタンプなら押したマスを左上にして全体を置く |
| 左ドラッグ | 通ったマスに置く（1 回の操作にまとまり、1 回のアンドゥで戻る）。スタンプはドラッグしても 1 回だけ置く |
| 右クリック／右ドラッグ | 離したマスのブロックを拾う（パレットが追従してスクロール） |
| Ctrl＋右ドラッグ | 矩形を複数ブロック（スタンプ）として選ぶ。パレット上でも同じ |
| パレットの左・右クリック | ブロックを選ぶ |
| 境界ブロックの左クリック／右クリック | 置く／拾う |

Ctrl＋右ドラッグ（Ctrl＋右クリック）でスタンプを選ぶと、選んだ範囲を等倍で出す小さな窓「Grosser Block」が開きます（× で閉じる。題名の帯をつかんで動かせます）。

設定 > グリッドの表示（Ctrl+G）、設定 > 表示サイズ で 2 倍表示、設定 > ブロックパレットの横幅（Ctrl+P）でパレットの 1 行の数を変えられます。

### 移動エリアタブ（移動エリアの設定）

移動許可の値を色つきで重ね、値を 16 進で描きます。右のパレットで値を選び、左クリック・左ドラッグで書き、右クリックで拾います。設定 > 移動エリアの設定の透明度 の値は AdvanceMap と同じく「マップ側の重み」です（既定 0.3 で、色 70%・マップ 30%）。

### イベントタブ（イベントの設定）

マップのイベントを文字の箱（P=人、橙の S=看板、W=ワープ、緑の S=スクリプト、F=フライトポジション）で描き、右のパネルで選んで編集します。どの編集も Ctrl+Z / Ctrl+Y で戻せます。

| 操作 | 動作 |
|---|---|
| 箱をクリック（左右どちらのボタンでも） | そのイベントを選ぶ。同じマスに重なっていれば、フライトポジション > 看板 > スクリプト > ワープ > 人 の順に上のものを選ぶ |
| 箱をドラッグ | イベントを動かす（1 回のドラッグが 1 回のアンドゥ）。マップの外へも動かせる |
| 箱をダブルクリック | ワープは「マップの移動」、看板・スクリプト・人は「スクリプトを開く」と同じ |
| 種別コンボ・イベント番号 | 選ぶイベントを変える。種別はマップを切り替えても保ち、番号は 0 に戻る |
| 選択カーソルの表示 | 選択中のイベントの赤い枠を出す・消す |
| イベントの削除 | 選択中のイベントを消す（後ろが前に詰まる） |
| イベント数の設定: | 人・看板・ワープ・スクリプトの数を変えて「イベント数の変更」。増やした分は値が全部 0 のイベントを末尾に足し、減らした分は末尾から消す。イベントの無いマップにも作れる |
| マップの移動（ワープ） | 行き先のマップを開き、行き先のワープを選ぶ。無いマップなら「指定したマップは存在しません！」 |
| スクリプトを開く | 設定 > スクリプトエディタの選択 のエディターを `"<エディター>" "<ROM>" 16F884` の形で起動する（ROM とオフセットの区切りは設定により空白か「:」。起動のしかたは場所の設定タブと同じで、「:」のときは `"<ROM>:16F884"` になる）。未設定なら「No script editor defined.」 |

- 欄の値は入力のたびに反映します（確定ボタンはありません）。同じ欄に続けて入力した分は、1 回のアンドゥでまとめて戻ります。
- 16 進の欄は AdvanceMap と同じく `$` を前に付けて読みます。空欄は 0、あふれた桁は切り捨てます（4 桁の欄の 10000 は 0）。読めない文字を入れると `'$ZZ' is not a valid integer value.` を出し、値は変えません。10 進のスピンは範囲の端に丸めます（300 は 255）。
- スクリプトのオフセットは下位 3 バイトだけを書き、上位 1 バイトは元のままです。
- 看板のイベントタイプが 05〜08 のときは、オフセットの代わりにアイテム ID・隠し ID・個数を出します。
- フライトポジションは ROM の表を読んで表示・編集できますが、`maps\` の形式に置き場所が無いため出力しません。
- 人の落とし物（ItemBalls）は画面では変えません。ほかの欄を編集しても、落とし物は保ったまま出力します。
- マップの外にイベントがあると、ステータスバーの右欄に「ノート:イベントがマップの外に配置されています」を出します。
- 設定 > オブジェクトの表示（ツールバーの主人公のボタン）をオンにすると、AdvanceMap と同じく人を ROM の OW 画像（下向きの 1 コマ目）で描き、人以外の箱は描きません。

AdvanceMap と違う点:

- 「マップの移動」で、行き先のマップの、ワープ No. のワープを選びます（AdvanceMap は番号 0 を選ぶ）。
- 未出力の変更があっても、「マップの移動」の前に確認しません（ZigzaguMap はマップごとの変更を持ったまま切り替えるため）。
- アイテム ID の名前は ROM の文字コード表で読みます（AdvanceMap では一部が文字化けする）。
- ポインタが 0 のイベントにスクリプトのオフセットを入れたときは、上位 1 バイトを 08 にします。

### 「保存」ボタンの読み替え

AdvanceMap で ROM へすぐ書き込む「保存」ボタン類（マップ名の変更を保存、マップスクリプトの変更、タイルセットの変更、保存してマップの再読み込み、コネクションの保存、設定の保存など）は、同じ場所に置き、押すと**編集中の状態へ反映**します。ROM には書かず、ファイル > 出力（Ctrl+S）でまとめて `maps\` へ書き出します。反映はどれも 1 回の操作として Ctrl+Z / Ctrl+Y で戻せます（1 回押して複数の項目が変わるときも 1 回のアンドゥで戻ります）。

### 場所の設定タブ

設定 > 高度なヘッダーを表示（Ctrl+H、初期はオン）で、通常表示と高度な表示を切り替えます（個人設定に残ります）。

通常表示:

| 枠 | 動作 |
|---|---|
| 名前: | 左のコンボは名前表（地名番号 0x58〜0xC4）の一覧。選ぶと右の欄に名前が入ります（このマップの地名番号は変えません）。「マップ名の変更を保存」は、コンボで選んでいる名前表の項目を書き換えます（同じ地名番号の全マップの名前が変わり、出力ではそれらの JSON を全部書きます）。文字はプロジェクトの `charmap.tbl`（無ければ同梱の表）で変換します。「Create new name」は AdvanceMap と同じく無効です |
| マップ名の表示/タイプ | ヘッダーの 0x19（名前表示・ダッシュ・穴抜け）。選ぶとすぐ反映します |
| マップオプション: | BGM（コンボと 16 進 4 桁の「No.」が連動。一覧に無い値ではコンボが空）、フラッシュ、天候、タイプ、戦闘背景の強制上書き。選ぶ・入れるとすぐ反映します。選択肢は改訂版 Japanese.ini と `Musik_jap.ini` の [Musik_BPR] のとおりで、表に無い番号は「0n ???」 |
| マップスクリプト | スクリプトNo. の上下で切り替え、種類・オフセットを変えます。種類 02・04（条件表）では、表の先頭の行を「イベント変数・イベント変数の値・スクリプトオフセット2」に出します（オフセット欄は無効で `$000000`）。追加・削除（確認なし）・欄の変更はメモリ上の表に対して行い、「マップスクリプトの変更」で反映します。種類「00 スクリプト未設定」のまま保存するとエラーです（一覧の終端と同じ値で保存できないため） |
| 使用するタイルセット: | 番号（AdvanceMap のタイルセット番号 0〜67）を入れて「タイルセットの変更」。確認なしで差し替えてマップを描き直します（合わないタイルセットでは絵が崩れるのも同じ） |
| マップのサイズ: | 横幅・高さを入れて「マップサイズの変更」。左上を基準に伸縮します。0 と空欄は無視します |

高度な表示:

| 枠 | 動作 |
|---|---|
| マップヘッダーの設定: | マップバンクテーブル、バンク番号、マップ番号、バンクの一覧、マップヘッダーの位置（すべて読み取り専用） |
| マップヘッダーデータ: | マップヘッダー 28 バイトの 16 進と、フッター・イベント・マップスクリプト・コネクションの位置。16 進を書き換えると「保存してマップの再読み込み」が押せ、0x10 以降の設定を反映します |
| マップフッターデータ: | フッター 28 バイトの 16 進と、横幅・高さ・タイルセット番号・境界ブロックの大きさの欄が連動します（タイルセット番号を変えるとタイルセットのオフセットも変わります） |
| 境界データ: | 境界のブロックの値（16 進）。変えると画像がすぐ変わります。「マップフッターデータ」の保存で一緒に反映します |
| タイルセットデータ: | 主・副タイルセットのヘッダー 24 バイトの 16 進。保存で圧縮フラグ・副フラグ・アニメーション関数などを反映します |

**オフセット欄の表示**: ZigzaguMap は ROM へ書かないので、ROM 上の位置が意味を持つのは「ベース ROM から読み、`maps\` の JSON が無いマップ」だけです。そのマップではベース ROM 上の位置を出します。JSON から読んだマップや新しく作ったマップでは、ヘッダー・フッターとその先のデータの位置を、AdvanceMap が未設定の位置に使う書式 `$000000` で出します（16 進欄のポインタ部分も 0）。バンク表とバンクの一覧は、ベース ROM にあるバンクなら出します。ポインタと位置は表示だけで、保存しても読み捨てます（出力時に作り直すため）。

### マップコネクション

ツール > マップコネクション（Ctrl+A）かツールバーの矢印アイコンで開きます（常に手前に出るダイアログで、メインの画面も操作できます）。

- コネクションNo. の上下で切り替え、方向（無し・下・上・左・右・ダイビング・浮上）、調整、バンク番号、マップ番号、不明（16 進）を変えます。
- 「追加」は方向 無し・調整 0・バンク 0・マップ 0 を末尾に足します（確認なし）。「削除」は「コネクションNo.nを削除しますか？」と聞きます。ここまではメモリ上の表に対して行い、「保存」で反映します。保存せずに閉じる・別のマップへ移ると変更は捨てます。
- 左の矢印ボタンは、その方向の 1〜3 番目のコネクションがあるときだけ押せます（2・3 番目の帯はあるときだけ出ます）。押すと相手のマップを開き、ダイアログも開いたマップのコネクションに切り替わります。
- 範囲は確かめず、書くときに切り詰めます（バンク・マップは 1 バイト、不明は 2 バイト。AdvanceMap と同じく -3 や 300 も入ります）。

### 野生ポケモンの設定タブ

- タイプ（草むら・水上・岩砕き・釣り）を選ぶと、そのタイプのエンカウント率と各枠（草むら 12、水上 5、岩砕き 5、釣り 10）を出します。データの無いタイプでは部品を隠し、「設定の保存」は押せません。タイプを切り替えると保存していない編集は捨てます。
- エンカウント率の欄・トラックバー・百分率（値÷255 の切り捨て）が連動します。0〜255 に丸め（300 → 255、-5 → 0）、`0x10` や `$10` の 16 進も受け付けます。トラックバーは矢印キーで 1、PageUp / PageDown で 25、Home / End で両端へ動きます。
- 最小・最大 Lv は検査せず、反映するときに 1 バイトに切り詰めます（300 → 44）。空欄は元の値のままです。種族はコンボから選びます（0 番は「選択してください」）。
- 「設定の保存」で、表示中のタイプのエンカウント率と各枠を反映します。
- 野生データの無いマップでは、野生データが無いという文言（[Allgemein] 941）と「野生ポケモンの追加」を出します。「野生ポケモンの追加」「タイプの追加」のダイアログで使うタイプにチェックを入れて OK を押すと、そのタイプを初期値（確率 0、全枠 Lv 1/1、「選択してください」）で作ります。何もチェックせずに OK を押すと「野生ポケモン設定の追加/変更を中止しました！」と出します。チェックを外したタイプのデータは消えます。
- 種族名は ROM の種族名表から読みます。読めない間は `No.番号` で出します。

### 入力エラー

数値欄に整数として読めない文字を入れると、AdvanceMap と同じ「'abc' is not a valid integer value.」（16 進欄は `'$zzzz' is …`）を出します。AdvanceMap は 1 文字入れるたびに確かめますが、ZigzaguMap は欄を確定したとき（Enter・フォーカスを外したとき・ボタンを押したとき）に確かめます。ほかのエラーの文言は改訂版 Japanese.ini（ini に無いものは AdvanceMap）に合わせています（タイルセット番号が表に無い: 「AdvanceMapError(1): Try to read at pos 0! …」、大きすぎるマップ: 「マップの横幅200の時のマップの高さの最大サイズは33です」、フッターの 16 進が不正: 「マップフッターに無効なポインタが設定されています！」）。

### AdvanceMap と違うところ（場所の設定・マップコネクション・野生ポケモンの設定）

- 「保存」は ROM ではなく編集中の状態へ反映します（上記）。
- タイルセット番号に表に無い番号（9999 など）を入れたときは、AdvanceMap は受け付けて崩れた絵を出しますが、ZigzaguMap は指せるタイルセットが無いのでエラーにします。マップの横幅に -1 を入れたとき、AdvanceMap は落ちますが ZigzaguMap はエラーにします。
- 高度なヘッダーの位置・ポインタは表示だけです。不正な 16 進を保存したとき、AdvanceMap は続けて「AdvanceMapError(1)」も出してヘッダーを壊しますが、ZigzaguMap は最初のエラーだけを出して何も変えません。
- マップコネクションの矢印ボタンの有効・無効は、下書きの表の方向から決めます（AdvanceMap は方向を変えたときに表と合わない状態になることがあります）。
- 「スクリプトを開く」は、設定 > スクリプトエディタの選択 で選んだ exe に、ベース ROM のパスとオフセットを渡します（maps\ の JSON から読んだマップでは、ベース ROM 上のオフセットと一致しないことがあります）。選んでいなければステータスバーにオフセットを出します。

### ブロックエディタ（ツール > ブロックエディタ、Ctrl+B）

マップを開いているときに、別ウィンドウで開きます（題名は「ブロックエディタ     第1部: N  第2部: M」）。左から、ブロック一覧（主の 640 個のあとに副）、ブロックの編集面とタイル一覧（1024 タイル。主 0x000〜、副 0x280〜）、マップデータです。

| 操作 | 動作 |
|---|---|
| ブロック一覧の左・右クリック | ブロックを選ぶ。8 マス（左が下層、右が上層）と属性 4 バイト、ブロック（16 進 3 桁）、オフセット（ベース ROM でのブロック定義の位置）を出す |
| タイル一覧の左・右クリック、ドラッグ | タイルを選ぶ（離した位置）。タイル欄とプレビューに出す |
| 8 マスの左クリック | 選んでいるタイル・X反転・Y反転・パレットを置く |
| 8 マスの右クリック | そのマスのタイル・X反転・Y反転・パレットを拾う |
| Palette0〜12 | タイル一覧とプレビューの色。置くタイルのパレット番号にもなる。パレットエディタと連動する |
| マップデータ | 上の 2 欄が属性の 0・1 バイト目、下の 2 欄が 2・3 バイト目（16 進）。0 バイト目は挙動のコンボ、3 バイト目は背景のコンボと連動する。16 進でない文字は「'$zz' is not a valid integer value.」 |
| 変更 | 選んでいるブロックの 8 タイルと属性を、編集中の状態へ確定する（AdvanceMap は ROM へ書く）。メインのマップ表示とブロックパレットがすぐ描き直される |

メニュー:

- 画像 > タイルセット1/2をファイルに保存する: 選んでいるパレットの色で 24 ビットの DIB（横 128、主 640 タイル・副 384 タイル）と、同じ名前の `.pal` を書きます（AdvanceMap と同じバイト列）。パレットに同じ色が 2 つ以上あると「Export of this palette not possible; …」を出して書きません。
- 画像 > タイルセット1/2にファイルから読み込む: DIB・BMP（1/4/8/24/32 ビット）と、インデックス PNG を読みます。色番号が 15 以下のインデックス画像は番号をそのまま、24 ビットの画像は選んでいるパレットの同じ色（無ければ一番近い色）にします。上限を超えるタイルは捨てます。
- 画像 > ブロックの再読み込み: メインから写しを取り直し、選んでいるブロックの編集中の値を捨てます。
- ブロック > タイルセット1/2をファイルに保存する・ファイルから読み込む: `.bvd`（ブロック数 u32、ブロック定義 16 バイト × 数、属性 4 バイト × 数、末尾 `FRLG`。Porymap の AdvanceMap 1.92 用の読み込みと同じ形式。末尾が `RSE ` の 2 バイト属性も読める）。開くとブロック数も `.bvd` の数になります。
- ブロック > ブロック数の追加/変更: タイルセット 2 のブロック数（上限 384 に丸める）。
- パレット > パレットエディタの表示／Change palette definition of block data: それぞれ別ウィンドウで開きます。
- パレット > パレットの変更を反映する: パレットエディタの「変更」で一時適用した色を、編集中の状態へ確定します（AdvanceMap の「パレットの変更をROMに上書きする」）。
- パレット > 現在のパレットをファイルに保存する・ファイルから読み込む: `.pal`（16 色 × `R, G, B, 0`）。開いた色は一時適用の扱いで、「パレットの変更を反映する」で確定します。

### パレットエディタ

16 色の見本を押して色を選び、赤・緑・青のスライダー（0〜31。右の数字は 8 倍）で変えます。15 ビットの値（`青<<10 | 緑<<5 | 赤`）を入れて「15bit to RGB」でも変えられます（最上位ビットは無視、16 進でなければ「'$ZZZZ' is not a valid integer value.」）。「変更」でブロックエディタのタイル一覧・8 マス・プレビューに出ます（ブロック一覧とメインは確定するまで変わりません）。「色の選択」を押すと、100ms ごとにマウスカーソルの下の画面の色を拾い、左ボタンを押したところで止めます（Esc かもう一度押しても止まる）。

### ブロックパレット一括変更

タイルセット 1 か 2 を選び、右の欄にパレットの変更先を入れて「Modify」を押すと、そのタイルセットの全ブロックのパレット番号を置き換えて閉じます（確認なし）。

### 別ウィンドウと編集中の状態

- 別ウィンドウ（ブロックエディタ・パレットエディタ・ブロックパレット一括変更）は Tauri の本物のウィンドウで、ワールドマップエディタと同じく中身は同じ `index.html` から、ウィンドウのラベルを見て組み立てます。エディタのコードは開いたときに初めて読み込み、閉じると WebView ごと破棄します。メインの起動では読み込みません（メイン側の窓口 `windows/ToolWindowHost.ts` も初めて開くときに読み込みます）。
- 編集中の状態（CommandBus とタイルセット）はメインウィンドウだけが持ちます。別ウィンドウはイベント `tool-request` で操作（コマンドの JSON）を送り、メインがそれを CommandBus で実行します。アンドゥ・リドゥはメインと同じ履歴に入り、どのウィンドウでも Ctrl+Z / Ctrl+Y（Ctrl+S は出力）で戻せます。
- タイルセットが変わると（どのウィンドウの操作でも、アンドゥでも）、メインは開いている別ウィンドウへイベント `tool-message` でタイルセットの写しを送り直します。選んでいるパレットと一時適用した色も、メインが持ってウィンドウどうしで共有します。
- マップを切り替えると、別ウィンドウはそのマップのタイルセットに追従します。ROM を開き直したときとマップを閉じたときは閉じます。
- 未出力のタイルセットの変更があるときも、閉じる・別の ROM を開くときに「変更を出力しますか？」と聞きます。

### AdvanceMap と違うところ（ブロックエディタ）

- 「変更」「パレットの変更をROMに上書きする」（改訂版の ini では Write palette changes to ROM）「Modify」「ブロック数の追加/変更」は ROM へ書かず、編集中の状態へ反映します（出力で `maps\tilesets\` に書く）。メニューの文言は「パレットの変更を反映する」にしました。
- 8 マスに置くタイルのパレット番号は、選んでいるパレットにします（AdvanceMap では反映されない場合があり、条件は分かっていません）。右クリックで拾うとパレットも拾います。
- タイルセット画像・`.bvd` の読み込みは、AdvanceMap では「Invalid filename.」で失敗しますが、ZigzaguMap では読み込めます。
- 一括変更の右の欄は 10 進で読みます（表の初期値が 10 進のため。数でなければ AdvanceMap と同じエラー）。

## 画面の構成

AdvanceMap 1.92 日本語版に合わせています。文言は、AdvanceMap 1.95 の言語ファイルをもとに改訂した Japanese.ini（リポジトリの `apps/desktop/src/i18n/source/Japanese.ini`）を基準にします。AdvanceMap の文言は ini から引き、ZigzaguMap 独自の文言（「出力」など）だけを `apps/desktop/src/i18n/ja*.ts` に直接書きます。作り直し方は「開発」を見てください。

- 上: メニューバー（Alt でフォーカス、矢印キーで移動、Enter・アクセスキーで実行、Esc で閉じる）、ツールバー（AdvanceMap と同じ並び。アイコンは自作の SVG）
- 左: マップ一覧（根は「ヘッダー」「iniファイル」「マップファイル」。並べ替えはツールバーのコンボか 設定 > マップリスト > ヘッダーのソート）と ROM 情報。境目の分割バーで幅を変えられます。設定 > コンボボックス をオンにすると、左の欄の代わりにツールバーの下へ「マップ名」と「マップ」のコンボが出ます（マップを選ぶと開く）。設定 > ツールバーの表示（Ctrl+T）でツールバーを隠せます
- 中央: タブ（マップの設定／移動エリアの設定／イベントの設定／野生ポケモンの設定／場所の設定）
- 下: ステータスバー（左: 座標・ブロック番号・移動許可の説明など、右: 読込時間やノート）
- 未出力のマップは、一覧の名前の後ろに ` *` が付きます。未出力のまま閉じる・別の ROM を開くときは「変更を出力しますか？」と聞きます
- 入力ダイアログ・確認・エラーは画面内に出します（Windows 標準のメッセージボックスと同じ並び）。ファイルやフォルダを選ぶダイアログだけは Windows 標準です
- まだ作っていないメニュー項目も全部置いてあり、押すとステータスバーに「未実装: 項目名」と出ます

## ワールドマップエディタ

ツール > ワールドマップエディタ（Ctrl+W、ツールバーの緑のアイコン）で、タウンマップ（空を飛ぶの地図）を別ウィンドウで開きます。初めて開いたときにベース ROM と `maps\regionmap.json` を読みます。画面の構成は AdvanceMap 1.92 の TWeltkarteForm と同じです（AdvanceMap は素の BPRJ では開けず、地図も黒いままですが、ZigzaguMap では地図の絵と全ての表を読めます）。

| 部分 | 動作 |
|---|---|
| 世界地図 | 左クリック（ドラッグしたときは離したマス）で位置を選び、そのマスの値を基本レイヤー・トップレイヤーの欄に読み込む。開いたときは、メインで開いているマップの地名の位置を選ぶ |
| エディットレイヤーの表示 / フライトポジション/人IDの表示 / トップレイヤーの座標を読み込む | 地名のあるマスの色、地名の位置の白い点、トップレイヤー（洞窟）のマスを重ねて描く。3 つ目を外すとトップレイヤーの欄は「未設定/非表示」 |
| マップ（16 進）・地名の一覧 | 地名を選んで、名前のオフセット・名前・座標・幅/高さ・人ID・フライトポジションを表示する。16 進でない入力は「'$zz' is not a valid integer value.」 |
| ポジションの保存 | 座標・幅/高さ・名前（基本レイヤーはフライトポジションも）を確定する。名前はマップ名表の書き換えなので、同じ地名番号の全マップの名前が変わる |
| フラグの保存 | 人ID（訪問フラグ。無しは FFFF）を確定する |
| マップの保存 | 選んでいるマスに、欄のマップの値を置く。置いていない値があるままタウンマップNo を切り替えると「ワールドマップの変更を保存しますか？」 |
| フライトポジション マップ/座標、このマップを開く | 左は空を飛ぶの行き先 3 バイト（バンク・マップ・飛び先の番号）、右は飛び先 6 バイト（バンク・マップ・X・Y）を ROM の並びの 16 進で出す。ボタンで行き先のマップをメインウィンドウで開く |
| タウンマップNo | 1: カントー、2: 1〜3のしま、3: 4〜5のしま、4: 6〜7のしま。「ワールドマップ番号の管理」は AdvanceMap と同じく押せない |
| ルーチンの変更 | ROM を書き換えないので、AdvanceMap の書き換え済みのときと同じ質問だけを出して何もしない |
| 再読み込み | 編集中の状態を読み直し、欄の入力を捨てる |

表の部分の名前は旧版の日本語訳です。画面の文言は改訂版 Japanese.ini の [WorldMapEditor] のとおりで、今は英語です（「Save map」「Save position」など）。

AdvanceMap の「保存」は、ZigzaguMap では編集中の状態への確定です。確定した操作はメインの履歴に積まれ、エディターの中でも Ctrl+Z / Ctrl+Y（入力欄の外）で取り消し・やり直し、Ctrl+S で出力できます。

### maps\regionmap.json

タウンマップの変更は `maps\regionmap.json` に書きます。ベース ROM と違う表だけを、項目ごとの読める形（base64 ではない）で書き、全部ベース ROM と同じに戻ったらファイルを消します。字下げは 2 空白、改行は CRLF です。

| キー | 中身 | ROM の表（BPRJ。括弧は表を指すポインタの位置） |
|---|---|---|
| `Format` | 1 | |
| `Layouts` | 変えた面・レイヤーだけ。`Page`（`kanto` / `sevii123` / `sevii45` / `sevii67`）、`Layer`（`map` = 基本レイヤー / `dungeon` = トップレイヤー）、`Rows`（15 行、各行は地名番号の 16 進 2 桁を空白区切りで 22 個） | u8[2][15][22] を 4 面: 0x3B9018・0x3B92AC・0x3B9540・0x3B97D4（0xC5378・0xC5380・0xC5388・0xC53B0、GetMapNo） |
| `Positions` | 地名 0x58〜0xC5 の全 110 件。`Id`（`"0x58"`）、`X`、`Y` | s16[n][2]: 0x3B89E8（0xC4F20、SetMapNo_and_Pos） |
| `Sizes` | 同じ 110 件。`Id`、`Width`、`Height` | u16[n][2]: 0x3B8D00（0xC4F1C） |
| `FlyDestinations` | 地名 0x58〜0xC3 の全 108 件。`Id`、`Bank`、`Map`、`HealLocation`（0 なら飛び先を使わずマップの真ん中へ） | u8[108][3]: 0x3B9A68（0xC648C、FlyDestination） |
| `HealLocations` | 飛び先 1〜20 の全件。`Index`、`Bank`、`Map`、`X`、`Y` | 8 バイト × 20: 0x3B5944（0xC0E94 の値 + 8、GetWarpPosByNo） |
| `MapVisitFlags` / `DungeonVisitFlags` | 地名 0x58〜0xC5 の全 110 件。`Id`、`Flag`（`"0x0890"`、無ければ null） | 表ではなく GetMapState（0x0C47C0）/ GetCaveState（0x0C4A5C）の switch 文。取り込むには表を引く命令への書き換えが要る |

名前は `regionmap.json` には書かず、ほかのマップ名の変更と同じく、その地名番号を使うマップの `maps\BB\MM.json` に入ります。地図の絵（タイル・パレット・タイルマップ）は読むだけで編集しません。

## 出力の仕様

- 書き出し先は `maps\BB\MM.json`（バンク・マップは 2 桁。ND の `scripts/map_project.py` と BochiBochiEditor 改造版と同じ形式）。
- 書くのは、ベース ROM と内容が違い、既存のファイルとも違うマップだけです。ベース ROM と同じに戻ったマップは、JSON があれば消します。
- タイルセット（ブロックエディタで変えたもの）は `maps\tilesets\<primary|secondary>_<ヘッダーの位置>\tileset.json` と `tiles.png` に書きます（Bochi と同じ形式）。ベース ROM と同じに戻ったら消します。同じタイルセットを使うマップはどれも、次に開いたときからこの内容で読みます。
- 何か書くときに `maps\project.json` が無ければ作ります。
- タウンマップの変更は `maps\regionmap.json` に書きます（上の「ワールドマップエディタ」）。
- ベース ROM には書き込みません。

## 構成

- `packages/core`: ROM の解析・描画・操作コマンド（TypeScript。Node とブラウザの両方で動く）
- `apps/desktop`: デスクトップアプリ（Tauri 2 + Vite + 素の TypeScript）。`src/windows/` が別ウィンドウ（`block-editor/`・`palette-editor/`・`block-adjust/`、メインとの同期は `ToolWindowHost`・`ToolClient`・`protocol`）

## 開発

Node.js 22 以降、pnpm、Rust（1.96 以降）、WebView2 が必要です。

```sh
pnpm install
pnpm typecheck   # 型チェック
pnpm test        # 単体テスト
```

画面の文言を変えるときは、`apps/desktop/src/i18n/source/Japanese.ini`（UTF-8）を直すか差し替えて、文言のモジュール `apps/desktop/src/i18n/ini.generated.ts` を作り直し、両方をコミットします。`ja*.ts` は生成物の値を `ini.節["番号"]` で引いています。

```sh
node scripts/gen-i18n.mjs          # ini.generated.ts を作り直す
node scripts/gen-i18n.mjs --check  # ini と生成物が合っているか確かめる
```

- 値の中の AdvanceMap 1.95 向けの注記（「(AM1.95未使用)」「(※AM1.95使用不可)」）は外します。外し方は `scripts/gen-i18n.mjs` の `stripNote` だけで決めています。行末の空白も外します。
- 注記を外して空になった番号と、ini に無い番号は生成物に入りません。`ja*.ts` がそれを引いていると型チェック（`pnpm typecheck`）で止まるので、旧版の文言を直接書くか、ini に足してください。
- ルビー・サファイア・エメラルドの挙動や季節など、ZigzaguMap に該当する機能の無い節は出しません（`EXCLUDED_SECTIONS`）。

ROM が要るテストは、環境変数 `ZIGZAGU_TEST_ROM` に素の BPRJ のパスを入れたときだけ実行されます。ROM はリポジトリに入れません。

```powershell
$env:ZIGZAGU_TEST_ROM = "C:\path\to\BPRJ.gba"; pnpm test
```

ND のベース ROM と NeoDark-CFRU のフォルダを `ZIGZAGU_TEST_ND_ROM` と `ZIGZAGU_TEST_ND_PROJECT` に入れると、`maps\` の JSON を読むテストも実行されます（フォルダには書き込みません）。

コアライブラリを Node から使うときは `pnpm --filter @zigzagumap/core build` で `dist` を作ります（`@zigzagumap/core` と `@zigzagumap/core/node`）。マップを PNG に書いて確かめるには次のようにします。

```sh
pnpm --filter @zigzagumap/core dump-map -- <rom> 3 0 out.png --events
pnpm --filter @zigzagumap/core dump-map -- <rom> 3 0 out.png --project <CFRU-JP のフォルダ>
```

アプリの起動とビルド:

```sh
cd apps/desktop
pnpm tauri dev     # 開発用に起動（自動操作の入口がポート 17890 で有効になる）
```

リリース用の exe は `scripts\build.cmd` で作ります（`apps/desktop/src-tauri/target/release/zigzagumap.exe`）。Visual Studio Build Tools の `vcvars64.bat` を読んでから `pnpm tauri build` を実行するので、cmd・PowerShell・Git Bash のどれからでも動きます（Git Bash だけで `pnpm tauri build` を実行すると、Git 付属の `link.exe` が先に見つかって失敗します）。

```sh
scripts\build.cmd          # リリースビルド
scripts\build.cmd debug    # デバッグビルド
scripts\build.cmd check    # cargo check だけ
```

出力先を変えたいときは、環境変数 `CARGO_TARGET_DIR` を設定してから実行します（exe は `<CARGO_TARGET_DIR>\release\zigzagumap.exe` にできます）。

コードの置き場所（`apps/desktop/src`）:

- `app/`: 状態（`EditorState`）、ROM とプロジェクト（`ProjectSession`、`TauriProjectFs`）、マップ一覧の組み立て（`MapCatalog`、`MapTreeModel`）、メニューの定義とアクション、設定、自動操作
- `ui/`: メニューバー、ツールバー、マップ一覧、タブ、ステータスバー、`ui/map/`（マップ表示・パレット・重ね描き）、`ui/tabs/`（各タブ）、`ui/event/`（イベントタブ: 共通部、種別ごとのパネル、マップ上の操作、イベントマネージャー）、`ui/form/`（16 進欄・スピン・コンボなどの入力部品）
- `input/`: マウス操作（ブロック・移動許可の配置）
- `styles/`: 部品ごとの CSS
- 画面の操作はすべて `packages/core` の操作コマンド（`paintBlocks`、`paintMovement`、`paintBorder` など）を CommandBus で実行します

## 自動操作の入口（テスト用）

開発ビルドか、起動引数 `--automation <ポート>` を付けたときだけ、`127.0.0.1:<ポート>` で HTTP の POST を受け付けます（通常の起動では待ち受けません）。リリースの exe に付けたときは、操作を奪わないようウィンドウを画面外に出し、アクティブにしません。

```sh
zigzagumap.exe --automation 17891
node scripts/automation-client.mjs 17891 '{"cmd":"state"}'
node scripts/automation-client.mjs 17891 '{"cmd":"screenshot"}' shot.png
```

本文は JSON 1 件で、返事は `{"ok":true,"result":...}` か `{"ok":false,"error":"..."}` です。

| cmd | 引数 | 動作 |
|---|---|---|
| `open` | `rom`、`project`（省略可） | ROM（とプロジェクトフォルダ）を開く。返事は `state` と同じ |
| `selectMap` | `bank`、`map` | マップを開く。返事の `switchMs` は切り替えにかかった時間 |
| `tab` | `name`（`map` / `movement` / `event` / `wild` / `header`） | タブを切り替える |
| `command` | `name`、`args` | CommandRegistry のコマンドを実行する（例: `{"cmd":"command","name":"paintBlocks","args":{"bank":3,"map":0,"cells":[{"x":5,"y":5,"block":9}]}}`） |
| `undo` / `redo` | | 元に戻す／やり直す |
| `export` | `dir`（素の ROM では必須） | 出力する。返事は書いたファイルと消したファイル |
| `selectBlock` | `block`、または `blocks` と `width` | 選択中のブロックを変える |
| `action` | `id` | メニューのアクションを実行する（例: `view.grid`） |
| `key` | `key`、`ctrl`・`alt`・`shift`、`id`（省略可） | キー操作をまねる（メニューの確認用）。`id` を付けるとその部品へ送る（トラックバーの PageUp など） |
| `getField` | `id` | 部品（`data-auto-id` 属性の ID）の状態。返事は `value`（入力欄の文字、コンボは選んでいる項目の文字、チェックは true / false、ラベルは文字）、`enabled`、`visible`、コンボなら `index` と `options`（64 件を超えるときは件数） |
| `setField` | `id`、`value` | 部品に値を入れ、人が入力したときと同じく `input` → `change` を送る。コンボは番号か項目の文字、チェックは true / false。返事は `getField` と同じ |
| `click` | `id` | ボタンなどを押す（無効なら失敗） |
| `canvasPng` | `tab`（省略時は表示中のタブ） | マップ表示の Canvas（重ね描きとグリッドを含む）を PNG（Base64）で返す |
| `screenshot` | | ウィンドウ全体を PNG（Base64）で返す（PrintWindow で取るので前面に出さない） |
| `cells` | | 表示中のマップの配置とボーダーの値 |
| `state` | | 開いている ROM・プロジェクト・マップ、タブ、選択中のブロック、未出力のマップ、履歴の数、ステータスバー、時間の記録 |
| `dialog` | `input`、`press`（どちらも省略可） | 画面内のダイアログ（入力・確認・エラー・ヘルプの窓）を読む。`input` で入力欄に入れ、`press` でボタンを押す（ボタンの文字列か `ok`・`yes`・`no`・`cancel`。`close` で ×）。返事は開いているダイアログの一覧 |
| `queuePath` | `path`（null でキャンセル） | 次に出るファイル・フォルダのダイアログで選ぶパスを積む（Windows のダイアログは出さない） |
| `pointer` | `target`（`map` / `movement` / `event` / `palette`）、`type`（`down` / `move` / `up`）、`x`・`y`（部品の左上からの表示上のピクセル）、`button`、`ctrl`、`shift` | マウス操作をまねる。返事はステータスバー |
| `exit` | | 確認なしで終了する |
| （ブロックエディタなど宛て） | `window`（`block-editor` / `palette-editor` / `block-adjust`）と各命令の引数 | `window` を付けると、そのウィンドウで命令を実行する（仕組みはワールドマップエディターと同じ。下の段落）。使える命令は `state`（欄の値）、`getField` / `setField` / `click`、`action`（メニューの項目。ブロックエディタの `tiles.save1`・`blocks.amount`・`palette.commit` など）、`dialog`、`queuePath`、`key`、`pointer`（`id` の部品の上。`x`・`y` は部品の左上から）、`canvasPng`（`id` の Canvas）、`snapshot`（メインから届いたタイルセットの写し）、`close`、`undo` / `redo`。`screenshot` も `window` で別ウィンドウを取れる。パレットエディタだけ `pickAt`（`source` のウィンドウの画像の `x`・`y` の色をスポイトで拾う） |
| `ui.list` | `root`（省略可） | 部品の一覧（`data-auto-id` の ID、値、有効か、表示されているか）。`root` に ID を渡すとその中だけ |
| `ui.type` | `id`、`text` | 1 文字ずつ入力する |
| `ui.shot` | `id` | 部品の範囲の画像を PNG（Base64）で返す（例: `event.panel` でイベントタブの右パネル） |
| `setting` | `key`、`value` | 個人設定の値をこの起動の間だけ変える（ファイルには保存しない） |
| `event.select` | `kind`（`person` / `sign` / `warp` / `trap` / `fly`）、`index` | イベントを選ぶ |
| `event.mouse` | `action`（`click` / `drag` / `dblclick` / `hover`）、`x`、`y`、`toX`、`toY` | マップ上のマウス操作（座標はマス）。返事は選択（`hover` はステータスバー） |
| `event.state` | | 選択中の種別と番号、個数、表示中のマップのイベントと落とし物、最後に起動したスクリプトエディター |

イベントタブの部品の ID（`getField` / `setField` / `click` の `id`）は `event.kind`、`event.number`、`event.cursor`、`event.remove`、`event.person.x` のような形です（`event.<種別>.<欄>`、イベントマネージャーは `event.manager.persons` と `event.manager.apply`）。

部品の ID は `<場所>.<名前>` の形です（例: 場所の設定タブ `header.music`・`header.saveScripts`、高度な表示 `pro.footer`・`pro.saveFooter`、コネクションマネージャー `conn.direction`・`conn.save`・`conn.down1`、出現ポケモンタブ `wild.type`・`wild.rate`・`wild.rateBar`・`wild.min.1`・`wild.species.1`・`wild.save`、追加ダイアログ `wildAdd.0`〜`wildAdd.3`・`wildAdd.ok`、ブロックエディタ `be.blocks`・`be.tiles`・`be.block`・`be.palette`・`be.xflip`・`be.attr0`〜`be.attr3`・`be.behavior`・`be.save`、パレットエディタ `pal.color.0`〜`pal.color.15`・`pal.red`・`pal.hex`・`pal.apply`・`pal.pick`、一括変更 `adj.tileset2`・`adj.to.0`〜`adj.to.14`・`adj.save`）。一覧は各部品を作るコードの第 1 引数です。

### 別ウィンドウ（ワールドマップエディタ）

要求に `"window": "world-map"` を付けると、そのウィンドウへ送ります（`screenshot` に付けるとそのウィンドウを撮る）。`{"cmd":"windows"}` は開いているウィンドウの一覧（`label`、`title`、`visible`、`ready`）です。部品の ID は AdvanceMap の部品名（`Txt_Wert`、`Cbo_Wert_NamenListe`、`Txt_PosX`、`Cmd_NameSpeichern`、`Txt_FlugWert`、`Cmd_GotoFlugPos`、`Cbo_Anzahl`、`WorldmapBox` など。トップレイヤーは名前の後ろに `2`）です。

| cmd | 引数 | 動作 |
|---|---|---|
| `state` | | 読み込んだか、面、選んでいるマス、両レイヤーの値、マスの値、地名の位置と行き先、メインで開いているマップ、履歴の有無 |
| `fields` / `getField` | `id`（getField） | 部品の値（`value`・`checked`・`text`・`enabled`、コンボは `index` と `count`） |
| `setField` | `id`、`value` | 入力欄は文字列、チェックは true/false、コンボは番号か文字列。input と change を起こす |
| `click` | `id` | ボタンを押す。返事は開いているダイアログ |
| `pointer` | `id`、`type`（`down` / `move` / `up`）、`x`・`y`、`button` | 部品の左上からの位置でマウス操作をまねる（世界地図は 1 マス 8px、マス (0,0) が (32,32)） |
| `canvasPng` | `id`（`WorldmapBox`） | 世界地図の Canvas を PNG（Base64）で返す |
| `key` | `key`、`ctrl`・`alt`・`shift`、`id`（省略時はフォーカスのある部品） | キー操作をまねる |
| `dialog` | `input`、`press` | メインと同じ |

画面側の準備ができる前の要求には `{"ok":false,"error":"画面の準備ができていません"}` を返します。

## 比較テスト

AdvanceMap 1.92 日本語版と ZigzaguMap に同じ操作をさせ、途中の状態（マップ表示領域の画像、入力欄・一覧の値、ダイアログの有無）を比べます（`tests/compare`）。出力まで進めることは確かめますが、出力物の中身は比べません。Windows だけで動きます。

- AdvanceMap は見えない別のデスクトップで起動し、ウィンドウメッセージだけで操作します（`tools/am-harness`）。ZigzaguMap は `--automation` 付きで画面外・非アクティブに起動し、自動操作の入口（ポート 17930〜17939 の空き）から操作します。どちらもユーザーのマウス・キーボードは使いません。
- ROM はシナリオごとに、未編集の ROM から作業用のコピーを作って使います（AdvanceMap が保存しても元は変わりません）。

### 準備

1. リポジトリの外に作業フォルダを作り、AdvanceMap 1.92 日本語版のコピーと素の BPRJ のコピーを置きます（AdvanceMap 本体・ROM・画面キャプチャはリポジトリに入れません）。
2. `pip install -r tools/am-harness/requirements.txt`（Pillow と numpy。仮想環境はリポジトリ外か `.venv`）。
3. `tests/compare/local.config.example.json` を `tests/compare/local.config.json` にコピーし、パスを直します（`.gitignore` 対象）。環境変数でも上書きできます。

| 項目 | 環境変数 | 内容 |
|---|---|---|
| `amSourceDir` | `ZZM_CMP_AM_SRC` | AdvanceMap のコピー（ここから `amWorkDir` を作る） |
| `amWorkDir` | `ZZM_CMP_AM_DIR` | 比較テスト専用の AdvanceMap（Ini の表示設定は毎回戻す） |
| `romOriginal` | `ZZM_CMP_ROM` | 素の BPRJ（読むだけ） |
| `scriptEditorStub` | `ZZM_CMP_STUB` | スクリプトエディタの代わりの exe（省略可） |
| `zigzaguExe` | `ZZM_CMP_EXE` | ZigzaguMap の exe（既定は `apps/desktop/src-tauri/target/release/zigzagumap.exe`） |
| `resultsDir` | `ZZM_CMP_RESULTS` | 結果の置き場（既定はリポジトリの隣の `compare-results`） |
| `keepRuns` | | 残す結果の数（既定 5。これより古い結果は summary に削除候補として書く。自動では消さない） |

exe のビルド出力を別のドライブに置くときは、`CARGO_TARGET_DIR` を設定してから `scripts\build.cmd` を実行し、`zigzaguExe` にその下の `release\zigzagumap.exe` を書きます。

### 実行

```sh
python tests/compare/run.py                         # 全シナリオ
python tests/compare/run.py --scenario S04 S08      # 名前の先頭で選ぶ
python tests/compare/run.py --only-zigzagu          # ZigzaguMap だけ動かし、AdvanceMap は前回の結果と比べる
python tests/compare/run.py --list-ops              # 抽象操作 → 実操作の対応表
python tests/compare/file_issues.py <結果フォルダ>   # 失敗したシナリオを issue にする（--dry-run で本文だけ表示）
```

失敗かエラーがあると終了コード 1 になります。`file_issues.py` は失敗したシナリオごとに issue（ラベル「テスト失敗」、マイルストーン「Phase1」）を作り、同じ題名の issue が開いていればコメントを足します。画像は上げず、結果フォルダ内のパスだけを書きます。

### シナリオ

`tests/compare/scenarios/*.json` に 1 本ずつ書きます。`name`、`title`、`issues`（関連する issue 番号）、`steps`（両アプリに共通の抽象操作の列）を持ちます。

```json
{"op": "selectMap", "bank": 3, "map": 0}
{"op": "selectBlock", "block": 9}
{"op": "dragPaint", "from": [2, 6], "to": [9, 9]}
{"op": "snapshot", "name": "after_drag", "target": "map"}
{"op": "compareFields", "fields": ["status.left", "title.map", "map.size"]}
```

操作の一覧と各アプリでの実現方法は `--list-ops` で出ます（定義は `tests/compare/lib/ops.py`、変換は `lib/drivers.py`）。ZigzaguMap の自動操作の入口にマウス操作の命令がないため、クリックやドラッグはコマンドで「代用」しています（代用した後はステータスバーの比較を「未対応」にします）。メニューの対応は `tests/compare/zigzagu_menu.json` です。

画像の比べ方（`snapshot` の `compare`）:

- `gba`（既定）: 各色を 5bit に落として画素ごとに比べる（AdvanceMap と ZigzaguMap で 8bit への広げ方が違うため）
- `cellMean`: マスごとの平均色で比べる（移動許可の文字の字形の違いを許す）
- `overlayCells`: ブロックだけの画像との差から「重ね描きのあるマス」を求め、その位置だけ比べる（イベントの箱の色や形は比べない）
- `target` に `blocks` を指定すると、どのタブにいてもブロックだけの画像（マップタブ）を比べる

入力欄の値は、全角・半角の空白、16 進の大文字小文字、先頭の `$` や `0x` をそろえてから比べます。

### 結果の見方

`<resultsDir>/<日時>/` に出ます。

- `summary.md` / `summary.json`: シナリオごとの判定と件数、失敗の中身
- `<シナリオ>/report.md`: ステップごとの両者の状態、値の対応表、画像のパス
- `<シナリオ>/<名前>.diff.png`: 左 AdvanceMap、中 ZigzaguMap、右 差分（赤 = 違う画素、黄の枠 = 違うマス）
- `<シナリオ>/advancemap/`・`zigzagu/`: 各スナップショットと窓全体の画像、`steps.json`

判定は「合格」（比べたものがすべて同じ）、「失敗」（違う、または ZigzaguMap がエラーを返した）、「未対応」（失敗はないが、比べられない手順がある）、「エラー」（AdvanceMap 側の操作が通らなかった。テスト側の問題）です。
